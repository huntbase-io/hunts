UAT-12643 Stager Abuse and Registry Persistence

High severity TLP:CLEAR Part 1 of 2 Research by Cisco Talos Published 19 Nov 2026

Hypothesis

An adversary is using signed Windows binaries to stage payloads on hosts running targeted software, establishing persistence through masqueraded Edge updater binaries in user-writable paths.

Brief

Why now

Cisco Talos recently published a report on UAT-12643, a suspected North Korea-aligned actor targeting blockchain users. The adversary uses signed binaries and masquerading to bypass standard security controls, focusing their efforts on users of specific VoIP and messaging applications.

How the hunt flows

The first phase filters the fleet for hosts running targeted software like Viber or MicroSIP. This scoping concentrates the hunt on the actor's preferred entry points and reduces the volume of data processed in later stages.

Next, the hunt queries for LOLBin abuse. It identifies processes like certutil, MpCmdRun, mshta, or MSBuild performing remote downloads or executing scripts. These signed binaries often evade basic execution blocks, but their command-line arguments reveal suspicious staging behavior.

If the lead query finds suspicious activity, the hunt pivots to registry and file activity. It searches for the MsgEdgeUpdate run key and identifies rare binaries in AppData or Temp folders. This correlates the initial staging behavior with the establishment of long-term presence on the endpoint.

Finally, an analyst or automated agent synthesizes the results. They confirm if the rare binaries match the actor's known masquerading patterns and determine if the full stager-to-persistence chain exists on the host.

What this hunt cannot see

This hunt relies on command-line and registry telemetry. If an environment lacks argument logging for MpCmdRun or registry write events, the stager and persistence steps cannot confirm the threat. The hunt also misses activity if the adversary uses MSBuild to compile and execute code entirely in memory without writing files to disk.

Blind spots

  • Needs hb_process_activity with command-line arguments. If command-line arguments are not logged, the download behavior of LOLBins is indistinguishable from routine execution. It would answer: whether MpCmdRun was used to download a file
  • Needs hb_registry_activity with set-value logging. Hosts without registry write event logging will hide the creation of persistence mechanisms. It would answer: whether the MsgEdgeUpdate run key was created
  • Needs AMSI logs or memory scan. The MSBuild downloader leaves no file on disk, making it invisible to file-based scanners and standard process-path monitors. It would answer: whether MSBuild compiled and executed C# directly in memory

# UAT-12643 Stager Abuse and Registry Persistence

This hunt identifies the execution of Living-off-the-Land Binaries used by UAT-12643 to download and stage malware. It begins by scoping hosts with targeted messaging and VoIP software, then lead-queries for certutil, MpCmdRun, and MSBuild abuse. If suspicious stagers are found, the hunt fans out to correlate these with rare binaries in user-profile directories and the specific registry run key 'MsgEdgeUpdate'. An agent synthesizes the staging and persistence evidence to route high-confidence hits to host isolation.
