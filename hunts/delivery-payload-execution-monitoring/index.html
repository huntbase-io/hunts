Delivery and Payload Execution Monitoring

An adversary has established initial access through a compromised supply chain or a phishing attachment, resulting in unusual package installations or rare process execution from browser-originating downloads.

Brief

Why this hunt?

Adversaries often bypass perimeter security by exploiting the human element or the software supply chain. The Unit 42 report, Top 5 Initial Access Threat Vectors Observed by Unit 42 in September 2026 (https://unit42.paloaltonetworks.com/top-5-initial-access-vectors-september-2026/), highlights that phishing and supply chain lures remain primary entry points. We designed this hunt to identify the footholds these vectors create on the endpoint.

How the Hunt Flows

The hunt begins with a scoping phase that inspects the hb_application_lifecycle surface. The first query identifies unusual or unsigned software installations, focusing on packages that lack valid signer subjects or originate from external HTTP URIs. This step narrows the investigation to hosts where potentially malicious software recently entered the environment.

After identifying candidate hosts, the hunt pivots to two parallel evidence-gathering streams. One stream queries hb_process_activity for rare processes running from user-writable paths like Downloads, Temp, or Public folders. By calculating the prevalence of these paths across the fleet, the hunt filters out common installers and highlights unique binaries that may represent a payload execution.

The second parallel stream monitors hb_file_activity to corroborate the delivery method. It searches for browser or mail processes writing files with executable or container extensions, such as .exe, .msi, or .iso. This provides the context needed to determine if a rare process launch originated from a recent download.

The final phase uses an automated agent to weigh the evidence from all three surfaces. The agent evaluates the installation history, the rare process launches, and the browser activity per host to produce a final verdict. This automated triage connects the delivery and execution events, reducing the time an analyst spends manually linking logs.

What the Hunt Cannot See

This hunt relies on specific endpoint telemetry. If a host lacks an active agent, it provides no signals and remains an invisible foothold. Furthermore, the application lifecycle surface primarily captures MSI and AppX installations; the hunt may miss legacy standalone executable installers that do not register through these providers.

    What a hit looks like. A row indicates an unsigned or potentially external package was installed. Silence proves no such installations were logged by the AppX or MSI providers.

  2. Rare processes from user-writable paths

    Query · baseline

    Find executables running from Downloads, Temp, or Public folders that are rare across the fleet, suggesting a user-initiated payload.

    reads hb_process_activitysql
    SELECT device_hostname, process_path, time FROM hb_process_activity WHERE (LOWER(process_path) LIKE '%\\downloads\\%' OR LOWER(process_path) LIKE '%\\temp\\%' OR LOWER(process_path) LIKE '%\\users\\public\\%') AND LOWER(process_path) IN (SELECT LOWER(process_path) FROM hb_process_activity WHERE (LOWER(process_path) LIKE '%\\downloads\\%' OR LOWER(process_path) LIKE '%\\temp\\%' OR LOWER(process_path) LIKE '%\\users\\public\\%') AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY 1 HAVING COUNT(DISTINCT device_hostname) <= 3) AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A binary seen on only one or two hosts in a user-writable path. High host counts likely indicate legitimate temporary software like installers or updaters.

  3. Suspicious file downloads from browsers

    Query · enrichment

    Corroborate phishing lures by identifying browser or mail processes writing files with executable or container extensions.

    reads hb_file_activitysql
    SELECT device_hostname, process_name, file_path, file_name, time FROM hb_file_activity WHERE instr(',' || '{{browser_processes}}' || ',', ',' || LOWER(process_name) || ',') > 0 AND (LOWER(file_name) LIKE '%.exe' OR LOWER(file_name) LIKE '%.msi' OR LOWER(file_name) LIKE '%.zip' OR LOWER(file_name) LIKE '%.iso' OR LOWER(file_name) LIKE '%.vbs' OR LOWER(file_name) LIKE '%.js' OR LOWER(file_name) LIKE '%.msix' OR LOWER(file_name) LIKE '%.appx' OR (instr(file_name, '.') > 0 AND instr(',' || '{{phishing_extensions}}' || ',', ',' || LOWER(SUBSTR(file_name, INSTR(file_name, '.'))) || ',') > 0)) AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Rows mapping a browser or mail client to a newly written payload file. Silence does not prove absence if the adversary used a non-standard download method.

# Delivery and Payload Execution Monitoring

Adversaries frequently bypass perimeter defenses by exploiting trusted software distribution channels or using social engineering to deliver payloads directly to the endpoint. This hunt monitors for these footholds by identifying unusual software installation events (supply chain leads) and corroborating them with browser-originating file activity and rare process launches in user-writable paths. An agent then evaluates the combined evidence per host to distinguish legitimate software deployment from malicious intrusion.
