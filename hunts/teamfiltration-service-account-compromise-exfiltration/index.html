TeamFiltration Service Account Compromise and Exfiltration

An adversary has compromised functional service accounts via credential spraying to bypass MFA, then used these ghost identities to exfiltrate bulk data from M365 and discover administrative portals.

Brief

Recent research by Proofpoint, Ghost Service Accounts Enable M365 Data Theft in Chile (https://www.proofpoint.com/us/newsroom/news/ghost-service-accounts-enable-m365-data-theft-chile), describes a campaign where attackers use the TeamFiltration toolkit to target service accounts. These accounts are often ghost identities—functional accounts created for specific tasks but left without multifactor authentication (MFA). Because these accounts are not tied to a human user, their compromise often goes unnoticed. This hunt provides a systematic way to find these vulnerabilities and the subsequent data theft.

The Scoping Phase

The hunt begins by identifying the attack surface. The first query scans the user directory for accounts containing keywords like svc, bot, payment, or admin that do not have MFA enabled. This step provides the list of candidate ghost accounts that the adversary is likely to target. By narrowing the scope to these high-risk identities, we reduce the noise in subsequent authentication and API queries.

Authentication Triage

Once we have a list of vulnerable accounts, the hunt pivots to authentication logs. It runs two queries in parallel. The first query looks for patterns of credential spraying, specifically identifying accounts that receive a high volume of login failures from multiple distinct IP addresses. This matches the rotation strategy used by the TeamFiltration toolkit. The second query looks for successful logons to the same accounts from rare or new IP addresses. An analyst then compares these two results to confirm if a spray attempt resulted in a successful compromise.

Identifying Cloud Impact

After identifying a potential compromise, the hunt examines cloud API activity. It searches for high-volume operations associated with data exfiltration, such as accessing mail items, downloading files, or starting Teams sessions. It also flags any activity involving administrative portals. Service accounts rarely need to browse the Azure portal or the M365 admin center; such activity strongly suggests an adversary is performing discovery to find higher-privilege targets or additional data sources. This correlation of identity vulnerability with cloud impact is why this is a hunt, not a simple detection rule.

Review and Containment

The hunt concludes with a tiered review. An automated agent evaluates the correlation between the authentication anomalies and the cloud API activity. If the agent confirms malicious behavior, the playbook routes the case to a containment action. This action disables the compromised account and revokes all active sessions. A final task directs a human analyst to perform a forensic audit of the specific files and emails accessed, ensuring the organization meets any regulatory disclosure requirements.

Blind Spots

The primary blind spot is the latency of the Microsoft 365 Unified Audit Log (UAL). Logs can take up to 24 hours to appear in the telemetry stream, meaning an active exfiltration event might not be visible until a day after it starts. Additionally, this hunt only sees VPN activity if the VPN logs are integrated into the normalized authentication surface.

    What a hit looks like. A list of service-named accounts with MFA disabled. Silence suggests all service-named accounts are properly hardened.

  2. Credential spraying precursors

    Query · detection candidate

    Detect accounts receiving authentication failures from multiple source IPs, indicating TeamFiltration's rotation strategy.

    reads hb_auth_signinsql
    SELECT actor_user_name, COUNT(*) as failure_count, COUNT(DISTINCT src_endpoint_ip) as ip_count FROM hb_auth_signin WHERE activity_id = 5 AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY actor_user_name HAVING ip_count >= 2 AND failure_count > 10 ORDER BY failure_count DESC

    What a hit looks like. A single account being targeted by multiple IPs with high failure counts. Silence proves no high-volume spraying occurred.

  3. Rare successful logons to ghost accounts

    Query · baseline

    Identify successful authentications to candidate ghost accounts from IPs that have not successfully logged in before.

    reads hb_auth_signinsql
    SELECT actor_user_name, src_endpoint_ip, device_hostname, COUNT(*) as successes, MIN(time) as first_seen FROM hb_auth_signin WHERE activity_id = 1 AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY actor_user_name, src_endpoint_ip, device_hostname HAVING successes < 5 ORDER BY first_seen DESC

    What a hit looks like. A successful logon from a new or rare IP address to a service identity. Silence suggests no compromise via new infrastructure occurred.

  4. Early stage impact read

    Agent triage

    Confirm which ghost accounts are compromised by correlating identity vulnerabilities with authentication anomalies.

  5. Portal discovery and data exfiltration

    Query · enrichment

    Identify follow-on activity by the potentially compromised accounts, specifically administrative portal browsing and bulk data access.

    reads hb_cloud_api_activitysql
    SELECT actor_user_name, api_operation, api_service_name, COUNT(*) as op_count, MIN(time) as first_op, MAX(time) as last_op FROM hb_cloud_api_activity WHERE (instr(',' || '{{exfil_operations}}' || ',', ',' || api_operation || ',') > 0 OR LOWER(api_service_name) LIKE '%portal%' OR LOWER(api_operation) LIKE '%portal%') AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY actor_user_name, api_operation, api_service_name HAVING op_count > 10 ORDER BY op_count DESC

    What a hit looks like. High counts of bulk data access operations or unusual administrative portal activity from service accounts. Silence means no follow-on activity was recorded.

  6. Final impact assessment

    Agent triage

    Synthesize the authentication findings with the cloud API activity to confirm malicious intent and scope data theft.

  7. Route on verdict

    Decision

    Determine whether to trigger immediate containment based on the agent's impact assessment.

  8. Revoke and disable compromised accounts

    Response action

    Halt active data theft by terminating the adversary's sessions and disabling the compromised identities.

  9. Forensic audit and disclosure review

    Analyst task

    Analyze the exact rows cited by the agents to determine what data was accessed and whether regulatory disclosure is required.

  10. Enforce service account hardening

    Response action

    Close the security gap that allowed the compromise by hardening all remaining functional identities.

# TeamFiltration Service Account Compromise and Exfiltration

This hunt identifies the lifecycle of a TeamFiltration campaign, which targets overlooked service accounts that lack multifactor authentication. The hunt follows a phased approach: it first scopes for potential service identities and identifies brute-force patterns and successful logons from new infrastructure. It then pivots to cloud API activity to detect administrative discovery (Azure/M365 portals) and automated data theft from Outlook, Teams, and SharePoint. A tiered agent review evaluates initial access before determining the final scope of exfiltration and triggering automated containment.
