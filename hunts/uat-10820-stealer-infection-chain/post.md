# Hunting UAT-10820 Multi-Stage Stealer and RMM Infection Chains

### The Context of UAT-10820 Compromise 13; 13;Cisco Talos recently detailed a multi-stage infection chain in their article, [We've got one word for it, and it's usually the wrong one](https://blog.talosintelligence.com/weve-got-one-word-for-it-and-its-usually-the-wrong-one/). The report describes an adversary using deceptive social engineering scripts to mount WebDAV shares, which lead to the deployment of the Amatera stealer and persistent remote access tools. This activity involves specific evasion techniques like rundll32 ordinal loading and the use of vulnerable drivers to disable endpoint security. 13; 13;### Hypothesis 13; 13;An intruder infects an endpoint using a WebDAV social engineering chain, followed by the execution of disguised DLLs via rundll32 ordinals and the installation of unauthorized RMM tools for persistence. 13; 13;### How the Hunt Flows 13; 13;The hunt begins by filtering the estate for Windows workstations and servers. This scoping ensures the subsequent queries target systems where WebDAV mounting and DLL loading are viable attack vectors. 13; 13;The first analysis phase runs two queries in parallel to catch the infection at the point of execution. The first search scans script activity logs for command blocks that use `net use` or `dav` keywords alongside script execution. This targets the specific behavior of users pasting encoded commands to mount remote attacker-controlled shares. The second query baselines `rundll32.exe` activity across the environment to find rare command lines using ordinal calls (e.g., `,#1`) rather than named function exports. This tactic often disguises the loading of malicious payloads like Amatera. 13; 13;The second phase pivots to persistence and defense evasion markers on any hosts identified in the previous step. The hunt searches for NetSupport Manager (client32.exe) and other RMM tools running from unusual, user-writable directories like AppData or Temp. Simultaneously, it inspects kernel driver activity for the loading of known vulnerable drivers. These drivers, such as those from Process Explorer or IObit, are frequently part of Bring Your Own Vulnerable Driver (BYOVD) attacks aimed at terminating security agents. 13; 13;Finally, an automated agent correlates these findings. It connects the early script execution signals to the rare process commands and the eventual RMM persistence. This links the entire intrusion chain into a single verdict for the analyst. 13; 13;### What the Hunt Cannot See 13; 13;This hunt has two primary blind spots. First, it cannot inspect the contents of encrypted WebDAV traffic. If the initial access does not leave clear script telemetry, the hunt relies entirely on the rundll32 and driver-loading signals. Second, it misses stealers that remain only in memory once the initial loader process terminates. Confirming the presence of memory-resident Amatera components requires live memory forensics or specialized memory scanning. 13; 13;### How to Run This Hunt 13; 13;This hunt is an open-source `hunt.md` playbook. You can import it directly into Huntbase or use any runtime that supports the `hunt.md` format. It requires Windows process activity, script execution logs, and kernel driver telemetry to provide full coverage of the UAT-10820 chain.
