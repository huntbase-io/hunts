Unauthorized ScreenConnect Client Deployment

High severity TLP:CLEAR Part 1 of 2 Research by Microsoft Published 14 Nov 2026

Hypothesis

An intruder has abused ScreenConnect management consoles or extension vulnerabilities to silently deploy unauthorized remote-access clients and the SCKit loader toolkit to managed endpoints.

Brief

Why now

High-trust administrative tools like ScreenConnect are frequent targets for abuse. Microsoft recently published research on SCKit (https://www.microsoft.com/en-us/security/blog/2026/11/13/sckit-abuses-screenconnect-deploy-remote-access-target-technician-sessions/), a toolkit attackers use to deploy unauthorized remote access clients. These deployments often bypass traditional identity perimeters by using existing management infrastructure.

How the hunt flows

The first phase scopes the estate by inventorying hosts that run ScreenConnect or ConnectWise software. This inventory identifies the potential attack surface and focuses the hunt on endpoints where the software is already present or recently installed. This scoping ensures the subsequent, more detailed queries target relevant hosts rather than the entire fleet.

The hunt then pivots to find leads involving silent MSI installations. It specifically searches for command lines containing sc.msi or session markers such as c=Exploited. These leads, often initiated via curl or msiexec, provide high-confidence indicators of unauthorized deployment activity rather than standard software updates. This phase acts as a filter to capture high-confidence signals of abuse.

An analyst evaluates these leads to determine if the command structure matches patterns seen in SCKit research. This manual gate is critical. It ensures that the hunt only proceeds to more resource-intensive queries when a lead appears suspicious. This prevents the noise of legitimate MSP maintenance from overwhelming the triage process.

If the lead passes the evaluation gate, the hunt gathers evidence in parallel. One query examines PowerShell script blocks for known SCKit loaders like stage0loader.ps1 or lateral movement scripts. Simultaneously, another query stacks MSI installation commands across the entire fleet to identify rare outliers. Legitimate management activity usually appears on dozens of hosts, while SCKit deployments typically target a specific subset of the estate.

The final phase correlates the behavioral lead with the script content and prevalence data. An analyst reviews the combined evidence to reach a final verdict. If the activity is confirmed as malicious, the hunt provides instructions for immediate host isolation and forensic capture. This structured approach moves from broad scoping to surgical response based on corroborated evidence.

What the hunt cannot see

This hunt relies on agent coverage. It cannot identify unauthorized clients installed on unmanaged endpoints, which could serve as blind beachheads. Furthermore, while the hunt detects the SCKit loader scripts, it requires PowerShell Script Block Logging (Event ID 4104) to see the actual commands executed after the scripts are decrypted in memory. Without this logging, the hunt confirms the presence of the toolkit but not the specific actions taken by the intruder.

Steps

  1. Query, scoping

    Scope ScreenConnect installations

    Find the hosts that currently have ScreenConnect or ConnectWise software to narrow the hunt scope.

    sql, reads hb_software_inventory
    SELECT device_hostname, package_name, package_versionFROM hb_software_inventoryWHERE (LOWER(package_name) LIKE '%screenconnect%' OR LOWER(package_name) LIKE '%connectwise%')

    What a hit looks like. A list of hosts with ScreenConnect installed. Presence of the software is expected; silence means the software is not inventoried or is missing from the estate.

  2. Query, detection candidate

    Lead: Silent MSI deployment with exploited markers

    Identify suspicious MSI installations involving sc.msi or session markers like c=Exploited initiated via curl or msiexec.

    sql, reads hb_process_activity
    SELECT device_hostname, process_cmd_line, user_name, timeFROM hb_process_activityWHERE (LOWER(process_cmd_line) LIKE '%sc.msi%' OR LOWER(process_cmd_line) LIKE '%c=exploited%')  AND (LOWER(process_cmd_line) LIKE '%msiexec%' OR LOWER(process_cmd_line) LIKE '%curl%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Command lines showing curl downloading sc.msi or msiexec installing it silently. The presence of session markers in the URL is a high-confidence lead.

  3. Agent triage

    Evaluate MSI installation lead

    Decide whether the observed lead represents a targeted intrusion attempt requiring further evidence collection.

  4. Decision

    Gate on lead verdict

    Terminate the hunt if no suspicious installations are found, saving resources for the more expensive script analysis.

  5. Query, enrichment

    SCKit toolkit script execution

    Identify the execution of the PowerShell-based decoders and loaders that extract the SCKit toolkit.

    sql, reads hb_script_activity
    SELECT device_hostname, script_name, script_content, timeFROM hb_script_activityWHERE (instr(',' || '{{sckit_scripts}}' || ',', ',' || LOWER(script_name) || ',') > 0 OR LOWER(script_content) LIKE '%panel-lateral%' OR LOWER(script_content) LIKE '%relaytrap%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Script blocks matching the toolkit logic. Finding these on the same hosts as the MSI lead strongly corroborates a compromise.

  6. Query, baseline

    Prevalence of MSI installation commands

    Stack-count the installation commands to separate legitimate fleet-wide management activity from unique, attacker-controlled outliers.

    sql, reads hb_process_activity
    SELECT LOWER(process_cmd_line) AS cmd, COUNT(DISTINCT device_hostname) AS hosts, MIN(time) AS first_seenFROM hb_process_activityWHERE (LOWER(process_cmd_line) LIKE '%sc.msi%' OR LOWER(process_cmd_line) LIKE '%c=exploited%')  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY 1HAVING hosts <= 3

    What a hit looks like. Command lines seen on only one or two hosts. Genuine MSP maintenance will typically have high host counts.

  7. Agent triage

    Triage deployment activity

    Correlate the behavioral lead, PowerShell script content, and fleet-wide prevalence to reach a final verdict per host.

  8. Decision

    Route on triage verdict

    Route the host for immediate isolation or further manual review depending on the severity of the findings.

  9. Response action

    Isolate compromised host

    Prevent further payload delivery and lateral movement from the unauthorized remote-access client.

  10. Analyst task

    Analyst remediation review

    Verify the findings, identify the management server used to issue the commands, and audit for persistence.

  11. Analyst task

    Close out hunt

    Record findings and findings to improve standing detections.

# Unauthorized ScreenConnect Client Deployment

This hunt identifies the initial entry and deployment phase of the SCKit campaign. It first scopes the estate for hosts with ScreenConnect software, then focuses on a lead query identifying silent installations (sc.msi) with session markers (c=Exploited) common in reported attacks. The hunt follows a gated flow: it only performs expensive PowerShell script analysis and fleet-wide command-line prevalence counting if the initial MSI lead is suspicious. This ensures high-fidelity triage of unauthorized support software without manual review of every legitimate installation.

<!-- Scope ScreenConnect installations -->
Find the hosts that currently have ScreenConnect or ConnectWise software to narrow the hunt scope.

```sqlite target=endpoint role=scoping
~~~yaml

  expected; silence means the software is not inventoried or is missing from the estate.
```
