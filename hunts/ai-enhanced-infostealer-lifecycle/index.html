AI-Enhanced Infostealer Lifecycle

An intruder has deployed an infostealer that uses headless browser sessions to harvest credentials and cryptocurrency wallets, followed by exfiltration to LLM providers for AI-driven data prioritization and automated cleanup via self-deletion.

Brief

Why now

Cisco Talos recently detailed the evolution of modern infostealers in their report, Bring a tent, I've got the coffee: Lessons from it-sa. The analysis highlights how tools like the VOLTA infostealer now use AI to speed up the monetization of stolen data. This shift requires a hunt that looks beyond the initial infection to find the automated prioritization and cleanup phases.

How the hunt flows

The hunt starts by scoping the environment. The first query checks the software inventory for any host with Chrome or Chromium installed. This narrows the focus to systems capable of supporting the infostealer's headless browser harvesting techniques.

The second phase investigates execution and harvesting in parallel. The hunt searches process activity for the --headless flag and identifies rare parent processes that do not match known automation servers. Simultaneously, it monitors file activity for access to sensitive files like wallet.json, seed.txt, or browser login data.

Next, an agent triages these results to find hosts where headless execution correlates with unauthorized file access. If a host appears suspicious, the hunt pivots to network telemetry. It searches DNS logs for connections to LLM API domains like OpenAI, Anthropic, or Mistral, which indicates the adversary is using AI to analyze the stolen data.

The final phase looks for evasion. The hunt identifies instances where a process deletes its own executable. This self-deletion event, occurring after suspicious harvesting and network activity, confirms the completion of the malware lifecycle.

What the hunt cannot see

This hunt has two primary blind spots. First, standard endpoint logs cannot see the specific interactions occurring inside a headless browser session. While we see the connection to a webmail domain, we cannot see the specific search terms used to find receipts or addresses. Second, the hunt depends on process and file telemetry. If an adversary operates on an unmanaged system without an endpoint agent, the harvesting remains invisible until exfiltration occurs at the network layer.

  3. Access to wallets and browser stores

    Query · detection candidate

    Find file activity where suspicious processes access cryptocurrency seeds or browser credential files.

    What a hit looks like. Non-browser processes reading files related to credentials or crypto wallets. Any hit here is a high-fidelity indicator of harvesting.

  4. Early-stage harvesting triage

    Agent triage

    Assess whether the headless browser launches and file access patterns indicate active harvesting on a per-host basis.

  5. Exfiltration to LLM endpoints

    Query · enrichment

    Correlate the suspicious hosts with DNS queries to known LLM API domains used for AI-driven data prioritization.

    What a hit looks like. Hosts already flagged for harvesting now resolving LLM provider domains. This confirms the prioritization and exfiltration phase.

  6. Cleanup via malware self-deletion

    Query · enrichment

    Find file activity where a process deletes its own executable, the final evasion step in the VOLTA lifecycle.

    reads hb_file_activitysql
    SELECT device_hostname, process_name, file_path, time FROM hb_file_activity WHERE activity_id = 4 AND LOWER(process_name) = LOWER(file_path) AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A binary deleting itself. While some installers do this, it is rare for sustained user processes and highly suspicious when following harvesting.

  7. Final lifecycle assessment

    Agent triage

    Synthesize the early-stage harvesting verdict with follow-on exfiltration and evasion evidence to reach a final decision.

  8. Route on final assessment

    Decision

    Direct the hunt based on the agent's final lifecycle assessment.

  9. Isolate host and revoke sessions

    Response action

    Halt the attack chain and invalidate stolen credentials immediately.

  10. Analyst forensic review

    Analyst task

    Conduct deep analysis to identify the initial infection vector and precisely which assets were targeted by the AI prioritization.

  11. Hunt close out

    Analyst task

    Finalize documentation and record tuning notes for future detections.

# AI-Enhanced Infostealer Lifecycle

This hunt identifies the mature VOLTA infostealer lifecycle by correlating behavioral endpoint indicators with network-based data prioritization patterns. It begins by scoping hosts with browser installations, then parallelizes the search for headless browser execution and sensitive file access (wallets/cookies). An agent triages these early-stage results before the hunt pivots to observe exfiltration to LLM API endpoints and malware self-deletion. This phased approach allows for the detection of automated, AI-assisted theft that baseline detection rules often miss due to the modular nature of the attack.
