# Hunting Decentralized C2 via Blockchain and SaaS Gateways

### Why This Hunt Matters 1010The DFIR Report recently published a flash alert regarding [The Gentleman Ransomware](https://thedfirreport.com/2026/05/11/flash-alert-etherrat-and-tuktuk-c2-end-in-the-gentleman-ransomware/). The investigation highlights how EtherRAT and TukTuk malware use decentralized infrastructure for command-and-control resolution. These malware families do not rely on static domain names that defenders can easily block. Instead, they use blockchain gateways and legitimate SaaS platforms to store and rotate their configuration data. 1010### The Hypothesis 1010An intruder uses decentralized blockchain gateways or SaaS platforms to resolve C2 configuration and tunnel traffic, bypassing static network perimeter filters. This pattern allows the malware to remain functional even if specific infrastructure nodes are taken down, as the resolution logic relies on public, high-reputation services. 1010### How the Hunt Flows 1010The first phase focuses on scoping via DNS telemetry. The query identifies resolutions for blockchain gateways such as Arweave or Ethereum RPC nodes and SaaS platforms like TryCloudflare. These services lack a business requirement for most enterprise endpoints, making any interaction a candidate for further review. 1010The second phase applies a prevalence baseline to the initial results. The hunt stacks domain lookups across the entire fleet to isolate rare outliers. By focusing on domains that appear on five or fewer hosts, the analyst removes common background noise and highlights unique infrastructure interactions associated with specific malware instances. 1010The third phase enriches the findings by correlating network connections with process behavior. The hunt specifically looks for outbound traffic from known abused binaries like node.exe or processes executing from user-writable paths like AppData. This link between the resolution of a decentralized gateway and a suspicious process increases the confidence of the finding. 1010The final phase uses an automated triage step to evaluate the collected evidence. The logic compares the rarity of the destination against the reputation of the initiating process path. A final verdict identifies hosts that require isolation or manual memory forensics to extract the C2 configuration blob. 1010### Blind Spots 1010This hunt relies on telemetry that links DNS queries to specific process IDs. If the endpoint sensor does not provide this correlation, an analyst may struggle to distinguish between a user visiting a site in a browser and background malware resolution. Additionally, because these gateways often serve traffic over encrypted channels, the hunt identifies the resolution event but cannot see the actual configuration payload without TLS inspection or host-based memory analysis. 1010### How to Run This Hunt 1010This hunt is provided as an open hunt.md playbook. You can import it into Huntbase or any hunt.md-aware runtime to execute the queries against your existing telemetry. Because it focuses on the pattern of decentralized resolution, it remains effective even as adversaries rotate specific domains or gateway providers.
