Zimbra Privilege Escalation and Root Persistence

An intruder has escalated from the Zimbra service account to root by symlinking application logs to PAM configurations and established persistence through a rare systemd service.

Brief

Why this hunt

The Microsoft Security Response Center recently detailed CVE-2026-73570 in their post Unauthenticated command injection on internet-facing mail servers: tracking CVE-2026-73570. This vulnerability allows unauthenticated command injection, but the subsequent steps an adversary takes to secure root access are particularly dangerous. Our team published a new hunt.md playbook to track these specific post-exploitation maneuvers.

How the hunt flows

The hunt begins with a scoping phase. The first query identifies every host running Zimbra software by checking the software inventory. This narrows the focus and prevents unnecessary data processing on unrelated systems. Following scoping, the hunt executes two behavioral queries in parallel. The first query focuses on persistence by stacking every systemd service found in /etc/systemd/system/ across the fleet. It looks for rare services appearing on only one or two hosts, specifically watching for names like zimlog.service or services that mimic legitimate system components like rsync or sshd. The second query monitors file activity. It looks for the zimbra user interacting with /etc/pam.d/sudo or the zmmailboxd.out log file. This pattern suggests the adversary is attempting to hijack the sudo configuration by redirecting log writes to sensitive system files. An analyst or automated agent then correlates these findings. The hunt does not just look for a new file; it looks for the specific sequence where a log modification precedes the appearance of a rare service. This automated triage helps distinguish between routine Zimbra maintenance and an active compromise.

Blind spots

The hunt has specific blind spots. If the file activity telemetry does not explicitly capture symlink targets, the creation of the link between the log and the PAM config might appear as a generic file creation or write. Additionally, the hunt relies on identifying new or rare services. If an adversary successfully timestomps the service file to match the modification times of legitimate system files, it may evade filters that look for recently changed configurations.

# Zimbra Privilege Escalation and Root Persistence

This hunt targets the complex post-exploitation chain observed in CVE-2026-73570. An adversary takes ownership of the sudo PAM configuration by symlinking application logs to sensitive system files. It then identifies rare systemd services created in /etc/systemd/system/, specifically focusing on services named zimlog.service or those whose timestamps have been modified to match legitimate system services like rsync or sshd. The hunt uses an agent to correlate these file and service anomalies, allowing an analyst to confirm root-level persistence.
