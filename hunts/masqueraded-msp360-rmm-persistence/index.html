Masqueraded MSP360 RMM Installer and Persistence

An attacker is distributing a legitimate but masqueraded MSP360 RMM installer via phishing lures to establish persistent, service-based administrative access on endpoints.

Brief

Why Now

Microsoft recently detailed a campaign where attackers abuse Remote Monitoring and Management (RMM) tools to establish persistent access. Specifically, the Microsoft Security Blog report 'Phishing Abuses RMM Tools for Persistent Access' (https://www.microsoft.com/en-us/security/blog/2026/09/29/phishing-abuses-rmm-tools-persistent-access/) describes how signed MSP360 installers are being masqueraded as legitimate software like Zoom or PDF updates. This technique is particularly effective because it uses signed, legitimate binaries to bypass reputation-based security controls.

How the Hunt Flows

The hunt begins by scoping the existing RMM footprint across the estate. We identify where MSP360 or other RMM agents already exist to provide a baseline for legitimate administrative activity. This helps differentiate between an IT-managed deployment and a rogue installation. The lead query focuses on the execution of the MSP360 RMM installer (v2.5.0.67) from user-writable directories. We look for process launches from paths like Downloads, Temp, or Desktop. The query specifically looks for filenames that contain version strings or hashes known to be associated with this campaign. A gating step involves an automated agent reviewing the filenames and paths. If an installer is named after a meeting invite or a document update but matches the RMM binary's characteristics, the hunt continues. This prevents the workflow from fanning out for every legitimate IT update. The hunt then corroborates the lead with evidence of successful persistence. We query for the creation of Windows services such as RMM.Agent or RMM.Agent.Launcher. Simultaneously, we perform a stack-count of the installer binary across the fleet. If the binary is rare and resulted in a service installation on a workstation, the suspicion level increases. A final triage step correlates the phishing lure, the persistent service creation, and the binary rarity. If all conditions are met, the hunt recommends immediate isolation of the endpoint and forensic collection of the installer.

What the Hunt Cannot See

This hunt relies on process and service telemetry. If a host lacks endpoint sensors or does not log service installation events (Event ID 4697/7045), the execution and subsequent persistence may go unobserved. We cannot see activities on hosts without these logs.

# Masqueraded MSP360 RMM Installer and Persistence

This hunt identifies the abuse of legitimate Remote Monitoring and Management (RMM) software, specifically MSP360 (v2.5.0.67), used to establish an initial foothold. The adversary distributes the signed installer through social-engineering lures themed around Zoom, PDF updates, or meeting invitations. Once executed from a user profile, the installer elevates and installs persistent Windows services. We open by scoping existing RMM footprints, then use a gated lead query to identify suspicious execution patterns. If the lead is judged suspicious, the hunt fanned out to investigate service persistence and the rarity of the installer across the estate to distinguish a targeted attack from legitimate IT activity.
