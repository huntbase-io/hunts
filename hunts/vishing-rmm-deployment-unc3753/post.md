# Hunting for UNC3753 Vishing and RMM Deployment Tactics

The recent report "UNC3753 targeted campaign against US law firms" by Google Cloud (https://cloud.google.com/blog/topics/threat-intelligence/targeted-campaign-us-law-firms) highlights a persistent threat actor using voice phishing (vishing) to gain initial access. Unlike traditional phishing, vishing bypasses email filters entirely. The adversary impersonates IT support, convincing users to install Remote Monitoring and Management (RMM) software. This hunt is designed to identify the footprint of this activity on the endpoint.\n\nThe hypothesis is that UNC3753 relies on the social engineering of a user to execute specific installation commands, often relayed through "self-destructing" note services like Privnote. These links provide the user with instructions, such as running a curl command to fetch an MSI or executing a specific RMM installer like SuperOps or AnyDesk. Because these tools are often legitimate, detection requires behavioral correlation.\n\nThe hunt begins by scoping the software inventory. We look for the presence of specific RMM tools that are not part of the standard corporate image. While AnyDesk or Zoho might be legitimate in some environments, their appearance on a workstation in a department like HR or Legal—following no internal IT ticket—is a significant pivot point for further investigation.\n\nFollowing the inventory check, the hunt moves into a parallel corroboration phase. We look for the execution of installers via msiexec or the use of curl to pull down files with "installer" or RMM-specific keywords in the command line. Simultaneously, we examine DNS telemetry for resolutions of privnote.com. While Privnote usage isn't inherently malicious, its proximity in time to an unauthorized software installation provides the necessary context to escalate an investigation.\n\nThe final stage involves an automated triage. An agent evaluates the overlap: did the same host resolve a self-destructing note service and then execute an RMM installer within a short window? This correlation is what makes this a hunt rather than a simple detection rule. A detection rule for "any RMM install" or "any curl command" would create an unmanageable volume of false positives in most modern environments.\n\nThere are critical blind spots to acknowledge. Social engineering via a phone call (vishing) leaves no footprint on the endpoint or the network edge. Without access to VoIP or PBX logs, we cannot verify if a call occurred; we can only see the technical actions that followed. Additionally, the hunt depends on active process telemetry. If a host is not reporting activity at the time of execution, the hunt will only pick up the software inventory change later, losing the behavioral context.\n\nThis hunt is available as a hunt.md playbook. It can be imported directly into Huntbase or any runtime that supports the open hunt.md standard to begin scanning for UNC3753's distinctive deployment patterns.
