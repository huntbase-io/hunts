# Shai-Hulud: Hunting for Identity and Secret Harvesting in CI Environments

Datadog Security Labs recently published a static analysis of Shai-Hulud, an open-source framework designed to automate post-exploitation tasks in cloud-native and CI/CD environments. The framework is particularly dangerous because it does not just target a single set of credentials; it uses specialized providers to systematically harvest secrets from across a compromised host. We have developed a hunt to identify this behavior in its early stages, specifically targeting the identity harvesting phase before the stolen data is exfiltrated or weaponized.\n\nThe hypothesis for this hunt is that an adversary has established an initial foothold and is now programmatically searching for cloud and CI secrets. This is not a manual discovery process; rather, the adversary is using automated logic to read configuration files and scrape process memory on developer workstations and CI runners. We expect to see a single process interacting with multiple high-value secret stores across different cloud providers in a manner that deviates from standard developer tooling.\n\nThe hunt begins by narrowing the focus to environments where these secrets are most likely to exist. We use the `hb_software_inventory` surface to identify hosts running the Bun runtime or common engineering toolsets such as the AWS CLI, kubectl, and various CI/CD agent packages. By scoping the hunt this way, we reduce the noise generated by standard administrative activities and focus our analysis on the systems that Shai-Hulud specifically targets for maximum impact.\n\nOnce the environment is scoped, the hunt pivots to file activity to identify the FileSystemService provider. A key behavioral signature of Shai-Hulud is a single process reading multiple different cloud configuration files within a tight temporal window. While a developer might legitimately read an AWS credentials file, it is highly unusual for a single process to concurrently read AWS, Azure, and Kubernetes configurations. We look for this specific multi-provider access pattern across the `hb_file_activity` surface.\n\nTo catch the GitHubRunner provider, the hunt monitors for unusual memory access patterns. Shai-Hulud attempts to bypass GitHub Actions secret masking by scraping the memory of runner processes through the proc filesystem. We use `hb_process_activity` to find processes that are accessing `/proc/pid/mem` or `/proc/pid/maps`. We prioritize findings where the accessor process is fileless—meaning it has no corresponding image on disk—which is a common characteristic of the framework’s memory-resident components.\n\nIf your environment provides script telemetry, the hunt incorporates an enrichment step using `hb_script_activity`. We search for the specific Python or Bun scraping logic described in the static analysis, such as the `isSecret` pattern-matching code. This step allows us to differentiate between generic memory inspection and the targeted extraction of CI environment variables. Finding these regex patterns within a script execution provides high confidence that the framework is active.\n\nIt is important to note that this hunt has specific telemetry requirements. In ephemeral CI/CD environments, memory scraping and process activity may not be captured if logs are not streamed to a central location before the runner terminates. Additionally, if your security stack does not provide visibility into the script content of non-standard interpreters like Bun, the higher-fidelity script-based indicators will be unavailable. Organizations should ensure they have real-time telemetry pipelines for all runner environments to mitigate these gaps.\n\nThis hunt is provided as a hunt.md playbook. It is designed to be imported into Huntbase or any other runtime that supports the hunt.md format. By following the ordered steps and pivots, analysts can systematically evaluate their developer and CI environments for the presence of Shai-Hulud harvesting providers. This structured approach allows for a more comprehensive investigation than single-point detection rules can provide. Source: Shai-Hulud open source framework static analysis (https://securitylabs.datadoghq.com/articles/shai-hulud-open-source-framework-static-analysis/)
