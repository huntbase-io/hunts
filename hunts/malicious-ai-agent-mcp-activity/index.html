Malicious AI Agent and MCP Server Host Activity

Medium severity TLP:CLEAR Part 1 of 2 Research by Elastic Security Labs Published 24 Nov 2026

Hypothesis

An intruder has compromised a developer workstation through a malicious MCP server or AI extension, using it to bypass safety checks, access local credentials, and establish persistence via OS-level startup mechanisms.

Brief

Why now

Elastic Security Labs recently published a deep dive into AI agent security in their article, Elastic ships 143 detection rules for AI agents and LLM platforms (https://www.elastic.co/security-labs/blog/ai-security-detection-rules-coding-agents-mcp). As developers adopt tools like Cursor, Claude, and various MCP servers, the attack surface shifts toward the workstation. These agents run with the developer identity and access, making them a direct path to sensitive secrets if the agent context is subverted.

How the hunt flows

The hunt begins by building an inventory of hosts running known AI coding tools or MCP server packages using the software inventory surface. This scoping phase identifies developer systems where these tools are present, even if they run as portable binaries rather than installed packages.

Next, the hunt analyzes process and file activity in parallel. The first pivot searches the process activity surface for AI agents launched with dangerous safety-bypass flags like --yolo or --dangerously-skip-permissions. Simultaneously, it queries the file activity surface to see if those same agent processes accessed sensitive files such as SSH keys, AWS credentials, or browser keychains. An analyst or automated agent evaluates these findings to determine if an agent context was likely hijacked.

If the early triage shows suspicious behavior, the hunt pivots to persistence surfaces across the entire host. It examines file writes to startup directories like LaunchAgents or rc.local, registry modifications to Run keys, and new scheduled jobs that involve AI agent binaries. This phase links the initial suspicious execution to evidence of long-term residency on the host.

Finally, the hunt provides a decision point for containment. If an analyst confirms the chain of bypass flags, secret access, and persistence, the workflow directs the isolation of the host to prevent further lateral movement or data exfiltration.

What the hunt cannot see

This design has two primary blind spots. It cannot see activity on unmanaged developer machines that lack the required endpoint telemetry agent. It also lacks visibility into the specific prompt or poisoned README file that triggered a bypass; it monitors the resulting OS behavior rather than the LLM instruction history.

  2. Query, baseline

    Rare AI Agent bypass flag usage

    Identify AI agents launched with safety bypass flags and count them across the fleet to find outliers.

    sql, reads hb_process_activity

    What a hit looks like. Commands showing explicit safety bypasses that are rare in the environment.

  3. Query, triage

    AI Agent processes touching sensitive files

    Identify AI tools reading developer credentials like SSH keys, AWS configs, or browser stores.

    What a hit looks like. AI agents reading secrets. Accessing ~/.ssh or keychains by these processes is highly unusual.

  4. Agent triage

    Evaluate early AI agent activity

    Determine if the observed bypasses and file access indicate a hijacked agent context.

  5. Query, detection candidate

    Persistence via files created by AI agents

    Search for OS-level persistence files created by AI agents, such as LaunchAgents or rc.local.

    What a hit looks like. New persistence files created by an AI agent.

  6. Query, enrichment

    Persistence via registry keys set by AI agents

    Identify Run or RunOnce registry keys modified by processes associated with AI tools.

    sql, reads hb_registry_activity

    What a hit looks like. Registry-based persistence created by AI agents.

  7. Query, enrichment

    AI Agent persistence via scheduled jobs

    Search for scheduled tasks or cron jobs whose commands involve known AI tools.

    sql, reads hb_scheduled_job
    SELECT device_hostname, job_name, job_cmd_line, timeFROM hb_scheduled_jobWHERE (('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0))  AND (LOWER(job_cmd_line) LIKE '%cursor%' OR LOWER(job_cmd_line) LIKE '%claude%' OR LOWER(job_cmd_line) LIKE '%mcp%' OR LOWER(job_cmd_line) LIKE '%openclaw%')  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Scheduled job persistence configured for AI agents.

  8. Agent triage

    Evaluate persistence validity

    Correlate early safety bypasses and key access with follow-on persistence to confirm a full intrusion.

  9. Decision

    Route based on compromise verdict

    Route the hunt to containment if the final triage confirms malicious persistence.

  10. Response action

    Isolate compromised host

    Prevent further exfiltration or lateral movement from the hijacked AI agent.

  11. Analyst task

    Forensic review and remediation

    Review findings and rotate potentially compromised credentials.

  12. Analyst task

    Hunt closure

    Document outcome and tune for future runs.

# Malicious AI Agent and MCP Server Host Activity

An agent weighs the execution and access evidence before a second stage confirms if persistence was successfully established. The hunt first identifies hosts running AI tools, then analyzes whether these agents used safety-bypass flags like --yolo or accessed sensitive developer credentials like SSH keys. Finally, it searches across file, registry, and task surfaces to confirm if the suspicious process established persistence.
