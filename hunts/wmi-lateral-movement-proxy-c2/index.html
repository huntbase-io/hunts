WMI Lateral Movement and Proxy-based C2

An intruder has moved laterally using WMI to execute code on internal Windows hosts and is maintaining command-and-control through multi-hop proxies or Tor to obfuscate traffic.

Brief

The Shift to Agentic Triage

Security teams struggle with the volume of WMI-related alerts. The recent Elastic Security Labs research, Alert Zero: AI-driven alert triage and attack investigation for the agentic SOC (https://www.elastic.co/security-labs/blog/agentic-soc-alert-triage-alertzero), highlights how automated agents handle the heavy lifting of evidence correlation. This hunt applies those principles to detect a common lateral movement pattern.

Scoping the Environment

The hunt begins by identifying every active Windows system. We focus on Windows because the WMI provider (wmiprvse.exe) is a standard mechanism for remote management on these hosts. This phase establishes the inventory of potential targets before diving into behavioral analysis.

Parallel Execution and Network Search

The second phase runs two queries in parallel. One query looks for suspicious child processes of wmiprvse.exe. It targets shells like cmd.exe and powershell.exe, as well as binaries launched from non-standard paths. Simultaneously, a second query identifies DNS resolutions for .onion domains and known proxy gateways. This parallel approach ensures we capture both the method of arrival and the method of communication.

Correlating the Lineage

An automated agent then takes these findings to find a match. It looks for a shared process identity or user context. If a shell spawned by WMI is the same process making proxy DNS requests, the confidence of an intrusion increases significantly. This step removes the noise of legitimate IT scripts that use WMI but do not connect to Tor.

Blind Spots and Limitations

This hunt has two primary limitations. First, if the environment uses DNS-over-HTTPS (DoH), standard DNS logging misses the proxy resolutions. Second, if the telemetry does not provide a direct link between a DNS query and a specific Process ID (PID), the analyst must manually align the timestamps to confirm the connection.

# WMI Lateral Movement and Proxy-based C2

This hunt identifies the dual behavior of internal lateral movement via Windows Management Instrumentation (WMI) and external command-and-control (C2) obfuscation via multi-hop proxies. It begins by scoping the environment for Windows-based systems that could be targets of WMI execution. A fan-out investigation then searches for suspicious child processes of the legitimate WMI provider (wmiprvse.exe) while simultaneously identifying DNS resolutions for known proxy and Tor infrastructure. An agent weighs these signals together to identify the complete attack chain described in the Alert Zero research, specifically looking for process-level relationships between WMI execution and proxy networking.
