# WMI Lateral Movement and Multi-hop Proxy C2

### The Shift to Agentic Triage. Security teams struggle with the volume of WMI-related alerts. The recent Elastic Security Labs research, Alert Zero: AI-driven alert triage and attack investigation for the agentic SOC (https://www.elastic.co/security-labs/blog/agentic-soc-alert-triage-alertzero), highlights how automated agents handle the heavy lifting of evidence correlation. This hunt applies those principles to detect a common lateral movement pattern. ### The Hypothesis. An intruder moves laterally using WMI to execute code on internal Windows hosts. Once established, they maintain command-and-control through multi-hop proxies or Tor to obfuscate their traffic. The attack is difficult to find because the execution and networking signals appear unrelated and are individually noisy. ### Scoping the Environment. The hunt begins by identifying every active Windows system. We focus on Windows because the WMI provider (wmiprvse.exe) is a standard mechanism for remote management on these hosts. This phase establishes the inventory of potential targets before diving into behavioral analysis. ### Parallel Execution and Network Search. The second phase runs two queries in parallel. One query looks for suspicious child processes of wmiprvse.exe. It targets shells like cmd.exe and powershell.exe, as well as binaries launched from non-standard paths. Simultaneously, a second query identifies DNS resolutions for .onion domains and known proxy gateways. This parallel approach ensures we capture both the method of arrival and the method of communication. ### Correlating the Lineage. An automated agent then takes these findings to find a match. It looks for a shared process identity or user context. If a shell spawned by WMI is the same process making proxy DNS requests, the confidence of an intrusion increases significantly. This step removes the noise of legitimate IT scripts that use WMI but do not connect to Tor. ### Blind Spots and Limitations. This hunt has two primary limitations. First, if the environment uses DNS-over-HTTPS (DoH), standard DNS logging misses the proxy resolutions. Second, if the telemetry does not provide a direct link between a DNS query and a specific Process ID (PID), the analyst must manually align the timestamps to confirm the connection. ### How to Run. This hunt is provided as a hunt.md playbook. You can import it into Huntbase or any hunt.md-aware runtime. It guides the analyst through the identification of targets, the correlation of signals, and the eventual isolation of malicious endpoints. By focusing on the relationship between execution and networking, practitioners move beyond simple alerts and conduct thorough investigations.
