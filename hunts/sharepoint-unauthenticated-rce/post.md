# Hunting for SharePoint RCE via Business Connectivity Services (CVE-2026-63520)

The recent disclosure of a SharePoint RCE chain (CVE-2026-63520) detailed by Rapid7 highlights a critical risk to internet-exposed SharePoint servers. The attack combines an authentication bypass with .NET deserialization via the Business Connectivity Services (BCS) endpoint, leading to remote code execution. This unauthenticated vector makes the vulnerability particularly dangerous for organizations with public-facing portals.Our hypothesis assumes an attacker is actively targeting these specific endpoints to instantiate malicious .NET gadget chains. Successful exploitation typically results in the SharePoint worker process (w3wp.exe) or the SharePoint Timer service (owstimer.exe) spawning an unexpected shell or a staged payload binary.The hunt begins by narrowing the scope to hosts with known vulnerabilities (CVE-2026-55040 or CVE-2026-63520) identified in the local environment. This scoping phase ensures the investigation is focused on high-risk assets before moving into behavioral analysis.Next, we monitor for the most direct indicator of success: command-line interpreters like cmd.exe or powershell.exe originating from the primary SharePoint service processes. Because attackers may use custom binaries or renamed tools, the hunt also includes a baselining step to find rare child processes that appear on only a few hosts across the estate, surfacing anomalies that standard shell-detection rules might miss.To provide higher confidence, the hunt correlates these process events with HTTP POST traffic directed at BCS endpoints like /_vti_bin/business. A successful POST followed by a shell spawn on the same host provides strong evidence of a compromise. This correlation allows an analyst to distinguish between external exploitation and local administrative activity.This hunt has two primary blind spots. First, while we can see the HTTP metadata (URL and method), we cannot inspect the POST bodies for the specific .NET gadget chain without full payload capture. Second, any SharePoint server without an endpoint agent will lack process-level visibility, potentially hiding the execution phase of the attack even if web traffic is logged.This is structured as a hunt rather than a simple detection because SharePoint services can occasionally spawn shells for legitimate administrative tasks. By baselining rare processes and correlating web traffic, we provide the context needed to distinguish routine maintenance from unauthenticated exploitation. This playbook is available as an open hunt.md file. It can be imported directly into Huntbase or any runtime that supports the hunt.md specification to automate the collection and correlation steps.
