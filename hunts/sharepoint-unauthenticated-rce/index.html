SharePoint Unauthenticated Remote Code Execution

An attacker is chaining an authentication bypass with a .NET gadget chain to execute shell commands on a SharePoint server via the Business Connectivity Services endpoint.

Brief

The recent disclosure of a SharePoint RCE chain (CVE-2026-63520) detailed by Rapid7 highlights a critical risk to internet-exposed SharePoint servers. The attack combines an authentication bypass with .NET deserialization via the Business Connectivity Services (BCS) endpoint, leading to remote code execution. This unauthenticated vector makes the vulnerability particularly dangerous for organizations with public-facing portals.Our hypothesis assumes an attacker is actively targeting these specific endpoints to instantiate malicious .NET gadget chains. Successful exploitation typically results in the SharePoint worker process (w3wp.exe) or the SharePoint Timer service (owstimer.exe) spawning an unexpected shell or a staged payload binary.The hunt begins by narrowing the scope to hosts with known vulnerabilities (CVE-2026-55040 or CVE-2026-63520) identified in the local environment. This scoping phase ensures the investigation is focused on high-risk assets before moving into behavioral analysis.Next, we monitor for the most direct indicator of success: command-line interpreters like cmd.exe or powershell.exe originating from the primary SharePoint service processes. Because attackers may use custom binaries or renamed tools, the hunt also includes a baselining step to find rare child processes that appear on only a few hosts across the estate, surfacing anomalies that standard shell-detection rules might miss.To provide higher confidence, the hunt correlates these process events with HTTP POST traffic directed at BCS endpoints like /_vti_bin/business. A successful POST followed by a shell spawn on the same host provides strong evidence of a compromise. This correlation allows an analyst to distinguish between external exploitation and local administrative activity.This hunt has two primary blind spots. First, while we can see the HTTP metadata (URL and method), we cannot inspect the POST bodies for the specific .NET gadget chain without full payload capture. Second, any SharePoint server without an endpoint agent will lack process-level visibility, potentially hiding the execution phase of the attack even if web traffic is logged.This is structured as a hunt rather than a simple detection because SharePoint services can occasionally spawn shells for legitimate administrative tasks. By baselining rare processes and correlating web traffic, we provide the context needed to distinguish routine maintenance from unauthenticated exploitation. This playbook is available as an open hunt.md file. It can be imported directly into Huntbase or any runtime that supports the hunt.md specification to automate the collection and correlation steps.

  2. SharePoint Processes Spawning Shells

    Query · detection candidate

    Detect a SharePoint worker or timer process launching a command-line interpreter, the direct outcome of RCE.

    reads hb_process_activitysql
    SELECT device_hostname, time, user_name, parent_process_name, process_name, process_cmd_line FROM hb_process_activity WHERE (instr(',' || '{{sharepoint_parents}}' || ',', ',' || LOWER(parent_process_name) || ',') > 0) AND (instr(',' || '{{shell_names}}' || ',', ',' || LOWER(process_name) || ',') > 0) AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A SharePoint process spawning a shell is highly unusual and suggests successful RCE.

  3. Baseline Rare SharePoint Child Processes

    Query · baseline

    Identify unusual binaries executed by SharePoint that are not standard shells, surfacing anomalies via prevalence.

    reads hb_process_activitysql
    SELECT LOWER(process_name) AS proc, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seen FROM hb_process_activity WHERE (instr(',' || '{{sharepoint_parents}}' || ',', ',' || LOWER(parent_process_name) || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY LOWER(process_name) HAVING host_count <= 2 ORDER BY host_count ASC

    What a hit looks like. A binary launched by SharePoint appearing on only one or two hosts. This captures custom payloads or renamed tools.

  4. BCS Endpoint HTTP POST Activity

    Query · enrichment

    Confirm HTTP interaction with Business Connectivity Services, where the RCE payload is delivered via .NET gadget chains.

    reads hb_http_activitysql
    SELECT device_hostname, src_endpoint_ip, url_path, http_method, user_agent, status_code, time FROM hb_http_activity WHERE (LOWER(url_path) LIKE '%_vti_bin/business%' OR LOWER(url_path) LIKE '%businessdatametadata%') AND http_method = 'POST' AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. POST requests to BCS-related endpoints. Successful POSTs (200 OK) followed by shell activity are strong indicators of exploitation.

  5. Triage Triage Results

    Agent triage

    Assess whether the combination of vulnerable host inventory, BCS web traffic, and unusual shell spawns constitutes a confirmed RCE intrusion.

  6. Route Based on Verdict

  7. Isolate Affected SharePoint Server

    Response action

    Immediately contain the host to prevent further lateral movement.

  8. Analyst Investigation

    Analyst task

    Conduct deep forensics on the shell commands and associated web traffic.

  9. Close and Document

    Analyst task

    Document findings or negative results.

# SharePoint Unauthenticated Remote Code Execution

This hunt identifies exploitation of CVE-2026-63520 and CVE-2026-55040. It starts by scoping the estate for vulnerable SharePoint instances and then monitors for the critical indicator of SharePoint worker processes (w3wp.exe) or the Timer service spawning command-line interpreters. It uses a parallel workstream to baseline rare child processes and monitor for specific HTTP POST activity directed at the Business Connectivity Services (BCS) endpoints, which are the primary vector for this chain.
