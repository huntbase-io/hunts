Unsigned Payloads and DLL Side-Loading Tagged by Defender

Medium severity TLP:CLEAR Part 3 of 5 Research by Protokol-7 Published 19 Nov 2026

Hypothesis

A loader delivered through a browser download, archive or messaging app wrote an unsigned executable, or a DLL beside a signed program, into a user-writable folder and ran it, and Defender tagged the file without raising a detection.

Brief

Why This Hunt Matters

Most commodity intrusions pass through the same step: a file arrives in a user's profile from a browser, an archive or a messaging app, and runs. The file is often an unsigned executable, or a malicious DLL placed beside a signed program that will load it. Defender frequently does not detect the payload, but it does make a note of it.

Protokol-7 documented the path tags Defender writes into its encrypted database, mpenginedb.db. NewPECreatedNoCert marks an unsigned PE being created, ExecutedPENoCert marks one being run, BM_IsPotentialSideLoad marks likely side-loading, and NewlyCreatedZip marks a new archive. Their examples included an unsigned PE in a temp folder and ffmpeg.dll and pcaui.dll in unusual places. Defender also queues executables it saw dropped and then run. The tags last about two weeks. The open-source osquery-defender-extension exposes them as osquery tables.

How the Hunt Flows

Microsoft does not document these tags, so the hunt first counts every tag the fleet produces, per host. A tag that appears on only one or two hosts, or one not yet in the hunt's list, is worth reading in full.

The main query then lists every tagged file in a user-writable folder with all of its tags, its current SHA-256 and its Authenticode result. A file tagged both created and executed without a certificate was dropped and run. The hunt stacks hashes across the fleet: an installer that unpacks under AppData on hundreds of machines falls away, and a binary seen on one host remains.

Two queries show how the files arrived. One is Defender's own dropped-and-executed queue. The other is file-write telemetry, which counts the rare executables written to user space and names the process that wrote them. A browser, 7-Zip, Explorer extracting a zip, Teams, Slack, Telegram or Discord writing a rare binary is how most loaders land. An agent combines the evidence and names the suspect files.

For the suspect hosts, the hunt checks for side-loading directly. It looks for a process loading a DLL that is not validly signed from the same user-writable folder as its own image. It also looks at what the payload started. A second agent gives a verdict per file. Malicious files go to an approval-gated action that preserves the file and the Scans folder, then isolates the host and scans the folder.

What the Hunt Cannot See

Tags expire after about two weeks, so older drops are gone unless the query is scheduled. Tag meanings are inferred from their names and Protokol-7's observations. When a tagged file has been deleted, there is nothing left to hash or verify. Defender's hash cache still holds its hash, but only with an MFT reference, not a path. Payloads signed with stolen or abused certificates never get the NoCert tags. Side-load confirmation needs image-load telemetry, which many fleets do not collect.

Steps

  1. Query, baseline

    Every path tag Defender wrote

    Count every path tag the engine set in the window, per host. Microsoft does not document these tags; this shows which ones this fleet produces and how common each is, so a tag that is rare here, or one not yet in pe_path_tags, stands out.

    sql, reads defender_mpengine_persist_context
    SELECT (SELECT hostname FROM system_info) AS device_hostname, context, COUNT(*) AS tagged_paths, MIN(insert_time) AS first_tagged, MAX(insert_time) AS last_taggedFROM defender_mpengine_persist_contextWHERE record_kind = 'path_tag'  AND file_path != 'MpTamperProtectionState'  AND insert_time >= (CAST(strftime('%s', 'now') AS INTEGER) - {{lookback_days}} * 86400)GROUP BY context

    What a hit looks like. NewPECreatedNoCert and NewlyCreatedZip on most hosts; ExecutedPENoCert and BM_IsPotentialSideLoad on fewer. A tag present on one or two hosts only is worth reading in full.

  2. Query, detection candidate

    Tagged files in user-writable folders

    For each tagged file in a user-writable folder, collect every tag it carries, its current SHA-256 and its signature status. A file that is both NewPECreatedNoCert and ExecutedPENoCert was dropped unsigned and then run; a DLL tagged BM_IsPotentialSideLoad is sitting where a signed program will load it.

    sql, reads defender_mpengine_persist_context
    SELECT (SELECT hostname FROM system_info) AS device_hostname, t.file_path, GROUP_CONCAT(DISTINCT t.context) AS tags, MIN(t.insert_time) AS first_tagged, MAX(t.insert_time) AS last_tagged, MAX(h.sha256) AS sha256, MAX(a.result) AS signature_result, MAX(a.subject_name) AS signerFROM defender_mpengine_persist_context tLEFT JOIN hash h ON h.path = t.file_pathLEFT JOIN authenticode a ON a.path = t.file_pathWHERE t.record_kind = 'path_tag'  AND t.insert_time >= (CAST(strftime('%s', 'now') AS INTEGER) - {{lookback_days}} * 86400)  AND instr(',' || LOWER('{{pe_path_tags}}') || ',', ',' || LOWER(t.context) || ',') > 0  AND (LOWER(t.file_path) LIKE '%\users\%' OR LOWER(t.file_path) LIKE '%\programdata\%' OR LOWER(t.file_path) LIKE '%\windows\temp\%' OR LOWER(t.file_path) LIKE '%\perflogs\%' OR LOWER(t.file_path) LIKE '%\$recycle.bin\%')GROUP BY t.file_path

    What a hit looks like. Installers and updaters unpacking under AppData appear on many hosts with the same SHA-256. An unsigned PE created and executed on one or two hosts, or a side-load candidate beside a signed binary, is the lead. sha256 is empty when the file is gone.

  3. Query, enrichment

    Executables Defender saw dropped and run

    Read the RQ_RecentExecDropped queues, where the engine lists executables it saw written and then executed.

    sql, reads defender_mpengine_rolling_queues
    SELECT (SELECT hostname FROM system_info) AS device_hostname, entry_key AS dropped_path, queue, insert_time, expire_timeFROM defender_mpengine_rolling_queuesWHERE queue_type = 'dropped_executable'  AND insert_time >= (CAST(strftime('%s', 'now') AS INTEGER) - {{lookback_days}} * 86400)

    What a hit looks like. Paths such as AppData\Local\Temp\7zS...\setup.exe. A path that is also in tagged-user-space-files confirms drop-and-run.

  4. Query, baseline

    Rare executables written to user space

    Stack every executable or DLL written to a user-writable folder by SHA-256 across the fleet, with the processes that wrote it. A browser, archive tool or messaging client writing a binary seen on fewer than three hosts is how most loaders arrive.

    sql, reads hb_file_activity
    SELECT file_hash_sha256, COUNT(DISTINCT device_hostname) AS hosts, GROUP_CONCAT(DISTINCT device_hostname) AS host_list, GROUP_CONCAT(DISTINCT process_name) AS writers, MIN(file_path) AS example_path, MIN(time) AS first_seenFROM hb_file_activityWHERE time >= datetime('now', '-{{lookback_days}} days')  AND (LOWER(file_path) LIKE '%.exe' OR LOWER(file_path) LIKE '%.dll' OR LOWER(file_path) LIKE '%.scr' OR LOWER(file_path) LIKE '%.cpl')  AND (LOWER(file_path) LIKE '%\users\%' OR LOWER(file_path) LIKE '%\programdata\%' OR LOWER(file_path) LIKE '%\windows\temp\%' OR LOWER(file_path) LIKE '%\perflogs\%' OR LOWER(file_path) LIKE '%\$recycle.bin\%')  AND file_hash_sha256 IS NOT NULL  AND file_hash_sha256 != ''GROUP BY file_hash_sha256HAVING COUNT(DISTINCT device_hostname) < 3

    What a hit looks like. Rare hashes with the writing process. Browser, 7-Zip, WinRAR, Explorer (zip extraction), Teams, Slack, Telegram or Discord as writer marks delivery.

  5. Agent triage

    Which tagged files were delivered payloads

    Combine Defender's tags with how each file arrived.

  6. Query, triage

    Unsigned DLLs loaded from the loader's own folder

    Confirm side-loading: a process loading a DLL that is not validly signed from the same user-writable folder as its own image.

    sql, reads hb_module_activity
    SELECT device_hostname, time, process_name, module_path, module_signed, module_signature_status, module_signature_subject, module_hash_sha256FROM hb_module_activityWHERE time >= datetime('now', '-{{lookback_days}} days')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND LOWER(module_path) LIKE '%.dll'  AND (LOWER(module_path) LIKE '%\users\%' OR LOWER(module_path) LIKE '%\programdata\%' OR LOWER(module_path) LIKE '%\windows\temp\%' OR LOWER(module_path) LIKE '%\perflogs\%' OR LOWER(module_path) LIKE '%\$recycle.bin\%')  AND LOWER(COALESCE(CAST(module_signed AS TEXT), '')) NOT IN ('1', 'true')  AND LOWER(rtrim(module_path, replace(module_path, '\', ''))) = LOWER(rtrim(process_name, replace(process_name, '\', '')))

    What a hit looks like. A signed executable in AppData or ProgramData loading an unsigned DLL from its own folder. Protokol-7's examples were ffmpeg.dll and pcaui.dll in uncommon places.

  7. Query, enrichment

    Execution from user-writable folders

    Show the user-space images that ran on the suspect hosts, their parents and children, to see what each payload started.

    sql, reads hb_process_activity
    SELECT device_hostname, time, user_name, parent_process_name, process_name, process_cmd_line, process_hash_sha256FROM hb_process_activityWHERE time >= datetime('now', '-{{lookback_days}} days')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND ((LOWER(process_name) LIKE '%\users\%' OR LOWER(process_name) LIKE '%\programdata\%' OR LOWER(process_name) LIKE '%\windows\temp\%' OR LOWER(process_name) LIKE '%\perflogs\%' OR LOWER(process_name) LIKE '%\$recycle.bin\%') OR (LOWER(parent_process_name) LIKE '%\users\%' OR LOWER(parent_process_name) LIKE '%\programdata\%' OR LOWER(parent_process_name) LIKE '%\windows\temp\%' OR LOWER(parent_process_name) LIKE '%\perflogs\%' OR LOWER(parent_process_name) LIKE '%\$recycle.bin\%'))

    What a hit looks like. The suspect image with its parent (browser, Explorer, archive tool) and the processes it started. Script hosts or LOLBins as children are the next stage.

Blind spots

  • Needs the defender_mpengine osquery extension loaded by osqueryd (running as SYSTEM) on every Windows host, with Microsoft Defender Antivirus as the active engine and defender_mpengine_status.error empty. Those hosts return no rows, which looks the same as a clean host. An attacker who has removed or stopped Defender also leaves an empty or stale database. It would answer: Did Defender record anything on hosts where the extension is missing, cannot decrypt the database, or Defender is passive behind another antivirus? Remediation: Deploy the extension through extensions.load on all Windows hosts and alert on defender_mpengine_status rows with a non-empty error.
  • Needs path tags younger than their expire_time (about two weeks). Older drops leave no tag; schedule the pack query to keep them. It would answer: Was an unsigned payload run before the tags expired?
  • Needs Microsoft documentation of AttributePersistContext tags. Meanings are inferred from the names and Protokol-7's observations. It would answer: Exactly when does Defender set each tag?
  • Needs the file still on disk, or MFT and USN journal data. hash and authenticode return nothing for a missing file. Defender's hash cache keeps the hash but only an MFT reference, not the path. It would answer: What was a tagged file that has since been deleted?
  • Needs code-signing reputation beyond signed or unsigned. NoCert tags never fire for signed payloads; only the side-load tag and rarity still apply. It would answer: Was the payload signed with a stolen or abused certificate?
  • Needs image-load events (Sysmon event 7 or EDR) in hb_module_activity. Image loads are often not collected for volume; side-loading then rests on Defender's tag alone. It would answer: Did the signed program actually load the tagged DLL?

# Unsigned Payloads and DLL Side-Loading Tagged by Defender

Defender notes things about files that it does not alert on. When an unsigned PE is created it sets NewPECreatedNoCert on the path; when one runs, ExecutedPENoCert; when behaviour monitoring sees a likely side-load, BM_IsPotentialSideLoad; when a new archive appears, NewlyCreatedZip. It also queues executables it saw dropped and then executed. These tags sit in mpenginedb.db for about two weeks.

This hunt reads the tags on every Windows host through the defender_mpengine osquery extension, keeps those in user-writable folders, and adds the file's current hash and signature. Stacking hashes across the fleet removes installers and updaters, and file-write telemetry shows which browser, archive tool or messaging client wrote each one. It first counts every tag the fleet produces, because the tag names are undocumented and others may matter.

Suspect files are then checked for side-loading (an unsigned DLL loaded from the same folder as the signed program loading it) and for what they started, before an agent and an analyst decide.

```sqlite target=endpoint role=baseline params=(lookback_days=lookback_days)
- file_hash_sha256
- process_name
silence: not_evidence_of_absence
source: hb_file_activity
verified: dry-run
verified_at: '2026-11-19'
~~~
SELECT file_hash_sha256, COUNT(DISTINCT device_hostname) AS hosts, GROUP_CONCAT(DISTINCT device_hostname) AS host_list, GROUP_CONCAT(DISTINCT process_name) AS writers, MIN(file_path) AS example_path, MIN(time) AS first_seen FROM hb_file_activity WHERE time >= datetime('now', '-{{lookback_days}} days') AND (LOWER(file_path) LIKE '%.exe' OR LOWER(file_path) LIKE '%.dll' OR LOWER(file_path) LIKE '%.scr' OR LOWER(file_path) LIKE '%.cpl') AND (LOWER(file_path) LIKE '%\users\%' OR LOWER(file_path) LIKE '%\programdata\%' OR LOWER(file_path) LIKE '%\windows\temp\%' OR LOWER(file_path) LIKE '%\perflogs\%' OR LOWER(file_path) LIKE '%\$recycle.bin\%') AND file_hash_sha256 IS NOT NULL AND file_hash_sha256 != '' GROUP BY file_hash_sha256 HAVING COUNT(DISTINCT device_hostname) < 3
```

## sideload-module-loads
<!-- Unsigned DLLs loaded from the loader's own folder -->
Confirm side-loading: a process loading a DLL that is not validly signed from the same user-writable folder as its own image.

```sqlite target=endpoint role=triage params=(lookback_days=lookback_days, scope_hosts=scope_hosts)
~~~yaml
expected: A signed executable in AppData or ProgramData loading an unsigned DLL from
  its own folder. Protokol-7's examples were ffmpeg.dll and pcaui.dll in uncommon
  places.
reads:
- time
- device_hostname
- module_path
- module_signed
- module_signature_status
- module_signature_subject
- module_hash_sha256
- process_name
silence: not_evidence_of_absence

verified: dry-run
verified_at: '2026-11-19'
~~~
SELECT device_hostname, time, process_name, module_path, module_signed, module_signature_status, module_signature_subject, module_hash_sha256 FROM hb_module_activity WHERE time >= datetime('now', '-{{lookback_days}} days') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND LOWER(module_path) LIKE '%.dll' AND (LOWER(module_path) LIKE '%\users\%' OR LOWER(module_path) LIKE '%\programdata\%' OR LOWER(module_path) LIKE '%\windows\temp\%' OR LOWER(module_path) LIKE '%\perflogs\%' OR LOWER(module_path) LIKE '%\$recycle.bin\%') AND LOWER(COALESCE(CAST(module_signed AS TEXT), '')) NOT IN ('1', 'true') AND LOWER(rtrim(module_path, replace(module_path, '\', ''))) = LOWER(rtrim(process_name, replace(process_name, '\', '')))
```
