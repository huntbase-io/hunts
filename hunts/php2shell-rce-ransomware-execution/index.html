PHP2Shell RCE and Ransomware Execution

An adversary has exploited the php2shell unauthenticated RCE vulnerability on a host running an end-of-life PHP version to deploy ransomware and encrypt local data.

Brief

Why this hunt?

Cisco Talos recently published 'I had plans for that second' (https://blog.talosintelligence.com/i-had-plans-for-that-second/), describing how threat actors exploit the PHP2Shell vulnerability. This flaw allows unauthenticated remote code execution on servers running end-of-life PHP. Adversaries use this access to deploy ransomware such as INC and The Gentlemen. This hunt provides a structured way to find these intrusions by linking unpatched software to post-exploitation behavior.

How the hunt flows

The hunt begins by scoping the environment. It queries the hb_software_inventory surface to identify any host running PHP versions 5.4 through 8.1. These versions are end-of-life and susceptible to the exploit. By starting here, we focus our investigation on the most at-risk assets. Next, the hunt searches for initial access signals. It looks at the hb_http_activity surface for requests targeting PHP scripts and checks the hb_process_activity surface for any instances of a PHP process spawning a shell like cmd.exe or sh. A shell launched by a web interpreter is a high-confidence indicator of remote code execution. After identifying suspicious process trees, the hunt looks for the impact of ransomware. It searches the hb_process_activity surface for hashes and filenames associated with INC and The Gentlemen ransomware. Simultaneously, it monitors the hb_file_activity surface for bulk file modifications, where a single process changes more than 100 files in a short window. Finally, an analyst or automated agent triages the results. They correlate the initial RCE with the ransomware execution to confirm a successful intrusion. If confirmed, the hunt provides steps to isolate the host and stop the encryption.

Blind Spots

The hunt has two primary blind spots. First, if the exploit occurs over an encrypted HTTPS connection and the network sensors do not have SSL decryption, the HTTP-level indicators will be invisible. Second, some endpoint configurations suppress file modification logs for high-volume processes to save resources. This could hide the evidence of mass encryption from the file activity queries.

# PHP2Shell RCE and Ransomware Execution

This phased hunt identifies internet-facing hosts running vulnerable, end-of-life PHP versions (5.4 through 8.1) and investigates signs of the php2shell RCE. The first phase looks for suspicious HTTP requests and unusual child processes spawned by the PHP interpreter. The second phase follows these leads to identify the deployment of specific ransomware payloads mentioned in the Talos research and evidence of mass file encryption. The hunt concludes by routing suspicious hosts for immediate isolation and analyst review.
