PHP2Shell RCE and Ransomware Execution

Critical severity TLP:CLEAR Research by Cisco Talos Published 23 Oct 2026

Hypothesis

An adversary has exploited the php2shell unauthenticated RCE vulnerability on a host running an end-of-life PHP version to deploy ransomware and encrypt local data.

Brief

Why this hunt?

Cisco Talos recently published 'I had plans for that second' (https://blog.talosintelligence.com/i-had-plans-for-that-second/), describing how threat actors exploit the PHP2Shell vulnerability. This flaw allows unauthenticated remote code execution on servers running end-of-life PHP. Adversaries use this access to deploy ransomware such as INC and The Gentlemen. This hunt provides a structured way to find these intrusions by linking unpatched software to post-exploitation behavior.

How the hunt flows

The hunt begins by scoping the environment. It queries the hb_software_inventory surface to identify any host running PHP versions 5.4 through 8.1. These versions are end-of-life and susceptible to the exploit. By starting here, we focus our investigation on the most at-risk assets. Next, the hunt searches for initial access signals. It looks at the hb_http_activity surface for requests targeting PHP scripts and checks the hb_process_activity surface for any instances of a PHP process spawning a shell like cmd.exe or sh. A shell launched by a web interpreter is a high-confidence indicator of remote code execution. After identifying suspicious process trees, the hunt looks for the impact of ransomware. It searches the hb_process_activity surface for hashes and filenames associated with INC and The Gentlemen ransomware. Simultaneously, it monitors the hb_file_activity surface for bulk file modifications, where a single process changes more than 100 files in a short window. Finally, an analyst or automated agent triages the results. They correlate the initial RCE with the ransomware execution to confirm a successful intrusion. If confirmed, the hunt provides steps to isolate the host and stop the encryption.

Blind Spots

The hunt has two primary blind spots. First, if the exploit occurs over an encrypted HTTPS connection and the network sensors do not have SSL decryption, the HTTP-level indicators will be invisible. Second, some endpoint configurations suppress file modification logs for high-volume processes to save resources. This could hide the evidence of mass encryption from the file activity queries.

Steps

  1. Query, scoping

    Identify EOL PHP environments

    Scope the estate to hosts running PHP versions 5.4 through 8.1 which are susceptible to PHP2Shell.

    sql, reads hb_software_inventory
    SELECT device_hostname, package_name, package_version, install_pathFROM hb_software_inventoryWHERE (LOWER(package_name) LIKE '%php%' OR LOWER(package_name) LIKE '%wordpress%' OR LOWER(package_name) LIKE '%drupal%' OR LOWER(package_name) LIKE '%magento%' OR LOWER(package_name) LIKE '%shopware%' OR LOWER(package_name) LIKE '%woocommerce%')  AND (package_version LIKE '5.%' OR package_version LIKE '6.%' OR package_version LIKE '7.%' OR package_version LIKE '8.0%' OR package_version LIKE '8.1%')

    What a hit looks like. A list of hosts and their PHP versions. Zero rows means no vulnerable versions are recorded in the inventory.

  2. Query, enrichment

    HTTP requests to PHP targets

    Find HTTP requests targeting PHP endpoints or application-specific paths on the scoped hosts.

    sql, reads hb_http_activity
    SELECT device_hostname, url_path, url_query, src_endpoint_ip, status_code, timeFROM hb_http_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND (LOWER(url_path) LIKE '%.php%' OR LOWER(url_query) LIKE '%php2shell%')  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Unusual HTTP requests targeting PHP scripts, potentially containing exploit strings.

  3. Query, detection candidate

    PHP spawning shells or interpreters

    Identify if a PHP interpreter launched a shell or common utility, indicating code execution.

    sql, reads hb_process_activity
    SELECT device_hostname, process_name, process_cmd_line, parent_process_name, user_name, timeFROM hb_process_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND LOWER(parent_process_name) LIKE '%php%'  AND (instr(',' || '{{interpreter_names}}' || ',', ',' || LOWER(process_original_file_name) || ',') > 0 OR instr(',' || '{{interpreter_names}}' || ',', ',' || LOWER(process_name) || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Processes like cmd.exe or sh whose parent is a PHP binary. This is highly indicative of successful RCE.

  4. Agent triage

    Evaluate early-stage signals

    Analyze whether the scoping and access queries together prove a php2shell exploit attempt.

  5. Query, triage

    Match known payload indicators

    Search for the specific SHA256 hashes and executables used by INC and The Gentlemen ransomware.

    sql, reads hb_process_activity
    SELECT device_hostname, process_name, process_cmd_line, process_hash_sha256, timeFROM hb_process_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND (instr(',' || '{{payload_hashes}}' || ',', ',' || LOWER(process_hash_sha256) || ',') > 0 OR instr(',' || '{{payload_names}}' || ',', ',' || LOWER(process_original_file_name) || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Execution of a binary matching the report's hashes or names. Any hit is high confidence for payload deployment.

  6. Query, baseline

    Detection of mass file modifications

    Identify processes performing high-volume file modifications, indicative of encryption.

    sql, reads hb_file_activity
    SELECT device_hostname, process_name, COUNT(DISTINCT file_path) AS unique_files, MIN(time) AS first_seen, MAX(time) AS last_seenFROM hb_file_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND activity_id IN (1, 3, 5)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY device_hostname, process_nameHAVING unique_files > 100

    What a hit looks like. A process modifying over 100 files on a single host. If that process matches the payload query, impact is confirmed.

  7. Agent triage

    Evaluate full intrusion chain

    Weigh the evidence from all stages to confirm a successful PHP-to-ransomware intrusion.

  8. Decision

    Route on final verdict

    Take immediate containment action if a ransomware intrusion is confirmed.

  9. Response action

    Isolate affected host

    Halt the spread of ransomware and stop data destruction.

  10. Analyst task

    Intrusion confirmation

    A human analyst reviews the evidence chain to plan full remediation.

  11. Analyst task

    Close out

    Document the hunt's findings and note vulnerable hosts for patching.

# PHP2Shell RCE and Ransomware Execution

This phased hunt identifies internet-facing hosts running vulnerable, end-of-life PHP versions (5.4 through 8.1) and investigates signs of the php2shell RCE. The first phase looks for suspicious HTTP requests and unusual child processes spawned by the PHP interpreter. The second phase follows these leads to identify the deployment of specific ransomware payloads mentioned in the Talos research and evidence of mass file encryption. The hunt concludes by routing suspicious hosts for immediate isolation and analyst review.
