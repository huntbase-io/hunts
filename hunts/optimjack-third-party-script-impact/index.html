OPTIMJACK Third-Party Script Supply Chain Impact

High severity TLP:CLEAR Research by Unit 42 Published 18 Nov 2026

Hypothesis

An adversary has exploited a trusted third-party vendor to distribute malicious JavaScript via their CDN, leading to mobile exploit delivery and credential skimming on internal corporate assets.

Brief

Why This Hunt Matters

The OPTIMJACK campaign, detailed by Unit 42 in "Borrowed Code, Real Consequences: What OPTIMJACK Teaches Us" (https://unit42.paloaltonetworks.com/optimjack-supply-chain-attack/), demonstrates the fragility of the third-party script ecosystem. Adversaries compromised the Optimizely CDN to inject malicious JavaScript into trusted pages. This script targeted users with mobile exploit kits, making the point of entry a legitimate, certificate-validated domain.

How the Hunt Flows

The hunt begins by scoping interactions with the Optimizely CDN within the hb_http_activity surface. This query establishes a candidate pool of hosts that loaded the potentially compromised script during the vulnerability window. By filtering for specific vendor domains, an analyst identifies the extent of exposure across the workstation fleet.

Next, the hunt pivots to triage evidence of the follow-on exploit stage. Two parallel queries search hb_http_activity and hb_dns_activity for keywords associated with the Coruna and DarkSword exploit kits. This phase looks for the actual delivery of the mobile payload or the resolution of attacker-controlled infrastructure.

In the final analysis phase, an analyst correlates the CDN interactions with the exploit kit markers. A host that visits the CDN and then immediately requests an exploit kit payload receives a malicious verdict. This correlation allows the hunt to find high-confidence compromise signals without alerting on every legitimate script load.

What the Hunt Cannot See

The hunt faces two primary visibility challenges. First, if the proxy gateway does not perform SSL/TLS decryption, full URL paths for exploit kit requests remain hidden. The hunt then relies on DNS telemetry, which may lack the granularity needed for certain exploit patterns. Second, the campaign targets mobile devices. If an employee uses an unmanaged iPad or iPhone that does not route traffic through corporate inspection, the exploitation stage remains invisible to internal telemetry.

Why This is a Hunt

This is a hunt because it correlates legitimate activity (CDN usage) with rare malicious follow-on activity across multiple surfaces. A single rule on Optimizely CDN traffic would be far too noisy to be actionable; an analyst must weigh the presence of exploit-kit markers against the CDN interaction to reach a verdict.

Steps

  1. Query, scoping

    Interactions with Optimizely CDN

    Identify hosts that interacted with the Optimizely CDN during the vulnerability window to establish a candidate pool for script execution.

    sql, reads hb_http_activity
    SELECT device_hostname, src_endpoint_ip, url_hostname, url_path, user_agent, MIN(time) AS first_access, MAX(time) AS last_accessFROM hb_http_activityWHERE instr(',' || '{{cdn_domains}}' || ',', ',' || LOWER(url_hostname) || ',') > 0  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY device_hostname, src_endpoint_ip, url_hostname, url_path, user_agent

    What a hit looks like. Rows indicating which hosts visited the affected infrastructure. Silence means no recorded interaction with the CDN during the window.

  2. Query, triage

    Exploit Kit HTTP Traffic

    Find HTTP requests containing keywords associated with the Coruna and DarkSword exploit kits.

    sql, reads hb_http_activity
    SELECT device_hostname, src_endpoint_ip, url_full, user_agent, timeFROM hb_http_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND (instr(LOWER(url_full), 'coruna') > 0 OR instr(LOWER(url_full), 'darksword') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Presence of exploit kit names in URL paths or hostnames. Silence indicates no clear HTTP markers for these kits were detected.

  3. Query, triage

    Exploit Kit DNS Resolutions

    Search DNS history for infrastructure associated with the Coruna and DarkSword kits that may not have full HTTP URL logging.

    sql, reads hb_dns_activity
    SELECT device_hostname, query_hostname, COUNT(*) AS count, MIN(time) AS first_seenFROM hb_dns_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND (instr(LOWER(query_hostname), 'coruna') > 0 OR instr(LOWER(query_hostname), 'darksword') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY device_hostname, query_hostname

    What a hit looks like. DNS resolutions for domains including exploit kit keywords. Silence suggests no resolution of those kit-specific domains occurred.

  4. Agent triage

    Weigh CDN and Exploit Evidence

    Assess whether hosts interacting with the Optimizely CDN subsequently triggered indicators for mobile exploit delivery.

  5. Decision

    Route on Verdict

    Route the hunt to containment if malicious activity is confirmed, or to analyst review if the findings are ambiguous.

  6. Response action

    Isolate Impacted Host

    Prevent potential lateral movement or further data exfiltration from a host showing exploit kit markers.

  7. Analyst task

    Detailed Analyst Investigation

    Review the browser history, local storage, and logs on the affected host to confirm the extent of the JS injection impact.

  8. Analyst task

    Close Out Hunt

    Record the findings and update the exclusion or detection logic for third-party script monitoring.

It would answer: Did the exploit kit successfully execute on personal mobile devices?

# OPTIMJACK Third-Party Script Supply Chain Impact

This hunt identifies hosts that interacted with the compromised Optimizely CDN infrastructure and subsequently engaged with known mobile exploit kit infrastructure (Coruna or DarkSword). By correlating trusted CDN traffic with rare exploit-delivery signatures across HTTP and DNS telemetry, the hunt uncovers potential data exposure even when delivered from a legitimate, certificate-validated source.

## optimizely-cdn-interaction
<!-- Interactions with Optimizely CDN -->
Identify hosts that interacted with the Optimizely CDN during the vulnerability window to establish a candidate pool for script execution.

```sqlite target=web role=scoping params=(cdn_domains=cdn_domains, lookback_days=lookback_days)
~~~yaml

  means no recorded interaction with the CDN during the window.
reads:
- device_hostname
- src_endpoint_ip
- url_hostname
- url_path
- user_agent
- time
silence: not_evidence_of_absence
source: hb_http_activity
verified: dry-run
```

## analyst-investigation
<!-- Detailed Analyst Investigation -->
```manual target=analyst

```
