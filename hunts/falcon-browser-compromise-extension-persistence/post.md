# Hunting Falcon Browser Extension Persistence and C2 Traffic

### Why Now Unit 42 recently published research titled [The XG Files: Falcon C2 Flying Under The (Browser) Radar](https://unit42.paloaltonetworks.com/falcon-c2-browser-compromise/), detailing a sophisticated campaign targeting government and defense sectors. The adversary uses malicious browser extensions to maintain persistent access and tunnel command-and-control (C2) traffic through standard web protocols. Traditional host-based detection often misses these extensions because they reside within the user’s browser profile and mimic legitimate analytics traffic. ### The Hypothesis An adversary establishes persistence via a malicious browser extension and uses it to communicate with a C2 framework via specific /config/ path structures and POST requests. The implant specifically mimics Baidu analytics tracking markers to blend into standard web traffic. ### How the Hunt Flows The first phase establishes a behavioral lead by querying HTTP activity. The hunt searches for rare POST requests directed at /config/ paths or specific C2 domains like fonts.tarotfree101.top or robot.avbliud.com. It also looks for the presence of the hm_lvt_ query parameter, which the framework uses to mimic Baidu tracking. By focusing on the rarity of these requests across the fleet, an analyst isolates suspicious communication before checking for local artifacts. This behavioral lead is stronger than searching for a single static IP address because it captures the framework tasking logic. Once the hunt identifies a lead, an analyst or automated agent assesses the network traffic against known Falcon indicators. This assessment is a gate. If the traffic aligns with the reported framework behavior, the hunt opens the second phase to gather more expensive endpoint telemetry. This prevents running high-impact file searches across every host in the environment. The third phase runs in parallel to find the local persistence mechanism. One query checks the software inventory for the specific Falcon extension ID mbidcmlcbgbphpoacojjbmfpohcimjji or names containing falcon. A second query monitors file activity in browser profile directories, looking for core JavaScript files like analytics-core.js or background.js being touched within extension folders. This dual-check identifies both registered extensions and those sideloaded manually. Finally, the hunt correlates the network, inventory, and file findings. An analyst reviews the combined evidence to determine if the extension activity matches the unauthorized network communication. This link between the /config/ POST traffic and the specific user profile directory provides a high-confidence verdict. If confirmed, the hunt provides instructions to isolate the host and remove the malicious files. ### What the Hunt Cannot See Visibility depends on the ability to inspect HTTP metadata. If the adversary uses encrypted WebSockets or custom TLS without a proxy or inspection point, the /config/ URI paths remain hidden. Additionally, this hunt relies on a 14-day lookback. If the adversary established persistence and remained dormant before this window, the initial installation and configuration activity will not appear in the results. ### How to Run the Hunt This hunt is an open hunt.md playbook. This format allows you to import the logic directly into Huntbase or any hunt.md-aware runtime. It uses a gated logic structure to ensure expensive file-system searches only run on hosts already showing suspicious network behavior, reducing the overall performance impact on the fleet.
