Machine-Speed Agent Tooling and Credential Harvesting

High severity TLP:CLEAR Part 2 of 3 Research by Microsoft Published 26 Nov 2026

Hypothesis

An automated agent is performing high-frequency tool execution to conduct reconnaissance and dump credentials from sensitive files like .env or /etc/shadow at machine speeds.

Brief

Why this hunt

In the report "What defenders need to know about ARTEX, the agentic AI framework threat actors abuse" (https://www.microsoft.com/en-us/security/blog/2026/11/25/what-defenders-need-to-know-artex-agentic-ai-framework-threat-actors-abuse/), Microsoft describes a shift toward autonomous agentic attacks. The ARTEX framework uses a Go-based backend to orchestrate LLM agents that execute offensive tools in rapid succession. This allows adversaries to perform reconnaissance and move laterally at speeds that exceed human intervention. This hunt provides a structured approach to identifying the endpoint telemetry left behind by this high-speed automation.

How the Hunt Flows

The first phase of the hunt searches the hb_process_activity surface for offensive tools explicitly mentioned in the ARTEX report. The query looks for binaries such as sqlmap, hydra, and netcat across all directory paths. This step acts as the primary lead, identifying hosts where known penetration testing tools are active.

Once we identify tool use, the hunt parallelizes the investigation to corroborate the "machine-speed" signature. We baseline the use of common interpreters like Node.js, Python, and PowerShell. The query identifies hosts running a burst of more than 20 commands through these interpreters within a single one-hour window. While legitimate CI/CD pipelines often produce high-frequency launches, we correlate this activity with the next two signals to reduce noise.

The hunt simultaneously inspects hb_file_activity for access to sensitive credential stores. The process targets environment files like .env and operating system files like /etc/shadow or passwd. At the same time, we check hb_dns_activity for outbound queries to webhook.site and other exfiltration domains used by ARTEX for script delivery or data return.

In the final phase, an automated agent triages the combined telemetry. The agent evaluates the proximity of tool execution, the frequency of interpreter use, and the specific files accessed. This helps an analyst distinguish between standard developer automation and the behavior of an autonomous framework.

Blind Spots

This hunt has two primary blind spots. First, standard endpoint monitoring may not capture access to restricted files like /etc/shadow unless the system is specifically configured for root-level file auditing. Second, because ARTEX agents use dynamically generated scripts, the exact intents of the agent remain obscured without full script block logging in hb_script_activity.

    What a hit looks like. Rows indicating that penetration testing tools like sqlmap or hydra are running. The query treats every directory and filename in the path as a potential match against the tool list.

  2. Query, baseline

    Baseline for machine-speed interpreter use

    Identify hosts running a burst of commands through common interpreters within a 1-hour window, suggesting AI-driven automation.

    sql, reads hb_process_activity
    SELECT device_hostname, user_name, strftime('%Y-%m-%d %H', time) AS hour_bucket, COUNT(*) AS launch_count, COUNT(DISTINCT process_name) AS unique_tools, MIN(time) AS first_launch, MAX(time) AS last_launchFROM hb_process_activityWHERE instr(',' || '{{interpreters}}' || ',', ',' || LOWER(replace(replace(process_name, '/', '\'), '\', ',')) || ',') > 0  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY device_hostname, user_name, hour_bucketHAVING launch_count > 20ORDER BY launch_count DESC

    What a hit looks like. A stack-count of hosts showing dozens of interpreter launches in a single hour. Legitimate CI/CD pipelines might appear here and must be filtered by user context.

  3. Query, enrichment

    Correlate with credential file access

    Check if processes are accessing files known to contain secrets, capturing the process name for correlation.

    sql, reads hb_file_activity

    What a hit looks like. Processes reading sensitive files like /etc/shadow or .env. The query is path-aware and captures the acting process to facilitate correlation with the tool-lead step.

  4. Query, enrichment

    Check for DNS exfiltration to webhook sites

    Identify hosts talking to webhook.site or other exfiltration domains mentioned in the report.

    What a hit looks like. Any row indicates a host communicating with a named exfiltration domain, often used by ARTEX for script delivery or data return.

  5. Agent triage

    Triage AI-driven tool behavior

    Analyze the combined telemetry to determine if tool use, high-speed execution, and file access constitute an automated ARTEX-like campaign.

  6. Decision

    Route on agent verdict

    Direct the hunt based on the agent's findings.

  7. Response action

    Isolate compromised host

    Contain the automated attack by isolating the affected host from the network.

# Machine-Speed Agent Tooling and Credential Harvesting

This hunt targets the endpoint activity of the ARTEX agentic AI framework. ARTEX uses a Go-based backend to orchestrate multiple LLM agents that execute offensive tools (like nc, sqlmap, and hydra) in rapid succession. This hunt identifies the 'machine-speed' execution pattern by baselining interpreter frequency within one-hour windows and corroborating that activity with access to sensitive credential stores like environment files and OS-level shadow files, alongside DNS signals to known exfiltration sites. An agent then evaluates the combined telemetry to distinguish between legitimate automation and an autonomous penetration testing framework.
