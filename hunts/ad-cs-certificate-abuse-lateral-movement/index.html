AD CS Certificate Abuse and Lateral Movement

An adversary is performing discovery against Active Directory Certificate Services to identify vulnerable templates (ESC1) or coercive authentication targets (ESC8), then obtaining certificates for privileged accounts to facilitate Kerberos authentication and data exfiltration.

Brief

Why now

Microsoft recently detailed a campaign in their article From help desk impersonation to AD CS abuse: Investigating ESC1 and ESC8 intrusion paths. The report highlights how attackers move from initial host access to domain-wide control by exploiting misconfigured certificate templates (ESC1) or using web enrollment coercion (ESC8). This hunt tracks that specific transition.

How the hunt flows

The hunt begins by identifying workstations that perform unusual LDAPS or SMB connections to domain infrastructure. The first query looks for template assessment or authentication coercion attempts, such as PetitPotam, by baselining connections to domain controllers. High-frequency or rare workstation-to-DC traffic on ports 389, 636, and 445 identifies potential beachheads.

Once the hunt identifies a beachhead, it fans out to collect parallel evidence across identity and network surfaces. One query searches for new certificates issued to machine accounts or administrative users within the same timeframe. Another query looks for the actual use of these certificates by filtering for Kerberos sign-ins that use the PKINIT protocol or include a certificate thumbprint. A third query monitors outbound network traffic for large data transfers originating from the involved hosts or identities.

In the final phase, an agent correlates the discovery, the new certificates, and the subsequent logons. It evaluates whether the certificates were requested by the same host that performed the initial discovery. This correlation provides the context needed to distinguish a standard administrative task from a multi-stage intrusion. If the agent confirms a match, the hunt provides steps for host isolation and certificate revocation.

What this hunt cannot see

This hunt has two primary blind spots. First, it relies on endpoint-side certificate visibility. If an attacker uses a remote tool to request a certificate from the CA and never installs it on a managed endpoint, the hb_certificates surface will not see it. Full visibility in that scenario requires Active Directory Certificate Services audit logs (Events 4886 and 4887). Second, because LDAPS traffic is encrypted, the hunt identifies the connection to the DC but cannot inspect the specific LDAP filters used to find vulnerable templates.

Steps

  1. AD CS Discovery via LDAPS and SMB

    Query · baseline

    Identify workstations performing unusual LDAP(S) or SMB connections to domain infrastructure, indicating template assessment or coercion attempts like PetitPotam.

    reads hb_network_connectionsql
    SELECT device_hostname, LOWER(process_name) AS process_name, dst_endpoint_ip, dst_endpoint_port, COUNT(*) AS connection_count, MIN(time) AS first_seen FROM hb_network_connection WHERE dst_endpoint_port IN (389, 636, 445, 3269) AND time >= datetime('now', '-{{lookback_days}} days') AND ('{{domain_controller_ips}}' = '' OR instr(',' || '{{domain_controller_ips}}' || ',', ',' || dst_endpoint_ip || ',') > 0) GROUP BY device_hostname, LOWER(process_name), dst_endpoint_ip, dst_endpoint_port ORDER BY connection_count DESC

    What a hit looks like. A small number of workstations making repetitive LDAPS or SMB calls to DCs. Silence suggests no automated discovery occurred during the window.

  2. New Privileged Certificates

    Query · enrichment

    Find certificates issued to domain controllers or administrative accounts within the lookback period.

    reads hb_certificatessql
    SELECT subject, issuer, common_name, serial_number, not_after, owner, provider FROM hb_certificates WHERE not_before >= datetime('now', '-{{lookback_days}} days') AND (LOWER(subject) LIKE '%$%' OR LOWER(subject) LIKE '%admin%' OR LOWER(subject) LIKE '%svc%') ORDER BY not_before DESC

    What a hit looks like. Certificates for machine accounts ($) or administrative users not requested by standard automation. Absence on endpoints does not prove the CA did not issue them.

  3. Certificate-Backed Logons (PKINIT)

    Query · detection candidate

    Detect use of certificates for Kerberos authentication, which the adversary uses after obtaining certificates via ESC1 or ESC8.

    reads hb_auth_signinsql
    SELECT actor_user_name, device_hostname, src_endpoint_hostname, src_endpoint_ip, auth_protocol, cert_thumbprint, time FROM hb_auth_signin WHERE (auth_protocol = 'PKINIT' OR (auth_protocol = 'Kerberos' AND cert_thumbprint IS NOT NULL)) AND time >= datetime('now', '-{{lookback_days}} days') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || src_endpoint_hostname || ',') > 0) ORDER BY time DESC

    What a hit looks like. Logon events indicating Kerberos with a certificate thumbprint, especially from identified beachheads. This is the primary indicator of certificate misuse.

  4. Large Outbound Data Transfers

    Query · triage

    Examine network connections for exfiltration patterns, particularly from accounts or hosts involved in the escalation chain.

    reads hb_network_connectionsql
    SELECT device_hostname, user_name, dst_endpoint_ip, SUM(traffic_bytes) AS total_bytes, MIN(time) AS start_time FROM hb_network_connection WHERE direction = 'outbound' AND time >= datetime('now', '-{{lookback_days}} days') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) GROUP BY device_hostname, user_name, dst_endpoint_ip HAVING total_bytes > {{exfil_threshold_bytes}} ORDER BY total_bytes DESC

    What a hit looks like. A user account with a newly issued certificate performing high-volume transfers to external IPs. Zero results is evidence of absence for the specific threshold.

  5. Triage AD CS Abuse Chain

    Agent triage

    Correlate discovery activity with certificate issuance and PKINIT logons to determine if a privileged account has been compromised.

  6. Route on Verdict

    Decision

    Route to containment if a certificate-based intrusion is confirmed.

  7. Isolate and Revoke

    Response action

    Immediately contain the host beachhead and invalidate the issued certificates.

  8. Analyst Validation

    Analyst task

    Review the agent's findings and confirm whether the activity was legitimate administration or an intrusion.

  9. Close-out

    Analyst task

    Record the hunt results and document any gaps in visibility.

# AD CS Certificate Abuse and Lateral Movement

This hunt identifies the transition from initial host foothold to Active Directory domain escalation through Certificate Services (AD CS). It starts by locating workstation-to-DC connections on LDAPS and SMB ports that suggest template enumeration or authentication coercion. It then fans out to find evidence of new privileged certificates, certificate-backed Kerberos (PKINIT) authentication, and large data transfers linked to the same identities. An agent correlates these results to distinguish administrative activity from a persistent intrusion that bypasses standard password-based controls.

<!-- AD CS Discovery via LDAPS and SMB -->
Identify workstations performing unusual LDAP(S) or SMB connections to domain infrastructure, indicating template assessment or coercion attempts like PetitPotam.

```sqlite target=network role=baseline params=(lookback_days=lookback_days, domain_controller_ips=domain_controller_ips)
~~~yaml
```
