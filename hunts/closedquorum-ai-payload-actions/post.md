# Hunting for CLOSEDQUORUM Autonomous AI Implant Activity

### Investigating CLOSEDQUORUM Autonomous Activity. Cisco Talos recently published "The Closed Quorum: Inside the first reported autonomous AI C2 implant" (https://blog.talosintelligence.com/the-closed-quorum-inside-the-first-reported-autonomous-ai-c2-implant/), describing a Go-compiled implant that uses LLM providers to decide its next move. This hunt focuses on the endpoint footprint left by these autonomous decisions. The research highlights how the implant coordinates between multiple models to avoid mistakes. Our hunt mirrors this by checking three distinct techniques that represent different implant modules. ### Hypothesis. The adversary performs credential theft, process injection, or WMI persistence based on plurality-vote decisions reached by a panel of LLM providers. ### How the hunt flows. The hunt begins with a lead query focused on crypto wallet harvesting. It searches for file access events involving known wallet filenames like exodus.wallet or wallet.dat. A hit here identifies a potentially compromised host where the "steal" module is active. The adversary targets wallet data to fund operations, and we look for these reads specifically from processes that do not normally touch user profile data. Next, the hunt fans out to check for fileless code. It identifies processes running without a corresponding binary on disk, targeting the implant's process hollowing and APC injection modules. This query looks for anomalies in standard system processes like svchost.exe or explorer.exe where the "on_disk" flag is false. Simultaneously, the hunt baselines WMI activity across the estate. It stack-counts WMI event subscription commands to find rare permanent consumers created for persistence. This step isolates unique ActiveScriptEventConsumer or CommandLineEventConsumer instances that deviate from the fleet's baseline. We are not just looking for execution; we are looking for the permanent event filters that allow the implant to survive reboots without a registry key. The final phase uses an agent to weigh the combined telemetry. If a host shows overlapping evidence of wallet access, injection, and rare WMI persistence, the agent confirms the presence of an autonomous implant session. An autonomous implant often performs these actions in a quick sequence once the LLM quorum reaches a decision. While a single WMI event might occur in isolation due to system management, the combination of fileless injection with these other indicators is a high-confidence signal. ### What the hunt cannot see. This hunt has two primary blind spots. First, it lacks memory visibility. If the implant injects code into a process that terminates before the hunt runs, the activity remains invisible. Second, it cannot see the AI's reasoning. Without TLS inspection of the HTTPS traffic to providers like DeepSeek or Gemini, we cannot view the JSON fields containing the reasoning behind the implant's actions. ### How to run it. This hunt is provided as a hunt.md playbook. You can import it into Huntbase or any hunt.md-aware runtime. It uses a lookback window to examine historical endpoint data and identifies rare behaviors that static detection rules often miss.
