ClickFix Shell Execution and Cookie Theft

Medium severity TLP:CLEAR Part 1 of 2 Research by Huntress Published 15 Oct 2026

Hypothesis

An intruder has used a social engineering lure to trick a macOS user into executing a malicious shell command in Terminal that steals browser session cookies for account takeover.

Brief

Why Now

Attackers increasingly target macOS users with sophisticated social engineering lures that bypass multi-factor authentication. A recent report by Huntress, ClickFix to BEC in 24 Hours: Tragic Quadrant, describes a workflow where users are directed to run a terminal command to "fix" a browser error. This command exfiltrates browser cookies, leading to a full account takeover in less than a day. This hunt provides a structured way to find these indicators in your environment.

How the Hunt Flows

The first phase scopes the environment for suspicious shell activity. A query scans process telemetry for shell interpreters like sh, bash, or zsh that execute commands containing both curl and base64. This specific combination is a hallmark of ClickFix payloads, which often use encoding to hide C2 URLs or data exfiltration logic. This step generates a list of suspect hosts for further investigation.

Once the hunt identifies suspect hosts, it runs two parallel checks to corroborate the threat. The first check baselines the command lines across the environment. It looks for rare shell payloads that appear on only a few hosts, separating one-off attacks from legitimate administrative scripts. This helps narrow the focus to truly anomalous activity.

The second parallel check monitors file activity for unauthorized access to browser cookie databases. The query looks for shell processes or curl reading files in paths associated with Google Chrome, Microsoft Edge, and Safari cookie storage. Under normal conditions, only the browser processes access these files. Seeing a terminal shell read these paths suggests active credential or session theft.

In the final phase, an analyst or automated agent triages the results. The hunt requires that the suspicious file access occurs shortly after the shell execution. If the temporal context and the rarity of the command align, the host moves to containment to revoke active sessions and isolate the device.

What This Hunt Cannot See

This hunt relies on full command-line arguments. If your telemetry provider truncates long commands or misses specific arguments, the initial scoping query may not distinguish ClickFix patterns from normal shell usage. Additionally, if an attacker uses memory-mapping techniques to read cookie files without triggering standard file-read events, the exfiltration might not appear in the file activity logs.

Steps

  1. Query, scoping

    Shell interpreters running curl and base64

    Identify hosts running the specific ClickFix pattern of shell interpreters executing curl with base64 payloads to serve as the suspect list for the hunt.

    sql, reads hb_process_activity
    SELECT device_hostname, process_name, process_cmd_line, user_name, timeFROM hb_process_activityWHERE (LOWER(process_name) LIKE '%/sh' OR LOWER(process_name) LIKE '%/bash' OR LOWER(process_name) LIKE '%/zsh')  AND LOWER(process_cmd_line) LIKE '%curl%'  AND LOWER(process_cmd_line) LIKE '%base64%'  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Hosts running encoded curl commands in Terminal. If zero rows are returned, no hosts are currently suspected of this ClickFix variant.

  2. Query, baseline

    Rare shell commands with encoding

    Identify unique shell payloads across suspect hosts to separate targeted ClickFix attacks from standard administrative activity.

    sql, reads hb_process_activity
    SELECT LOWER(process_cmd_line) AS cmd, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seenFROM hb_process_activityWHERE (LOWER(process_name) LIKE '%/sh' OR LOWER(process_name) LIKE '%/bash' OR LOWER(process_name) LIKE '%/zsh')  AND LOWER(process_cmd_line) LIKE '%base64%'  AND time >= datetime('now', '-{{lookback_days}} days')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)GROUP BY LOWER(process_cmd_line)HAVING host_count <= 3ORDER BY host_count ASC

    What a hit looks like. Specific payload strings seen only on one or two suspected hosts.

  3. Query, enrichment

    Non-browser access to cookie files

    Identify when shell interpreters or curl access browser cookie storage files on suspect hosts, indicating successful theft.

    sql, reads hb_file_activity
    SELECT device_hostname, process_name, file_path, activity_name, timeFROM hb_file_activityWHERE (instr(LOWER(file_path), 'library/application support/google/chrome/') > 0 OR instr(LOWER(file_path), 'library/application support/microsoft edge/') > 0 OR instr(LOWER(file_path), 'library/cookies/') > 0 OR LOWER(file_path) LIKE '%cookies.binarycookies%')  AND (LOWER(file_path) LIKE '%cookies%' OR LOWER(file_path) LIKE '%login data%' OR LOWER(file_path) LIKE '%cookies.binarycookies%')  AND (LOWER(process_name) LIKE '%sh' OR LOWER(process_name) LIKE '%bash' OR LOWER(process_name) LIKE '%zsh' OR LOWER(process_name) LIKE '%curl')  AND time >= datetime('now', '-{{lookback_days}} days')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)

    What a hit looks like. A shell or curl process reading a cookie database for Chrome, Edge, or Safari.

    Triage endpoint activity

    Analyze the suspect shell execution and subsequent file access to confirm session theft.

  5. Decision

    Route on verdict

    Direct results toward containment or analyst review based on the triage.

  6. Response action

    Isolate host and revoke sessions

    Prevent the attacker from utilizing stolen session cookies for BEC.

  7. Analyst task

    Analyst forensic review

    Confirm the entry point and the malicious lure.

  8. Analyst task

# ClickFix Shell Execution and Cookie Theft

This hunt targets the initial endpoint stages of a ClickFix-style attack on macOS. It lead with a scoping query to identify hosts running shell interpreters with curl and base64 encoding. It then corroborates these leads by identifying rare command strings and unauthorized access to browser cookie databases, including Safari and Chromium-based paths, specifically on the suspect hosts. An agent weighs the combined evidence to identify successful session theft, ensuring that the file exfiltration occurred after the suspicious command execution.

## shell-curl-patterns
<!-- Shell interpreters running curl and base64 -->
Identify hosts running the specific ClickFix pattern of shell interpreters executing curl with base64 payloads to serve as the suspect list for the hunt.

```sqlite target=endpoint role=scoping params=(lookback_days=lookback_days)
~~~yaml

  no hosts are currently suspected of this ClickFix variant.
reads:
- device_hostname
- process_name
- process_cmd_line
- user_name
- time
silence: evidence_of_absence
source: hb_process_activity
verified: dry-run
verified_at: '2026-10-15'
~~~
SELECT device_hostname, process_name, process_cmd_line, user_name, time FROM hb_process_activity WHERE (LOWER(process_name) LIKE '%/sh' OR LOWER(process_name) LIKE '%/bash' OR LOWER(process_name) LIKE '%/zsh') AND LOWER(process_cmd_line) LIKE '%curl%' AND LOWER(process_cmd_line) LIKE '%base64%' AND time >= datetime('now', '-{{lookback_days}} days')
```
