# Industrial Protocol Abuse on Legacy Manufacturing Assets

### The Manufacturing Security GapIn many industrial environments, the hardware that controls the plant floor is decades old. These systems, often running Windows XP or Windows 7, cannot be patched without risking production downtime or violating vendor support agreements. As noted in the Huntress report "7 Key Manufacturing Cybersecurity Trends for 2027" (https://www.huntress.com/blog/manufacturing-cybersecurity-trends), these aging assets remain a primary target for adversaries looking to bridge the gap between IT and OT networks.### The HypothesisAdversaries exploit unencrypted management protocols on legacy HMIs to move laterally within industrial networks. Because these systems lack modern protections, attackers use services like Telnet and FTP to establish control and pivot into deeper OT segments without triggering standard alerts.### Phase 1: Inventorying Legacy AssetsThe hunt begins by identifying every Windows 7 and Windows XP device in the environment. We query the device inventory to build a target list of workstations that likely serve as Human-Machine Interfaces or industrial controllers. This scoping step ensures that subsequent network queries focus only on the most vulnerable systems.### Phase 2: Detecting Inbound ExposureOnce we have a list of legacy hosts, the hunt examines inbound network traffic. We look specifically for established connections on ports 21 (FTP), 23 (Telnet), and 80 (HTTP). While these protocols might be used for legitimate maintenance by local technicians, they expose credentials in cleartext and provide a simple entry point for an adversary.### Phase 3: Baselining Lateral MovementThe most critical phase of the hunt involves stacking outbound connections from these legacy hosts. We baseline the destinations and frequency of Telnet and FTP traffic leaving the HMIs. If a workstation that usually only talks to a specific PLC suddenly attempts to connect to multiple internal assets, it suggests the host is being used as a jump box. We filter for rare destinations to highlight anomalous pivots.### Phase 4: Automated TriageAn agent triages the results by correlating the OS version with the presence of inbound insecure sessions and rare outbound traffic. This reduces the noise for the analyst, providing a per-host verdict. If a host shows both insecure inbound management and rare outbound connections, it receives a high-risk rating for immediate review.### Blind SpotsThis hunt has two primary limitations. First, it relies on port-based detection. If an adversary tunnels Telnet traffic inside another protocol (T1572), simple port queries will not see the activity. Deep Packet Inspection would be required to unmask such tunneling. Second, the hunt only identifies active sessions. Insecure services that are listening but have not been accessed during the lookback window will not appear in the results.### Running the HuntThis hunt is packaged as a hunt.md playbook. You can import it directly into Huntbase or any runtime that supports the hunt.md format. The playbook guides you through the inventory, traffic analysis, and automated triage steps to secure your legacy industrial assets.
