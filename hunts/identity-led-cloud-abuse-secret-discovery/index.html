Identity-Led Cloud Abuse and Secret Discovery

An attacker has used stolen credentials harvested from unmanaged devices to bypass MFA via push fatigue, subsequently discovering cloud secrets and internal shares to exfiltrate data.

Brief

Why this hunt matters

In a recent post, Sekoia Digital Risk (https://www.sekoia.com/blog/with-sekoia-intelligence-we-gave-you-half-the-picture-heres-the-other-half) highlights the shift toward identity-led breaches. Attackers no longer rely solely on exploits; they use stolen credentials to walk through the front door. This hunt focuses on the 'other half' of that picture: what happens after a credential is stolen. We focus on the transition from an unmanaged device sign-in to the discovery of high-value secrets.

How the hunt flows

The first phase scopes the environment for risk. The query identifies users signing in from non-compliant or unmanaged devices using the hb_auth_signin surface. These sign-ins represent the highest risk for credential theft, as personal devices often lack the endpoint protections found on corporate assets.

Next, the hunt pivots to authentication patterns. It looks for MFA push fatigue, specifically targeting instances where multiple authentication failures are followed by a single success. We enrich this data using Hudson Rock domain exposure logs to see if the organization’s credentials are currently circulating in stealer markets.

Once a suspicious identity is identified, the hunt fans out to look for resource discovery. It examines the hb_cloud_api_activity surface for sensitive operations like GetSecretValue or AssumeRole. Simultaneously, it checks hb_smb_activity for access to administrative shares or backup folders. This correlation separates a simple login anomaly from a confirmed intrusion.

Finally, an agent evaluates the combined evidence. If the hunt connects a non-compliant sign-in and MFA fatigue to specific secret discovery, it triggers a recommendation for account suspension.

Blind spots

This hunt has two primary limitations. First, it requires visibility into device compliance; if the identity provider does not track device state, we cannot distinguish between managed and personal hardware. Second, it does not detect session cookie replay. If an attacker steals a valid session token, they bypass the authentication logs entirely, making their activity appear as a continuation of a valid session.

Steps

  1. Identify non-compliant device sign-ins

    Query · scoping

    Scope the estate to users and hosts accessing corporate resources from devices that do not meet management policy.

    reads hb_auth_signinsql
    SELECT DISTINCT device_hostname, actor_user_name, provider, src_endpoint_ip, time FROM hb_auth_signin WHERE device_is_compliant = 'false' AND time >= datetime('now', '-{{lookback_days}} days') ORDER BY time DESC

    What a hit looks like. A list of hosts and users signing in from personal or unmanaged machines. Silence suggests high compliance.

  2. MFA push fatigue patterns

    Query · detection candidate

    Detect many authentication failures followed by a success for a single user, indicating a push bombing attack.

    reads hb_auth_signinsql
    SELECT actor_user_name, src_endpoint_ip, SUM(CASE WHEN activity_id = 5 THEN 1 ELSE 0 END) as failures, SUM(CASE WHEN activity_id = 1 THEN 1 ELSE 0 END) as successes FROM hb_auth_signin WHERE time >= datetime('now', '-{{lookback_days}} days') GROUP BY actor_user_name, src_endpoint_ip HAVING failures >= 5 AND successes > 0 ORDER BY failures DESC

    What a hit looks like. A high count of failures followed by success. This is the primary indicator for the Uber-style compromise.

  3. Check organizational exposure

    Query · enrichment

    Enrich the hunt by checking if the organizational domain has existing stealer log exposure.

    reads hudsonrock_search_by_domainsql
    SELECT domain, total_stealers, last_employee_compromised FROM hudsonrock_search_by_domain WHERE domain = '{{target_domain}}'

    What a hit looks like. Confirmed stealer log exposure for the domain, increasing the likelihood that recent sign-ins involve stolen material.

  4. Evaluate initial access risk

    Agent triage

    Weigh compliance state, MFA patterns, and domain exposure to determine if an account was compromised.

  5. Cloud secret discovery and exfiltration

    Query · enrichment

    Search Cloud API logs for secret-reading operations or large data transfers.

    reads hb_cloud_api_activitysql
    SELECT actor_user_name, api_operation, resource_type, resource_name, bytes_out, time FROM hb_cloud_api_activity WHERE (instr(',' || '{{secret_api_ops}}' || ',', ',' || api_operation || ',') > 0 OR bytes_out > 50000000) AND time >= datetime('now', '-{{lookback_days}} days') ORDER BY bytes_out DESC

    What a hit looks like. A user reading access keys, assuming roles, or downloading large amounts of data from S3 or similar services.

  6. Sensitive SMB share access

    Query · enrichment

    Correlate identity access with discovery of backup files or credentials on administrative shares.

    reads hb_smb_activitysql
    SELECT actor_user_name, share_name, file_name, device_hostname, time FROM hb_smb_activity WHERE instr(',' || '{{sensitive_shares}}' || ',', ',' || LOWER(share_name) || ',') > 0 AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') ORDER BY time DESC

    What a hit looks like. Users previously identified as high-risk accessing sensitive shares like ADMIN$ or backup locations.

  7. Correlate intent and impact

    Agent triage

    Connect anomalous initial access with specific discovery and exfiltration activity.

  8. Route on verdict

    Decision

    Direct the hunt to containment or review based on the agent's findings.

  9. Suspend compromised identity

    Response action

    Immediately halt the attacker's progress by suspending the user account.

  10. Analyst remediation review

    Analyst task

    Ensure all traces of the identity-led breach are addressed.

  11. Close out hunt

    Analyst task

    Finalize the hunt and record findings.

# Identity-Led Cloud Abuse and Secret Discovery

This hunt follows the transition from compromised identity to resource abuse, as seen in the Snowflake and Uber breaches. It begins by scoping users signing in from non-compliant devices, then examines authentication patterns for MFA fatigue and proxy usage. The second phase correlates these suspicious logons with secret discovery in cloud control planes and administrative SMB shares, connecting initial access to malicious intent.
