EDR Impairment and RMM-Driven Ransomware Execution

An adversary has established a foothold and is systematically disabling security controls via process termination and Bring Your Own Vulnerable Driver (BYOVD) techniques to facilitate ransomware execution via RMM tools.

Brief

The recent Cisco Talos report, "IR trends Q3 2026: Actors impersonate IT help desks in vishing attacks as ransomware activity increases" (https://blog.talosintelligence.com/ir-trends-q3-2026/), describes how ransomware operators now spend significant time on defense evasion. Groups like VYPR and Interlock do not encrypt immediately. Instead, they focus on the systematic impairment of EDR solutions and system integrity tools to clear a path. This hunt provides a structured process for detecting these preparation phases. 1.0

How the hunt flows

The hunt begins with a lead query that identifies the termination of security-related processes. This query targets the cessation of tools like Cisco Secure Endpoint (cscm.exe), Windows Defender (msmpeng.exe), and the Windows System File Checker (sfc.exe). It also flags the use of taskkill.exe with force parameters. The adversary performs these actions to remove the primary obstacles to their final payload.

After identifying suspicious terminations, the hunt executes two parallel queries to corroborate the threat. The first query investigates kernel driver activity. Ransomware groups use the BYOVD technique by loading known-vulnerable drivers to bypass or disable security agents. The hunt counts unique driver loads per host and highlights non-standard signers. A sudden spike in new drivers suggests the adversary is experimenting with kernel-level exploits.

The second parallel query monitors application lifecycle events for the deployment of remote monitoring and management (RMM) tools. The adversary uses these tools to maintain persistence and execute PowerShell commands. This query looks for the installation of packages like MeshAgent or the deployment of generic MSI files via powershell.exe. This activity, when paired with prior EDR impairment, indicates a ransomware operator is staging the environment.

The final phase uses an automated agent to triage the findings. The agent weighs the evidence across the process, driver, and application surfaces. It produces a malicious verdict for any host where security process termination occurs alongside suspicious driver loads or RMM installations. This logic allows an analyst to focus on hosts at immediate risk.

What the hunt cannot see

This hunt has specific blind spots. If the adversary disables the EDR agent or the underlying logging service before the hunt begins, the telemetry for subsequent driver loading or RMM activity will not exist. Additionally, if the adversary clears local event logs and the organization does not use off-device log forwarding to a central SIEM, the lead query will find nothing. Interlock actors specifically clear logs to hinder this type of analysis.

  2. Kernel driver load stacking

    Query · baseline

    The hunt identifies hosts where the adversary loaded an unusually high number of drivers, indicating a BYOVD attack.

    reads hb_kernel_extension_activitysql

    What a hit looks like. A single host with more than 3 unique driver loads in a short window, particularly with non-standard signers. This aligns with VYPR BYOVD tactics.

# EDR Impairment and RMM-Driven Ransomware Execution

This hunt targets the execution and defense evasion stages observed in Q3 2026 ransomware campaigns, such as VYPR and Interlock. It identifies the direct impairment of security agents like Cisco Secure Endpoint and the Windows System File Checker (sfc.exe). The hunt corroborates these leads by detecting kernel driver stacking—a signature of BYOVD experimentation—and the deployment of RMM tools used for PowerShell-based MSI installations. An agent weighs the combined evidence of control disruption and suspicious deployment to identify hosts at immediate risk of impact.
