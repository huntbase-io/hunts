# Hunting Path Traversal in Thermo Fisher Torrent Suite Software

### Vulnerability Context CISA published advisory ICSMA-26-288-01 detailing a path traversal vulnerability in Thermo Fisher Torrent Suite Software. This software manages sensitive genomic and medical data, making it a high-value target for intruders. The vulnerability, tracked as CVE-2026-107777, allows an authenticated user to access files outside the intended web directory. This hunt provides a structured method to identify vulnerable servers and determine if exploitation occurred. ### The Hypothesis An authenticated intruder exploits a path traversal vulnerability in Torrent Suite Software to exfiltrate sensitive configuration and system files. The adversary uses valid credentials—potentially obtained via phishing or credential stuffing—to access the application and then sends crafted HTTP requests to read files like /etc/shadow or web.config. ### How the Hunt Flows The hunt starts by narrowing the scope to relevant assets. The first query uses software inventory data to list every host running Torrent Suite version 5.18 or lower. This prevents the hunt from processing data for patched or irrelevant systems. Next, the hunt baselines authentication activity. Because this vulnerability requires a valid account, the hunt identifies rare successful sign-ins to the vulnerable servers. An analyst looks for accounts logging in from unusual geographies or during non-business hours, as these often precede exploitation. The third phase examines HTTP activity for behavioral indicators. The query searches for dot-dot-slash sequences in URL paths. The hunt specifically flags requests that return a 200 OK status, which suggests the server processed the traversal attempt successfully. The final phase confirms the breach by monitoring file system access. It identifies the web service account—such as apache or nginx—reading sensitive files from a predefined list. When a web process reads /etc/passwd or a .env file, it confirms the adversary successfully bypassed the web root. ### Beyond Simple Detection This is structured as a hunt because simple alerts on traversal strings often produce excessive false positives from vulnerability scanners or administrative scripts. By correlating the software version with rare authentication and the actual file-read event on the host, the hunt provides the context needed to confirm a compromise. It transforms a high-volume signal into a high-fidelity investigation. ### Blind Spots and Limitations This hunt relies on comprehensive HTTP logging. If the environment does not capture full URL strings, unsuccessful traversal probes remain invisible. Additionally, the hunt does not address the initial access vector. If an attacker acquired credentials through phishing, that activity occurs on surfaces like email or proxy logs which this hunt does not include. ### How to Run the Hunt This hunt exists as an open hunt.md playbook. You can import this file into Huntbase or any runtime that supports the hunt.md format. The playbook automates the pivots between inventory, authentication, and file behavior, allowing an analyst to reach a verdict quickly.
