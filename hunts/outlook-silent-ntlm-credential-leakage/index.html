Outlook Silent NTLM Credential Leakage

High severity TLP:CLEAR Research by Rapid7 Published 18 Nov 2026

Hypothesis

An attacker is exploiting CVE-2026-124194 by forcing Outlook to initiate outbound SMB connections to an external listener, silently leaking the user's NTLM v2 hash upon opening a crafted file.

Brief

Why now

The Rapid7 — Patch Tuesday - November 2026 report (https://www.rapid7.com/blog/post/em-patch-tuesday-november-2026) describes CVE-2026-124194 as a critical spoofing vulnerability in Microsoft Outlook. This flaw allows an adversary to trigger outbound NTLM authentication by forcing the client to load a crafted file. Because this process happens silently, traditional detection rules often fail to distinguish malicious hash leakage from legitimate network traffic. This hunt provides a structured way to verify if these silent leaks occur in your environment.

How the hunt flows

The hunt identifies vulnerable Outlook hosts first. The first query pulls data from the hb_vulnerability_finding surface to locate assets where scanners confirmed the presence of CVE-2026-124194. This initial scoping step ensures the analyst focuses on the endpoints where exploitation is technically possible, which reduces the volume of telemetry to be reviewed in subsequent phases.

Next, the hunt baselines legitimate Outlook network destinations. Using the hb_network_connection surface, the query stack-counts all outbound connections from the Outlook process to external IP addresses. By identifying destinations that appear on only a few hosts, the analyst isolates rare or unique IPs that likely represent attacker-controlled infrastructure rather than standard Microsoft or cloud services.

The core of the hunt targets the specific behavioral signature of hash theft. The hunt searches for instances where Outlook initiates a connection on port 445 (SMB) to a non-private external address. Since Outlook has no standard requirement to perform SMB operations over the public internet, any signal here strongly suggests forced NTLM authentication.

Finally, the analyst correlates the findings into a triage verdict. The workflow examines the overlap between the vulnerable hosts identified in the scoping phase and the suspicious SMB egress found later. This correlation allows us to distinguish between systems that are merely unpatched and those where exploitation behavior suggests an active credential theft attempt.

What the hunt cannot see

This hunt relies on consistent network connection telemetry from the endpoint. If a host lacks EDR coverage or if logging is disabled, an outbound leak will go unrecorded. Furthermore, the vulnerability may attempt to fall back to WebDAV over port 80 or 443 if SMB is blocked. This hunt focuses primarily on port 445; identifying WebDAV-based leaks requires deep packet inspection or proxy logs to differentiate them from normal web traffic.

Steps

  1. Query, scoping

    Identify vulnerable Outlook hosts

    Locate assets where vulnerability scanners have confirmed the presence of CVE-2026-124194 to focus analysis on at-risk endpoints.

    sql, reads hb_vulnerability_finding
    SELECT resource_uid, device_uid, affected_package_version, severity, collected_atFROM hb_vulnerability_findingWHERE cve_uid = '{{cve_id}}'  AND status != 'suppressed'

    What a hit looks like. A list of unique IDs and versions for exposed assets. Silence suggests the patch is applied or the scanner has not yet detected the vulnerability.

  2. Query, baseline

    Baseline Outlook external destinations

    Stack-count outbound destinations from Outlook to external IPs to identify rare endpoints that might be attacker-controlled listeners.

    sql, reads hb_network_connection
    SELECT dst_endpoint_ip, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seen, MAX(time) AS last_seenFROM hb_network_connectionWHERE (LOWER(process_name) LIKE '%outlook.exe' OR LOWER(process_path) LIKE '%outlook.exe')  AND direction = 'outbound'  AND NOT (dst_endpoint_ip LIKE '10.%' OR dst_endpoint_ip LIKE '172.%' OR dst_endpoint_ip LIKE '192.168.%' OR dst_endpoint_ip LIKE '127.%' OR dst_endpoint_ip LIKE '169.254.%')  AND time >= datetime('now', '-{{lookback_days}} days')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)GROUP BY dst_endpoint_ipHAVING host_count <= 3ORDER BY host_count ASC

    What a hit looks like. A list of external IPs contacted by Outlook on very few hosts. Legitimate Microsoft services should show high host counts.

  3. Query, detection candidate

    Detect forced SMB authentication

    Focus on the specific behavioral signature of hash theft: Outlook connecting to an external IP on port 445 (SMB).

    sql, reads hb_network_connection
    SELECT device_hostname, process_name, dst_endpoint_ip, dst_endpoint_port, timeFROM hb_network_connectionWHERE (LOWER(process_name) LIKE '%outlook.exe' OR LOWER(process_path) LIKE '%outlook.exe')  AND dst_endpoint_port = 445  AND NOT (dst_endpoint_ip LIKE '10.%' OR dst_endpoint_ip LIKE '172.%' OR dst_endpoint_ip LIKE '192.168.%' OR dst_endpoint_ip LIKE '127.%' OR dst_endpoint_ip LIKE '169.254.%')  AND time >= datetime('now', '-{{lookback_days}} days')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)

    What a hit looks like. Any row showing Outlook connecting to an external SMB listener is highly suspicious and indicative of forced NTLM authentication.

  4. Agent triage

    Evaluate exposure and behavioral evidence

    Correlate vulnerability status with unusual outbound SMB traffic to identify hosts likely targeted for credential theft.

  5. Decision

    Route on triage results

    Direct the workflow to remediation review if exploitation evidence exists, or close-out if only general exposure is identified.

  6. Analyst task

    Remediation and perimeter verification

    Address confirmed exploitation attempts and ensure perimeter blocks are active.

  7. Analyst task

    Exposure audit close-out

    Document the exposure status across the estate when no exploitation evidence was found.

# Outlook Silent NTLM Credential Leakage

This hunt identifies Windows assets vulnerable to the silent spoofing vulnerability CVE-2026-124194 and monitors for the primary indicator of exploitation: Outlook initiating outbound connections on port 445 (SMB) to non-private IP addresses. The flow first identifies vulnerable hosts using scanner findings, baselines legitimate Outlook network activity to identify rare external destinations, and then focuses specifically on high-risk SMB egress that suggests forced authentication for hash theft.


<!-- Route on triage results -->

indeterminate: → remediation-review
unavailable: → remediation-review (blind_spot: limited-network-telemetry)
else: → close-out

## remediation-review
<!-- Remediation and perimeter verification -->
```manual target=analyst
Review the external IP destinations identified in the triage verdict. If they are unaffiliated with corporate services, prioritize the November 2026 Outlook updates on those hosts. Ensure that the network perimeter is explicitly blocking outbound port 445 (SMB) and 137-139 (NetBIOS) to external destinations.
```
→ end

## close-out
<!-- Exposure audit close-out -->
```manual target=analyst
Record the number of vulnerable assets identified. If no suspicious SMB activity was found, recommend that patching for CVE-2026-124194 be prioritized in the standard maintenance window to reduce the exposure window.
```
→ end
