# Hunting Shai-Hulud Framework Secret Harvesting and Cloud Discovery

### Why Now The Datadog Security Labs report, Shai-Hulud open source framework static analysis (https://securitylabs.datadoghq.com/articles/shai-hulud-open-source-framework-static-analysis/), highlights a specialized tool designed for automated credential harvesting and infrastructure mapping. Unlike traditional malware that might target a single set of keys, Shai-Hulud integrates endpoint scraping with cloud-native discovery. ### Hypothesis An intruder has deployed the Shai-Hulud framework to extract credentials from filesystem paths and process memory, subsequently using them to automate the discovery of cloud and Kubernetes infrastructure secrets. The adversary focuses on bypassing standard secret masking by reading raw process memory. ### How the Hunt Flows The hunt starts by scoping for sensitive file access. The first query identifies hosts where processes read high-value credential files such as AWS configs, Azure tokens, or Kubernetes configuration files. This phase identifies the initial beachhead where harvesting begins. Next, the hunt fans out into a parallel investigation of memory and network activity. The first branch looks for rare instances of processes reading their own or other processes' memory via the /proc filesystem. It specifically monitors for access to the GitHub Runner.Worker process, a known target for Shai-Hulud's memory-scraping logic. The second branch of the parallel investigation examines cloud and Kubernetes discovery traffic. It identifies surges in API requests to Secrets Manager, SSM Parameter Store, or the Kubernetes API. The hunt focuses on rare API paths or high-volume enumeration that deviates from standard developer behavior on those specific hosts. The final phase uses a triage agent to correlate these three signals. By linking credential file access and memory reads with subsequent API enumeration on the same host, the hunt confirms the presence of the framework's logic rather than isolated anomalous events. ### Blind Spots This hunt relies on endpoint visibility via an agent. If the adversary harvests secrets from unmanaged workstations or BYOD devices, they can pivot into the cloud environment invisibly to this endpoint-centric hunt. Additionally, without TLS inspection for cloud API endpoints, discovery activity may appear as generic HTTPS traffic, masking the specific nature and volume of the enumeration. ### How to Run It This hunt is provided as a hunt.md playbook. You can import it into Huntbase or any hunt.md-aware runtime. The playbook includes the logic to baseline memory reads and correlate them with network traffic automatically. Run it periodically across your CI/CD runners and developer workstations to ensure these high-value environments remain secure.
