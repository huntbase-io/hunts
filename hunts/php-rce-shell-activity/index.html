PHP Remote Code Execution and Shell Activity

High severity TLP:CLEAR Research by CISA Published 22 Oct 2026

Hypothesis

An adversary is exploiting the php2shell vulnerabilities (CVE-2026-109618 or CVE-2026-109619) to execute unauthenticated code, which manifests as PHP worker processes spawning interactive shells or utility tools to retrieve secondary payloads.

Brief

Why This Hunt

The CISA advisory, Critical Vulnerabilities in PHP Require Immediate Patching, details flaws that allow unauthenticated remote code execution. Because PHP is a foundational component for many web applications and is often embedded in other software, these vulnerabilities present a high risk for unauthorized access. This hunt provides a systematic way to verify if an adversary has weaponized these flaws within your environment.

How the Hunt Flows

The hunt begins by establishing the vulnerable surface. It queries the software inventory for any hosts running PHP versions below the security fix thresholds. This provides a focused list of systems where exploitation is most likely. Because vulnerability scanners sometimes miss embedded PHP installations, the hunt uses raw package data to ensure better coverage.

Next, the hunt moves to behavioral analysis of the scoped hosts. It examines the child processes of PHP handlers such as php-fpm, php-cgi, or php.exe. By stack-counting these children across the environment, it identifies rare binaries that appear on only a few hosts. This baseline helps isolate custom scripts or malicious binaries that differ from standard web server behavior.

In the third phase, the hunt looks for high-confidence indicators of exploitation. It searches for specific shells and downloaders like bash, powershell.exe, curl, or certutil.exe being launched directly by PHP workers. This specific pattern is highly unusual for legitimate web applications and is a primary signal for a successful compromise.

Finally, an agent reviews the findings. It correlates the presence of vulnerable software with the observed process behavior to provide a host-by-host verdict. This final check ensures that legitimate administrator maintenance is not confused with active exploitation.

What This Hunt Cannot See

This hunt has two primary blind spots. First, it does not have visibility into the HTTP request body. It cannot see the exploit payload itself as it arrives at the server; it only observes the resulting process activity. Second, the scoping relies on the freshness of the software inventory. If a server is unmanaged or has not reported inventory data recently, the hunt might not include it in the initial scope.

Steps

  1. Query, scoping

    Identify vulnerable PHP instances

    Inventory systems running PHP versions below the security fix thresholds to establish the vulnerable surface.

    sql, reads hb_software_inventory
    SELECT device_hostname, package_name, package_versionFROM hb_software_inventoryWHERE (LOWER(package_name) = 'php' OR LOWER(package_name) LIKE 'php%')  AND (package_version < '8.2.35' OR (package_version >= '8.3' AND package_version < '8.3.36') OR (package_version >= '8.4' AND package_version < '8.4.27') OR (package_version >= '8.5' AND package_version < '8.5.12'))

    What a hit looks like. A list of hostnames running unpatched versions of PHP. Silence indicates no known vulnerable PHP installations are present in the inventory.

  2. Query, baseline

    Rare child processes of PHP workers

    Stack-count children of PHP worker processes across the scoped hosts to find anomalous binaries that differ from standard web server behavior.

    sql, reads hb_process_activity
    SELECT LOWER(process_name) AS child_process, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seenFROM hb_process_activityWHERE (LOWER(parent_process_name) LIKE '%php-fpm%' OR LOWER(parent_process_name) LIKE '%php.exe%' OR LOWER(parent_process_name) LIKE '%php-cgi%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY child_processHAVING host_count <= 3ORDER BY host_count ASC

    What a hit looks like. Anomalous binaries appearing on only a few hosts stand out from fleet-wide standard children. Silence suggests the PHP processes are only performing expected operations.

  3. Query, detection candidate

    Specific shell or downloader activity from PHP

    Monitor for the high-confidence behavioral indicator of a PHP worker process launching common shells or ingress tools.

    sql, reads hb_process_activity
    SELECT device_hostname, user_name, process_name, process_cmd_line, parent_process_name, timeFROM hb_process_activityWHERE (LOWER(parent_process_name) LIKE '%php-fpm%' OR LOWER(parent_process_name) LIKE '%php.exe%' OR LOWER(parent_process_name) LIKE '%php-cgi%')  AND (instr(',' || '{{suspicious_tools}}' || ',', ',' || LOWER(process_name) || ',') > 0 OR instr(',' || '{{suspicious_tools}}' || ',', ',' || LOWER(process_original_file_name) || ',') > 0)  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A hit shows a PHP process spawning a shell or utility, which is a strong indicator of successful remote code execution. Silence is evidence of absence for this specific behavioral pattern.

  4. Agent triage

    Analyze PHP exposure and child behavior

    Correlate the list of vulnerable hosts with the observed rare and suspicious process behavior to identify compromised systems.

  5. Decision

    Exploitation decision

    Route to remediation if an agent identifies evidence of unauthenticated shell execution on a vulnerable PHP host.

  6. Analyst task

    Remediation and patching review

    Conduct an incident response investigation for compromised hosts and ensure all vulnerable hosts are prioritized for immediate patching.

  7. Analyst task

    Close out hunt

    Record the hunt results and notify the vulnerability management team of the current exposure status.

Blind spots

  • Needs recent hb_software_inventory collection. A newly deployed or unmanaged server running vulnerable PHP would not appear in the scoping query, creating a blind spot for the rest of the hunt. It would answer: Which systems have unpatched PHP versions but have not reported inventory in the last 24 hours?
  • Needs hb_http_activity with full request body. Without the request body, the hunt cannot observe the exploitation attempt itself, only the resulting process behavior, which an adversary could attempt to obfuscate. It would answer: Does the HTTP request contain the php2shell exploit payload?

# PHP Remote Code Execution and Shell Activity

This hunt identifies internet-facing systems running vulnerable versions of PHP and monitors for post-exploitation indicators following an unauthenticated remote code execution. It follows the exposure flow, starting with a scope of vulnerable software versions, then baselines the normal behavior of PHP worker processes like php-fpm or php.exe to find rare child processes. Finally, it looks for specific, high-confidence behavior of shells and downloaders being spawned directly from PHP handlers. An agent then weighs the prevalence and behavior together to identify compromised hosts.

<!-- Identify vulnerable PHP instances -->
Inventory systems running PHP versions below the security fix thresholds to establish the vulnerable surface.

```sqlite target=endpoint role=scoping
~~~yaml

  no known vulnerable PHP installations are present in the inventory.
reads:
- device_hostname
- package_name
- package_version
silence: not_evidence_of_absence
source: hb_software_inventory

```

## analyze-php-activity
<!-- Analyze PHP exposure and child behavior -->
```agent target=hunter
cite: required
context:
- identify-vulnerable-php-instances
- rare-php-child-processes
- detect-suspicious-php-children
max_iterations: 4
objective: Review the inventory of vulnerable PHP hosts and determine if any match
  the hosts exhibiting rare child processes or specific shell/tool launches. Determine
  if the behavior is malicious exploitation or benign administrator activity.
success_criteria: A verdict for each host citing evidence from process logs and inventory
  state.
tools:
- endpoint
```

## exploitation-decision
<!-- Exploitation decision -->
if~: "the verdict for any host is malicious based on shell or tool activity from a PHP worker" (confidence: high, judge=hunter)
then: → remediation-review
indeterminate: → remediation-review
unavailable: → remediation-review (blind_spot: vulnerability-scan-staleness)
else: → close-out

## remediation-review
<!-- Remediation and patching review -->
```manual target=analyst
For hosts identified with malicious shell activity, perform an incident response investigation to determine the extent of the breach and lateral movement. For all other hosts identified in the scoping step, immediately update PHP to the patched versions (8.5.12, 8.4.27, 8.3.36, or 8.2.35) as mandated by CISA.
```
→ end

## close-out
<!-- Close out hunt -->
```manual target=analyst
Confirm that no indicators of active exploitation were found during the lookback period. Provide the list of vulnerable PHP hostnames to the patching team for remediation and close the hunt.
```
→ end
