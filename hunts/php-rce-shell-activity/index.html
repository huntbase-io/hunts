PHP Remote Code Execution and Shell Activity

An adversary is exploiting the php2shell vulnerabilities (CVE-2026-109618 or CVE-2026-109619) to execute unauthenticated code, which manifests as PHP worker processes spawning interactive shells or utility tools to retrieve secondary payloads.

Brief

Why This Hunt

The CISA advisory, Critical Vulnerabilities in PHP Require Immediate Patching, details flaws that allow unauthenticated remote code execution. Because PHP is a foundational component for many web applications and is often embedded in other software, these vulnerabilities present a high risk for unauthorized access. This hunt provides a systematic way to verify if an adversary has weaponized these flaws within your environment.

How the Hunt Flows

The hunt begins by establishing the vulnerable surface. It queries the software inventory for any hosts running PHP versions below the security fix thresholds. This provides a focused list of systems where exploitation is most likely. Because vulnerability scanners sometimes miss embedded PHP installations, the hunt uses raw package data to ensure better coverage.

Next, the hunt moves to behavioral analysis of the scoped hosts. It examines the child processes of PHP handlers such as php-fpm, php-cgi, or php.exe. By stack-counting these children across the environment, it identifies rare binaries that appear on only a few hosts. This baseline helps isolate custom scripts or malicious binaries that differ from standard web server behavior.

In the third phase, the hunt looks for high-confidence indicators of exploitation. It searches for specific shells and downloaders like bash, powershell.exe, curl, or certutil.exe being launched directly by PHP workers. This specific pattern is highly unusual for legitimate web applications and is a primary signal for a successful compromise.

Finally, an agent reviews the findings. It correlates the presence of vulnerable software with the observed process behavior to provide a host-by-host verdict. This final check ensures that legitimate administrator maintenance is not confused with active exploitation.

What This Hunt Cannot See

This hunt has two primary blind spots. First, it does not have visibility into the HTTP request body. It cannot see the exploit payload itself as it arrives at the server; it only observes the resulting process activity. Second, the scoping relies on the freshness of the software inventory. If a server is unmanaged or has not reported inventory data recently, the hunt might not include it in the initial scope.

    Query · scoping

    What a hit looks like. A list of hostnames running unpatched versions of PHP. Silence indicates no known vulnerable PHP installations are present in the inventory.

  2. Rare child processes of PHP workers

    Query · baseline

    Stack-count children of PHP worker processes across the scoped hosts to find anomalous binaries that differ from standard web server behavior.

    reads hb_process_activitysql
    SELECT LOWER(process_name) AS child_process, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seen FROM hb_process_activity WHERE (LOWER(parent_process_name) LIKE '%php-fpm%' OR LOWER(parent_process_name) LIKE '%php.exe%' OR LOWER(parent_process_name) LIKE '%php-cgi%') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY child_process HAVING host_count <= 3 ORDER BY host_count ASC

    What a hit looks like. Anomalous binaries appearing on only a few hosts stand out from fleet-wide standard children. Silence suggests the PHP processes are only performing expected operations.

  3. Specific shell or downloader activity from PHP

    Query · detection candidate

    Monitor for the high-confidence behavioral indicator of a PHP worker process launching common shells or ingress tools.

    What a hit looks like. A hit shows a PHP process spawning a shell or utility, which is a strong indicator of successful remote code execution. Silence is evidence of absence for this specific behavioral pattern.

    Agent triage

    Correlate the list of vulnerable hosts with the observed rare and suspicious process behavior to identify compromised systems.

# PHP Remote Code Execution and Shell Activity

This hunt identifies internet-facing systems running vulnerable versions of PHP and monitors for post-exploitation indicators following an unauthenticated remote code execution. It follows the exposure flow, starting with a scope of vulnerable software versions, then baselines the normal behavior of PHP worker processes like php-fpm or php.exe to find rare child processes. Finally, it looks for specific, high-confidence behavior of shells and downloaders being spawned directly from PHP handlers. An agent then weighs the prevalence and behavior together to identify compromised hosts.
