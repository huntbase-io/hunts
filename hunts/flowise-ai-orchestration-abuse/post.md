# Hunting for Flowise AI Orchestration Platform Abuse

### Why Now Sekoia published a report titled Sekoia Honeypot Captures an Attack on GenAI Infrastructure (https://www.sekoia.com/blog/a-honeypots-tale-deconstructing-an-attack-on-genai-infrastructure). The research details how actors scan for and exploit unauthenticated AI orchestration tools like Flowise. These platforms sit in privileged positions with access to internal data and external AI models. ### The Hypothesis The adversary exploits unauthenticated Flowise instances to harvest stored API credentials and hijack AI agents for internal network reconnaissance and financial data exfiltration. ### How the Hunt Flows The hunt starts by identifying hosts running the Flowise package. This scoping step uses software inventory data to define the search space. By narrowing the focus early, the hunt avoids unnecessary telemetry analysis on unrelated systems. Once the hosts are scoped, the hunt performs a parallel search for early indicators of compromise. One query examines HTTP activity for successful GET requests to sensitive API routes such as /api/v1/credentials and /api/v1/chatflows. These endpoints contain the secrets used to connect the AI agents to external providers. Simultaneously, another query checks for outbound network connections to known attacker infrastructure or rare high ports. An automated triage step then weighs these results. It flags hosts that show both unauthenticated API access and new outbound callbacks. This correlation helps distinguish targeted exploitation from general internet background noise. The hunt then moves to analyze the semantic content of the interaction. It examines HTTP request logs for POST or PUT payloads sent to the prediction endpoints. The hunt searches for keywords like system status, financial data, or internal IP addresses. These indicators suggest the attacker is attempting to manipulate the AI agent to probe the internal environment. In the final phase, an agent correlates the reconnaissance and callback activity with the malicious prompts. This provides a high-confidence assessment of a successful breach. ### Blind Spots This hunt has two main limitations. First, if HTTP traffic is encrypted and the body is not captured in the logs, the semantic intent of the prompts remains hidden. Second, the hunt relies on host-level networking. If the AI server queries internal resources via a separate VPC or private link, those connections might not appear in standard network logs. ### How to Run This hunt is an open hunt.md playbook. You can import it into Huntbase or any hunt.md-aware runtime to begin auditing your AI orchestration infrastructure.
