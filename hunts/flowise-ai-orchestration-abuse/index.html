Abuse of Flowise AI Orchestration Platforms

High severity TLP:CLEAR Research by Sekoia Published 20 Oct 2026

Hypothesis

An attacker is exploiting unauthenticated Flowise instances to harvest stored API credentials and hijack AI agents for internal network reconnaissance and financial data exfiltration.

Brief

Why Now

Sekoia published a report titled Sekoia Honeypot Captures an Attack on GenAI Infrastructure (https://www.sekoia.com/blog/a-honeypots-tale-deconstructing-an-attack-on-genai-infrastructure). The research details how actors scan for and exploit unauthenticated AI orchestration tools like Flowise. These platforms sit in privileged positions with access to internal data and external AI models.

How the Hunt Flows

The hunt starts by identifying hosts running the Flowise package. This scoping step uses software inventory data to define the search space. By narrowing the focus early, the hunt avoids unnecessary telemetry analysis on unrelated systems. Once the hosts are scoped, the hunt performs a parallel search for early indicators of compromise. One query examines HTTP activity for successful GET requests to sensitive API routes such as /api/v1/credentials and /api/v1/chatflows. These endpoints contain the secrets used to connect the AI agents to external providers. Simultaneously, another query checks for outbound network connections to known attacker infrastructure or rare high ports. An automated triage step then weighs these results. It flags hosts that show both unauthenticated API access and new outbound callbacks. This correlation helps distinguish targeted exploitation from general internet background noise. The hunt then moves to analyze the semantic content of the interaction. It examines HTTP request logs for POST or PUT payloads sent to the prediction endpoints. The hunt searches for keywords like system status, financial data, or internal IP addresses. These indicators suggest the attacker is attempting to manipulate the AI agent to probe the internal environment. In the final phase, an agent correlates the reconnaissance and callback activity with the malicious prompts. This provides a high-confidence assessment of a successful breach.

Blind Spots

This hunt has two main limitations. First, if HTTP traffic is encrypted and the body is not captured in the logs, the semantic intent of the prompts remains hidden. Second, the hunt relies on host-level networking. If the AI server queries internal resources via a separate VPC or private link, those connections might not appear in standard network logs.

  1. Query, scoping

    Identify Flowise Orchestration Instances

    Find hosts running the Flowise package to define the search space for the rest of the hunt.

    sql, reads hb_software_inventory
    SELECT DISTINCT device_hostname, package_versionFROM hb_software_inventoryWHERE LOWER(package_name) LIKE '%flowise%'

    What a hit looks like. A list of hosts running Flowise. If no hosts are returned, the estate may not use this specific AI orchestration platform.

  2. Query, enrichment

    API Reconnaissance and Secret Access

    Detect successful GET requests to sensitive Flowise endpoints that expose version data and credentials.

    sql, reads hb_http_activity
    SELECT device_hostname, url_path, status_code, http_method, COUNT(*) as request_count, MIN(time) as first_seenFROM hb_http_activityWHERE (LOWER(url_path) LIKE '%/api/v1/ping%' OR LOWER(url_path) LIKE '%/api/v1/version%' OR LOWER(url_path) LIKE '%/api/v1/node-configs%' OR LOWER(url_path) LIKE '%/api/v1/chatflows%' OR LOWER(url_path) LIKE '%/api/v1/credentials%' OR LOWER(url_path) LIKE '%/credentials/%')  AND status_code = 200  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY device_hostname, url_path, status_code, http_method

    What a hit looks like. Successful GET requests to credential and metadata routes suggest an attacker is harvesting secrets.

  3. Query, baseline

    Anomalous Outbound Network Callbacks

    Identify outbound connections to known attacker infrastructure or rare high ports from the AI servers.

    sql, reads hb_network_connection
    SELECT device_hostname, dst_endpoint_ip, dst_endpoint_port, COUNT(*) AS connection_count, MIN(time) as first_seenFROM hb_network_connectionWHERE direction = 'outbound'  AND (instr(',' || '{{callback_ips}}' || ',', ',' || dst_endpoint_ip || ',') > 0 OR dst_endpoint_port = 19999)  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY device_hostname, dst_endpoint_ip, dst_endpoint_port

    What a hit looks like. Outbound connections to the reported IPs or on port 19999 indicate the creation of a persistent callback channel.

  4. Agent triage

    Early-Stage Evidence Triage

    Weigh the API secret access and network callbacks to identify hosts currently undergoing active exploitation.

  5. Query, detection candidate

    LLM Agent Hijacking and Manipulation

    Analyze HTTP request payloads for attempts to modify chatflows or hijack the agent via malicious prompts.

    sql, reads hb_http_activity
    SELECT device_hostname, url_path, http_method, log_line, timeFROM hb_http_activityWHERE (http_method IN ('POST', 'PUT', 'PATCH'))  AND (LOWER(url_path) LIKE '%/prediction%' OR LOWER(url_path) LIKE '%/chatflows%')  AND (LOWER(log_line) LIKE '%system status%' OR LOWER(log_line) LIKE '%154.217.251.226%' OR LOWER(log_line) LIKE '%rag%' OR LOWER(log_line) LIKE '%financial%' OR LOWER(log_line) LIKE '%10.0.0.5%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Requests containing keywords like 'system status', 'financial', or 'RAG' in the payload indicate the agent is being manipulated to exfiltrate internal data.

  6. Agent triage

    Final Compromise Assessment

    Correlate early reconnaissance and secret access with follow-on LLM hijacking attempts to confirm a successful breach.

  7. Decision

    Route on Compromise Verdict

    Direct response actions based on the agent's assessment of platform compromise.

  8. Response action

    Isolate Compromised Flowise Host

    Halt the attack and prevent further internal reconnaissance from the platform.

  9. Analyst task

    Revoke and Rotate Leaked Credentials

    Mitigate the impact of stolen API keys and database credentials stored in Flowise.

  10. Analyst task

    Manual Analyst Review

    Review HTTP logs manually when semantic prompts cannot be definitively classified.

  11. Analyst task

    Remediation and Hardening

    Harden the Flowise deployment to prevent future exploitation.

# Abuse of Flowise AI Orchestration Platforms

Flowise AI orchestration servers are high-value targets because they consolidate API keys for LLMs and maintain bridges into internal data via RAG pipelines. This hunt follows a phased flow: first, it identifies hosts running Flowise and examines them for unauthenticated API reconnaissance and secret exfiltration; second, it looks for anomalous outbound callbacks to reported attacker infrastructure; third, it analyzes inference logs for malicious prompts that attempt to manipulate the agent into probing internal systems. An agent correlates the early discovery with the follow-on abuse to identify successful platform breaches.
