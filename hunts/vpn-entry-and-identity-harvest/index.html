VPN Entry and Identity Harvest

Brief

Why this hunt

In the article "The First 24 Hours: What Happens When Ransomware Lands" (https://www.huntress.com/blog/what-happens-during-a-ransomware-attack), Huntress describes the rapid progression from initial access to full estate encryption. We designed this hunt to intercept that progression during the critical identity-harvesting window before the adversary reaches the encryption phase.

How the hunt flows

The first step identifies every host with VPN-related sign-in activity over the last 14 days. This scoping provides a list of potential beachheads and administrative workstations to focus the subsequent, more intensive queries. The second phase runs two queries in parallel. One query looks for authentication events where multi-factor authentication is absent or bypassed. The other query searches for PowerShell or shell script blocks containing offensive keywords like 'kerberoast' or 'minidump'. An analyst then triages these findings to link unhardened access with credential theft attempts on the same host. The third phase pivots to detect the impact. It checks for rare DNS lookups to exfiltration domains such as mega.nz or rclone.org. Simultaneously, it searches for process commands that delete volume shadow copies, which signifies the final stage before encryption. The final triage synthesizes the entire chain. If an analyst confirms a high-confidence match between the VPN entry and the subsequent impact commands, they authorize immediate host isolation and a double reset of the krbtgt account to revoke all active tickets.

What this hunt cannot see

This hunt relies on VPN provider logs appearing in the authentication surface. If the provider does not report MFA status or if logs are not ingested, the initial entry point remains hidden. Additionally, the script-based detection requires PowerShell Script Block Logging (Event 4104) to be active. If an adversary uses native binaries or obfuscated code without script logging, the harvesting phase stays invisible.

# VPN Entry and Identity Harvest

The adversary enters via a VPN that lacks multi-factor authentication, then harvests credentials to move laterally. This hunt identifies the unhardened sign-ins and the subsequent identity-focused script blocks. It then pivots to find evidence of outbound data transfer and the destruction of system backups. By correlating early-stage access with later-stage destructive behavior, the hunt provides the evidence required for an analyst to authorize isolation and identity resets before the encryption phase completes across the estate.
