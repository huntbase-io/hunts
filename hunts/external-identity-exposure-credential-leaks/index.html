External Identity Exposure and Credential Leaks

Adversaries are using corporate credentials harvested from unmanaged personal devices by infostealers to bypass authentication controls and gain initial access to cloud resources.

Brief

Why This Hunt Matters

High-profile intrusions, such as the 2024 Snowflake and CircleCI breaches, demonstrate that the perimeter now begins at the employee's home browser. Adversaries do not always need to exploit a zero-day when they can simply buy valid credentials. In the post Introducing Sekoia Digital Risk: Track Identity-Led Breaches, Sekoia highlights the necessity of monitoring the criminal "stealer" economy to complete the security picture.

How the Hunt Flows

The first phase identifies active corporate workstations. The query scans authentication logs to build a list of hostnames where corporate domain logons occur. This scoping ensures the hunt focuses on active identities rather than stale accounts.

Next, the hunt branches into two parallel paths. The first path establishes a behavioral baseline by stack-counting source IPs per user. It identifies rare authentication sources that deviate from the user's normal pattern. Simultaneously, the second path performs an enrichment lookup against Hudson Rock. This check identifies if corporate identities for the target domain have recently appeared in indexed stealer logs from families like RedLine or Lumma.

In the triage phase, an analyst or automated agent weighs the intersection of these two paths. The hunt flags users who show both external exposure in criminal markets and internal behavioral anomalies, such as a login from an IP never seen before in the environment. If the correlation holds, the hunt provides instructions to revoke active sessions and force a credential reset.

What the Hunt Cannot See

This hunt has two primary blind spots. First, it lacks visibility into the unmanaged endpoint. We can see the result of a credential theft, but we cannot see the initial infection on the user's personal machine or what other personal data was stolen. Second, there is a latency gap. A credential might be stolen and used by an adversary before it is indexed by external monitoring platforms. During this window, the hunt cannot rely on enrichment data to flag the identity.

How to Run the Hunt

This hunt is provided as an open hunt.md playbook. It is designed to be portable and imports directly into Huntbase or any runtime that supports the hunt.md standard. Because it relies on both internal logs and external API lookups, ensure your environment has the necessary integrations for authentication telemetry and Hudson Rock data.

    Query · scoping

  2. Find rare authentication sources

    Query · baseline

    Stack-count source IPs per user on the scoped hosts to find anomalous logins that might indicate stolen credential or session usage.

    reads hb_auth_signinsql
    SELECT device_hostname, actor_user_name, src_endpoint_ip, src_location_country, COUNT(*) AS login_count, MIN(time) AS first_seen FROM hb_auth_signin WHERE LOWER(actor_user_name) LIKE '%@{{target_domain}}' AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY device_hostname, actor_user_name, src_endpoint_ip HAVING login_count < 10

    What a hit looks like. Login events from source IPs seen rarely across the scoped fleet, potentially indicating attacker infrastructure.

  3. Check for domain-wide identity leaks

    Query · enrichment

    Identify if corporate credentials for the domain have recently appeared in stealer logs indexed by Hudson Rock.

    reads hudsonrock_search_by_domainsql
    SELECT domain, total_stealers, last_employee_compromised, stealer_families, employees_urls FROM hudsonrock_search_by_domain WHERE domain = '{{target_domain}}'

    What a hit looks like. A summary of recent compromises, listing stealer families (Lumma, RedLine) and counts. Silence means no indexed exposure for this domain in the Hudson Rock archive.

  4. Weigh exposure and sign-in behavior

    Agent triage

    Correlate the external compromise data with internal rare sign-in patterns to find high-confidence identity compromises.

  5. Route on verdict

    Decision

    Direct the hunt to containment or review based on the severity of the findings.

  6. Revoke sessions and reset credentials

    Response action

    Contain the risk by immediately revoking access for compromised identities found in the hunt.

  7. Examine post-login activity

    Analyst task

    Review internal logs for the compromised identities to determine if any unauthorized actions were performed before containment.

  8. Close out hunt

    Analyst task

    Document findings and update the behavioral baseline.

# External Identity Exposure and Credential Leaks

An agent weighs the intersection of these surfaces to find 'unlocked doors' before they are exploited at scale. The hunt identifies compromised corporate identities by correlating external exposure data from infostealer logs with anomalous internal sign-in behavior. Inspired by the Snowflake and CircleCI breaches, the hunt first identifies active workstations used by corporate identities, then fans out to check for domain-wide exposure in criminal markets (via Hudson Rock) alongside a search for rare authentication patterns from those same workstations.

## rare-authentication-patterns
<!-- Find rare authentication sources -->
Stack-count source IPs per user on the scoped hosts to find anomalous logins that might indicate stolen credential or session usage.

```sqlite target=identity role=baseline params=(target_domain=target_domain, scope_hosts=scope_hosts, lookback_days=lookback_days)
~~~yaml
baseline:
  compare: first_seen
  window: '{{lookback_days}}d'
expected: Login events from source IPs seen rarely across the scoped fleet, potentially
  indicating attacker infrastructure.
prevalence:
  by: device_hostname
  key:
  - src_endpoint_ip
  rare_below: 3
reads:
- device_hostname
- actor_user_name
- src_endpoint_ip
- src_location_country
- time
silence: not_evidence_of_absence
source: hb_auth_signin
verified: dry-run
verified_at: '2026-10-13'
~~~
SELECT device_hostname, actor_user_name, src_endpoint_ip, src_location_country, COUNT(*) AS login_count, MIN(time) AS first_seen FROM hb_auth_signin WHERE LOWER(actor_user_name) LIKE '%@{{target_domain}}' AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY device_hostname, actor_user_name, src_endpoint_ip HAVING login_count < 10
```

## revoke-identity-sessions
<!-- Revoke sessions and reset credentials -->
```action target=identity
~~~yaml
approval: required
~~~
Revoke all active browser and OAuth sessions for the confirmed identities. Trigger a forced password reset and require an MFA re-enrollment.
```
→ manual-analyst-review

## manual-analyst-review
<!-- Examine post-login activity -->
```manual target=analyst
Use hb_cloud_api_activity and hb_auth_signin to trace the actions of the compromised identities. Look for mass data access (S3/SharePoint) or modification of IAM policies.
```
→ close-out

## close-out
<!-- Close out hunt -->
```manual target=analyst
Record the identities found and the specific stealer families involved. Recommend security policy updates such as requiring managed devices for all administrative cloud access.
```
