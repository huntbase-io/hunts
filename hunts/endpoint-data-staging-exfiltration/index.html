Brief

The Final Stage of the Pivot

The recent analysis by Unit 42, Inside the Modern SOC: Defending the Cross-Environment Pivot, highlights how adversaries move across environments to reach their ultimate goals. Often, those goals involve the collection and removal of sensitive data. While early-stage detection focuses on initial access, this hunt targets the final, high-impact behaviors: data staging and exfiltration.

An adversary stages sensitive information in temporary directories and exfiltrates that data via rare outbound network connections or DNS lookups.

Phase 1: Identifying Staging

The hunt begins on the endpoint by examining file system activity. The first query searches the hb_file_activity surface for the creation of compressed archives, such as ZIP, 7z, or RAR files. It specifically targets user-writable directories like \Users\Public\, \Temp\, /tmp/, and /dev/shm/. Adversaries use these locations because they often lack strict write protections and serve as convenient collection points before the data leaves the environment. This step creates a list of candidate hosts and filenames for further investigation.

Phase 2: Correlating Network and DNS Anomalies

Once the hunt identifies staging activity, it pivots to the network and DNS surfaces in parallel. One path examines outbound network connections to external IP addresses. It applies a prevalence filter to find destinations that appear on only a few hosts across the entire fleet. A connection to a rare external IP address shortly after an archive is created in a temp folder is a strong indicator of exfiltration.

Simultaneously, the hunt looks for behavioral DNS anomalies. It identifies rare domain queries that do not match known local or internal patterns. Adversaries frequently use unique domains or subdomains for command-and-control and data tunneling. Finding a rare domain query on the same host that performed data staging increases the confidence in a malicious verdict.

Phase 3: Triage and Verdict

An agent reviews the combined evidence from all three surfaces. The triage process looks for process-level links: did the same process that created the archive also initiate the rare network connection? If the agent finds a single host performing all three behaviors, it flags the activity as malicious. This multi-surface correlation allows the hunt to ignore a sysadmin who creates a backup archive but does not send it to an unknown external destination.

Blind Spots and Limitations

The primary blind spot is the mapping between processes and network sockets. If the endpoint agent cannot definitively link a file-creation process to a network flow, an analyst must manually confirm the timing and parentage. Additionally, encrypted exfiltration via HTTPS or custom protocols hides the specific content and volume of the data transfer, making it difficult to assess the full scope of the theft without TLS inspection.

    Query · detection candidate

    Locate hosts with archives created in writable directories.

    reads hb_file_activitysql
    SELECT device_hostname, file_path, process_name, time FROM hb_file_activity WHERE activity_id = 1 AND (LOWER(file_path) LIKE '%.zip' OR LOWER(file_path) LIKE '%.7z' OR LOWER(file_path) LIKE '%.rar') AND (LOWER(file_path) LIKE '%\\users\\public\\%' OR LOWER(file_path) LIKE '%\\temp\\%' OR LOWER(file_path) LIKE '%\\appdata\\local\\temp\\%' OR LOWER(file_path) LIKE '/tmp/%' OR LOWER(file_path) LIKE '/var/tmp/%' OR LOWER(file_path) LIKE '/dev/shm/%') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Rows naming archives created in user-writable paths. Silence suggests no common staging activity occurred.

  2. Rare outbound network connections

    Query · baseline

    Find connections to external IP addresses that appear on fewer than the threshold number of hosts.

    reads hb_network_connectionsql
    SELECT dst_endpoint_ip, process_name, COUNT(DISTINCT device_hostname) AS host_count, COUNT(*) AS connection_count, GROUP_CONCAT(DISTINCT device_hostname) AS affected_hosts FROM hb_network_connection WHERE direction = 'outbound' AND disposition = 'Allowed' AND dst_endpoint_ip NOT LIKE '10.%' AND dst_endpoint_ip NOT LIKE '192.168.%' AND dst_endpoint_ip NOT LIKE '172.16.%' AND dst_endpoint_ip NOT LIKE '172.17.%' AND dst_endpoint_ip NOT LIKE '172.18.%' AND dst_endpoint_ip NOT LIKE '172.19.%' AND dst_endpoint_ip NOT LIKE '172.2%.%' AND dst_endpoint_ip NOT LIKE '172.3%.%' AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY dst_endpoint_ip, process_name HAVING host_count <= {{rare_threshold}}

    What a hit looks like. An IP address visited by only one or two hosts, potentially representing an exfiltration drop site.

  3. Rare behavioral DNS queries

    Query · baseline

    Identify rare domain queries on suspect hosts that might indicate C2 or exfiltration endpoints.

    What a hit looks like. Domain queries unique to a small set of hosts. Silence suggests no unusual DNS patterns for the lookback period.

# Endpoint Data Staging and Exfiltration

This hunt targets the final stages of an intrusion: collection and exfiltration. It identifies the creation of compressed archives in user-writable paths like Public or Temp on Windows and /tmp or /dev/shm on Linux, then correlates that activity with rare outbound network connections and behavioral DNS anomalies. An agent evaluates the combined evidence to distinguish administrative archiving from malicious data theft.
