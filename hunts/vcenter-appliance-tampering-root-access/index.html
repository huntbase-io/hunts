vCenter Appliance Administrative Tampering and Root Access

High severity TLP:CLEAR Part 2 of 2 Research by Rapid7 Published 25 Nov 2026

Hypothesis

An attacker is established on a vCenter appliance and is using administrative APIs to create local persistence and enable restricted shells for root-level command execution.

Brief

Background

Recent analysis from Rapid7 (Rapid7 Analysis: VMware vCenter SRP Authentication Bypass to Root (CVE-2026-123890) at https://www.rapid7.com/blog/post/ra-rapid7-analysis-vmware-vcenter-srp-authentication-bypass-to-root-cve-2026-123890) details a critical authentication bypass in VMware vCenter Server. This vulnerability allows an attacker to gain root access to the appliance. Our team developed a hunt to find the specific tampering that occurs after an attacker successfully bypasses authentication.

Hunt Flow

The hunt begins by identifying the blast radius. The first query lists every host running the vCenter service or the vpxd package by searching software inventory logs. This step ensures that the subsequent, more resource-intensive queries only target relevant appliances across the estate.

Once we define the scope, the hunt fans out to examine the management plane through HTTP activity logs. The analyst searches for rare calls to API paths that enable SSH or create local accounts, such as /api/appliance/access/ssh. By stack-counting these requests across the fleet, the hunt identifies configurations that differ from standard maintenance patterns.

Simultaneously, the hunt searches the operating system plane using Linux audit logs. It looks for execution records where an attacker adds a user to the superAdmin group or uses sudo to spawn an interactive bash shell. These signals provide the proof of the privilege escalation that follows the initial management plane tampering.

Finally, the hunt correlates the rare API activity with the suspicious OS commands. This activity is a hunt rather than a detection because it relies on the rarity and timing of these events across standardized appliances. A single sudo use might be benign, but sudo plus a rare management API call indicates a high-confidence exploit chain.

Blind Spots

This hunt has two primary limitations. If the management traffic passes through a proxy, the HTTP logs may only show the proxy's IP address rather than the attacker's true origin. Additionally, if EXECVE logging is disabled in the Linux audit configuration, the hunt identifies that a shell was opened but cannot see the specific commands the attacker executed inside it.

Steps

  1. Query, scoping

    Identify vCenter Appliances

    Inventory the hosts that run vCenter services to define the hunt's blast radius.

    sql, reads hb_software_inventory
    SELECT device_hostname, package_name, package_versionFROM hb_software_inventoryWHERE (LOWER(package_name) LIKE '%vcenter%' OR LOWER(package_name) LIKE '%vpxd%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)

    What a hit looks like. A list of hosts currently identified as vCenter appliances. Silence indicates no vCenter software is present.

  2. Query, baseline

    Rare Management API Activity

    Detect rare or unauthorized use of the appliance configuration APIs that enable SSH or create accounts.

    sql, reads hb_http_activity
    SELECT url_path, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seen, MAX(time) AS last_seenFROM hb_http_activityWHERE (instr(',' || '{{api_paths}}' || ',', ',' || LOWER(url_path) || ',') > 0 OR LOWER(url_path) LIKE '%/api/appliance/access/%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY url_pathHAVING host_count <= 2ORDER BY host_count ASC

    What a hit looks like. An API call used on one or two appliances, suggesting non-standard maintenance. Normal activity typically appears fleet-wide.

  3. Query, detection candidate

    OS Persistence and Root Escalation

    Search Linux audit logs for command arguments used in administrative persistence and root shell spawning.

    sql, reads hb_linux_audit
    SELECT device_hostname, raw_record, timeFROM hb_linux_auditWHERE record_type = 'EXECVE'  AND ( (LOWER(raw_record) LIKE '%useradd%' AND instr(',' || LOWER('{{persistence_groups}}') || ',', ',superadmin,') > 0 AND LOWER(raw_record) LIKE '%superadmin%') OR (LOWER(raw_record) LIKE '%sudo%' AND LOWER(raw_record) LIKE '%/bin/bash%') )  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Rows showing the manual creation of a superAdmin user or the use of sudo to open an interactive Bash shell as root.

  4. Agent triage

    Triage Tampering Evidence

    Assess whether the management API calls and OS-level commands together indicate a post-exploitation chain.

  5. Decision

    Route on Triage Result

    Drive automated containment for high-confidence hits and analyst review for ambiguous signals.

  6. Response action

    Isolate Compromised Appliance

    Prevent further management plane commands or data theft by isolating the vCenter appliance.

  7. Analyst task

    Forensic Review of vmdir Logs

    Perform deeper analysis to identify the origin of the bypass and the full extent of tampering.

  8. Analyst task

    Verify Remediation and Patching

    Ensure the appliance is updated and the vulnerable configuration is addressed.

  9. Analyst task

    Close-out and Documentation

    Record the hunt results and update baseline exclusions for legitimate vCenter administrators.

# vCenter Appliance Administrative Tampering and Root Access

This hunt identifies post-exploitation activity on VMware vCenter Server Appliances following an authentication bypass. It looks for the use of management APIs to create administrative local accounts and the enablement of SSH or the Bash shell. It correlates these management plane changes with OS-level execution logs where an attacker typically joins the 'superAdmin' group and uses sudo to spawn interactive root shells. By stack-counting these events across the appliance fleet, the hunt separates legitimate maintenance from targeted tampering.

## analyst-forensic-review
<!-- Forensic Review of vmdir Logs -->
```manual target=analyst
Examine the vmdir logs for unexpected SRP verifier creation. Verify if any directory database copies were granted before the account creation. Reconstruct the attacker's shell commands from /var/log/audit/audit.log.
```
→ remediation-verification

## remediation-verification
<!-- Verify Remediation and Patching -->
```manual target=analyst
Verify that the appliance has been updated to the fixed version (e.g., 8.0 U3m). Confirm that all local accounts created during the intrusion have been deleted.
```
→ close-out

<!-- Close-out and Documentation -->
```manual target=analyst

```
