# Hunting Persistent IDE Extensions and Workspace Cleanup in Developer Environments

Proofpoint recently published an analysis of the UNK_DeadDrop phishing campaign, titled "UNK_DeadDrop phishing campaign targets developers." The research describes a threat actor targeting the developer community with social engineering to gain access to intellectual property and cryptocurrency. Once a developer opens a malicious project, the actor achieves persistence through Visual Studio Code or Cursor IDE extensions. This behavior moves beyond simple binary execution into the environment where developers spend the majority of their time.

Our hypothesis is that an attacker has established persistence by installing a malicious extension masquerading as a Google-provided service. To evade detection, the actor also performs a cleanup of the workspace, deleting the scripts used during the initial infection phase. We developed this hunt to find these specific artifacts across both macOS and Linux environments, focusing on the overlap of rare software installs and suspicious file deletions.

The hunt begins by scoping the environment to find hosts with developer IDEs like Visual Studio Code or Cursor. This narrowing step ensures we are focusing telemetry analysis on the most relevant assets where extension-based persistence is possible. Identifying these hosts via software inventory is the first pivot point for the investigation.

Next, we pivot to file activity, looking for any new extensions written to the IDE directories that contain "google" in their path. While many legitimate Google extensions exist, the threat actor specifically names theirs to look like a system update or official support tool, such as "google-update-support." We do not rely on the name alone; we use prevalence stacking to find extensions that appear on only a few hosts, which separates standard tools from unique malicious installs.

The third phase involves looking for the missing evidence. The UNK_DeadDrop campaign is known for deleting infection scripts such as run-update.sh or run-update.vbs and clearing the tasks.json file. We correlate the presence of rare extensions with these specific file deletion events to build a high-confidence picture of a compromised developer workstation. Finding a rare extension and a simultaneous deletion of these specific filenames provides the necessary signal to justify host isolation.

There are blind spots to consider. This hunt relies heavily on EDR visibility into user home directories, specifically hidden folders like .vscode and .cursor. If your telemetry collection is limited to system paths or standard Program Files, these persistent extensions will remain invisible. Additionally, if software inventory tools do not track the Cursor IDE specifically, those hosts might be missed during the initial scoping.

We designed this as a hunt rather than a simple detection rule because google extensions and script deletions are not inherently malicious. A static alert would likely trigger on legitimate developer activity or common configuration changes. This process uses frequency analysis and behavioral correlation to identify the specific footprint of the UNK_DeadDrop actor.

This hunt is available as a hunt.md playbook. It can be imported into Huntbase or any hunt.md-aware runtime to automate the data collection and analysis steps across your fleet. Manual triage is still recommended to confirm the nature of any rare extensions identified before taking remediation actions.
