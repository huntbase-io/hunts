Brief

Overview\n\nPalo Alto Networks' Unit 42 recently detailed a long-running campaign in their report, "Untracked Nightmares: The Threats Hiding Behind Commodity Infrastructure". This campaign, identified as CL-CRI-1171, has reportedly compromised over 10,000 systems over two years. It leverages trojanized installers for common software like WinDirStat or Bluetooth drivers to deliver a variety of payloads, including the Insomnia RAT and ARKTunnel. Catching this early requires looking at the delivery gating rather than just the final payload.\n\n## Hypothesis\n\nThe hunt is built on the premise that an active infection can be identified by looking for trojanized Inno Setup installers that drop and execute temporary (.tmp) binaries from user-writable directories. This activity is expected to be accompanied by network beaconing to rotational, compound-word domains and specific HTTP request parameters used for Pay-Per-Install (PPI) environment fingerprinting.\n\n## Hunt Flow\n\n### Scoping the Environment\n\nThe hunt begins by checking software inventory surfaces for known lure keywords. While many of these installers are run as standalone executables and may not leave a permanent footprint in the inventory, identifying machines with unusual installations of WinDirStat or driver packages provides a starting point for the investigation. This helps analysts focus on systems where third-party software may have been downloaded recently.\n\n### Process Analysis\n\nWe focus on the behavior of Inno Setup, which is frequently used by the OfferLoader family. The logic looks for parent processes with "setup" or "install" in their names that spawn executable files with .tmp extensions from AppData or Public directories. This pattern is characteristic of the Pascal script execution used to launch the next stage of the infection and is a key pivot point for our behavioral analysis.\n\n### Network Corroboration\n\nTo increase confidence and reduce noise, we pivot to DNS and HTTP telemetry. The campaign uses rotational domains often ending in .cfd, .space, or .info. We look for rare DNS resolutions to these TLDs that appear on only a few hosts. Simultaneously, we inspect HTTP traffic for the "click_id" parameter, which the PPI infrastructure uses to track and gate successful infections based on the victim's environment.\n\n### Triage and Isolation\n\nThe final stage involves an automated agent correlating the timing of the process execution with the network markers. This correlation is necessary because WinDirStat or Inno Setup may be used legitimately in some environments. By linking the suspicious process behavior to the specific PPI gating traffic, we can isolate the host with high confidence and prevent the delivery of secondary RATs.\n\n## Blind Spots\n\nAnalysts should be aware of two primary blind spots. First, the hunt relies on HTTP visibility for the "click_id" marker. If TLS decryption is not present, we lose the ability to see URI queries. Second, the .tmp binaries are often deleted by the installer immediately after execution. If the endpoint telemetry does not capture file hashes in real-time, the primary payload artifact may be lost before it can be retrieved for forensic analysis.\n\n## How to Run\n\nThis hunt is provided as a hunt.md playbook. It can be imported into Huntbase or any compatible runtime that supports the hunt.md format. Once imported, you can adjust the lookback period and customize the list of lure domains based on your specific threat intelligence feeds. This workflow is designed as a hunt rather than a detection because it requires correlating multiple signals across different telemetry surfaces to make a high-confidence determination.

  • Needs hb_http_activity with full URI/referrer visibility. Without referrer data, we cannot distinguish between accidental lure clicks and intentional searches, leading to lower confidence in initial access attribution. It would answer whether the traffic originated from a YouTube link or a Blogspot redirect. Remediation: Enable TLS decryption and log referrers on edge proxies.

OfferLoader often deletes its intermediate files immediately after dropping the next stage; if real-time process/file events are missed, the primary artifact is gone. It would answer the hash of the .tmp file before it is deleted by the installer. Remediation: Ensure EDR is configured to capture file hashes for all temporary directory activity.

# OfferLoader Trojanized Installer and PPI Gating

This hunt targets the delivery and gating phase of the CL-CRI-1171 campaign. It identifies the execution of trojanized installers (like WinDirStat or Bluetooth Drivers) that use Inno Setup to drop and run temporary (.tmp) payloads. It further corroborates this by looking for the distinctive rotational C2 domains and the presence of Base64 fingerprints (click_id) in HTTP traffic, which are characteristic of the Pay-Per-Install (PPI) gating mechanism.
