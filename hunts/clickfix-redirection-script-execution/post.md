# ClickFix Redirection and PowerShell Clipboard Execution Hunt

### Why this hunt The Huntress team recently detailed a shift in ClickFix tradecraft in their article, Beyond the clipboard: The evolving tradecraft of ClickFix (https://www.huntress.com/blog/the-evolving-tradecraft-of-clickfix). The campaign uses refined social engineering lures to convince users their browser or document viewer is broken, providing a PowerShell snippet to fix the issue. This hunt identifies those users who fell for the lure and executed code from their clipboard. ### The Hypothesis An adversary lures users to a malicious site that tricks them into pasting a PowerShell command from the clipboard. This command executes in memory and stages a malicious payload in a temporary directory. ### How the hunt flows The hunt starts by scoping the environment to hosts with active browser installations or Node.js runtimes. This narrows the focus to endpoints that possess the primary attack surface used by ClickFix lures. Once the scope is defined, the hunt runs three parallel queries to gather evidence. The first query identifies DNS resolutions to known lure domains like vvestalw.ghost.io or westlaw-signon.com. The second query performs stack-counting on PowerShell processes that use Get-Clipboard or contain specific hex strings found in recent payloads. The third query looks for file creation events in ProgramData or Temp directories, specifically looking for cf_verify.zip or encoded text files. An agent then analyzes these three signals. It looks for hosts that resolved a lure domain and followed it with a rare PowerShell command within a short window. This correlation is what separates an active compromise from a sysadmin using PowerShell for legitimate tasks. ### Blind Spots Analysts must account for three visibility gaps. First, modern browsers may use DNS-over-HTTPS, which hides the lure domain resolution from system-level DNS logs. Second, if the user executes the lure on an unmanaged or BYOD device, the endpoint agent will see nothing. Finally, because the malicious code resides in the clipboard, the original data is lost if the user clears the clipboard before forensics begin. ### How to run this hunt This hunt is available as an open hunt.md playbook. You can import it directly into Huntbase or any hunt.md-aware runtime to begin the scoping phase. Because the PowerShell query uses prevalence-based filtering, the hunt is designed to be run across the entire estate to find the needle in the haystack without flooding an analyst with benign administrative alerts.
