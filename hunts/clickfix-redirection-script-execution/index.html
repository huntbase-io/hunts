ClickFix Redirection and Script Execution

High severity TLP:CLEAR Part 1 of 2 Research by Huntress Published 12 Nov 2026

Hypothesis

An adversary has lured users to a malicious site that tricks them into pasting a PowerShell command from the clipboard, which then executes and stages a malicious payload.

Brief

Why this hunt

The Huntress team recently detailed a shift in ClickFix tradecraft in their article, Beyond the clipboard: The evolving tradecraft of ClickFix (https://www.huntress.com/blog/the-evolving-tradecraft-of-clickfix). The campaign uses refined social engineering lures to convince users their browser or document viewer is broken, providing a PowerShell snippet to fix the issue. This hunt identifies those users who fell for the lure and executed code from their clipboard.

How the hunt flows

The hunt starts by scoping the environment to hosts with active browser installations or Node.js runtimes. This narrows the focus to endpoints that possess the primary attack surface used by ClickFix lures. Once the scope is defined, the hunt runs three parallel queries to gather evidence. The first query identifies DNS resolutions to known lure domains like vvestalw.ghost.io or westlaw-signon.com. The second query performs stack-counting on PowerShell processes that use Get-Clipboard or contain specific hex strings found in recent payloads. The third query looks for file creation events in ProgramData or Temp directories, specifically looking for cf_verify.zip or encoded text files. An agent then analyzes these three signals. It looks for hosts that resolved a lure domain and followed it with a rare PowerShell command within a short window. This correlation is what separates an active compromise from a sysadmin using PowerShell for legitimate tasks.

Blind Spots

Analysts must account for three visibility gaps. First, modern browsers may use DNS-over-HTTPS, which hides the lure domain resolution from system-level DNS logs. Second, if the user executes the lure on an unmanaged or BYOD device, the endpoint agent will see nothing. Finally, because the malicious code resides in the clipboard, the original data is lost if the user clears the clipboard before forensics begin.

  1. Query, scoping

    Scope to hosts with web browsers or Node.js

    Identify hosts that possess the primary attack surface (web browsers) or specific runtimes (Node.js) mentioned in the ClickFix campaigns.

    What a hit looks like. A list of hosts currently running software that facilitates the ClickFix lure or payload execution.

  2. Query, enrichment

    DNS lookups to lure domains

    Identify hosts that visited the malicious redirection domains.

    sql, reads hb_dns_activity
    SELECT device_hostname, query_hostname, process_name, timeFROM hb_dns_activityWHERE instr(',' || '{{lure_domains}}' || ',', ',' || LOWER(query_hostname) || ',') > 0  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Hosts resolving known malvertising or typosquatted domains associated with the ClickFix campaign.

  3. Query, detection candidate

    Rare PowerShell clipboard operations

    Detect PowerShell commands that interact with the clipboard or use specific hex strings found in ClickFix payloads, stack-counting to isolate rare behaviors.

    sql, reads hb_process_activity
    SELECT LOWER(process_cmd_line) AS cmd, COUNT(DISTINCT device_hostname) AS hosts, COUNT(*) AS executions, MIN(time) AS first_seenFROM hb_process_activityWHERE (LOWER(process_name) LIKE '%\\powershell.exe' OR LOWER(process_name) LIKE '%\\pwsh.exe')  AND (LOWER(process_cmd_line) LIKE '%get-clipboard%' OR LOWER(process_cmd_line) LIKE '%6341434163416441%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY cmdHAVING hosts <= 3ORDER BY hosts ASC

    What a hit looks like. Highly specific PowerShell commands used to retrieve and execute code from the user's clipboard. Typical administrator use of Get-Clipboard is expected to be more common than attacker scripts.

  4. Query, enrichment

    Creation of staged payloads

    Search for specific files created by ClickFix PowerShell stagers in temporary directories.

    sql, reads hb_file_activity
    SELECT device_hostname, file_path, process_name, timeFROM hb_file_activityWHERE (LOWER(file_path) LIKE '%\\cf_verify.zip' OR LOWER(file_path) LIKE '%\\6341434163416441.txt')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Creation of a ZIP archive or a temporary text file containing encoded PowerShell in directories like ProgramData or Temp.

  5. Agent triage

    Assess ClickFix chain

    Correlate lure site visits with subsequent clipboard execution and file staging to confirm a successful social engineering compromise.

  6. Decision

    Route on verdict

    Determine the next action based on the agent's assessment.

  7. Response action

    Isolate compromised host

    Halt the attack chain before the adversary establishes persistent C2 or moves laterally.

  8. Analyst task

    Analyst manual review

    Confirm the agent's findings and identify any follow-on activity such as DLL sideloading or persistence.

  9. Analyst task

    Close out

    Finalize the hunt results and record lessons learned.

# ClickFix Redirection and Script Execution

ClickFix represents a refined social engineering attack where malicious sites mimic legitimate verification checks or document tools. This hunt identifies the initial access vector by finding DNS requests to known lure domains and corroborates these with rare PowerShell executions involving clipboard operations and file staging evidence. An agent evaluates the chain of redirection and execution to identify successful social engineering completions.
