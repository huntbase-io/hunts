ClickFix Redirection and Script Execution

An adversary has lured users to a malicious site that tricks them into pasting a PowerShell command from the clipboard, which then executes and stages a malicious payload.

Brief

Why this hunt

The Huntress team recently detailed a shift in ClickFix tradecraft in their article, Beyond the clipboard: The evolving tradecraft of ClickFix (https://www.huntress.com/blog/the-evolving-tradecraft-of-clickfix). The campaign uses refined social engineering lures to convince users their browser or document viewer is broken, providing a PowerShell snippet to fix the issue. This hunt identifies those users who fell for the lure and executed code from their clipboard.

How the hunt flows

The hunt starts by scoping the environment to hosts with active browser installations or Node.js runtimes. This narrows the focus to endpoints that possess the primary attack surface used by ClickFix lures. Once the scope is defined, the hunt runs three parallel queries to gather evidence. The first query identifies DNS resolutions to known lure domains like vvestalw.ghost.io or westlaw-signon.com. The second query performs stack-counting on PowerShell processes that use Get-Clipboard or contain specific hex strings found in recent payloads. The third query looks for file creation events in ProgramData or Temp directories, specifically looking for cf_verify.zip or encoded text files. An agent then analyzes these three signals. It looks for hosts that resolved a lure domain and followed it with a rare PowerShell command within a short window. This correlation is what separates an active compromise from a sysadmin using PowerShell for legitimate tasks.

Blind Spots

Analysts must account for three visibility gaps. First, modern browsers may use DNS-over-HTTPS, which hides the lure domain resolution from system-level DNS logs. Second, if the user executes the lure on an unmanaged or BYOD device, the endpoint agent will see nothing. Finally, because the malicious code resides in the clipboard, the original data is lost if the user clears the clipboard before forensics begin.

Blind spots

  • Needs Complete endpoint agent coverage across all workstations. Attackers targeting users via personal devices or unmanaged hosts will not be seen by hb_dns_activity or hb_process_activity. It would answer whether social engineering occurred on unmanaged or BYOD devices.
  • Needs Browser extension or proxy-level logging of HTTPS traffic. Modern browsers using DoH bypass traditional system-level DNS logging, making lure domain resolutions invisible to hb_dns_activity. It would answer whether lure domains were resolved via DNS-over-HTTPS (DoH).

Telemetry shows the command that *reads* the clipboard, but if the user has already cleared or replaced the clipboard, the malicious data is lost for forensic analysis. It would answer the original contents of the clipboard before it was used by PowerShell.

# ClickFix Redirection and Script Execution

ClickFix represents a refined social engineering attack where malicious sites mimic legitimate verification checks or document tools. This hunt identifies the initial access vector by finding DNS requests to known lure domains and corroborates these with rare PowerShell executions involving clipboard operations and file staging evidence. An agent evaluates the chain of redirection and execution to identify successful social engineering completions.
