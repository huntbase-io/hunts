# Hunting for Entra ID Agent User Abuse in Microsoft Teams

Recent research published by Red Canary in their article, "Investigating suspicious AI workflows in Microsoft Entra Agent ID: Agent’s user account" (https://redcanary.com/blog/threat-detection/entra-id-ai-workflows-teams/), highlights a shift in adversary tactics. Attackers are moving beyond simple user account takeovers to target Agent Users—identities designed for AI and automation. Because these accounts are trusted to perform non-interactive tasks, their activity often bypasses standard MFA and phishing controls. This hunt provides a structured approach to identifying when these identities are repurposed for malicious message distribution.Our hypothesis is that an adversary who has compromised Entra ID Agent User credentials will use PowerShell—specifically on non-Windows platforms like macOS—to interface with the Microsoft Graph API. They do this to send malicious links or files through Teams channels, leveraging the inherent trust users have in internal automated notifications. This hunt looks for the technical intersection of unexpected cross-platform PowerShell usage, non-interactive authentication patterns, and specific Graph API calls associated with Teams messaging.The hunt flow begins with an inventory check. We scope the environment for hosts running PowerShell (pwsh) on macOS. While PowerShell is cross-platform, its use on macOS is often limited to specific administrative or automated tasks. Identifying where it exists narrows our search to systems capable of running the reported Graph API automation scripts used by attackers.Next, we pivot to identity telemetry. We examine Entra ID sign-in logs for non-interactive OAuth token exchanges. We are looking for sign-ins from suspicious IP addresses or instances where these automated flows occur without the context of a legitimate interactive session. This helps separate routine background syncs from potential session hijacking or credential abuse.Behavioral analysis follows via network telemetry. We stack-count HTTP requests directed at Microsoft Graph domains. The primary indicator here is the User-Agent; we are looking for PowerShell-based requests to Graph messaging endpoints that appear with low frequency. These rare connections are often the first sign of a scripted attack attempting to move laterally into Teams.Finally, we perform deep inspection of script blocks. By examining script activity for specific cmdlets like `Connect-MgGraph` or `New-MgBetaTeamChannelMessage`, we can confirm the 'how' of the attack. This step provides the high-fidelity evidence needed to distinguish between a developer running a legitimate script and an attacker automating the spread of malicious content.The hunt has two primary blind spots. First, without Microsoft Graph Activity Logs or Purview Audit, we cannot see the actual content of the messages or the specific recipients. We only see that a message was sent. Second, if the environment has weak Conditional Access policies, the non-interactive token exchange might not generate MFA telemetry, making it harder to definitively prove a session was hijacked.To run this, download the hunt.md playbook from our repository. It is designed for use in Huntbase or any hunt.md-aware runtime. It provides the exact logic needed to correlate these disparate data sources and isolate the affected host and identity.
