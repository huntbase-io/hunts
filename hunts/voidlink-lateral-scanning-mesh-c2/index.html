VoidLink Lateral Scanning and Mesh C2

An intruder is using a VoidLink implant to perform automated internal reconnaissance and establish a peer-to-peer mesh command-and-control network between compromised Linux servers.

Brief

Why this hunt

Cisco Talos recently published research on VoidLink, an AI-aided modular framework used by UAT-9921. This framework is a defense-contractor grade tool designed for stealthy reconnaissance and resilient command-and-control routing. It represents a significant shift in how attackers manage internal persistence on Linux infrastructure. We published this hunt to help practitioners find the specific traces of VoidLink lateral movement and peer-to-peer mesh networking.

How the hunt flows

The hunt starts with a scoping phase that scans for common lateral movement tools. The first query identifies hosts running fscan, gscan, or SOCKS proxies. This provides a lead list of potentially compromised servers where the adversary has established a beachhead. Once the lead list exists, the hunt fans out into two parallel network investigations. The first investigation looks for targeted discovery of container management APIs. It searches for outbound connections to Docker and Kubernetes management ports from the scoped hosts. This reflects VoidLink known interest in cloud and container infrastructure. The second parallel investigation baselines internal peer-to-peer traffic. It looks for rare outbound connections between internal IP addresses where both the source and destination ports are high-numbered. This pattern identifies the mesh routing nodes VoidLink uses to move traffic between internal servers while avoiding boundary firewalls. Finally, an analyst correlates these signals. A host that runs reconnaissance tools and then initiates rare internal P2P connections or container discovery receives a malicious verdict.

What this hunt cannot see

This hunt has two primary blind spots. First, if the VoidLink implant uses a rootkit to hide its processes, the initial lead query will return nothing. In that scenario, the hunt relies entirely on network telemetry. Second, without deep packet inspection, the hunt cannot confirm the contents of the mesh traffic. It relies on the statistical rarity of the connection pattern to infer malicious intent.

    Query · enrichment

    Identify network attempts to access Kubernetes or Docker management endpoints, reflecting VoidLink's cloud-aware reconnaissance.

    reads hb_network_connectionsql
    SELECT device_hostname, dst_endpoint_ip, dst_endpoint_port, COUNT(*) as events FROM hb_network_connection WHERE (dst_endpoint_port IN (2375, 2376, 6443)) AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY device_hostname, dst_endpoint_ip, dst_endpoint_port

    What a hit looks like. Connections from Linux servers to Docker or Kubernetes management ports. Silence confirms no discovery of these specific services occurred from the scoped hosts.

  3. Baseline internal peer-to-peer traffic

    Query · baseline

    Find the rare internal network connections between high-numbered ports that indicate a VoidLink mesh network bypassing boundary controls.

    reads hb_network_connectionsql
    SELECT device_hostname, dst_endpoint_ip, COUNT(*) as connection_count, MIN(time) as first_seen FROM hb_network_connection WHERE direction = 'outbound' AND (dst_endpoint_ip LIKE '10.%' OR dst_endpoint_ip LIKE '192.168.%' OR dst_endpoint_ip LIKE '172.%') AND src_endpoint_port > 1024 AND dst_endpoint_port > 1024 AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY device_hostname, dst_endpoint_ip HAVING connection_count <= 20 ORDER BY connection_count ASC

    What a hit looks like. A few rare connections between internal servers that are not part of known server-to-server patterns (e.g., DB or logging).

    Correlate the process-based leads with the network-based discovery and mesh evidence to confirm a VoidLink intrusion.

  5. Route on VoidLink verdict

  6. Isolate the compromised host

    Stop the adversary's automated lateral scanning and mesh routing by isolating the host from the network.

    Examine the peer IPs from the mesh connection results to identify other nodes in the VoidLink network.

# VoidLink Lateral Scanning and Mesh C2

VoidLink is an AI-aided modular framework used by UAT-9921 for stealthy reconnaissance and resilient C2 routing. This hunt focuses on identifying the indicators of a VoidLink intrusion by detecting the execution of lateral movement tools like FSCAN, identifying attempts to discover Kubernetes or Docker management endpoints, and baselining rare internal peer-to-peer network connections that signify the framework's unique mesh routing capability. The hunt starts with a lead based on process execution and then fans out to examine network telemetry for cloud-specific discovery and statistical outliers in internal traffic.
