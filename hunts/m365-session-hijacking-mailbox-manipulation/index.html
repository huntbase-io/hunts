M365 Session Hijacking and Mailbox Manipulation

An adversary has hijacked an authenticated Microsoft 365 session using stolen cookies, bypassing MFA to create stealthy inbox rules and perform fraudulent financial transactions.

Brief

Why This Hunt

Adversaries favor session hijacking over credential theft to bypass multi-factor authentication. The Huntress report, ClickFix to BEC in 24 Hours: Tragic Quadrant (https://www.huntress.com/blog/clickfix-bec-tragic-quadrant-doris), details how a fake browser update leads to Business Email Compromise (BEC) within 24 hours. After an attacker steals a session cookie, they access the target inbox without triggering new MFA challenges.

How the Hunt Flows

The hunt starts by querying M365 cloud activity for the creation or modification of inbox rules. We look specifically for rules with minimalist names like ".", "..", " ", or "z". These names are common in BEC attacks because they are easily overlooked by users in the Outlook interface. This step identifies the specific user accounts that might be under attacker control.

Once the hunt identifies a suspicious rule, an analyst or automated agent evaluates the lead. Not every minimalist rule name is malicious, but in the context of a potential BEC, this activity is a high-fidelity gate for the more resource-intensive steps that follow. If the rule is deemed suspicious, the hunt fanned out to investigate both authentication and mailbox impact simultaneously.

The hunt then investigates authentication and mailbox impact simultaneously. The first branch of the parallel investigation examines authentication logs for the flagged users. We look for session concurrency anomalies, such as a shift in the User-Agent string or a change in the source country while a session is active. A sudden move from a known corporate IP to a residential proxy or a different browser type suggests cookie theft.

The second branch of the parallel investigation searches for impact. We look for the technical side effects of BEC: the hard deletion of messages, emptying of folders, or the sending of unauthorized emails. Attackers often delete their own sent messages or incoming replies from victims to keep the legitimate user unaware of the ongoing fraud.

Finally, the hunt synthesizes these points—the suspicious rule, the session anomaly, and the destructive mailbox activity—into a single verdict. If the evidence aligns, the hunt provides an automated action to revoke all active M365 sessions for the user, which kills the stolen cookie.

Blind Spots

This hunt relies on the Microsoft 365 Unified Audit Log (UAL). If UAL is disabled or if the tenant lacks the necessary licensing level for advanced audit features, the signals for rule creation and mailbox deletions are invisible. Additionally, Microsoft logs can experience a latency of several hours. An attacker moving at high speed may complete their objectives before the logs are available for the hunt to process.

  1. Lead: Suspicious M365 Inbox Rule Creation

    Query · detection candidate

    Identify the creation or modification of inbox rules with minimalist names like '..' which attackers use to hide mailbox manipulation.

    reads hb_cloud_api_activitysql
    SELECT actor_user_name, resource_name, api_operation, src_endpoint_ip, user_agent, time FROM hb_cloud_api_activity WHERE provider = 'm365' AND (api_operation = 'New-InboxRule' OR api_operation = 'Set-InboxRule') AND (instr(',' || '{{suspicious_rule_names}}' || ',', ',' || LOWER(substr(resource_name, instr(resource_name, '\') + 1)) || ',') > 0 OR LENGTH(substr(resource_name, instr(resource_name, '\') + 1)) <= 2) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A row indicates a rule created with a near-invisible name. Silence indicates no such rules were created via the API in the window.

  2. Evaluate Rule Lead

    Agent triage

    Decide if the identified inbox rule creation warrants a full investigation of the user session.

  3. Gate: Suspicious Rules Detected?

    Decision

    Limit expensive concurrency and impact queries to only those cases where a suspicious rule lead exists.

  4. M365 Session Concurrency Anomalies

    Query · baseline

    Examine the session history for flagged users to find browser-string shifts or proxy use concurrent with the rule creation.

    reads hb_auth_signinsql
    SELECT actor_user_name, user_agent, src_endpoint_ip, src_location_country, is_proxy, MIN(time) as first_seen, MAX(time) as last_seen FROM hb_auth_signin WHERE provider = 'm365' AND status_id = 1 AND ('{{scope_users}}' = '' OR instr(',' || '{{scope_users}}' || ',', ',' || actor_user_name || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY actor_user_name, user_agent, src_endpoint_ip, src_location_country, is_proxy

    What a hit looks like. Users with disparate browser strings or VPN use within the same window. Silence implies single-browser sessions.

  5. M365 Mailbox Impact Actions

    Query · enrichment

    Identify fraudulent emails being sent or the deletion of evidence to hide the attacker's presence, specifically for the flagged users.

    reads hb_cloud_api_activitysql
    SELECT actor_user_name, api_operation, resource_name, src_endpoint_ip, time FROM hb_cloud_api_activity WHERE provider = 'm365' AND ('{{scope_users}}' = '' OR instr(',' || '{{scope_users}}' || ',', ',' || actor_user_name || ',') > 0) AND (api_operation IN ('Send', 'MoveToDeletedItems', 'HardDelete', 'EmptyFolder') OR (api_operation = 'Update' AND LOWER(resource_name) LIKE '%inbox%')) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A burst of email deletions or sends from a user who also showed rule anomalies. Silence indicates no destructive mailbox actions.

  6. Triage Investigation

    Agent triage

    Synthesize the rule creation, the session browser shift, and the mailbox impact to confirm a BEC event.

  7. Route on Verdict

    Decision

    Automate the containment request if the session hijack is confirmed.

  8. Revoke M365 Sessions

    Response action

    Immediately invalidate the stolen session cookie and prevent further unauthorized access.

  9. Analyst Manual Review

    Analyst task

    Provide human oversight for indeterminate or suspicious cases.

  10. Close Out

    Analyst task

    Finalize the hunt and record findings.

# M365 Session Hijacking and Mailbox Manipulation

This hunt identifies the transition from endpoint compromise to identity-based fraud. It starts by finding suspicious inbox rule creations that use minimalist or hidden naming conventions common in BEC attacks. If found, the hunt expands to analyze authentication anomalies, specifically concurrent sessions using different browser fingerprints or locations, and corroborates these with mailbox activities like unauthorized email sending or permanent deletion of evidence. This flow follows the scenario where a stolen session cookie allows an attacker to manipulate an inbox for hours without triggering MFA alerts.
