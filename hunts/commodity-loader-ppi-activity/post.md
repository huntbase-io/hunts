# Hunting multi-stage pay-per-install loaders and follow-on RATs

### From Commodity Loaders to Persistent Backdoors 1010Unit 42 recently detailed a cluster of activity they call CL-CRI-1171 in the report "Untracked Nightmares: The Threats Hiding Behind Commodity Infrastructure" (https://unit42.paloaltonetworks.com/ppi-network-malware-campaign-analysis/). While many practitioners dismiss pay-per-install (PPI) activity as a nuisance, this research shows how these loaders serve as the primary delivery mechanism for persistent backdoors like Insomnia RAT and ARKTunnel. 1010### The Hypothesis 1010An intruder uses trojanised software installers, promoted through YouTube gaming lures and SEO-poisoned search results, to deploy a multi-stage loader. This loader beacons to rotational C2 domains before downloading and executing follow-on backdoors. These final payloads use script interpreters and network tunneling to maintain access to the environment. 1010### Phase 1: Identifying the Lure 1010The hunt begins by examining endpoint process activity. The adversary often masquerades as utility software or drivers. The first query searches for specific filenames mentioned in the research, such as WinDirStat or Bluetooth driver installers. An analyst uses this scoping step to identify the initial point of entry and the specific hosts that interacted with the malicious lures. 1010### Phase 2: Monitoring the Loader and Infrastructure 1010Once a lure executes, it typically launches an installer that spawns temporary files. This phase pivots to process activity to find .tmp files executed from user profile paths, especially those spawned by setup-related parent processes. Simultaneously, the hunt checks DNS activity for lookups to rotational C2 infrastructure. The adversary uses specific top-level domains like .cfd, .space, and .xyz with low-frequency, compound-word hostnames. Correlating these DNS requests with the timing of the suspicious process execution helps confirm the loader presence. 1010### Phase 3: Uncovering Follow-on Payloads 1010If the loader succeeds, it deploys script-based backdoors. The third phase of the hunt looks for script interpreter activity, focusing on Node.js or Python environments. The adversary uses these interpreters to run scripts that establish network sockets. We search for script content containing socket or connection logic, which is an anomaly on most standard user workstations. Additionally, the hunt examines network connections originating from these interpreters directed toward common web ports like 443 or 8080, which often indicates the presence of ARKTunnel or Socks5Systemz. 1010### Blind Spots 1010This hunt faces two primary limitations. First, ARKTunnel can use steganography to hide payloads within bitmap images. If host telemetry does not capture specific memory operations or the loading of these images into a script environment, the final payload may go unnoticed. Second, without full HTTP URI and request body logging, we cannot see the Base64-encoded click identifiers used in the initial redirectors. The hunt relies on DNS and process patterns as a proxy for this visibility. 1010### How to Run the Hunt 1010This hunt exists as an open hunt.md playbook. You can import it into Huntbase or any runtime that supports the hunt.md format. Because the adversary uses rotational infrastructure, analysts should regularly update the C2 domain parameters with new observations from their environment.
