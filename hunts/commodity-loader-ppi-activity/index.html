Brief

From Commodity Loaders to Persistent Backdoors

Unit 42 recently detailed a cluster of activity they call CL-CRI-1171 in the report "Untracked Nightmares: The Threats Hiding Behind Commodity Infrastructure" (https://unit42.paloaltonetworks.com/ppi-network-malware-campaign-analysis/). While many practitioners dismiss pay-per-install (PPI) activity as a nuisance, this research shows how these loaders serve as the primary delivery mechanism for persistent backdoors like Insomnia RAT and ARKTunnel.

Phase 1: Identifying the Lure

The hunt begins by examining endpoint process activity. The adversary often masquerades as utility software or drivers. The first query searches for specific filenames mentioned in the research, such as WinDirStat or Bluetooth driver installers. An analyst uses this scoping step to identify the initial point of entry and the specific hosts that interacted with the malicious lures.

Phase 2: Monitoring the Loader and Infrastructure

Once a lure executes, it typically launches an installer that spawns temporary files. This phase pivots to process activity to find .tmp files executed from user profile paths, especially those spawned by setup-related parent processes. Simultaneously, the hunt checks DNS activity for lookups to rotational C2 infrastructure. The adversary uses specific top-level domains like .cfd, .space, and .xyz with low-frequency, compound-word hostnames. Correlating these DNS requests with the timing of the suspicious process execution helps confirm the loader presence.

Phase 3: Uncovering Follow-on Payloads

If the loader succeeds, it deploys script-based backdoors. The third phase of the hunt looks for script interpreter activity, focusing on Node.js or Python environments. The adversary uses these interpreters to run scripts that establish network sockets. We search for script content containing socket or connection logic, which is an anomaly on most standard user workstations. Additionally, the hunt examines network connections originating from these interpreters directed toward common web ports like 443 or 8080, which often indicates the presence of ARKTunnel or Socks5Systemz.

Blind Spots

This hunt faces two primary limitations. First, ARKTunnel can use steganography to hide payloads within bitmap images. If host telemetry does not capture specific memory operations or the loading of these images into a script environment, the final payload may go unnoticed. Second, without full HTTP URI and request body logging, we cannot see the Base64-encoded click identifiers used in the initial redirectors. The hunt relies on DNS and process patterns as a proxy for this visibility.

    What a hit looks like. Execution of a .tmp file in the Local Settings Temp directory, often spawned by an installer.

  3. Query, baseline

    Rotational C2 beaconing

    Match DNS requests to the report's seed domains and identify lookups to the specific TLDs used by the rotational infrastructure.

    sql, reads hb_dns_activity
    SELECT device_hostname, query_hostname, COUNT(*) AS lookup_count, MIN(time) AS first_seenFROM hb_dns_activityWHERE (instr(',' || '{{c2_domains}}' || ',', ',' || LOWER(query_hostname) || ',') > 0 OR LOWER(query_hostname) LIKE '%.cfd' OR LOWER(query_hostname) LIKE '%.space' OR LOWER(query_hostname) LIKE '%.xyz' OR LOWER(query_hostname) LIKE '%.info')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY device_hostname, query_hostnameHAVING lookup_count <= 100

    What a hit looks like. Low-frequency DNS requests to the mentioned TLDs, potentially matching the compound word pattern described in the report.

  4. Agent triage

    Early stage triage

    Evaluate if the installer execution and the C2 network activity confirm the first phase of the OfferLoader intrusion.

  5. Query, triage

    Script-based backdoors

    Identify Insomnia RAT behavior by searching for Node.js and Python script executions containing network-socket logic.

    sql, reads hb_script_activity
    SELECT script_content, device_hostname, script_type, MIN(time) as first_seenFROM hb_script_activityWHERE instr(',' || '{{rat_interpreters}}' || ',', ',' || LOWER(script_type) || ',') > 0  AND (LOWER(script_content) LIKE '%socket%' OR LOWER(script_content) LIKE '%connect%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY script_contentHAVING COUNT(*) < 5

    What a hit looks like. Script blocks performing network operations, appearing in Node.js or Python environments which are rare for standard users.

  6. Query, enrichment

    Network tunneling activity

    Identify ARKTunnel and Socks5Systemz through WebSocket or non-standard protocol tunneling connections.

    sql, reads hb_network_connection
    SELECT device_hostname, dst_endpoint_ip, dst_endpoint_port, protocol, process_name, timeFROM hb_network_connectionWHERE dst_endpoint_port IN (443, 80, 8080)  AND (LOWER(process_name) LIKE '%node%' OR LOWER(process_name) LIKE '%python%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Outgoing connections to web ports originating from script interpreters, which may indicate WebSocket tunneling.

  7. Agent triage

    Follow-on analysis

    Synthesize the early-stage compromise evidence with follow-on RAT activity to confirm a successful PPI infection.

  8. Decision

    PPI infection decision

    Route the hunt based on the agent's confidence in the multi-stage infection.

  9. Response action

    Isolate host

    Stop the RAT beaconing and potential data theft by isolating the infected endpoint.

  10. Analyst task

    Analyst review

    Verify the agent's findings and document the specific RATs that were executed.

  11. Analyst task

    Close out

    Final reporting and parameter tuning.

This hunt identifies the CL-CRI-1171 cluster, which distributes malware through YouTube gaming lures and SEO poisoning. The hunt follows the infection chain from the execution of masquerading installers to the subsequent deployment of script-based payloads and network-tunneling backdoors associated with pay-per-install marketplaces.
