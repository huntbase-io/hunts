ClickFix Run-Dialog Social Engineering and LOLBIN Execution

Medium severity TLP:CLEAR Research by Huntress Published 6 Oct 2026

Hypothesis

An intruder is using social engineering to trick users into pasting obfuscated commands into the Windows Run dialog, using explorer.exe to launch downloaders like finger.exe for payload retrieval.

Brief

Why this hunt

The Huntress team recently detailed a campaign called ClickFix in their article, "How Huntress Detects and Responds to a ClickFix Attack" (https://www.huntress.com/blog/fix-for-clickfix). This attack shifts the burden of execution to the user. Instead of delivering a malicious file that an EDR might block on write, the adversary presents a fake error message. This message directs the user to open the Windows Run dialog and paste a pre-copied command. Because the command executes directly from the user's interactive session, it often bypasses traditional perimeter and file-based defenses.

How the hunt flows

The hunt begins by identifying every Windows host in the environment using hb_software_inventory. This scoping step ensures behavioral queries target systems where the Windows Run dialog is a standard interface. By narrowing the scope, we reduce the processing load and focus on the most likely targets.

The lead generation phase examines hb_process_activity for explorer.exe parentage. It looks for explorer spawning cmd.exe or common LOLBINs like finger.exe. The search specifically identifies caret obfuscation, such as "f^i^n^g^e^r", and social engineering strings used to hide the malicious command from the user’s immediate view.

An analyst or automated agent then evaluates the logic of these command lines. This phase checks for "for /f" loops used to execute retrieved data and specific social engineering padding like "push the enter key". This logic gate filters out legitimate administrative tasks that might use shells but lack these specific attack patterns.

Once a suspicious command is found, the hunt initiates parallel enrichment steps. It calculates the prevalence of the child process across the fleet using hb_process_activity to find rare binaries. Simultaneously, it searches hb_dns_activity for connections to known payload delivery domains like linkeders.net. Finding a rare process and a C2 resolution on the same host provides strong evidence of a successful intrusion.

The final triage phase synthesizes the evidence chain. If a host shows an explorer-spawned shell with caret obfuscation, the process is rare in the environment, and the host contacted a known C2 domain, the analyst confirms the verdict. This ensures we do not rely on a single indicator that the adversary could easily change.

What the hunt cannot see

This hunt requires parent-process visibility to distinguish user-initiated Run dialog commands from other system activities. If telemetry does not track the relationship between explorer.exe and its children, the lead query will return high noise or miss the execution entirely. Additionally, a lack of DNS logging prevents confirmation that the finger.exe cradle successfully retrieved its payload.

    What a hit looks like. A shell or system binary launched by explorer.exe containing caret characters, for-loops, or the social engineering padding. This is the primary lead.

  3. Agent triage

    Evaluate launcher suspiciousness

    Analyze the command line for ClickFix characteristics like social engineering padding and download cradle logic.

  4. Decision

    Gate on lead suspicion

    Only proceed to expensive prevalence and network queries if the lead shows ClickFix behavior.

  5. Query, baseline

    Rare processes spawned by explorer

    Stack-count children of explorer.exe to find anomalous launchers across the fleet.

    sql, reads hb_process_activity

    What a hit looks like. The binary name used in the ClickFix attack appearing on very few hosts compared to standard Windows activity.

  6. Query, enrichment

    DNS resolutions to ClickFix infrastructure

    Search for DNS lookups to domains associated with ClickFix payload delivery.

    sql, reads hb_dns_activity
    SELECT device_hostname, query_hostname, timeFROM hb_dns_activityWHERE instr(',' || '{{c2_domains}}' || ',', ',' || LOWER(query_hostname) || ',') > 0  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A hostname resolving linkeders infrastructure shortly after the explorer launcher event.

  7. Agent triage

    Triage ClickFix intrusion chain

    Synthesize the launcher lead, the rarity baseline, and the network indicators to confirm a successful intrusion.

  8. Decision

    Route on triage verdict

    Direct the analyst to isolation for confirmed threats or review for ambiguous findings.

  9. Response action

    Isolate host and revoke sessions

    Halt the attack chain and prevent data exfiltration by the infostealer payload.

  10. Analyst task

    Analyst forensic remediation

    Inspect the host for persistence and stage-two payloads.

  11. Analyst task

    Close out hunt

    Document the hunt outcome and any negative results.

# ClickFix Run-Dialog Social Engineering and LOLBIN Execution

ClickFix attacks bypass traditional file-based defenses by delivering commands directly into the user interactive session via the Windows Run dialog. The command usually contains caret obfuscation to defeat string matching and uses built-in Microsoft binaries like finger.exe to fetch and execute a remote payload. This hunt identifies the specific explorer.exe to cmd.exe or LOLBIN process relationship, detects the obfuscated command patterns, and stack-counts rare explorer children to separate legitimate activity from the attack.

## scoping-windows-inventory
<!-- Scope to Windows endpoints -->
Identify Windows systems which are the primary target for ClickFix social engineering via the Run dialog.

```sqlite target=endpoint role=scoping
~~~yaml
expected: A list of hostnames running Windows. This list is used to scope subsequent
  behavioral queries.
reads:
- device_hostname
- vendor_name
- package_name
silence: not_evidence_of_absence
source: hb_software_inventory
verified: dry-run
verified_at: '2026-10-06'
~~~
SELECT DISTINCT device_hostname FROM hb_software_inventory WHERE LOWER(vendor_name) LIKE '%microsoft%' AND LOWER(package_name) LIKE '%windows%'
```

## rare-explorer-children
<!-- Rare processes spawned by explorer -->
Stack-count children of explorer.exe to find anomalous launchers across the fleet.

```sqlite target=endpoint role=baseline params=(lookback_days=lookback_days)
~~~yaml
baseline:
  compare: first_seen
  window: '{{lookback_days}}d'
expected: The binary name used in the ClickFix attack appearing on very few hosts
  compared to standard Windows activity.
prevalence:
  by: device_hostname
  key:
  - process_name
  rare_below: 3
reads:
- process_name
- device_hostname
- parent_process_name
- time
silence: not_evidence_of_absence
source: hb_process_activity
verified: dry-run
verified_at: '2026-10-06'
~~~
SELECT LOWER(process_name) AS binary, COUNT(DISTINCT device_hostname) AS hosts, COUNT(*) AS launches FROM hb_process_activity WHERE LOWER(parent_process_name) LIKE '%\explorer.exe' AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY 1 HAVING hosts <= 3 ORDER BY hosts ASC
```

## analyst-forensic-review
<!-- Analyst forensic remediation -->
```manual target=analyst
Review the full process tree around the identified launcher. Look for randomly named executables or scripts in %APPDATA% or %TEMP% that may represent the infostealer stage. Confirm browser profiles are intact and force user password resets.
```
→ close-out-negative

<!-- Close out hunt -->
