Langflow RCE and Cloud Metadata Discovery

High severity TLP:CLEAR Part 1 of 2 Research by Rapid7 Published 18 Nov 2026

Hypothesis

An attacker is exploiting unauthenticated remote code execution vulnerabilities in Langflow AI endpoints and subsequently querying the cloud metadata service to harvest identity tokens for lateral movement.

Brief

Why hunt for Langflow exploitation

Recent vulnerability research highlighted in the Rapid7 — Metasploit Wrap Up: Langflow, MongoDB, and More describes unauthenticated remote code execution (RCE) in Langflow. Because Langflow serves as an orchestration layer for AI pipelines, these instances often reside in cloud environments with attached identity roles. An attacker who gains code execution on a Langflow container can immediately pivot to the cloud provider's metadata service to steal credentials. This hunt identifies those critical hand-off points between initial access and lateral movement.

How the hunt flows

The hunt begins by scoping the estate. The first query checks the software inventory for any packages matching Langflow. If the inventory is outdated or incomplete, the analyst uses this list of known hosts to narrow the subsequent network telemetry queries, though the hunt can run across the full estate if necessary.

Once the scope is defined, the hunt runs three queries in parallel to gather behavioral evidence. The first query monitors HTTP activity for requests hitting sensitive endpoints such as /api/v1/build, /api/v1/validate, or eval_custom_component_code. These are the primary vectors for the Metasploit modules and represent the initial access phase.

The second parallel query looks for outbound HTTP traffic from those same hosts to the cloud metadata service IP. While some applications legitimately query metadata for configuration, a sudden spike or a request originating from an AI orchestration service is a high-fidelity indicator of post-exploitation discovery. This provides the link between the web-facing exploit and the cloud environment.

The final parallel query baselines external traffic. It stack-counts source IPs hitting the Langflow endpoints and filters for those appearing on three or fewer hosts. This helps the analyst ignore wide-scale automated scanners or internal health checks, focusing instead on targeted exploitation attempts from rare external actors.

An analyst then triages the results by correlating the time and source IP of the API requests with the metadata access events. A match across both surfaces indicates a successful intrusion and immediate credential theft, leading to host isolation and session revocation.

What this hunt cannot see

This hunt faces two primary blind spots. First, without TLS decryption or application-level logging of HTTP request bodies, the analyst cannot see the specific Python code an attacker submits. They can confirm the endpoint was called and the status code returned, but the payload remains opaque. Second, the hunt sees the attempt to reach the metadata service but cannot confirm if the request was successful or if the cloud environment uses IMDSv2 protections that would prevent token theft. Audit logs from the cloud provider are required to confirm if the stolen identity was used.

    Locate hosts running Langflow to establish the hunt scope.

    sql, reads hb_software_inventory

    What a hit looks like. A list of hosts and their Langflow versions. Silence means the product is not recorded in the package inventory.

  2. Query, detection candidate

    Detect Suspicious API Calls

    Find HTTP requests to the Langflow endpoints targeted by the Metasploit modules.

    sql, reads hb_http_activity
    SELECT device_hostname, src_endpoint_ip, url_path, status_code, user_agent, timeFROM hb_http_activityWHERE (LOWER(url_path) LIKE '%/api/v1/build%' OR LOWER(url_path) LIKE '%/api/v1/validate%' OR LOWER(url_path) LIKE '%eval_custom_component_code%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Requests to sensitive build or validate endpoints. Frequent 200 OK responses from unusual source IPs indicate potential successful exploitation.

  3. Query, enrichment

    Detect Metadata Access

    Identify attempts to reach the cloud metadata service from the same hosts.

    sql, reads hb_http_activity
    SELECT device_hostname, src_endpoint_ip, url_full, user_agent, timeFROM hb_http_activityWHERE (url_hostname = '{{metadata_ip}}' OR dst_endpoint_ip = '{{metadata_ip}}')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Outbound HTTP requests to the metadata service. This is anomalous for standard AI workflow builder operations and suggests credential theft.

  4. Query, baseline

    Baseline External Traffic

    Stack-count source IPs to isolate rare external actors hitting Langflow endpoints.

    sql, reads hb_http_activity
    SELECT src_endpoint_ip, COUNT(DISTINCT device_hostname) AS host_count, COUNT(*) AS request_count, MIN(time) AS first_seenFROM hb_http_activityWHERE (LOWER(url_path) LIKE '%/api/v1/build%' OR LOWER(url_path) LIKE '%/api/v1/validate%')  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY src_endpoint_ipHAVING host_count <= 3ORDER BY host_count ASC

    What a hit looks like. A list of source IPs hitting Langflow on 3 or fewer hosts. High-volume, fleet-wide traffic usually indicates internal health checks or automated scanners.

  5. Agent triage

    Triage Langflow Intrusion

    Analyze the HTTP traffic patterns to determine if an intrusion has occurred.

  6. Decision

    Route on Verdict

    Direct the hunt based on the agent's confidence in the detected activity.

  7. Response action

    Isolate Host

    Prevent further credential exfiltration by containing the compromised host.

  8. Analyst task

    Analyst Remediation

    Verify the extent of the breach and identify any stolen secrets.

  9. Analyst task

    Close-out

    Record the hunt results and finalize documentation.

# Langflow RCE and Cloud Metadata Discovery

This hunt identifies Langflow installations within the estate and monitors for exploitation attempts against the build and validate API endpoints. It correlates these suspicious HTTP requests with outbound traffic to the cloud metadata service (169.254.169.254), a common post-exploitation step used to pivot from a compromised container or instance into the cloud control plane. The hunt uses a stack-counting baseline to isolate rare external actors hitting these sensitive AI orchestration paths.
