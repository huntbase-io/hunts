Brief

Why this hunt matters

Small and medium-sized businesses often face a widening gap between limited security resources and the increasing speed of automated threats. As highlighted in the ESET article, The quest for simplicity: Why SMBs want advanced protection without the complexity, practitioners need workflows that handle complex attack chains without requiring an army of analysts. This hunt addresses the reality of high-speed ransomware by looking for the transition from a vulnerable state to active data destruction.

How the hunt flows

The hunt begins by narrowing the environment down to the most likely targets. The first query identifies hosts with unpatched, high-severity vulnerabilities. This scoping step ensures that subsequent, more intensive telemetry searches focus on the assets most at risk of exploitation.

The second phase looks for signs of entry in parallel. We search for clusters of web server errors (403 and 500) that target configuration files or scripts, which indicates automated probing. Simultaneously, the hunt checks for excessive authentication failures that suggest a credential stuffing or brute force attempt. An agent then correlates these findings to prioritize hosts that are both vulnerable and showing signs of active interest from an adversary.

Once a potential beachhead is identified, the hunt pivots to execution and impact. We search for rare processes running from user-writable directories like AppData or Public. At the same time, we monitor for bursts of file modifications exceeding 1,000 touches per hour. This combination of rare execution and high-speed file activity differentiates ransomware from typical administrative tasks or backup processes.

Finally, the analyst triages the results. If a host shows the full chain—vulnerability, access anomaly, and mass file impact—the hunt provides an automated action to isolate the host and stop further encryption.

What this hunt cannot see

This hunt relies on endpoint telemetry and process-level monitoring. It cannot see activity on unmanaged servers or IoT devices where an agent is not installed. If an attack starts on one of these invisible assets and moves laterally via encrypted channels, this hunt will only pick up the trail once the adversary reaches a managed endpoint. Additionally, we do not inspect network traffic for data exfiltration; if the adversary steals data over HTTPS to a common cloud provider before encrypting, that egress remains a blind spot.

Why this is a hunt, not a detection

A single detection rule for mass file modification often triggers on legitimate software, leading to alert fatigue. This hunt is a playbook because it requires the context of three distinct attack phases. We only reach a high-confidence verdict by correlating the vulnerable state, the initial access evidence, and the rare process execution. This multi-surface approach reduces noise and ensures that response actions, like host isolation, are based on a confirmed attack chain.

  1. Query, scoping

    Identify vulnerable hosts

    Locate hosts with high-severity vulnerabilities to establish the probable initial attack surface.

    sql, reads hb_vulnerability_finding

    What a hit looks like. A list of host identifiers and their vulnerabilities; this establishes where exploitation is most likely to occur.

  2. Query, baseline

    Web exploitation attempts

    Detect automated probing by finding high-severity web errors targeting sensitive application files.

    sql, reads hb_http_activity
    SELECT device_hostname, url_path, status_code, COUNT(*) as counts, MIN(time) as first_seenFROM hb_http_activityWHERE status_code IN (403, 500)  AND (LOWER(url_path) LIKE '%.php%' OR LOWER(url_path) LIKE '%.jsp%' OR LOWER(url_path) LIKE '%.env%' OR LOWER(url_path) LIKE '%.config%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY device_hostname, url_path, status_codeHAVING counts > 5

    What a hit looks like. Clusters of 403 or 500 errors targeting PHP, JSP, or configuration files, indicating automated exploitation probes.

  3. Query, enrichment

    Auth anomaly check

    Identify high-volume sign-in failures that indicate password exploitation or brute force attempts.

    sql, reads hb_auth_signin
    SELECT actor_user_name, device_hostname, src_endpoint_ip, COUNT(*) as failuresFROM hb_auth_signinWHERE status_id = 2  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY actor_user_name, device_hostname, src_endpoint_ipHAVING failures > 20

    What a hit looks like. Specific user accounts or source IPs exhibiting excessive authentication failures consistent with credential stuffing.

  4. Agent triage

    Early-stage triage

    Identify vulnerable hosts showing signs of active exploitation.

  5. Query, detection candidate

    Rare writable processes

    Detect malicious code deployment by finding rare binaries running from user-writable directories.

    sql, reads hb_process_activity
    SELECT process_name, process_path, COUNT(DISTINCT device_hostname) as fleet_count, MIN(time) as first_seenFROM hb_process_activityWHERE (LOWER(process_path) LIKE '%\users\public\%' OR LOWER(process_path) LIKE '%\appdata\%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY process_name, process_pathHAVING fleet_count <= 2

    What a hit looks like. Processes with low fleet prevalence running from suspicious, user-writable locations.

  6. Query, triage

    High-speed file impact

    Detect ransomware encryption activity by identifying processes with extreme bursts of file touches.

    sql, reads hb_file_activity
    SELECT device_hostname, process_name, COUNT(*) as file_touchesFROM hb_file_activityWHERE activity_id IN (1, 3, 5)  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-1 hours')GROUP BY device_hostname, process_nameHAVING file_touches > 1000

    What a hit looks like. A single process modifying or renaming over 1,000 files in a single hour, consistent with high-speed encryption.

  7. Agent triage

    Follow-on triage

    Correlate early access beachheads with execution and file-level impact evidence.

  8. Decision

    Route on verdict

    Direct response based on the agent's findings.

  9. Response action

    Contain host

    Isolate the compromised endpoint to prevent further data encryption or exfiltration.

  10. Analyst task

    Analyst deep dive

    Perform manual forensic review to confirm the attack vector and assess data loss.

  11. Analyst task

    Close out hunt

    Document the hunt outcome and confirm the current security posture.

# AI-Driven Ransomware and Data Extortion

This hunt identifies the progression of high-speed ransomware attacks starting from initial access attempts via application exploitation or credential abuse. It scopes the hunt to vulnerable assets, correlates those vulnerabilities with anomalous sign-ins and web traffic, and then pivots to find evidence of malicious execution and bulk file impact. This phased approach is designed to catch automated threats before they complete the encryption phase.
