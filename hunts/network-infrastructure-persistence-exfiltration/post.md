# Hunting Persistence and Config Exfiltration on Compromised Network Infrastructure

### Background
Recent reporting from Cisco Talos on [Static Tundra: long-term exploitation of end-of-life network devices](https://blog.talosintelligence.com/static-tundra/) details how Russian FSB actors (APT28) leverage legacy network infrastructure for long-term persistence. These devices, often running end-of-life firmware, represent a significant visibility gap because they cannot support traditional EDR agents. Once compromised via vulnerabilities like CVE-2018-0171, they are used to exfiltrate configuration data and serve as covert proxies.

### The Hypothesis
Our hunt is built on the hypothesis that a state-sponsored actor has successfully exploited vulnerable Cisco Smart Install services to gain initial access. Following this, the adversary likely enables a local TFTP server to pull configuration files and maintains access via legacy management protocols (Telnet or SNMP) from infrastructure they control. 

### How the Hunt Flows
The hunt begins with scoping through vulnerability and exposure surfaces. We first identify assets in the environment known to be susceptible to CVE-2018-0171 using vulnerability scan data. Simultaneously, we map the external attack surface to find assets with management ports (23, 69, 161, 162) exposed to the internet. This creates a prioritized list of high-risk infrastructure.

Next, the hunt moves into behavioral analysis within the network fabric. We look for outbound TFTP connections originating from these devices, which is a common method for exfiltrating the startup configuration. Because TFTP is often used for legitimate internal updates, we prioritize traffic directed toward external or unusual internal destinations.

We then analyze management access patterns. Instead of looking for any Telnet or SNMP traffic—which would be far too noisy for a standard detection—we stack-rank the source IPs. The goal is to isolate rare source IPs that connect to only one or two devices, distinguishing targeted adversary activity from the high-volume traffic generated by enterprise-wide management tools or scanners.

### What the Hunt Cannot See
This design has specific blind spots. Without deep packet inspection (DPI), we cannot see the TCP option headers required to confirm the presence of firmware implants like "SYNful Knock." Furthermore, network flow data lacks visibility into the specific terminal commands executed on the device; confirming if an actor modified ACLs or created local users requires a manual configuration audit or centralized syslog with command logging enabled.

### How to Run This Hunt
This hunt is published as an open `hunt.md` playbook. It is designed to be portable and can be imported into Huntbase or any runtime environment that supports the hunt.md standard. The playbook includes the logic to pivot from vulnerability context into network flow baselines, helping practitioners identify infrastructure-level persistence that often goes unnoticed by host-centric monitoring.
