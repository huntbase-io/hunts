High-Tempo Host Execution and C2 Burst Analysis

An adversary is using agentic offensive frameworks like ARTEX or CyberStrikeAI to automate initial access and command execution, evidenced by high-frequency network bursts and browser processes spawning system shells.

Brief

Why this hunt

Elastic Security Labs recently published "Inside the loop: Five AI attack frameworks that never ask permission" documenting the evolution of agentic offensive tools. Frameworks like ARTEX and CyberStrikeAI move beyond simple scripts; they use LLMs to plan and execute commands autonomously. Because these agents can issue requests every few seconds, they operate at a speed that manual observation cannot match. This hunt provides a structured way to identify the footprints of these automated agents before they move from initial access to full lateral movement.

How the hunt flows

The hunt begins with a scoping phase focused on the external perimeter. We identify hosts running web-facing services that have high-severity vulnerabilities like remote code execution or injection. By focusing on these assets, we isolate the most likely entry points for an automated framework attempting to establish a foothold. Following the scoping, we run three behavioral checks in a parallel phase to gather evidence from both the network and the host. The first check focuses on network tempo. We group HTTP activity into 30-second windows and flag source IPs that exceed a density threshold of 20 requests. This high-frequency heartbeat is a primary indicator of an automated AI loop. The second check looks for DNS resolutions of domains known to be associated with these offensive frameworks, such as update.pentagi.com. The third check identifies browser processes like Chrome or Edge acting as the parent to system shells like PowerShell or Bash. This matches the known tradecraft of using malicious extensions to execute commands. The final phase is the triage correlation. An analyst or an automated agent examines the overlap of these three signals. We look for specific hosts that show both the network burst pattern and the corresponding browser-originated shell execution. This correlation is what distinguishes the hunt from a simple detection. While a browser spawning a shell might be a one-off anomaly, the alignment with high-tempo network windows provides the context needed to identify an active offensive agent.

Blind spots

This hunt has two primary blind spots. First, we do not have visibility into the HTTP request payloads. We rely on the tempo and timing of the traffic to identify the agent rather than the specific commands being sent. Second, while we identify the browser as the parent process, we do not have a direct inventory of the specific malicious extension ID. Confirming the responsible extension requires manual forensic investigation or additional endpoint telemetry like osquery extension logs.

  1. Identify vulnerable web-facing assets

    Query · scoping

    Identify hosts with high-severity vulnerabilities in web-facing components. The analyst should resolve these device_uids to hostnames and populate the scope_hosts parameter for subsequent steps.

    reads hb_vulnerability_findingsql
    SELECT device_uid, resource_uid, title, cve_uid, severity FROM hb_vulnerability_finding WHERE severity_id >= 4 AND (LOWER(title) LIKE '%rce%' OR LOWER(title) LIKE '%injection%' OR LOWER(title) LIKE '%web%')

    What a hit looks like. A list of vulnerable resources. The presence of these hosts prioritizes the behavioral checks in the parallel stage.

  2. High-tempo HTTP bursts

    Query · baseline

    Detect external IPs hitting hosts with request density exceeding human interaction by bucketing traffic into 30-second windows.

    reads hb_http_activitysql
    SELECT device_hostname, src_endpoint_ip, strftime('%Y-%m-%d %H:%M', time) || ':' || (CASE WHEN CAST(strftime('%S', time) AS INT) < 30 THEN '00' ELSE '30' END) AS window_30s, COUNT(*) AS req_count FROM hb_http_activity WHERE time >= datetime('now', '-{{lookback_days}} days') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) GROUP BY device_hostname, src_endpoint_ip, window_30s HAVING req_count >= {{burst_threshold}}

    What a hit looks like. Source IPs with high request counts within single 30-second buckets, indicating an automated agentic loop.

  3. Resolution of framework-associated domains

    Query · enrichment

    Corroborate high-tempo network activity with resolutions for domains known to be used by agentic framework operators.

    reads hb_dns_activitysql
    SELECT device_hostname, query_hostname, COUNT(*) AS resolution_count, MIN(time) AS first_seen FROM hb_dns_activity WHERE instr(',' || '{{c2_domains}}' || ',', ',' || LOWER(query_hostname) || ',') > 0 AND time >= datetime('now', '-{{lookback_days}} days') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) GROUP BY device_hostname, query_hostname

    What a hit looks like. DNS resolutions for the framework-associated domains on the same hosts seeing high-tempo HTTP traffic.

  4. Browser processes spawning shells

    Query · detection candidate

    Identify shells executed by browsers, matching the T1176 tradecraft where extensions are used to drive local command execution.

    reads hb_process_activitysql
    SELECT device_hostname, process_name, parent_process_name, process_cmd_line, user_name, time FROM hb_process_activity WHERE instr(',' || '{{browser_names}}' || ',', ',' || LOWER(parent_process_name) || ',') > 0 AND instr(',' || '{{shell_names}}' || ',', ',' || LOWER(process_name) || ',') > 0 AND time >= datetime('now', '-{{lookback_days}} days') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)

    What a hit looks like. Browser processes acting as parents to command shells or interpreters, specifically on the hosts being targeted by network bursts.

  5. Triage automated attack behavior

    Agent triage

    Analyze the alignment of high-frequency HTTP buckets and process execution to determine if an automated agentic loop is driving the endpoint.

  6. Decision on triage results

    Decision

    Route to containment or manual review based on the agent's high-tempo correlation findings.

  7. Isolate compromised host

    Response action

    Halt the automated attack loop by isolating the affected endpoint and revoking sessions.

  8. Manual analyst review

    Analyst task

    Investigate the isolated host to confirm the presence of a malicious browser extension or framework persistence.

  9. Hunt closeout

    Analyst task

    Document findings and finalize detection improvements.

# High-Tempo Host Execution and C2 Burst Analysis

Agentic offensive frameworks represent a shift from human-speed operators to automated planning loops that issue commands in intervals as short as two seconds. These frameworks often exploit web vulnerabilities (T1190) or abuse authenticated browser sessions via extensions (T1176). This hunt identifies the entry point by scoping to vulnerable internet-facing assets and then correlating three signals: high-density HTTP request patterns measured in 30-second windows, resolution of known framework-associated domains, and browser processes executing command-line interpreters. An agent weighs these behaviors per host to distinguish automated AI loops from benign web traffic or human administration.

## high-tempo-http
<!-- High-tempo HTTP bursts -->
Detect external IPs hitting hosts with request density exceeding human interaction by bucketing traffic into 30-second windows.

```sqlite target=web role=baseline params=(lookback_days=lookback_days, scope_hosts=scope_hosts, burst_threshold=burst_threshold)
~~~yaml

  compare: new_this_window
  window: '{{lookback_days}}d'
expected: Source IPs with high request counts within single 30-second buckets, indicating
  an automated agentic loop.
prevalence:
  by: device_hostname
  key:
  - src_endpoint_ip
  rare_below: 5

- device_hostname
- src_endpoint_ip
- time
silence: not_evidence_of_absence
source: hb_http_activity
```
