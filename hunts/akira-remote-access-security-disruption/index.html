Akira: Remote Access and Security Software Disruption

High severity TLP:CLEAR Part 1 of 2 Research by Huntress Published 8 Oct 2026

Hypothesis

An adversary has gained lateral access via RDP and is disabling security software to perform credential dumping from staging directories like PerfLogs.

Brief

Why This Hunt Matters

Recent analysis from Huntress in Up a Creek Without a Command Line: Mapping an Akira Ransomware Attack details how Akira affiliates move laterally and blind defenses. These actors often skip complex exploits in favor of simple RDP sessions and manual service disruption. If an analyst only looks for service stops or only looks for RDP, the signal disappears into the noise of daily administration. This hunt correlates these events to find the intrusion before the adversary reaches their final objective.

How the Hunt Flows

The first phase scopes the environment for inbound RDP connections. It specifically searches for the workstation name C1IFRYXI, which has been associated with Akira activity, or high-volume remote interactive logins from other external sources. This step identifies the potential entry points and sets the scope for deeper investigation.

Once the hunt identifies high-risk hosts, it runs two parallel checks. One query looks for the cessation or disablement of Bitdefender services, a common target for Akira blinding efforts. The second query identifies rare binaries executing from C:\PerfLogs or Temp directories. Threat actors often use these locations to stage tools like ProcDump for memory harvesting.

An automated agent then triages the results. It builds a host-by-host timeline, looking for a specific sequence: a remote login followed shortly by security service disruption and the execution of a staging tool. This correlation distinguishes an active compromise from routine server maintenance.

Blind Spots

This hunt relies on Service Control Manager (SCM) telemetry to detect service stops. If an adversary kills the security process directly or uses registry modifications to prevent the service from starting after a reboot, the specific SCM event may not trigger. Additionally, the hunt focuses on C:\PerfLogs and Temp directories for staging. While common for Akira, an adversary who uses a deeply nested or randomized user profile directory may evade the path-specific filters unless the binary is rare enough to be caught by the prevalence check.

  2. Query, baseline

    Rare Processes in PerfLogs

    Find rare executables running from PerfLogs or Temp directories, which are used by Akira for staging tools like ProcDump.

    sql, reads hb_process_activity
    SELECT LOWER(process_path) AS path, COUNT(DISTINCT device_hostname) AS hosts, COUNT(*) AS exec_count, MIN(time) AS first_seenFROM hb_process_activityWHERE (LOWER(process_path) LIKE '%\\perflogs\\%' OR LOWER(process_path) LIKE '%\\temp\\%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY LOWER(process_path)HAVING hosts <= 3ORDER BY hosts ASC

    What a hit looks like. A binary like procdump.exe or svchost.exe (masqueraded) running from C:\PerfLogs on a small number of hosts.

  3. Query, detection candidate

    Bitdefender Service Disruption

    Identify security service disablement following RDP access.

    sql, reads hb_service_activity
    SELECT device_hostname, service_name, service_state, timeFROM hb_service_activityWHERE (LOWER(service_name) LIKE '%bitdefender%')  AND (LOWER(service_state) LIKE '%stop%' OR LOWER(service_state) LIKE '%disable%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Multiple Bitdefender services being stopped on a host shortly after an inbound RDP session.

# Akira: Remote Access and Security Software Disruption

This hunt identifies early-stage Akira ransomware activity by correlating inbound RDP connections with subsequent efforts to blind security tools. It specifically looks for the cessation of Bitdefender services and the execution of rare binaries from the PerfLogs directory, a known staging area for this threat actor.

By examining authentication, service activity, and process telemetry, the hunt builds a timeline of compromise from initial lateral entry to the dumping of LSASS memory. An agent evaluates the combined evidence to distinguish between administrative maintenance and a coordinated ransomware precursor.
