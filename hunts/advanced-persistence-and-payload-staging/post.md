# Hunting Persistence via ELF Injection and Privileged Docker Containers

### Why this hunt?  Recent updates in the Metasploit Wrapup: Unauth RCE modules in Network Perimeter Devices and much more (https://www.rapid7.com/blog/post/pt-metasploit-wrapup-unauth-rce-modules-in-network-perimeter-devices-and-much-more) highlight a move toward more robust post-exploitation modules for perimeter devices. Adversaries are moving beyond simple commands to drop specialized payloads and secure their foothold on non-standard architectures.  ### Hypothesis An intruder stages non-standard architecture payloads using multi-protocol fetch adapters and establishes persistence via Linux ELF binary injection or privileged Docker containers with host root mounts.  ### How the hunt flows The hunt begins with a broad search for execution leads on the endpoint. It identifies mentions of the LoongArch64 architecture in command lines, the use of chmod to prepare binaries in temporary directories, and the creation of Docker containers with privileged access or host filesystem mounts. This step acts as a low-cost filter to identify potentially compromised hosts.  Once the lead query identifies a suspect host, the hunt opens two parallel investigations. The first examines network activity, looking for rare outbound connections on FTP, TFTP, or HTTP from common utilities like curl and wget. The query focuses on destinations that appear on three or fewer hosts to find attacker-controlled staging infrastructure.  Simultaneously, the hunt audits the integrity of system-critical binaries and staging paths. It identifies file creations or modifications in standard binary directories like /bin and /usr/bin. This surfaces cases where an attacker replaces a legitimate utility with a malicious ELF binary to ensure persistence.  The final phase triages these results. An analyst or agent correlates the initial execution behavior with the subsequent network and file evidence. By linking the staging process with the resulting persistent state, the hunt provides a high-confidence verdict for containment.  ### What this hunt cannot see This hunt relies on EDR process and file telemetry. If an adversary modifies an ELF binary via direct disk writes that bypass standard system calls, the file activity surface may not capture the change. Additionally, if the initial staging occurs on a device without process auditing, the lead query will remain silent, and the hunt will not progress to the deeper audit phases.  ### How to run it This hunt is a hunt.md playbook. You can import it into Huntbase or any runtime that supports the hunt.md standard. The flow is gated to ensure you only spend resources on deep audits when the initial process leads suggest an active intrusion.
