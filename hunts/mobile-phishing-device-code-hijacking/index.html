Mobile Ingress and Device Code Hijacking

An adversary is targeting employees with mobile phishing links (smishing) that lure them into performing Entra ID device-code authentication, allowing the attacker to hijack cloud sessions from compromised or unmanaged mobile devices.

Brief

Why now

Sekoia and Zimperium recently published a post titled Sekoia + Zimperium: Investigate Mobile Threats In Your SOC. The article explains how integrating mobile threat defense (MTD) with SOC telemetry improves visibility into mobile-centric attacks. Traditional endpoint detection often stops at the desktop, leaving a visibility gap where smishing and mobile-first phishing thrive. This hunt uses the integration concepts discussed by Sekoia to detect and respond to device-code hijacking.

How the Hunt Flows

The hunt begins by identifying the relevant assets. It scopes the estate to find hosts running mobile management or defense software, such as Zimperium. This step identifies which devices are likely to provide the necessary telemetry and alerts for a mobile-centric investigation. Identifying these hosts early ensures that the subsequent triage focuses on the most monitored devices in the fleet. The next phase queries DNS activity for resolutions to known phishing domains and EvilTokens infrastructure. An automated agent assesses these hits to determine if they represent a credible phishing ingress attempt. This assessment is a gate; the hunt only proceeds to more intensive queries if it identifies a suspicious lead. This prevents the hunt from overwhelming analysts with standard web activity. When a lead passes the gate, the hunt runs two queries in parallel. The first examines Entra ID sign-in logs for device-code protocol usage or browser-based authentication targeting Microsoft identity services. The second query retrieves mobile-specific detections from the endpoint, such as rooting, jailbreaking, or MTD-identified smishing alerts. A final triage agent correlates the phishing ingress with the authentication patterns and device risk signals. If the evidence confirms an active session theft, the hunt triggers a revocation action. This action invalidates the user's active tokens and refresh tokens in Entra ID, stopping the attacker's access immediately.

Blind Spots

This hunt has two primary limitations. It relies on DNS visibility. If a user clicks a phishing link while connected to cellular data or a home network without an active corporate VPN, the DNS resolution does not appear in monitored logs. The hunt also requires MTD telemetry, such as Zimperium findings, to confirm if a device is rooted or jailbroken. Without this data, the analyst sees the authentication but cannot prove the device was tampered with.

# Mobile Ingress and Device Code Hijacking

This hunt identifies the early stages of mobile-centric intrusions by correlating phishing ingress signals with subsequent authentication anomalies. It starts by identifying hosts running mobile management software, then hunts for resolutions to known phishing and EvilTokens infrastructure. A gate assessments the lead before fan-out queries examine device-code authentication flows and Zimperium-style device risk detections (like rooting or jailbreaking) side-by-side. An agent weighs the combined evidence to identify successful session theft before a revocation action stops the attack.
