# Mobile Smishing and Entra ID Device Code Hijacking

### Why now Sekoia and Zimperium recently published a post titled [Sekoia + Zimperium: Investigate Mobile Threats In Your SOC](https://www.sekoia.com/blog/from-mobile-threat-detection-to-autonomous-investigation-connecting-zimperium-with-sekoia). The article explains how integrating mobile threat defense (MTD) with SOC telemetry improves visibility into mobile-centric attacks. Traditional endpoint detection often stops at the desktop, leaving a visibility gap where smishing and mobile-first phishing thrive. This hunt uses the integration concepts discussed by Sekoia to detect and respond to device-code hijacking. ### The Hypothesis The adversary targets employees with mobile phishing links (smishing) to lure them into performing Entra ID device-code authentication. This interaction allows the attacker to hijack cloud sessions from compromised or unmanaged mobile devices, bypassing multi-factor authentication (MFA) implementations. ### How the Hunt Flows The hunt begins by identifying the relevant assets. It scopes the estate to find hosts running mobile management or defense software, such as Zimperium. This step identifies which devices are likely to provide the necessary telemetry and alerts for a mobile-centric investigation. Identifying these hosts early ensures that the subsequent triage focuses on the most monitored devices in the fleet. The next phase queries DNS activity for resolutions to known phishing domains and EvilTokens infrastructure. An automated agent assesses these hits to determine if they represent a credible phishing ingress attempt. This assessment is a gate; the hunt only proceeds to more intensive queries if it identifies a suspicious lead. This prevents the hunt from overwhelming analysts with standard web activity. When a lead passes the gate, the hunt runs two queries in parallel. The first examines Entra ID sign-in logs for device-code protocol usage or browser-based authentication targeting Microsoft identity services. The second query retrieves mobile-specific detections from the endpoint, such as rooting, jailbreaking, or MTD-identified smishing alerts. A final triage agent correlates the phishing ingress with the authentication patterns and device risk signals. If the evidence confirms an active session theft, the hunt triggers a revocation action. This action invalidates the user's active tokens and refresh tokens in Entra ID, stopping the attacker's access immediately. ### Blind Spots This hunt has two primary limitations. It relies on DNS visibility. If a user clicks a phishing link while connected to cellular data or a home network without an active corporate VPN, the DNS resolution does not appear in monitored logs. The hunt also requires MTD telemetry, such as Zimperium findings, to confirm if a device is rooted or jailbroken. Without this data, the analyst sees the authentication but cannot prove the device was tampered with. ### How to Run This Hunt This playbook is an open hunt.md file. You can import it directly into Huntbase or any runtime that supports the hunt.md standard. The file includes all queries and agent instructions to run the hunt across your environment, provided you have DNS, authentication, and endpoint detection telemetry available in your data lake. This unified approach ensures that your security operations center can respond to mobile threats with the same rigor applied to traditional desktop endpoints.
