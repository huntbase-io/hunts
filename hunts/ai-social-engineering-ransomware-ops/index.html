Brief

The Shift to AI-Powered Lures

Cybersecurity leaders are looking toward 2027 and the rise of sophisticated, AI-generated social engineering as a primary threat vector. In the article "What Cybersecurity Leaders Must Prioritize in 2027" (https://www.huntress.com/blog/what-does-the-future-hold-for-todays-cybersecurity-leaders), the team highlights how automation and AI lower the barrier for high-conviction phishing. This hunt focuses on the gap between initial access and final impact.

How the Hunt Flows

The hunt starts by identifying hosts running Remote Monitoring and Management (RMM) software like ScreenConnect or ConnectWise. These hosts are high-value targets for adversaries seeking broad access or lateral movement opportunities. The scoping step ensures the analyst focuses on the most critical infrastructure first.

The first lead generation query searches hb_process_activity for browsers spawning system interpreters or shells. Browsers such as Chrome, Edge, or Firefox should not typically launch powershell.exe, cmd.exe, or mshta.exe. This activity suggests a user clicked a malicious link or downloaded a loader disguised by an AI-generated lure.

Rather than immediately pulling all file and network logs, the hunt uses a gate. An agent or analyst reviews the process command lines from the previous step to determine if the activity looks like a malicious loader. This prevents the hunt from processing high volumes of benign traffic data on irrelevant hosts.

Once a suspicious foothold is confirmed, the hunt pulls data from hb_network_connection and hb_file_activity in parallel. It looks for outbound transfers exceeding 50MB and rapid file modifications within user directories or AppData. This phase connects the initial browser-based execution to tangible impact like data theft or ransomware encryption.

What the Hunt Cannot See

This hunt relies on process lineage. If the telemetry provider does not track parent-child relationships, the connection between the browser and the shell will remain hidden. Additionally, the hunt monitors for exfiltration via dedicated processes; if an adversary uploads data directly through the browser interface to a cloud storage provider, these queries will not flag the traffic. It also requires an endpoint control agent to perform the isolation step.

    Query · scoping

    The hunt finds the hosts running RMM software like ScreenConnect that are high-priority targets for platform hijacking and lateral movement.

    What a hit looks like. A list of hosts running ConnectWise or ScreenConnect software. Silence means no such RMM software is installed via managed package managers.

  2. Browser-spawned shell or interpreter

    Query · detection candidate

    The hunt finds the initial execution of an AI-powered social engineering lure where a browser launches a system shell.

    reads hb_process_activitysql
    SELECT device_hostname, process_name, process_cmd_line, parent_process_name, user_name, time FROM hb_process_activity WHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND instr(',' || '{{browser_names}}' || ',', ',' || LOWER(parent_process_name) || ',') > 0 AND instr(',' || '{{shell_names}}' || ',', ',' || LOWER(process_name) || ',') > 0 AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A shell process whose parent is a common web browser. Silence means no direct shell execution from browsers was observed in this window.

  3. Analyze Lead for Malicious Intent

    Agent triage

    The agent assesses whether the browser-spawned activity looks like a malicious lure (e.g., encoded commands or web downloads) to avoid expensive impact queries on benign activity.

  4. Gate Decision

    Decision

    The hunt routes execution to impact queries only if the agent finds a suspicious foothold.

  5. High-volume outbound exfiltration

    Query · enrichment

    The hunt detects potential exfiltration by finding processes sending unusually large amounts of data to external IPs.

    reads hb_network_connectionsql
    SELECT device_hostname, process_name, dst_endpoint_ip, SUM(traffic_bytes) as total_bytes, COUNT(*) as connection_count FROM hb_network_connection WHERE direction = 'outbound' AND state_kind = 'log' AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY device_hostname, process_name, dst_endpoint_ip HAVING total_bytes > {{exfil_byte_threshold}} ORDER BY total_bytes DESC

    What a hit looks like. A host sending >50MB to a single destination. Silence suggests no high-volume exfiltration occurred via tracked network flows.

  6. Rapid file modification

    Query · triage

    The hunt identifies potential ransomware encryption by counting file modifications in user-writable paths.

    reads hb_file_activitysql
    SELECT device_hostname, process_name, COUNT(DISTINCT file_path) as file_count FROM hb_file_activity WHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND activity_name IN ('Create', 'Update', 'Rename', 'Delete') AND (LOWER(file_path) LIKE '%\\users\\%' OR LOWER(file_path) LIKE '%\\appdata\\%') AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY device_hostname, process_name HAVING file_count > {{file_threshold}} ORDER BY file_count DESC

    What a hit looks like. A single process modifying hundreds of files. Silence means no large-scale file manipulation was observed.

  7. Final Correlative Triage

    Agent triage

    The agent weighs the initial lure execution against subsequent impact to confirm a ransomware operation.

  8. Route based on impact

    Decision

    The hunt triggers containment if the agent confirms impact.

  9. Isolate Infected Host

    Response action

    The hunt stops encryption and data theft immediately.

  10. Final Analyst Review

    Analyst task

    The analyst confirms the operation and prepares a report.

  11. Close out benign

    Analyst task

    The analyst records findings for non-malicious runs.

Blind spots

  • Needs hb_process_activity with parent-child tracking. A host without lineage tracking will show the shell but not its browser origin, hiding the social engineering vector. It would answer whether a browser spawned a malicious shell.
  • Needs hb_http_activity with request body size. This hunt focuses on non-browser processes for exfiltration; a direct upload to Dropbox or Mega.nz from the browser would be missed. It would answer whether data was exfiltrated directly through the browser.
  • Needs Endpoint control agent for isolation. If the host is not enrolled in an isolation-capable provider, encryption will continue until manual intervention occurs. It would answer can the host be isolated automatically.

# AI Social Engineering and Ransomware Operations

This hunt identifies social engineering lures that bypass traditional filters. The hunt identifies hosts with remote management tools, then queries for browsers spawning interpreters. The hunt gates expensive queries into data staging and exfiltration only when the agent confirms a suspicious foothold, allowing the analyst to weigh the initial execution against subsequent volumes of file and network activity.
