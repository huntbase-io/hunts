Resident Watchdog and Masquerading on Linux Edge

High severity TLP:CLEAR Part 1 of 2 Research by Rapid7 Published 3 Oct 2026

Hypothesis

An intruder has installed persistence on a Linux appliance by using a shell script to stage binaries in /sbin, then deleting the files to leave the processes running as fileless masqueraded daemons.

Brief

Why this hunt?

Edge appliances are high-value targets for persistent, silent access. Research from Rapid7, "SMTP is the key: BPFDoor and AVERAT hitting the network edge" (https://www.rapid7.com/blog/post/tr-smtp-is-the-key-bpfdoor-averat-hitting-the-network-edge), details how attackers use regionalized process masquerading to blend into these environments. Standard file-based detections often miss these implants because the dropper deletes its secondary binaries shortly after execution.

How the hunt flows

The first phase identifies the fleet's Linux appliances by looking for activity in non-standard mount paths like /addpkg/ or /hdd/. It then searches for evidence of the initial infection or the shell-script staging mechanism, specifically looking for files like updiptable.php or dropper hashes identified in the research.

The second phase pivots to behavioral markers of residency. We stack-count processes across the fleet to find rare instances of binaries running without an on-disk image. The hunt looks for processes adopting common daemon names like ntpdate, udevds, or chronyd that appear on very few hosts.

The final phase identifies environment variable manipulation used to suppress forensic evidence. The hunt searches for command lines containing HISTFILE=/dev/null or HISTSIZE=0, which attackers use to hide their activity from system logs.

Blind Spots

If the staging script exists for less than the polling interval of the telemetry sensor, the creation and deletion event may be missed. Additionally, BPFDoor uses a passive backdoor trigger that does not bind to a port, making it invisible to conventional socket monitoring. This hunt relies on process masquerading markers to bridge that gap.

  1. Query, scoping

    Scope hosts with appliance mount paths

    Identify the fleet's Linux appliances by looking for activity in non-standard mount paths used by regional edge vendors.

    What a hit looks like. A list of hostnames. Silence means no hosts in the estate use these vendor-specific directory conventions.

  2. Query, triage

    Search for AVERAT dropper files

    Find the initial dropper binary using known hashes or the specific add-on package path.

    What a hit looks like. A file match on one or more hosts. Silence proves the reported hashes and path were not written in the window.

  3. Query, triage

    Search for shell-script staging

    Detect the creation of the shell script or watchdog markers used to deploy secondary payloads.

  4. Agent triage

    Evaluate initial infection signals

    Assess the first stage results to confirm if any hosts show strong markers of the AVERAT infection chain.

  5. Query, baseline

    Baseline rare processes with no on-disk image

    Stack-count processes that match the disguise names or run with no binary on disk.

    sql, reads hb_process_activity

  6. Query, enrichment

    Detect command history suppression

    Identify shells attempting to suppress history, a common anti-forensic measure for these implants.

  7. Agent triage

    Final verdict on resident implants

    Combine early-stage signals with residency behaviors to confirm which appliances are compromised.

  8. Decision

    Route on resident compromise

    Route the hunt based on whether a resident implant is confirmed.

  9. Response action

    Isolate compromised appliance

    Sever network access to prevent command execution or data exfiltration.

  10. Analyst task

    Perform memory and shell forensics

    Extract the resident payload and verify the extent of the history evasion.

  11. Analyst task

    Review and close hunt

    Record findings and tune detection parameters for future runs.

# Resident Watchdog and Masquerading on Linux Edge

This hunt examines the host-level deployment of AVERAT and BPFDoor variants, which use regionalized process masquerading to blend into telecommunications environments. The attack chain involves a dropper writing a shell script to an appliance storage mount, which then stages payloads under common daemon names like ntpdate or udevds and deletes the source files ten seconds later while the processes continue running.

We pivot from initial file activity in appliance-specific paths to a behavioral check for processes running without an on-disk image, stack-counting these across the fleet to identify rare, malicious residency. The hunt further searches for environment variable manipulation used to suppress command history and vim logs, providing multiple points of correlation for resident implants.
