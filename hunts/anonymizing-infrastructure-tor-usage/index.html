Anonymizing Infrastructure and Tor Usage

An intruder or unauthorized user is using commercial VPNs or the Tor Browser to bypass network security controls, leaving evidence in software inventory, rare outbound port patterns, and proxy-flagged authentications.

Brief

Why Now

The Huntress article, What Does the Dark Web Look Like? Pulling Back the Curtain, highlights how anonymizing technologies facilitate both privacy and malicious persistence. When these tools appear on enterprise endpoints without authorization, they create unmonitored tunnels that bypass perimeter defenses, Data Loss Prevention (DLP) controls, and geographic sign-in restrictions. We developed this hunt to find the infrastructure behind these connections.

How the Hunt Flows

The hunt begins with a broad scan of the hb_software_inventory surface. The first query searches for known anonymizing package names such as Tor Browser, NordVPN, and ProtonVPN. This provides a fast, low-cost list of candidate hosts. Because many users install these tools for legitimate reasons or via portable binaries, this lead requires a manual triage step to scope the investigation before proceeding to more resource-intensive data sources. Once an analyst confirms suspicious software or identifies specific high-value hosts, the hunt fans out into parallel checks on the hb_network_connection and hb_auth_signin surfaces. The network query examines outbound connections to common Tor relay ports like 9001 and 9050. To reduce noise, the query calculates fleet-wide prevalence and highlights connections that are rare across the environment. This identifies active listeners that may not have a corresponding entry in the managed software inventory. Simultaneously, the hunt pulls sign-in data from the identity plane via hb_auth_signin to find events flagged with a proxy attribute. Finding a host with an unauthorized VPN installed that also generates sign-ins from a known proxy provides high-confidence evidence of a security bypass. The final phase correlates these findings into a single view. By combining confirmed software hits with rare network activity and proxy-flagged sign-ins, an analyst identifies active, persistent tunnels. This allows the team to isolate malicious hosts or verify sanctioned business exceptions.

Blind Spots and Constraints

This hunt focuses on registered software and standard port patterns. It does not see Tor usage via portable executables that run from user-writable paths unless those processes trigger the rare network port query. Furthermore, this design cannot identify Tor traffic using obfuscated bridges, such as obfs4, which disguises traffic as standard HTTPS on port 443. Advanced users who use these bridges will not appear in the network relay results.

# Anonymizing Infrastructure and Tor Usage

This hunt identifies the presence and active use of anonymizing tools designed to obscure network traffic. It follows a gated flow: first performing a broad scan for known anonymizing software packages, then gating expensive network and identity checks behind a manual host scoping step. The hunt correlates rare outbound relay ports with identity-plane proxy flags to detect persistent tunnels that avoid standard domain-based detection rules.

## lead-software-scan
<!-- Lead: Anonymizing software in inventory -->
Identify hosts where known VPN or Tor Browser packages are registered in the managed software inventory.

```sqlite target=endpoint role=scoping params=(anonymizer_keywords=anonymizer_keywords)
~~~yaml

  Absence suggests no known packages are in the managed inventory.
reads:
- device_hostname

- vendor_name
- package_version
```
