Storm-3168 Web Application Probing

An adversary is conducting automated web reconnaissance by probing for specific administrative and AI-related paths to identify vulnerable entry points for a subsequent cloud-focused intrusion.

Brief

Why this hunt

Microsoft recently detailed Storm-3168, also known as JADEPUFFER, and their use of agentic ransomware in cloud environments. Their operations often begin with automated web reconnaissance to find a foothold. By the time they reach cloud resources, the window for prevention is narrow. We focus on the initial probing phase to identify these actors while they are still testing the perimeter. The full report is available at Storm-3168: Agentic-driven cloud attacks using compromised service principals (https://www.microsoft.com/en-us/security/blog/2026/09/25/storm-3168-agentic-driven-cloud-attacks-using-compromised-service-principals/).

Hunt Flow

The first phase focuses on the 'python-requests/2.34.2' user agent and specific paths like /php-cgi/ and /api/v1/validate/code. These are known signals for JADEPUFFER activity. By filtering for these specific markers, the hunt narrows millions of logs down to a manageable set of potential leads. The hunt then evaluates the prevalence of the source IPs. In the prevalence check, the logic identifies source IPs that target more than one hostname. This behavior is typical of automated scripts that spray a range of assets rather than a single accidental visitor. The hunt calculates the 'host_targets' count to surface the most aggressive scanners. Simultaneously, the hunt checks internal asset inventory to see if the targeted hosts actually run the software being probed. It uses the hb_exposed_assets surface to identify which hosts in your environment run WordPress, PHP, or LangFlow. This ensures that an analyst does not waste time on probes hitting systems that aren't even running the targeted service. A match between a probe for /wp-admin/ and a host confirmed to run WordPress is a high-confidence signal. Finally, an analyst or automated agent reviews the combined telemetry. They verify if the source IP successfully reached a sensitive endpoint and determine if the activity aligns with known Storm-3168 behavior before initiating a block at the network perimeter.

Blind Spots

This hunt relies on HTTP telemetry. It cannot see probes against unmanaged or shadow IT assets that do not report logs to a central system. Additionally, without TLS inspection or application-level payload logs, we cannot see the contents of POST requests. A successful response status might indicate a successful exploit, but the hunt can only confirm the reconnaissance attempt.

# Storm-3168 Web Application Probing

This hunt identifies reconnaissance activity linked to Storm-3168 (JADEPUFFER), an actor known for agentic ransomware operations. The actor uses automated scripts to identify web-based entry points by probing for WordPress administrative paths, PHP-CGI vulnerabilities, and LangFlow code validation endpoints. The hunt filters HTTP telemetry for specific user agents and URI paths, then cross-references findings with source IP scanning prevalence and exposed asset context to distinguish directed actor activity from general internet background noise.

## http-probing-lead
<!-- HTTP probing for sensitive paths -->
Identify HTTP requests matching known actor user agents or targeted vulnerability paths.

```sqlite target=web role=detection-candidate params=(probing_paths=probing_paths, langflow_path=langflow_path, storm_user_agent=storm_user_agent, lookback_days=lookback_days)
~~~yaml

- url_hostname
- url_path

- status_code
- http_method
- time
silence: not_evidence_of_absence
```
