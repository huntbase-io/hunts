# Hunting Post-Compromise Evasion and Ransomware Impact

### Why this hunt ESET recently highlighted the confusion SMBs face during security incidents in their article, When confusion reigns, trusted vendors must guide their SMB customers (https://www.welivesecurity.com/en/business-security/when-confusion-reigns-trusted-vendors-guide-smb-customers/). Small and medium-sized businesses often lack specialized resources to distinguish between administrative tool use and sophisticated post-compromise activity. This hunt addresses that gap by focusing on how adversaries transition from stealthy defense evasion to material impact. ### The Hypothesis An adversary is using signed system binaries to proxy execution of infostealers or ransomware, transitioning from stealthy credential harvesting to mass file encryption. Attackers frequently abuse trusted binaries like mshta.exe or certutil.exe to bypass application whitelisting and download malicious payloads. Once they establish a foothold, they pivot to stealing stored credentials or encrypting the file system. ### How the hunt flows The first step uses a lead query on the hb_process_activity surface. It identifies instances of signed Microsoft binaries being used to execute code or fetch content. The query specifically monitors binaries like mshta.exe, certutil.exe, and regsvr32.exe for command lines containing network protocols like http or ftp. This step provides a list of suspicious hosts that require deeper investigation. The second phase runs two queries in parallel, scoped strictly to the hosts identified in the lead. The first parallel branch examines the hb_file_activity surface for access to sensitive credential stores. It looks for processes reading files such as browser cookies, login data, or master keys. By limiting this search to the suspicious hosts, we minimize the false positives generated by legitimate profile synchronization or backup software. The second parallel branch monitors the same suspicious hosts for signs of ransomware. It calculates the velocity of file modifications and searches for common ransom note filenames like readme.txt or decrypt.txt. A process touching more than 500 unique files within the lookback window suggests active encryption. This dual-track analysis allows the hunt to catch both infostealer activity and the early stages of a ransomware outbreak. Finally, the hunt uses an automated triage step to correlate the LOLBAS execution with the observed file impacts. This triage produces a per-host verdict that links the evasion technique to a concrete impact. A malicious verdict is only reached if a host shows both the suspicious binary execution and either credential access or mass file activity. ### What the hunt cannot see This hunt has specific blind spots. It cannot identify mass encryption if the adversary targets unmonitored disks or network mounts that the agent does not track. Additionally, sophisticated infostealers that read credentials directly from memory, such as by scraping LSASS, will not be caught by the file-based credential check. ### How to run it This hunt is packaged as a hunt.md playbook. You can import this file directly into Huntbase or any other runtime that supports the hunt.md standard. The playbook is self-contained and allows you to adjust parameters like the lookback period and the list of monitored LOLBAS paths to fit your environment's baseline.
