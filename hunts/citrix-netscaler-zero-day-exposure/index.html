Citrix NetScaler Zero-Day Exposure

An attacker is exploiting zero-day remote code execution vulnerabilities in Citrix NetScaler appliances, characterized by anomalous HTTP requests to management interfaces followed by the execution of unauthorized shell commands.

Brief

Why this hunt?On

September 27, 2026, CISA released an alert regarding eight critical zero-day vulnerabilities in Citrix NetScaler ADC and Gateway (CVE-2026-88771 through CVE-2026-88778). These flaws allow unauthenticated remote code execution. Because these appliances often lack standard security agents, detecting exploitation requires a specific focus on network traffic and appliance-level process telemetry. This hunt identifies if an adversary has already compromised the environment before the patching process begins. The source details are available in the CISA Alert: Critical Zero-Day Vulnerabilities Exploited in Citrix NetScaler ADC, Gateway.

HypothesisAn attacker exploits critical remote code execution vulnerabilities in

Citrix NetScaler appliances by sending anomalous HTTP requests to management interfaces and executing unauthorized shell commands.

How the hunt flowsThe first query scopes the hunt by identifying appliances with active vulnerability findings for the 2026

Citrix zero-days. This step ensures the analyst focuses on the most exposed assets. If vulnerability data is unavailable, the hunt falls back to software inventory records to find any host running NetScaler software.The second phase examines HTTP activity on the scoped appliances. The query stacks request paths to management endpoints like /mgmt/, /logon/, and /vpn/. It filters for rare URIs with low request counts over the last 14 days. These outliers often represent exploit payloads or unauthorized administrative access attempts that deviate from baseline traffic.The third phase searches for evidence of post-exploitation activity. The analyst looks for the execution of standard Unix shells, such as sh or bash, or the use of network utilities like curl and nc. These processes are uncommon in the normal operation of a specialized NetScaler appliance and suggest successful code execution.The final phase provides a decision framework. An agent correlates the vulnerability status, anomalous traffic, and process executions to provide a verdict. If the hunt identifies suspicious activity, it directs the team to forensic preservation and incident response. If the result is negative, it clears the appliance for standard patching.

Blind spotsThis hunt relies on the appliance logging web traffic to a central collector

If the NetScaler does not transmit HTTP logs for its management interfaces, the exploitation phase remains invisible. Furthermore, many proprietary appliances do not support traditional EDR agents. This gap means in-memory exploitation or activity that does not spawn a new process may not be captured in standard process telemetry.

# Citrix NetScaler Zero-Day Exposure

The adversary exploits eight critical vulnerabilities in Citrix NetScaler ADC and Gateway (CVE-2026-88771 through CVE-2026-88778) to gain initial access. These flaws allow for unauthenticated remote code execution and are actively being exploited globally. The hunt identifies vulnerable assets, then analyzes web traffic for rare URI patterns that deviate from normal administrative use. Finally, the analyst searches for evidence of post-exploitation activity such as shell spawning or network utility usage on the appliances to confirm the absence of compromise before remediation begins.

## rare-management-traffic
<!-- Anomalous requests to management interfaces -->
Stack-count HTTP request paths on the scoped appliances to find rare URIs that deviate from normal administrative traffic.

```sqlite target=web role=baseline params=(scope_hosts=scope_hosts, lookback_days=lookback_days)
~~~yaml
baseline:
  compare: first_seen
  window: '{{lookback_days}}d'
expected: Rare URI paths targeted at appliance management or VPN login endpoints.
  Silence suggests no unusual traffic was captured within the window.
prevalence:
  by: device_hostname
  key:
  - url_path
  rare_below: 20
reads:
- device_hostname
- time
- url_path
silence: not_evidence_of_absence
source: hb_http_activity
verified: dry-run
verified_at: '2026-09-29'
~~~
SELECT device_hostname, url_path, COUNT(*) AS request_count, MIN(time) AS first_seen, MAX(time) AS last_seen FROM hb_http_activity WHERE (('{{scope_hosts}}' = '') OR (instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)) AND (LOWER(url_path) LIKE '/mgmt/%' OR LOWER(url_path) LIKE '/logon/%' OR LOWER(url_path) LIKE '/vpn/%') AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY device_hostname, url_path HAVING request_count < 20 ORDER BY request_count ASC
```
