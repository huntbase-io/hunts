# Investigating Exploitation of Citrix NetScaler Zero-Day Vulnerabilities

### Why this hunt?On September 27, 2026, CISA released an alert regarding eight critical zero-day vulnerabilities in Citrix NetScaler ADC and Gateway (CVE-2026-88771 through CVE-2026-88778). These flaws allow unauthenticated remote code execution. Because these appliances often lack standard security agents, detecting exploitation requires a specific focus on network traffic and appliance-level process telemetry. This hunt identifies if an adversary has already compromised the environment before the patching process begins. The source details are available in the [CISA Alert: Critical Zero-Day Vulnerabilities Exploited in Citrix NetScaler ADC, Gateway](https://www.cisa.gov/news-events/alerts/2026/09/27/critical-zero-day-vulnerabilities-exploited-citrix-netscaler-adc-gateway).### HypothesisAn attacker exploits critical remote code execution vulnerabilities in Citrix NetScaler appliances by sending anomalous HTTP requests to management interfaces and executing unauthorized shell commands.### How the hunt flowsThe first query scopes the hunt by identifying appliances with active vulnerability findings for the 2026 Citrix zero-days. This step ensures the analyst focuses on the most exposed assets. If vulnerability data is unavailable, the hunt falls back to software inventory records to find any host running NetScaler software.The second phase examines HTTP activity on the scoped appliances. The query stacks request paths to management endpoints like /mgmt/, /logon/, and /vpn/. It filters for rare URIs with low request counts over the last 14 days. These outliers often represent exploit payloads or unauthorized administrative access attempts that deviate from baseline traffic.The third phase searches for evidence of post-exploitation activity. The analyst looks for the execution of standard Unix shells, such as sh or bash, or the use of network utilities like curl and nc. These processes are uncommon in the normal operation of a specialized NetScaler appliance and suggest successful code execution.The final phase provides a decision framework. An agent correlates the vulnerability status, anomalous traffic, and process executions to provide a verdict. If the hunt identifies suspicious activity, it directs the team to forensic preservation and incident response. If the result is negative, it clears the appliance for standard patching.### Blind spotsThis hunt relies on the appliance logging web traffic to a central collector. If the NetScaler does not transmit HTTP logs for its management interfaces, the exploitation phase remains invisible. Furthermore, many proprietary appliances do not support traditional EDR agents. This gap means in-memory exploitation or activity that does not spawn a new process may not be captured in standard process telemetry.### How to run itThis hunt is an open hunt.md playbook. You can import it into Huntbase or any hunt.md-aware runtime to execute the queries across your environment. By automating the correlation between vulnerability state and behavioral telemetry, you can confirm the state of the appliance before starting remediation.
