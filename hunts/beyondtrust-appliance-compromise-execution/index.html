Brief

Detecting Post-Exploitation on BeyondTrust Appliances 10/16/2026 10:16 PM 10/16/2026 10:16 PM

CISA recently issued an alert (https://www.cisa.gov/news-events/alerts/2026/10/16/cisa-urges-patching-critical-vulnerability-beyondtrust-remote-support) regarding a critical authentication bypass in BeyondTrust Remote Support, tracked as CVE-2026-102764. While patching is the priority, security teams must determine if attackers exploited the vulnerability before the fix. This hunt focuses on the behavioral artifacts left behind after an adversary bypasses authentication to execute code on the appliance. 10/16/2026 10:16 PM 10/16/2026 10:16 PM

Scoping the Estate 10/16/2026 10:16 PM

The first phase of the hunt identifies every instance of BeyondTrust or Bomgar software across the environment. We use software inventory data to build this list rather than relying on vulnerability scan results, which may be stale. This broad scoping ensures we monitor every potential target, regardless of its reported patch status. 10/16/2026 10:16 PM 10/16/2026 10:16 PM

Identifying Rare Interpreters 10/16/2026 10:16 PM

Once we define the target hosts, the hunt examines process activity for rare shell or interpreter execution. We look for instances of sh, bash, python, or perl that appear on only a small number of appliances. In a standard deployment, these appliances perform predictable tasks. An interactive shell session or a python script running on a single unit suggests manual attacker activity rather than standard appliance operations. 10/16/2026 10:16 PM 10/16/2026 10:16 PM

Detecting Script Creation 10/16/2026 10:16 PM

The hunt simultaneously searches for the creation of new script files in sensitive directories like /tmp, /var/tmp, or web-accessible folders. Attackers often drop .sh or .py files to facilitate their next steps. By filtering for these file extensions in transient directories, we isolate evidence of staging that occurs immediately after the authentication bypass. 10/16/2026 10:16 PM 10/16/2026 10:16 PM

Blind Spots

10/16/2026 10:16 PM This hunt relies on endpoint telemetry from the appliance operating system. If the appliance is a closed system that does not support an agent, we cannot see the file or process events. Furthermore, this hunt focuses on the aftermath of the exploit. Without HTTP-level logs or specific appliance web logs, we cannot confirm the exact URI or payload used for the initial authentication bypass. 10/16/2026 10:16 PM 10/16/2026 10:16 PM

    Query · baseline

    The query stack-counts the execution of shells and interpreters on appliances so that one-host sessions stand out from fleet-wide activity.

    reads hb_process_activitysql
    SELECT LOWER(process_path) AS shell_path, COUNT(DISTINCT device_hostname) AS host_count, COUNT(*) AS run_count, MIN(time) AS first_seen FROM hb_process_activity WHERE (on_disk = 0 OR (LOWER(process_path) LIKE '%/sh' OR LOWER(process_path) LIKE '%/bash' OR LOWER(process_path) LIKE '%/python%' OR LOWER(process_path) LIKE '%/perl' OR LOWER(process_path) LIKE '%/php')) AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY shell_path HAVING host_count <= 3 ORDER BY host_count ASC, run_count ASC

    What a hit looks like. A shell or interpreter path seen on very few hosts. Silence suggests no unusual shell sessions occurred during the window.

# BeyondTrust Appliance Compromise and Execution

This hunt targets the exploitation of BeyondTrust Remote Support (formerly Bomgar) appliances. It first identifies affected appliances in the estate, then fans out to search for the outcomes of the authentication bypass: the creation of unrecognized script files and the execution of rare shells or interpreters. By combining inventory scoping with behavioral activity, the hunt identifies compromised appliances even when network-level exploitation logs are missing.

## rare-shell-execution
<!-- Rare shell and interpreter execution -->
The query stack-counts the execution of shells and interpreters on appliances so that one-host sessions stand out from fleet-wide activity.

```sqlite target=endpoint role=baseline params=(lookback_days=lookback_days, scope_hosts=scope_hosts)
~~~yaml
baseline:
  compare: first_seen
  window: '{{lookback_days}}d'
expected: A shell or interpreter path seen on very few hosts. Silence suggests no
  unusual shell sessions occurred during the window.
prevalence:
  by: device_hostname
  key:
  - process_path
  rare_below: 3
reads:
- process_path
- device_hostname
- time
- on_disk
silence: not_evidence_of_absence
source: hb_process_activity
verified: dry-run
verified_at: '2026-10-17'
~~~
SELECT LOWER(process_path) AS shell_path, COUNT(DISTINCT device_hostname) AS host_count, COUNT(*) AS run_count, MIN(time) AS first_seen FROM hb_process_activity WHERE (on_disk = 0 OR (LOWER(process_path) LIKE '%/sh' OR LOWER(process_path) LIKE '%/bash' OR LOWER(process_path) LIKE '%/python%' OR LOWER(process_path) LIKE '%/perl' OR LOWER(process_path) LIKE '%/php')) AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY shell_path HAVING host_count <= 3 ORDER BY host_count ASC, run_count ASC
```
