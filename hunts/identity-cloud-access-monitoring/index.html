Identity and Cloud Access Monitoring

An adversary has gained initial access via phished credentials or a public-facing vulnerability and is now attempting to abuse cloud identities, evidenced by MFA fatigue patterns and rare credential-related API operations.

Brief

Why this hunt

Modern defense requires looking beyond the endpoint. In the Huntress article "10 Endpoint Security Trends and Tips for 2027", the shift toward identity-centric security is clear. Attackers no longer stop at the local disk; they use compromised hosts to pivot into cloud environments. This hunt focuses on that transition point. It finds where an adversary moves from a vulnerable public-facing server into the identity infrastructure of the organization.

How the Hunt Flows

The hunt begins with a scoping step. It identifies hosts with critical vulnerabilities, specifically those related to remote execution or authentication bypass, that are currently exposed to the internet. These hosts represent the most likely beachheads for an external attacker. Identifying these vulnerable assets first allows the hunt to prioritize authentication signals from the most at-risk systems.

Next, the hunt runs two behavioral queries in parallel to gather evidence. One query monitors for MFA fatigue by identifying users experiencing a high volume of sign-in failures within a short window. It flags source IPs and usernames that exceed a specific failure threshold. The second query baselines cloud API activity to find rare operations involving access keys, tokens, or policy changes. These low-frequency calls often indicate an attacker establishing a persistent back-door or rotating credentials after a successful takeover.

In the final phase, an automated triage agent synthesizes the results. The agent correlates the source IP addresses from the MFA fatigue events with the network-accessible IPs of the vulnerable hosts found during scoping. If the agent finds a match, it provides a verdict on the likelihood of a successful identity takeover. This correlation ensures the hunt focuses on genuine pivots rather than general internet background noise.

Blind Spots

This hunt has two primary limitations. First, it requires cloud telemetry from the target tenant. If an attacker accesses an unmonitored cloud environment, their actions remain invisible, creating a gap in our persistence detection. Second, we cannot currently correlate a successful authentication immediately following an MFA fatigue burst without specific status detail logs. This means we might see the attempt but cannot confirm the exact moment the user approved a fraudulent request.

  1. Find vulnerable beachheads

    Query · scoping

    Identify hosts with critical vulnerabilities that serve as likely entry points, prioritizing those with an active external exposure.

    reads hb_vulnerability_findingsql
    SELECT v.device_uid, d.hostname, v.cve_uid, v.title, e.ip_address FROM hb_vulnerability_finding v JOIN hb_devices d ON v.device_uid = d.device_uid JOIN hb_exposed_assets e ON d.ip_address = e.ip_address WHERE v.severity_id >= 4 AND v.status != 'suppressed' AND (LOWER(v.title) LIKE '%remote%' OR LOWER(v.title) LIKE '%execution%' OR LOWER(v.title) LIKE '%bypass%')

    What a hit looks like. A list of hosts with unpatched critical vulnerabilities that are also exposed to the internet. Silence indicates no such high-risk vulnerabilities are currently indexed.

  2. Monitor for MFA fatigue

    Query · detection candidate

    Find users experiencing high volumes of sign-in failures, indicating an attacker attempting to bypass MFA via exhaustion.

    reads hb_auth_signinsql
    SELECT actor_user_name, src_endpoint_ip, device_hostname, COUNT(*) as failures, MIN(time) as first_attempt, MAX(time) as last_attempt FROM hb_auth_signin WHERE activity_id = 5 AND time >= datetime('now', '-{{lookback_days}} days') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || LOWER(device_hostname) || ',') > 0) GROUP BY actor_user_name, src_endpoint_ip, device_hostname HAVING failures >= {{mfa_failure_threshold}} ORDER BY failures DESC

    What a hit looks like. Specific users or source IPs with failure counts above the threshold. Silence means no fatigue pattern was detected.

  3. Rare cloud credential manipulation

    Query · baseline

    Find unusual API operations that create or update cloud identities and tokens, which suggests post-compromise persistence.

    reads hb_cloud_api_activitysql
    SELECT api_operation, actor_user_name, cloud_account_uid, src_endpoint_ip, COUNT(*) as call_count, MIN(time) as first_seen FROM hb_cloud_api_activity WHERE (LOWER(api_operation) LIKE '%accesskey%' OR LOWER(api_operation) LIKE '%token%' OR LOWER(api_operation) LIKE '%policy%') AND activity_id IN (1, 3) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY api_operation, actor_user_name, cloud_account_uid, src_endpoint_ip HAVING call_count < 10 ORDER BY call_count ASC

    What a hit looks like. Low-frequency API calls that modify access controls or credentials. Silence means no unusual credential changes were seen.

  4. Triage identity compromise risk

    Agent triage

    Synthesize the scoping vulnerabilities, authentication patterns, and cloud activity into a single verdict.

  5. Route based on risk

    Decision

    Direct the hunt to containment actions if high-confidence evidence of compromise is found.

  6. Contain and revoke

    Response action

    Halt the attack by isolating the source endpoint and revoking compromised cloud credentials.

  7. Manual analyst review

    Analyst task

    Verify the automated triage results and perform a deeper audit of the user's cloud activity.

  8. Hunt close out

    Analyst task

    Finalize the hunt and record findings for tuning.

# Identity and Cloud Access Monitoring

This hunt centers on the article's focus on identity as the new perimeter. It identifies vulnerable entry points and correlates them with identity-based attacks. By monitoring for MFA fatigue (high-frequency sign-in failures) alongside rare cloud credential manipulations, the hunt finds attackers who have pivoted from endpoint compromise to cloud account takeover. The hunt flows through a scoping step for vulnerable assets, a fan-out of behavioral queries on authentication and cloud logs, and a final agent-led triage to confirm the compromise.

<!-- Find vulnerable beachheads -->


<!-- Rare cloud credential manipulation -->
Find unusual API operations that create or update cloud identities and tokens, which suggests post-compromise persistence.

```sqlite target=endpoint role=baseline params=(lookback_days=lookback_days)
~~~yaml
```
