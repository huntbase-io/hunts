ClickFix DLL Sideloading and Infostealer Injection

An adversary has deployed a ClickFix script to sideload a malicious library into a signed Microsoft binary, followed by hollowing a system process to run an infostealer and using a BYOVD driver to blind endpoint security.

Brief

Why Now

Elastic Security Labs recently detailed the ClickFix campaign in their article, "From 88 lines to 1: Detecting DLL hijacking with Elastic Defend." The campaign combines search-order hijacking with evasion techniques like process hollowing and security-blinding drivers. While a single detection rule might catch the final payload, understanding and hunting for the entire execution chain is necessary to confirm the scope of an intrusion.

How the Hunt Flows

The hunt begins with a scoping phase using the hb_software_inventory surface. We identify hosts that possess software frequently targeted for sideloading, such as Microsoft Visual Basic utilities or various upgrade tools. This step does not confirm an infection but narrows our search to systems where the attack surface is present. Following scoping, the hunt enters a parallel lead detection phase. The first query monitors the hb_module_activity surface for the library mscoree.dll. An adversary loads this library from paths other than the standard Windows System32 directory. We specifically filter for modules seen on three or fewer hosts to isolate rare activity. Simultaneously, the second query searches the hb_script_activity surface for PowerShell script blocks that contain hexadecimal flags like 0x8000004. The adversary uses these flags to create suspended processes, which is a prerequisite for hollowing. An analyst triages these leads by host. If a system shows both an unusual library load and the suspicious PowerShell staging content, the findings indicate a coordinated ClickFix staging event rather than a routine administrative task. Once an analyst confirms a staging lead, the hunt pivots to detect the impact of the intrusion. We query the hb_process_activity surface for the ServiceModelReg.exe process. The adversary hollows this process, leaving the binary reported as missing from disk. This on_disk equals zero state is a high-confidence indicator that the Remus infostealer is running in memory. In parallel, the hunt scans the hb_file_activity surface for the creation of .sys driver files in user-writable directories like Temp or Users. The adversary drops these files as vulnerable drivers to blind endpoint security products. The final triage step synthesizes the entire chain. An analyst reviews the evidence from the staging leads through to the active injection and driver deployment. This holistic view allows for a definitive verdict on the intrusion.

Blind Spots

This hunt has two primary blind spots. First, the detection of process hollowing in ServiceModelReg.exe relies on a snapshot of the process state. If the infostealer is ephemeral and terminates between collection intervals, the hunt misses the hollowed process. Second, the script activity query depends on PowerShell Script Block Logging. If IT Operations has not enabled this logging, the hunt cannot inspect the de-obfuscated content of the ClickFix scripts, which may hide the staging flags.

Blind spots

  • Needs Event-based process monitoring for NtUnmapViewOfSection. A snapshot-based process check will miss hollowing if the process terminates before the next collection cycle; an ephemeral infostealer could steal credentials and exit unnoticed. It would answer whether a hollowed process ran and terminated between collection intervals. Remediation: Enable Sysmon Event ID 1 (Process Create) and Event ID 10 (Process Access) to monitor for CREATE_SUSPENDED patterns in real-time.
  • Needs PowerShell Script Block Logging (Event ID 4104). If obfuscation is high and script block logging is disabled, the script-activity query will fail to find the hex flags even if the script executes successfully. It would answer the full de-obfuscated content of the ClickFix staging script. Remediation: Enable PowerShell Script Block Logging via GPO for all Windows endpoints.

# ClickFix DLL Sideloading and Infostealer Injection

This hunt identifies a multi-stage infection chain starting with PowerShell script staging and mscoree.dll search-order hijacking. It then pivots to monitor for the subsequent execution of the Remus infostealer inside a hollowed ServiceModelReg.exe process and the deployment of malicious drivers designed to disable EDR products.

The hunt follows the phased flow: first establishing the initial access and persistence leads via module loads and script block telemetry, then correlating these with evidence of active in-memory injection and defense evasion. This approach distinguishes targeted binary abuse from legitimate system administration by verifying the presence of the entire attack sequence.
