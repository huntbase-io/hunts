Perimeter Access and Identity Fraud

Adversaries target unpatched perimeter assets or use AI-generated personas for initial access, indicated by high-severity vulnerabilities on internet-facing hosts coupled with anomalous sign-ins and successful unauthorized web requests.

Brief

Why Now

Unit 42's Threat Intelligence Highlights for Nov. 2, 2026 (https://unit42.paloaltonetworks.com/u42-threat-intelligence-highlights-oct-2026/) describes a trend where adversaries target perimeter assets and use AI-driven deception for initial access. This hunt provides a structured way to verify if these techniques have succeeded in your environment.

How the Hunt Flows

The hunt begins by inventorying the perimeter. A query joins vulnerability findings with device inventory and external exposure data. This identifies hostnames that are both internet-exposed and suffer from high-severity vulnerabilities to focus the rest of the investigation.

The next phase pivots to identity and web surfaces. The hunt searches for rare user agents, geographic shifts, and MFA bypass patterns in sign-in logs. Simultaneously, it inspects web traffic for successful HTTP requests that contain directory traversal or command injection patterns targeting the vulnerable hosts.

Finally, an agent correlates these independent signals. It weighs the presence of a vulnerability against the observed anomalous behaviors on specific hosts. This step provides the context an analyst needs to confirm a successful breach versus a failed scan, leading to a decision on host isolation or manual review.

Blind Spots

If perimeter traffic remains encrypted without decryption at the server or gateway, the hunt cannot see the payloads inside HTTPS requests. The queries look for success codes, but the specific exploit remains hidden. Additionally, the results depend on the freshness of vulnerability scans; stale data may cause the scoping step to miss newly vulnerable systems.

Steps

  1. High-severity perimeter vulnerabilities

    Query · scoping

    Identify internet-facing assets with high-severity vulnerabilities that could serve as initial entry points by joining vulnerability findings with device inventory and external exposure data.

    reads hb_vulnerability_findingsql
    SELECT DISTINCT d.hostname AS device_hostname, v.cve_uid, v.severity, v.title FROM hb_vulnerability_finding v JOIN hb_devices d ON v.device_uid = d.device_uid JOIN hb_exposed_assets e ON (d.hostname = e.domain_or_ip OR d.ip_address = e.ip_address) WHERE v.severity_id >= 4 AND v.status != 'suppressed' AND v.resource_type = 'device'

    What a hit looks like. A list of hostnames currently exposed to high-severity vulnerabilities on the perimeter. These hosts should be provided in the scope_hosts parameter for subsequent steps.

  2. Anomalous sign-ins and identity risk

    Query · baseline

    Detect sign-ins that may indicate executive impersonation or session hijacking, focusing on rare user-agents, geographic anomalies, and unusual authentication requirements.

    reads hb_auth_signinsql
    SELECT actor_user_name, user_agent, is_proxy, risk_state, src_location_country, mfa, auth_requirement, device_hostname, COUNT(*) as signin_count, MIN(time) as first_seen FROM hb_auth_signin WHERE (('{{scope_hosts}}' = '') OR (instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY actor_user_name, user_agent, is_proxy, risk_state, src_location_country, mfa, auth_requirement, device_hostname HAVING signin_count <= 3 ORDER BY signin_count ASC

    What a hit looks like. Login events from rare combinations of location, user-agent, and auth protocol, especially those flagged as proxies. Silence indicates no anomalous logins were captured for the specified hosts.

  3. Perimeter exploitation behavioral probes

    Query · detection candidate

    Identify successful web requests targeting sensitive files or attempting command injection on vulnerable assets by filtering for successful HTTP response codes.

    reads hb_http_activitysql
    SELECT device_hostname, url_full, status_code, user_agent, time FROM hb_http_activity WHERE (('{{scope_hosts}}' = '') OR (instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)) AND status_code BETWEEN 200 AND 299 AND (LOWER(url_full) LIKE '%etc/passwd%' OR LOWER(url_full) LIKE '%/bin/sh%' OR LOWER(url_full) LIKE '%/cgi-bin/%' OR LOWER(url_full) LIKE '%.env%' OR LOWER(url_full) LIKE '%/wp-config%') AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. HTTP requests with directory traversal or command execution patterns that returned a 2xx success code. Silence indicates no successful probe-like requests were captured.

  4. Triage initial access evidence

    Agent triage

    Correlate identified vulnerabilities with anomalous logins and successful web traffic to determine if a breach occurred.

  5. Decision on Initial Access

    Decision

    Route the hunt based on the agent's triage verdict.

  6. Isolate compromised host

    Response action

    Immediately isolate the host to prevent lateral movement following a confirmed breach.

  7. Manual analyst review

    Analyst task

    Verify the agent's findings and assess the scope of the incident.

  8. Close out hunt

    Analyst task

    Finalize the hunt results and initiate remediation for identified vulnerabilities.

# Perimeter Access and Identity Fraud

This hunt focuses on the external-facing attack surface by identifying vulnerable assets and monitoring for subsequent signs of exploitation or identity-based deception. It uses a scoping step to identify hosts with high-severity vulnerabilities that are confirmed to be internet-exposed. The hunt simultaneously evaluates identity-based anomalies (such as rare user agents, geographic shifts, and MFA bypass patterns) and behavioral web probes. An agent weighs these independent indicators per host to identify successful initial access via unpatched services or sophisticated phishing lures.

## vulnerable-perimeter-inventory
<!-- High-severity perimeter vulnerabilities -->
Identify internet-facing assets with high-severity vulnerabilities that could serve as initial entry points by joining vulnerability findings with device inventory and external exposure data.

```sqlite target=endpoint role=scoping
~~~yaml
expected: A list of hostnames currently exposed to high-severity vulnerabilities on
  the perimeter. These hosts should be provided in the scope_hosts parameter for subsequent
  steps.
reads:
- device_uid
- severity_id
- status
- resource_type
- cve_uid
- title
silence: not_evidence_of_absence
source: hb_vulnerability_finding
verified: dry-run
verified_at: '2026-11-03'
~~~
SELECT DISTINCT d.hostname AS device_hostname, v.cve_uid, v.severity, v.title FROM hb_vulnerability_finding v JOIN hb_devices d ON v.device_uid = d.device_uid JOIN hb_exposed_assets e ON (d.hostname = e.domain_or_ip OR d.ip_address = e.ip_address) WHERE v.severity_id >= 4 AND v.status != 'suppressed' AND v.resource_type = 'device'
```

## anomalous-signins
<!-- Anomalous sign-ins and identity risk -->
Detect sign-ins that may indicate executive impersonation or session hijacking, focusing on rare user-agents, geographic anomalies, and unusual authentication requirements.

```sqlite target=identity role=baseline params=(scope_hosts=scope_hosts, lookback_days=lookback_days)
~~~yaml
baseline:
  compare: first_seen
  window: '{{lookback_days}}d'
expected: Login events from rare combinations of location, user-agent, and auth protocol,
  especially those flagged as proxies. Silence indicates no anomalous logins were
  captured for the specified hosts.
prevalence:
  by: device_hostname
  key:
  - user_agent
  - actor_user_name
  - src_location_country
  rare_below: 3
reads:
- actor_user_name
- user_agent
- is_proxy
- risk_state
- src_location_country
- mfa
- auth_requirement
- device_hostname
- time
silence: not_evidence_of_absence
source: hb_auth_signin
verified: dry-run
verified_at: '2026-11-03'
~~~
SELECT actor_user_name, user_agent, is_proxy, risk_state, src_location_country, mfa, auth_requirement, device_hostname, COUNT(*) as signin_count, MIN(time) as first_seen FROM hb_auth_signin WHERE (('{{scope_hosts}}' = '') OR (instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY actor_user_name, user_agent, is_proxy, risk_state, src_location_country, mfa, auth_requirement, device_hostname HAVING signin_count <= 3 ORDER BY signin_count ASC
```
