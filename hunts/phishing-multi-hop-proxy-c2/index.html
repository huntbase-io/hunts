Phishing and Multi-hop Proxy C2 Hunt

An attacker has gained initial access via browser-based phishing and established command-and-control using a masqueraded proxy binary that originates from a renamed tunneling tool.

Brief

Recent insights from Elastic Security Labs — SOC case management and detection rule history emphasize the value of historical context and rule evolution. Building on that foundation, we have designed a hunt to capture the movement from a successful phishing lure to the establishment of a multi-hop proxy tunnel. This transition is a critical window for intervention before an attacker can move laterally or exfiltrate data.\n\n### The Hypothesis\nWe hypothesize that an attacker has gained initial access via a browser-based phishing lure and is maintaining command-and-control (C2) using a proxy tool. To remain stealthy, the attacker has renamed the proxy binary (e.g., Chisel, Tor, or Ngrok) to masquerade as a common Windows system process. Detection is achieved by correlating the browser's execution environment and rare network destinations with process metadata that reveals the binary's true identity.\n\n### How the Hunt Flows\nThe hunt begins on the hb_process_activity surface. We look for browsers (Chrome, Edge, Firefox) running with high-risk command-line arguments such as --no-sandbox or --remote-debugging-port. These flags are often used by attackers to weaken browser security or by automation tools during credential harvesting. While these flags can be used legitimately by developers, they serve as a high-signal scoping mechanism for this hunt.\n\nNext, we pivot to hb_http_activity to perform prevalence analysis on URL hostnames. We are looking for hostnames accessed by only one or two devices across the entire estate within the last 14 days. These rare hostnames often represent the specific infrastructure used for a targeted phishing campaign or a dedicated C2 listener.\n\nThe core of the hunt resides in identifying masqueraded binaries. We query hb_process_activity to find instances where the process_name (what the user sees) does not match the process_original_file_name found in the binary's PE metadata. For example, a process named svchost.exe that has an original file name of tor.exe is a high-confidence indicator of evasion. By focusing on common masquerade targets like lsass.exe or runtimebroker.exe, we narrow the noise.\n\nFinally, we enrich these suspect processes using hb_network_connection and hb_dns_activity. We look for outbound traffic and DNS lookups for known proxy services or unusual top-level domains. A triage agent then correlates these events, looking for a temporal relationship between the browser activity and the execution of the masqueraded binary.\n\n### What This Hunt Cannot See\nThis hunt relies on the EDR agent's ability to capture the original file name from the binary's metadata. If the attacker has stripped this metadata or if the EDR provider does not collect it, the masquerading detection will fail. Additionally, if the proxy traffic is encapsulated within fully encrypted HTTPS tunnels without TLS inspection, we can see the destination domain but not the internal proxy headers that would confirm the C2 behavior.\n\n### How to Run This Hunt\nThis hunt is provided as a hunt.md playbook. It can be imported directly into Huntbase or any other hunt.md-aware runtime. It uses standard SQL syntax to query across process, network, and DNS surfaces. If you are running this manually, focus your review on developers or high-risk workstation groups where proxy tools might be misused.

    Query · baseline

    Identify rare URL hostnames accessed by processes, providing a baseline for potential phishing or credential harvesting sites.

    What a hit looks like. A list of hostnames accessed by 2 or fewer devices. Malicious lures are often specific to one or two targets.

# Phishing and Multi-hop Proxy C2 Hunt

This hunt identifies the transition from initial access to persistent C2 by correlating high-risk browser configurations and rare web traffic with the execution of masqueraded binaries. It focuses on the 'masquerading' technique where proxy tools like Tor or Ngrok are renamed to appear as system processes (e.g., svchost.exe). By pivoting on the process name from a masquerading event to its network and DNS activity, we can distinguish legitimate system noise from an obfuscated network tunnel initiated within the same timeframe as a suspicious web download or click.

<!-- Identify high-risk browser execution -->
Find hosts where browsers are running with insecure configurations or debugging flags often exploited or used by attackers to bypass security sandboxes.

```sqlite target=endpoint role=scoping params=(lookback_days=lookback_days, scope_hosts=scope_hosts)
~~~yaml

  are running with default security postures.

- process_name
- process_cmd_line
- user_name
- time
```
