SCKit Persistence and RelayTrap Targeting

High severity TLP:CLEAR Part 2 of 2 Research by Microsoft Published 14 Nov 2026

Hypothesis

An intruder who has compromised a ScreenConnect client is maintaining access via script-based Registry persistence and is using the RelayTrap component to target connecting technician sessions.

Brief

Why now

Microsoft Security Blog published details on SCKit abuses ScreenConnect to deploy remote access and target technician sessions. The research describes a sophisticated toolkit that exploits a specific ScreenConnect vulnerability to establish persistence and hijack active sessions. This hunt provides a systematic way to find the toolkit across your estate.

How the hunt flows

The hunt begins with a scoping phase using the hb_vulnerability_finding surface. It identifies unpatched hosts susceptible to CVE-2026-84869. While patching mitigates the initial vector, the hunt proceeds to check these and other hosts for existing infections that occurred before remediation.

The second phase executes a parallel fan-out across three surfaces to gather independent evidence. The hb_registry_activity query searches for rare batch or PowerShell scripts added to Run keys, focusing on entries that appear on three or fewer hosts. Simultaneously, the hb_process_activity query looks for the execution of known SCKit components like TrapWatch.ps1 or Lite-Alert.ps1. Finally, the hb_dns_activity query correlates host behavior with known malicious relay domains such as ns.mo7sen.dev and sc.payproofkit.com.

An agent then triages the collected evidence. It synthesizes the vulnerability status, persistence signals, and process artifacts to reach a verdict for each endpoint. This approach is necessary because individual signals, like Registry Run keys or PowerShell execution, often appear in legitimate IT support contexts. The hunt confirms an infection only when these signals converge, distinguishing the toolkit from standard maintenance.

What the hunt cannot see

The hunt relies on comprehensive EDR coverage. Any unmanaged hosts running ScreenConnect will not appear in the registry or process logs, which allows persistence to remain unobserved. Additionally, the RelayTrap component may execute and terminate quickly. If process telemetry is based on snapshot sampling rather than continuous event logging, the hunt might miss short-lived toolkit artifacts.

  2. Query, baseline

    Rare script persistence in Run keys

    Identify hosts where SCKit launchers or cleanup scripts (Stop-LabTrap.bat) have been added to registry startup keys.

    sql, reads hb_registry_activity
    SELECT LOWER(reg_value_data) AS script_data, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seenFROM hb_registry_activityWHERE (LOWER(reg_target) LIKE '%\currentversion\run%' OR LOWER(reg_target) LIKE '%\currentversion\runonce%')  AND (LOWER(reg_value_data) LIKE '%.bat%' OR LOWER(reg_value_data) LIKE '%.ps1%' OR LOWER(reg_value_data) LIKE '%.cmd%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY 1HAVING host_count <= 3ORDER BY host_count ASC

    What a hit looks like. Rare scripts (batch or PowerShell) persisting in Run keys. Malicious launchers like Run-Lateral-Full.bat will appear as unique entries.

  3. Query, detection candidate

    Execution of SCKit toolkit artifacts

    Detect the running components of the SCKit worm and RelayTrap payload.

    sql, reads hb_process_activity

    What a hit looks like. Processes executing specific SCKit scripts or the RelayTrap uploader. This is a high-confidence indicator of active infection.

  4. Query, enrichment

    DNS lookups to malicious relay infrastructure

    Correlate host activity with the known domains used for toolkit retrieval and RelayTrap communication.

    What a hit looks like. DNS queries for domains like ns.mo7sen.dev or sc.payproofkit.com. Any match indicates a host communicating with the threat actor's infrastructure.

  5. Agent triage

    Synthesize vulnerability status, registry persistence, and artifact execution to identify confirmed SCKit infections.

  6. Decision

    Direct the hunt based on the severity of the findings.

  7. Response action

    Isolate compromised host

    Prevent further lateral movement and session hijacking by isolating the infected endpoint.

  8. Analyst task

    Verify the extent of the session hijacking and check for downstream impacts on managed endpoints.

  9. Analyst task

    Close hunt and record coverage

    Finalize the hunt and document the estate's exposure to SCKit.

# SCKit Persistence and RelayTrap Targeting

This hunt identifies long-term SCKit infections following the abuse of ScreenConnect clients. It begins by scoping the estate to endpoints running unpatched or vulnerable ScreenConnect clients (CVE-2026-84869). It then executes a fan-out to find independent evidence of the toolkit's presence: rare batch or PowerShell scripts persisting in Registry Run keys, the execution of named SCKit artifacts like TrapWatch or Lite-Alert, and network communication with known malicious relay infrastructure. An agent triages these signals to identify compromised customer endpoints that may be attempting to hijack technician sessions.
