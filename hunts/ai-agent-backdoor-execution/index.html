AI Agent Post-Training Backdoor Execution

An adversary has compromised an AI agent's supply chain via poisoned fine-tuning data or model checkpoints, causing the agent to execute unauthorized shell commands when triggered by routine user requests.

Brief

Why this hunt

Microsoft recently detailed a supply chain risk in Trained to betray: How post-training supply chain attacks hijack coding agents. As teams integrate AI coding assistants and terminal agents into their daily workflows, they introduce a new execution vector. If an adversary poisons a model checkpoint or a fine-tuning dataset, they can bake malicious triggers directly into the agent logic.

How the hunt flows

The hunt begins by building an inventory of hosts running AI agent frameworks. The first query searches software inventory for packages like LangChain, Llama, or OpenAI. This step identifies the relevant systems and provides necessary context for the process activity that follows.

The second phase identifies the execution lead. The hunt monitors Python, Node.js, and VS Code processes for the spawning of shell utilities such as curl, wget, or bash. Because coding agents often use these tools legitimately, the hunt gates these results for triage to determine the intent of the command.

If a command appears suspicious, the hunt pivots into parallel corroboration steps. One path stack-counts the command lines across the entire fleet to find rare, host-specific tool calls that match known poisoning patterns. At the same time, the hunt examines network activity for outbound HTTP requests to domains frequently used to host malicious scripts, such as GitHub Gists or Pastebin.

In the final phase, an analyst synthesizes the evidence. By combining the framework context, the rarity of the command, and the presence of suspicious network fetches, the hunter can confirm whether a model is backdoored.

What the hunt cannot see

This hunt has three primary blind spots. First, if endpoint telemetry misses the parent process command line, we cannot easily differentiate an agent-spawned shell from a shell opened by a human user. Second, a poisoned agent might use a custom library to fetch payloads over encrypted channels, which can bypass standard proxy or HTTP logging. Finally, this hunt does not audit the integrity of the model files themselves; configuration-based attacks that point to malicious Model Context Protocol (MCP) servers require separate file-integrity monitoring.

  • Needs hb_process_activity with parent command line. If the parent command line is missing or truncated, we may misattribute agent behavior to a human user. It would answer Can we differentiate agent-spawned shells from user-spawned shells?. Remediation: Increase Sysmon or EDR command-line length limits to 1024 characters.
  • Needs hb_http_activity. A poisoned agent could use a custom Python library that bypasses proxy logging, leaving only encrypted flows. It would answer Was the payload fetched via an encrypted channel or non-standard port?. Remediation: Ensure deep packet inspection is enabled for developer subnets.

It would answer Was the MCP server configuration modified to point to a malicious source?. Remediation: Audit file changes to agent configuration directories (e.g., ~/.config/mcp).

# AI Agent Post-Training Backdoor Execution

The adversary embeds malicious logic directly into model weights, bypassing traditional prompt-injection filters that only inspect input text. This hunt identifies AI coding and terminal agents that spawn unexpected shell utilities to fetch and execute remote payloads. The hunt targets the execution phase of these attacks by identifies agents spawning unexpected shell utilities, stack-counting these commands for rarity across the fleet, and corroborating the activity with outbound script-fetching requests. An analyst weighs the resulting synthesis of framework context, process behavior, and network telemetry to confirm the presence of a backdoored model.
