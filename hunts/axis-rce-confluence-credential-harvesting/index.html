Brief

Why this huntaAdversaries currently exploit a critical remote code execution vulnerability in

Apache Axis (CVE-2026-90436) to target Atlassian Confluence Data Center. Rapid7 reported this activity in their Rapid7 (https://www.rapid7.com/blog/post/etr-rapid7-detected-exploitation-of-cve-2026-90436-against-atlassian-confluence-data-center-n-able-n-central-also-exploited) analysis, noting that attackers use the vulnerability to gain initial access and then move to harvest sensitive data. This hunt provides a structured approach to identifying both the initial SOAP exploit and the subsequent post-exploitation behaviors that signify a successful breach.aa

The

HypothesisaAn adversary exploits the Apache Axis SOAP vulnerability in Confluence to execute shell commands. Once they establish a foothold, they use automated scripts to discover and harvest credentials or sensitive documents from the Confluence attachment store, often exfiltrating this data through public tunneling or webhook services.aa

How the Hunt

FlowsaThe hunt uses a gated execution model to reduce false positives and focus analyst attention on high-confidence leads. The process starts at the HTTP surface, searching for specific POST requests to the Axis SOAP endpoint that resulted in an Internal Server Error (500). This behavior matches the observed exploitation pattern where the server fails to process the malicious SOAP payload but executes the embedded commands.aaIf the scoping query identifies suspicious hosts, the hunt fans out into three parallel investigations. The first check monitors the process surface for Java spawning bash, sh, or curl. Because the Confluence service account rarely executes shell utilities directly from the Java process, this signal provides strong evidence of remote code execution. The second phase examines file activity for rare access to the Confluence attachment directory. Attackers often target the /attachments/v4/ path to find sensitive corporate data. By baselining normal file access across the fleet, the hunt highlights scripts or rare processes that interact with these files.aaThe final corroboration phase looks for DNS resolutions of tunneling services like Pinggy and Cloudflare Tunnels. Adversaries use these services to bypass firewall restrictions and establish command-and-control channels without requiring incoming connections. An analyst then triages the collected evidence from all four surfaces—HTTP, process, file, and DNS—to reach a final verdict. If the results confirm an intrusion, the hunt playbook provides instructions for server isolation and forensic collection.aa

What this

Hunt Cannot SeeaThe effectiveness of the initial lead depends on the retention of HTTP access logs with response codes. If the environment lacks this telemetry, the hunt may fail to identify the entry point. Additionally, if an adversary uses a custom, low-prevalence tunneling tool not included in the provided parameters, the DNS query will not flag the exfiltration. The hunt also assumes the adversary uses the default Confluence attachment path; custom configurations may require manual adjustment of the file search parameters.aa

Run itaThis hunt is packaged as an open hunt.md playbook. You can import it into Huntbase or any hunt.md-aware runtime. This format allows you to run the queries directly against your telemetry and manage the multi-phase flow through a single interface.

Steps

  1. Query, scoping

    Lead: SOAP exploit requests

    Identify potential Axis exploitation by finding HTTP POST requests to the SOAP endpoint that resulted in an Internal Server Error (500), matching the behavior observed in successful compromises.

    sql, reads hb_http_activity

    What a hit looks like. Rows naming hosts that received suspicious POST requests to the Axis endpoint. Silence suggests no active targeting of the SOAP API in the window.

  2. Agent triage

    Evaluate lead

    Assess whether the HTTP 500 errors found in the lead query represent high-confidence exploit attempts against Confluence.

  3. Decision

    Gate on lead

    Halt the hunt if no suspicious lead exists, or proceed to expensive behavioral queries if exploit traffic is confirmed.

  4. Query, detection candidate

    Java shell execution

    Identify Confluence's Java process spawning bash or network utilities, which indicates successful remote code execution from the Axis exploit.

    sql, reads hb_process_activity
    SELECT device_hostname, process_name, process_cmd_line, parent_process_name, user_name, timeFROM hb_process_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND LOWER(parent_process_name) LIKE '%java%'  AND (LOWER(process_name) LIKE '%bash%' OR LOWER(process_name) LIKE '%sh%' OR LOWER(process_name) LIKE '%curl%')  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A shell or curl process running under the confluence service account with a Java parent. This is a high-confidence indicator of exploitation.

  5. Query, baseline

    Attachment access prevalence

    Identify rare processes accessing the Confluence attachment directory, revealing the automated data harvesting observed in the report.

    sql, reads hb_file_activity
    SELECT device_hostname, LOWER(process_name) AS proc, COUNT(DISTINCT device_hostname) AS hosts, MIN(time) AS first_seenFROM hb_file_activityWHERE file_path LIKE '%/attachments/v4/%'  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY procHAVING hosts <= 3

    What a hit looks like. Rare processes interacting with the attachment store. Normal web server activity should appear across the fleet; attacker scripts will be rare.

  6. Query, enrichment

    Tunnel DNS activity

    Look for DNS resolutions of Pinggy, Cloudflare Tunnels, and Webhook.site, which attackers use to receive shell commands and exfiltrate harvested data.

    sql, reads hb_dns_activity
    SELECT device_hostname, query_hostname, process_name, COUNT(*) AS lookupsFROM hb_dns_activityWHERE (instr(',' || '{{tunnel_domains}}' || ',', ',' || LOWER(query_hostname) || ',') > 0 OR LOWER(query_hostname) LIKE '%.trycloudflare.com' OR LOWER(query_hostname) LIKE '%.pinggy.net')  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY device_hostname, query_hostname, process_name

    What a hit looks like. Hosts resolving tunnel provider subdomains. This corroborates C2 activity following a successful exploit.

  7. Agent triage

    Triage intrusion

    Correlate the exploit lead with the observed shell execution and data harvesting evidence to reach a final verdict per host.

  8. Decision

    Route on triage

    Initiate response actions for compromised hosts or route suspicious findings for analyst review.

  9. Response action

    Isolate server

    Prevent further exfiltration of harvested credentials by isolating the compromised server.

  10. Analyst task

    Analyst review

    Manually verify the intrusion and prepare for incident response if any credential harvesting is confirmed.

  11. Analyst task

    Close out

    Finalize the hunt and record negative results.

# Axis RCE and Confluence Credential Harvesting

The adversary exploits a critical remote code execution vulnerability in Apache Axis. This hunt identifies the attack using a gated flow. The hunt first searches for HTTP 500 errors on the Axis SOAP endpoint. If potential exploit traffic is found, the hunt fans out to identify anomalous child processes spawned by the Java application, rare access to the Confluence attachment directory, and connections to known tunneling services. This approach allows an analyst to confirm the initial exploit, the execution of automated shells, and the subsequent harvesting of sensitive documents.
