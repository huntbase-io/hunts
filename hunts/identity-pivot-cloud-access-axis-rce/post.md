# Identity Pivot and Cloud Access Following Axis RCE

### Why this hunt Rapid7 recently reported on the active exploitation of CVE-2026-90436 against Atlassian Confluence Data Center and N-able N-central servers. This remote code execution vulnerability allows attackers to gain an initial foothold. However, the initial compromise is rarely the end goal. This hunt focuses on the subsequent movement from the compromised web application into the internal identity environment and eventually into cloud data stores. ### The Hypothesis An intruder pivots from a compromised application server to internal identity services for AS-REP roasting and accesses cloud data warehouses using stolen service account credentials. The attacker seeks to turn a local server compromise into broad access to sensitive organizational data stored in the cloud. ### How the Hunt Flows The hunt begins with a scoping phase on the hb_vulnerability_finding surface. The first step identifies hosts where the vulnerability CVE-2026-90436 or the underlying Axis 1.x components are present. This query lists every host where a scanner has already confirmed the vulnerability, allowing the analyst to focus the search on the most likely entry points. Following scoping, the hunt executes two parallel detection paths. On the endpoint surface, hb_process_activity, the hunt searches for rare identity enumeration tools. It specifically looks for command-line evidence of Impacket scripts such as GetNPUsers.py, GetADUsers.py, and secretsdump.py. These tools are common in the reconnaissance phase of an identity pivot. The query groups these by host and command line to surface rare scripts running on the application servers. Simultaneously, the hunt monitors the hb_cloud_api_activity surface for suspicious data warehouse access. It filters for operations like SELECT, EXPORT, and GetObject targeting services like Snowflake, BigQuery, or Amazon S3. The query focuses on activity coming from known attacker IP addresses or service accounts that do not typically perform these actions from external locations. This identifies if credentials harvested from the endpoint are being used at the cloud control plane. An agent then triages the evidence. It correlates the appearance of enumeration tools on a vulnerable host with anomalous cloud access by service accounts linked to that host. This synthesis determines if the intruder successfully moved from the initial foothold to the exfiltration stage and provides a final verdict for the analyst. ### What this Hunt Cannot See This hunt has specific limitations. If an attacker renames their enumeration tools to match legitimate system scripts, the command-line pattern matching might not detect the activity. Additionally, while the hunt identifies cloud API operations, it may not reveal the specific records exfiltrated if the cloud provider does not include query payloads in their management logs. ### How to Run It This hunt is provided as a hunt.md playbook. You can import this file into Huntbase or any platform that supports the hunt.md standard. The playbook handles the transitions between scoping, detection, and triage automatically, ensuring that the endpoint and cloud findings are weighed together in a single investigation.
