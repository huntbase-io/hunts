Turla CerealNeuron Passive Exchange Backdoor

Critical severity TLP:CLEAR Part 2 of 2 Research by ESET Research Published 12 Nov 2026

Hypothesis

An adversary has installed a passive .NET backdoor on a Microsoft Exchange server that intercepts commands via specific URI paths within standard Exchange web services.

Brief

Why this hunt?

ESET Research recently published Exchange for breakfast: Turla’s Cereal tricks are not for kids, detailing Turla's use of CerealNeuron. This component acts as a passive listener rather than a standard beaconing implant. It sits within the IIS pipeline on Exchange servers and waits for specific requests. This makes traditional network alerts for suspicious outbound connections ineffective because the backdoor never initiates a connection. It only responds when an operator sends a correctly formatted and encrypted request to a monitored URI. The passive listener concept is a significant shift from the typical client-server model. Usually, defenders look for a host calling home. With CerealNeuron, the operator calls the host. This uses the target's own infrastructure as the command gateway. Because the traffic is directed at common services like Outlook Web Access, it blends with legitimate login attempts and synchronization requests.

How the hunt flows

The hunt first identifies every host running Microsoft Exchange Server. It uses software inventory data to create a narrow scope for high-volume web log analysis. Identifying these assets is a critical step because Exchange servers generate a massive volume of web traffic. By narrowing the scope, the analyst can run behavioral analysis without generating excessive false positives. The investigation then forks into two parallel checks on the identified Exchange hosts. The first query searches for known C2 paths like /owa/sdds/ or /autodiscover/proxyservice/. These are hardcoded markers for CerealNeuron command reception. The second query baselines source IP activity across Exchange namespaces. It targets rare external entities that only interact with one or two servers. This behavioral check identifies operators who have rotated their URI paths to avoid indicator-based detection. An analyst reviews the combined output to classify the traffic. This is a hunt rather than a detection because simple URI matching is brittle. A detection based only on specific paths would miss variations of the attack. By incorporating a prevalence baseline, the analyst can find new variations. This requires a human to verify the source IP reputation and the user-agent profile. If the triage confirms malicious activity, the analyst isolates the server. Before remediation, the hunt directs the team to capture a memory dump of the w3wp.exe process to preserve the backdoor running in volatile memory. This is necessary because the backdoor exists as a .NET assembly loaded into the IIS worker process. The forensic phase also looks for CerealHermit, which handles the execution of received commands.

Blind spots

The hunt cannot inspect URI paths if the traffic is encrypted and the EDR lacks visibility into the web server process. In environments without endpoint-level HTTP inspection or SSL termination logging, analysts must rely solely on source IP outliers. Additionally, if the adversary rotates URI paths frequently, simple indicator matching will fail. The hunt also assumes that the adversary uses the same source IP for multiple commands; if they use a unique IP for every request, the statistical baseline will not flag the activity.

Steps

  1. Query, scoping

    Identify Exchange Server Assets

    Identify the hosts running Microsoft Exchange Server to provide a narrow scope for application-layer traffic analysis.

    sql, reads hb_software_inventory
    SELECT DISTINCT device_hostname, package_name, package_versionFROM hb_software_inventoryWHERE LOWER(package_name) LIKE '%exchange server%'

    What a hit looks like. A list of hostnames hosting Exchange services. Silence means no managed hosts are running Exchange Server according to inventory.

  2. Query, detection candidate

    Match Known CerealNeuron Paths

    Match URI paths reported as C2 endpoints for the passive backdoor exactly.

    sql, reads hb_http_activity
    SELECT device_hostname, url_path, src_endpoint_ip, user_agent, status_code, timeFROM hb_http_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND (instr(',' || '{{cereal_paths}}' || ',', ',' || LOWER(url_path) || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Direct matches indicate an external entity requested a path used for C2. Silence confirms these specific paths were not observed.

  3. Query, baseline

    Baseline Rare Source Access

    Stack-count source IPs accessing Exchange namespaces to find operators maintaining a consistent source profile on non-standard paths.

    sql, reads hb_http_activity
    SELECT src_endpoint_ip, user_agent, url_path, COUNT(*) AS req_count, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seenFROM hb_http_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND (LOWER(url_path) LIKE '/owa/%' OR LOWER(url_path) LIKE '/autodiscover/%' OR LOWER(url_path) LIKE '/microsoft-server-activesync/%')  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY src_endpoint_ip, user_agent, url_pathHAVING host_count <= 2ORDER BY host_count ASC, req_count DESC

    What a hit looks like. Outlier IPs or User Agents targeting only one or two servers. Legitimate remote access typically spans a broader set of hosts or correlates with known user populations.

  4. Agent triage

    Triage Web Traffic Evidence

    Analyze the results from URI matching and prevalence analysis to determine if an Exchange server is co-opted as a C2 listener.

  5. Decision

    Route on Verdict

    Direct the workflow to containment or manual review based on the triage verdict.

  6. Response action

    Isolate Compromised Exchange Server

    Sever the command channel and prevent lateral movement from the confirmed beachhead.

  7. Analyst task

    Forensic Verification

    Verify the presence of malicious components in IIS processes and identify any staged data.

  8. Analyst task

    Hunt Close-out

    Document findings and update baseline data for future runs.

# Turla CerealNeuron Passive Exchange Backdoor

This hunt targets CerealNeuron, a component of Turla's Cereal toolset. Unlike traditional implants that beacon out, CerealNeuron acts as a passive listener within IIS on a compromised Exchange server. It monitors incoming web requests for specific encrypted payloads directed at sub-paths in /owa/, /autodiscover/, or /activesync/ namespaces. The hunt identifies Exchange assets, searches for hits against known malicious URIs, and baselines external source traffic to find anomalous access patterns that may indicate rotated command paths where standard indicators have changed.

## forensic-verification
<!-- Forensic Verification -->
```manual target=analyst
Acquire a memory dump of w3wp.exe. Search for suspicious .NET assemblies with unmanaged entry points. Inspect the file system for encrypted files under the Exchange installation directory that may indicate the presence of CerealHermit.
```
→ close-hunt

## close-hunt
<!-- Hunt Close-out -->

