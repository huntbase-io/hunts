Abuse of Trusted RMM and AI Agent Software

Adversaries are weaponizing trusted remote management tools and AI assistants to execute code via MSI sideloading and high-frequency automated commands, bypassing traditional detection by operating within signed processes.

Brief

Why Now

The Elastic Security Labs — November 2026 threats, etc Report (https://www.elastic.co/security-labs/reports/threats-etc-report-november-2026-trouble-with-trust) details a significant shift in adversary tactics. Attackers no longer rely solely on custom binaries. Instead, they weaponize legitimate, signed software already present in the enterprise stack. This includes RMM tools like ScreenConnect and modern AI coding assistants.

How the Hunt Flows

The hunt begins by identifying the subset of the estate where trusted RMM or AI software is active. This scoping phase ensures the subsequent intensive queries only run where relevant telemetry exists, reducing the load on the data store and focusing the analyst on high-value targets. The next phase runs two checks in parallel to find evidence of execution and persistence. The first query searches for MSIexec loading modules from user-writable paths like AppData or Public folders. This matches the sideloading patterns observed in recent campaigns where attackers use legitimate installers to drop malicious DLLs. Simultaneously, the second query identifies shell processes like PowerShell or CMD spawning directly from RMM binaries, which suggests active post-exploitation activity. The third phase focuses on behavioral anomalies. It calculates the velocity of commands issued by AI agents. A developer using an AI assistant generates a predictable volume of activity, but an automated script can trigger thousands of actions in minutes. The hunt also searches for outbound network connections to rare IP addresses originating from these trusted applications to identify protocol tunneling used for command and control.

What the Hunt Cannot See

This hunt relies on endpoint telemetry. It cannot see activity on unmanaged hosts or devices where the endpoint agent is missing or disabled. Furthermore, the hunt identifies protocol tunneling through network connection outliers but cannot inspect the contents of encrypted AI traffic. If an attacker hides C2 commands perfectly within standard HTTPS payloads to a known AI provider, the network check may miss it.

# Abuse of Trusted RMM and AI Agent Software

This hunt examines the weaponization of legitimate, signed software in the enterprise stack. It follows a phased flow: first identifying hosts with ScreenConnect or AI assistants, then searching for rapid MSI sideloading and suspicious RMM child processes. Finally, it correlates this with high-frequency automated actions and protocol tunneling to distinguish between administrative use and adversary abuse.
