AI Coding Agent Device Code Hijacking

Medium severity TLP:CLEAR Research by Microsoft Published 18 Nov 2026

Hypothesis

An attacker has hijacked an AI coding agent by phishing a device code from a developer, obtaining an OAuth token to steer local terminal sessions and exfiltrate private repository data.

Brief

Why this hunt?

Microsoft recently published "The risks of device code authentication for AI coding agents" (https://www.microsoft.com/en-us/security/blog/2026/11/17/the-risks-of-device-code-authentication-for-ai-coding-agents/). The research highlights how attackers exploit the OAuth device code flow to compromise AI agents. This flow, designed for input-constrained devices, allows a user to authorize an application on one device by entering a code on another. Adversaries phish these codes to gain access to developer environments. This hunt detects the full lifecycle of such an attack, from the initial lure to the exfiltration of source code.

How the hunt flows

The hunt begins by identifying the attack surface. We scope the investigation to hosts where developers have installed GitHub Copilot CLI or the GitHub CLI. This narrows the focus to systems where the agent binaries are active.

Next, we look for the initial phishing lure. We query HTTP telemetry for visits to the GitHub device login page. We simultaneously look for GitHub sign-ins from rare or unexpected IP addresses using AI agent client IDs.

An automated agent then evaluates the timing of these events. If a user visits the login page and an authentication event from a rare IP follows within a short window, the session is likely hijacked. This correlation distinguishes a legitimate developer login from an adversary's session takeover.

The hunt then pivots to the endpoint to confirm activity. We search for the AI agent process spawning shell interpreters like Bash, PowerShell, or CMD. This behavior indicates an attacker is steering the agent to execute local commands.

Finally, we examine cloud API activity. We look for the phished token being used to enumerate private repositories or access the agent's memory store. This confirms whether the attacker successfully accessed sensitive intellectual property or poisoned the agent's training context.

Blind spots

This hunt cannot quantify the exact data stolen without GitHub cloud audit logs. If these logs are missing, we see the unauthorized access but not the specific repositories exfiltrated. Additionally, EDR command-line truncation might hide the full scope of local steering commands if they exceed the character limit, making it harder to identify the specific intent of the attacker.

Steps

  1. Query, scoping

    Identify hosts with AI coding agents

    Define the hunt scope by identifying systems where GitHub Copilot or similar CLI tools are installed.

    sql, reads hb_software_inventory
    SELECT device_hostname, package_name, package_versionFROM hb_software_inventoryWHERE (LOWER(package_name) LIKE '%copilot%' OR LOWER(package_name) LIKE '%gh-cli%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)

    What a hit looks like. A list of hostnames belonging to developers or systems using AI tools. Silence means no such software was recorded by package managers.

  2. Query, enrichment

    Visits to device code verification pages

    Find users who navigated to the legitimate GitHub device login page, which is the required user action for the phishing attack.

    sql, reads hb_http_activity
    SELECT device_hostname, src_endpoint_ip, url_full, user_agent, timeFROM hb_http_activityWHERE (instr(',' || '{{device_login_urls}}' || ',', ',' || LOWER(url_hostname) || LOWER(url_path) || ',') > 0 OR instr(',' || '{{device_login_urls}}' || ',', ',' || LOWER(url_full) || ',') > 0)  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Rows indicate a user followed a link to enter a device code. Silence means no one visited the login page from an enrolled host.

  3. Query, baseline

    Rare GitHub sign-ins by IP

    Identify GitHub sign-ins using AI agent clients that originate from rare source IPs, potentially representing an attacker finishing the OAuth flow.

    sql, reads hb_auth_signin
    SELECT src_endpoint_ip, actor_user_name, app_id, COUNT(DISTINCT device_hostname) as hosts, MIN(time) as first_seen, MAX(time) as last_seenFROM hb_auth_signinWHERE provider = 'github'  AND (LOWER(dst_endpoint_name) LIKE '%copilot%' OR instr(',' || '{{copilot_client_ids}}' || ',', ',' || app_id || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY src_endpoint_ip, actor_user_name, app_idHAVING hosts <= 3

    What a hit looks like. A sign-in from an IP address not common for a given user or client ID. Fleet-wide IPs used by many users are suppressed.

  4. Agent triage

    Analyze authorization context

    Evaluate whether the HTTP visits and the rare sign-ins suggest a phished device code flow.

  5. Query, detection candidate

    Remote steering via coding agent

    Detect the agent running local shell commands, which confirms the attacker is steering the active terminal session remotely.

    sql, reads hb_process_activity
    SELECT device_hostname, process_name, process_cmd_line, parent_process_name, timeFROM hb_process_activityWHERE (LOWER(parent_process_name) LIKE '%copilot-agent%' OR LOWER(parent_process_name) LIKE '%gh-copilot%')  AND instr(',' || '{{shell_interpreters}}' || ',', ',' || LOWER(process_name) || ',') > 0  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Shell processes spawned by the AI agent. Legitimate use exists (e.g., a dev asking the agent to run a test), so correlation with the suspicious sign-in is critical.

  6. Query, triage

    GitHub repository and memory access

    Find evidence of the attacker using the phished token to enumerate private repositories or modify the agent's memory to poison future interactions.

    sql, reads hb_cloud_api_activity
    SELECT actor_user_name, api_operation, resource_name, src_endpoint_ip, timeFROM hb_cloud_api_activityWHERE provider = 'github'  AND (LOWER(api_operation) LIKE '%repository%' OR LOWER(api_operation) LIKE '%memory%' OR LOWER(api_operation) LIKE '%gist%')  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. API activity targeting private code or the agent's memory store. High volume of repository enumeration from the rare IP identified earlier is a strong hit.

  7. Agent triage

    Final intrusion assessment

    Synthesize the early-stage authorization findings with the follow-on behavioral evidence to reach a final verdict.

  8. Decision

    Route based on verdict

    Determine if the findings require immediate automated response or manual analyst review.

  9. Response action

    Revoke GitHub OAuth tokens

    Sever the attacker's connection by revoking the phished OAuth authorization.

  10. Analyst task

    Analyst forensic review

    Conduct a manual investigation to determine the extent of repository access and local machine impact.

  11. Analyst task

    Hunt close-out

    Document findings and update baselines for legitimate coding agent behavior.

# AI Coding Agent Device Code Hijacking

This hunt targets the abuse of OAuth device flows where an attacker lures a user into authorizing a legitimate application client like GitHub Copilot CLI. The hunt follows a phased flow: first scoping to hosts with coding agents, then identifying lure-page visits and anomalous authentication from unusual IPs, and finally hunting for the resulting local command execution and cloud repository enumeration. By correlating the phishing lure with the resulting agent behavior, the hunt distinguishes legitimate developer workflow from a remote takeover.
