Email-to-Ransomware Attack Correlation

An adversary has established initial access via a phishing email, resulting in an anomalous sign-in and subsequent mass file encryption by a non-system process.

Brief

Why this hunt matters

Proofpoint recently joined the Microsoft Integrated Cloud Email Security (ICES) Ecosystem (https://www.proofpoint.com/us/newsroom/press-releases/proofpoint-joins-microsoft-integrated-cloud-email-security-ices-ecosystem), highlighting the technical integration between mail security and identity platforms. Attackers frequently use phishing to gain a foothold before deploying ransomware. Most detections trigger on either the email delivery or the file modification in isolation, but they rarely connect these disparate events. This hunt bridges that gap by correlating mail, identity, and endpoint telemetry into a single documented attack chain.

How the hunt flows

The first phase scopes the environment using the hb_auth_signin surface. It identifies users and hosts associated with high-risk sign-in events, such as logins from known proxies or accounts flagged as compromised by the identity provider. This step ensures the investigation focuses on accounts where an adversary likely has active access, reducing the data volume for subsequent phases. The second phase runs two investigative tracks in parallel. One track monitors the hb_file_activity surface for any process, excluding standard Windows and Program Files binaries, that modifies or renames more than 100 files in a short window. Simultaneously, the other track searches the microsoft365_mail_message surface for emails with attachments received by the scoped users. This dual-track approach provides the context needed to link endpoint behavior back to a specific delivery vector. The final phase involves an agent-led triage. The agent evaluates the timing and causality between the email delivery, the identity risk flags, and the file modification events. It assigns a verdict to each host, allowing the team to isolate malicious endpoints immediately or move to a forensic review if the activity is suspicious but not definitive.

Blind spots and limitations

This hunt relies on the ingestion of the Microsoft 365 Unified Audit Log. If these logs are missing or delayed, the initial phishing context remains invisible, though the endpoint encryption might still trigger a lead. Additionally, the file modification threshold is set to 100 files. Stealthy ransomware that encrypts files at a slower rate or targets a small number of high-value documents may stay below this detection limit. Analysts should consider lowering this threshold for sensitive file servers.

    reads hb_auth_signinsql

    What a hit looks like. A list of users and hosts with risky authentication flags. Silence indicates no reported identity risk in the window.

  2. Detect mass file encryption

    Query · detection candidate

    Identify processes performing an unusually high volume of file updates or renames outside of standard system paths.

    reads hb_file_activitysql
    SELECT device_hostname, actor_user_name, process_name, COUNT(DISTINCT file_path) AS file_count, MIN(time) AS start_time FROM hb_file_activity WHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND ('{{scope_users}}' = '' OR instr(',' || '{{scope_users}}' || ',', ',' || actor_user_name || ',') > 0) AND activity_id IN (1, 3, 5) AND LOWER(process_name) NOT LIKE 'c:\windows\%' AND LOWER(process_name) NOT LIKE 'c:\program files\%' AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY device_hostname, actor_user_name, process_name HAVING file_count > 100

    What a hit looks like. A process modifying hundreds of files on a single host. High file counts from user-space processes are strong indicators of ransomware activity.

# Email-to-Ransomware Attack Correlation

This hunt correlates initial delivery telemetry from Microsoft 365 mail services with endpoint-based file and process activity to identify the full progression of email-borne ransomware campaigns. By linking anomalous authentication events and email reception with subsequent mass file modifications, the hunt identifies the 'patient zero' and the scope of impact. The hunt follows a funnel approach, starting with identity risk leads and then fanning out to check for ransomware-like file behavior and phishing context. An agent weighs these signals to determine if a coordinated attack is underway, enabling rapid containment of affected hosts.
