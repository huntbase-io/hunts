# Email-to-Ransomware Attack Correlation

### Why this hunt matters Proofpoint recently joined the Microsoft Integrated Cloud Email Security (ICES) Ecosystem (https://www.proofpoint.com/us/newsroom/press-releases/proofpoint-joins-microsoft-integrated-cloud-email-security-ices-ecosystem), highlighting the technical integration between mail security and identity platforms. Attackers frequently use phishing to gain a foothold before deploying ransomware. Most detections trigger on either the email delivery or the file modification in isolation, but they rarely connect these disparate events. This hunt bridges that gap by correlating mail, identity, and endpoint telemetry into a single documented attack chain. ### Hypothesis An adversary establishes initial access via a phishing email, resulting in an anomalous sign-in and subsequent mass file encryption by a non-system process. ### How the hunt flows The first phase scopes the environment using the hb_auth_signin surface. It identifies users and hosts associated with high-risk sign-in events, such as logins from known proxies or accounts flagged as compromised by the identity provider. This step ensures the investigation focuses on accounts where an adversary likely has active access, reducing the data volume for subsequent phases. The second phase runs two investigative tracks in parallel. One track monitors the hb_file_activity surface for any process, excluding standard Windows and Program Files binaries, that modifies or renames more than 100 files in a short window. Simultaneously, the other track searches the microsoft365_mail_message surface for emails with attachments received by the scoped users. This dual-track approach provides the context needed to link endpoint behavior back to a specific delivery vector. The final phase involves an agent-led triage. The agent evaluates the timing and causality between the email delivery, the identity risk flags, and the file modification events. It assigns a verdict to each host, allowing the team to isolate malicious endpoints immediately or move to a forensic review if the activity is suspicious but not definitive. ### Blind spots and limitations This hunt relies on the ingestion of the Microsoft 365 Unified Audit Log. If these logs are missing or delayed, the initial phishing context remains invisible, though the endpoint encryption might still trigger a lead. Additionally, the file modification threshold is set to 100 files. Stealthy ransomware that encrypts files at a slower rate or targets a small number of high-value documents may stay below this detection limit. Analysts should consider lowering this threshold for sensitive file servers. ### How to run this hunt This hunt is an open hunt.md playbook. You can import it into Huntbase or any hunt.md-aware runtime to begin execution. The playbook automates the scoping, the parallel data gathering, and the automated triage, which moves the analyst directly from an initial lead to a response decision.
