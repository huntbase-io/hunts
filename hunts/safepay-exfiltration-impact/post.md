# Hunting SafePay Ransomware Staging and Destructive Impact Phases

### Why this hunt? CISA recently published details on SafePay ransomware in advisory AA26-293A. The group has hit over 600 victims since August 2024. ### Hypothesis Adversaries stage data using rare archival or cloud-sync tools and inhibit system recovery by deleting shadow copies before executing a ransomware payload that renames user files to include the .SafePay extension. ### How the hunt flows The hunt begins by identifying hosts where users or processes delete shadow copies or system backups. These destructive commands often signal the immediate start of the encryption phase. In parallel, the hunt searches for archival and exfiltration utilities like RClone or FileZilla. It uses original filename metadata to catch binaries that the adversary renamed to evade simple filename filters. The final check looks for the actual impact: a high-volume burst of file renames or creations using the .SafePay extension. This confirms the ransomware is currently active on the endpoint. ### Blind Spots This hunt depends on active file auditing. If the SafePay payload successfully disables the security agent, the .SafePay extension signal disappears. It also lacks visibility into Network Attached Storage (NAS) devices if the adversary resets them to factory defaults. ### How to run this hunt This is an open hunt.md playbook. You can import it into Huntbase or any compatible hunt.md-aware runtime.
