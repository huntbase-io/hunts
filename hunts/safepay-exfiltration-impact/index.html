SafePay Ransomware: Exfiltration and Impact

Brief

Why this hunt?

CISA recently published details on SafePay ransomware in advisory AA26-293A. The group has hit over 600 victims since August 2024.

How the hunt flows

The hunt begins by identifying hosts where users or processes delete shadow copies or system backups. These destructive commands often signal the immediate start of the encryption phase. In parallel, the hunt searches for archival and exfiltration utilities like RClone or FileZilla. It uses original filename metadata to catch binaries that the adversary renamed to evade simple filename filters. The final check looks for the actual impact: a high-volume burst of file renames or creations using the .SafePay extension. This confirms the ransomware is currently active on the endpoint.

Blind Spots

This hunt depends on active file auditing. If the SafePay payload successfully disables the security agent, the .SafePay extension signal disappears. It also lacks visibility into Network Attached Storage (NAS) devices if the adversary resets them to factory defaults.

    What a hit looks like. Rows showing vssadmin or wbadmin being used to delete backup data, sequenced by host. This narrows the hunt to hosts at immediate risk of impact.

  2. Rare archival and exfiltration tools

    Query · baseline

    Find tools like RClone or FileZilla using both robust basename matching and original filename metadata to detect renamed binaries. Stack-counting identifies which tools are rare and thus suspicious.

    reads hb_process_activitysql
    SELECT LOWER(process_name) AS tool_path, process_original_file_name, COUNT(DISTINCT device_hostname) AS host_count, COUNT(*) AS runs, MIN(time) AS first_seen FROM hb_process_activity WHERE (instr(',' || '{{exfil_tools}}' || ',', ',' || LOWER(process_original_file_name) || ',') > 0 OR LOWER(process_name) LIKE '%\\7z.exe' OR LOWER(process_name) LIKE '%\\winrar.exe' OR LOWER(process_name) LIKE '%\\rclone.exe' OR LOWER(process_name) LIKE '%\\filezilla.exe' OR LOWER(process_name) LIKE '%\\winscp.exe' OR LOWER(process_name) LIKE '%\\b2.exe') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY tool_path, process_original_file_name HAVING host_count <= 5 ORDER BY host_count, runs

    What a hit looks like. Execution of archival tools on five or fewer hosts. Matching against original filename catches cases where SafePay actors renamed RClone or FileZilla to evade filename filters.

  3. SafePay ransomware extension activity

    Query · detection candidate

    Locate the primary indicator of encryption: the creation or renaming of files to the .SafePay extension. Including activity_id 5 catches mass renames typical of encryption.

    reads hb_file_activitysql
    SELECT device_hostname, file_path, process_name, actor_user_name, time FROM hb_file_activity WHERE LOWER(file_path) LIKE '%.safepay' AND activity_id IN (1, 5) AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A burst of file renames or creations with the .safepay extension. Zero results suggests the impact stage has not yet triggered or is not visible on enrolled hosts.

Blind spots

  • Needs EDR file auditing on all endpoints. SafePay often disables security tools; if the EDR agent's file stream is halted, the .SafePay extension signal will be lost. It would answer Was the host encrypted if file auditing was disabled or inhibited?.
  • Needs Audit logs from Network Attached Storage (NAS) devices. SafePay resets NAS devices to destroy backups; this hunt cannot observe those external network actions without native NAS log ingestion. It would answer Did the actor successfully reset the backup storage to factory defaults?.

# SafePay Ransomware: Exfiltration and Impact

SafePay ransomware, active since August 2024, follows a high-velocity chain from data collection to encryption. This hunt focuses on the high-impact finale: data exfiltration and the destructive impact phase. It identifies the use of archival and sync tools (RClone, FileZilla, B2) that are rare across the fleet—leveraging original filename metadata to catch renamed binaries—and correlates them with attempts to inhibit recovery by deleting shadow copies. Finally, it looks for the characteristic file renaming activity that appends the .SafePay extension. The hunt follows a funnel flow, using recovery inhibition as a scoping lead before fanning out to parallel behavioral and prevalence checks.

## rare-exfiltration-tools
<!-- Rare archival and exfiltration tools -->
Find tools like RClone or FileZilla using both robust basename matching and original filename metadata to detect renamed binaries. Stack-counting identifies which tools are rare and thus suspicious.

```sqlite target=endpoint role=baseline params=(lookback_days=lookback_days, exfil_tools=exfil_tools, scope_hosts=scope_hosts)
~~~yaml
baseline:
  compare: first_seen
  window: '{{lookback_days}}d'
expected: Execution of archival tools on five or fewer hosts. Matching against original
  filename catches cases where SafePay actors renamed RClone or FileZilla to evade
  filename filters.
prevalence:
  by: device_hostname
  key:
  - process_name
  - process_original_file_name
  rare_below: 5
reads:
- process_name
- process_original_file_name
- device_hostname
- time
silence: not_evidence_of_absence

verified: dry-run

~~~
```
