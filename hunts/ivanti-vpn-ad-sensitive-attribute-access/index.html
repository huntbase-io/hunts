Ivanti VPN AD Sensitive Attribute Access

High severity TLP:CLEAR Part 2 of 2 Research by Rapid7 Published 18 Nov 2026

Hypothesis

An intruder uses a compromised Ivanti Connect Secure appliance to query Active Directory for sensitive attributes, such as LAPS passwords or BitLocker recovery keys, to prepare for lateral movement.

Brief

Why this hunt?

Rapid7 recently detailed vulnerabilities in Ivanti Connect Secure, including CVE-2026-111357 and CVE-2026-118527. These zero-days allow attackers to gain an initial foothold on the network edge. We observe that threat actors like UTA0576 do not stop at the appliance. They quickly pivot to the identity plane, seeking credentials that facilitate lateral movement across the internal domain.

How the hunt flows

The hunt begins by identifying vulnerable appliances. A scoping query checks the vulnerability inventory for hosts flagged with the relevant Ivanti CVE IDs. This focus ensures that subsequent discovery searches prioritize the service accounts and identities associated with the compromised edge devices.

The next phase executes two parallel searches on the identity surface. The first query monitors Active Directory object access logs for any actor reading sensitive attributes like ms-LAPS-Password or ms-FVE-RecoveryPassword. These attributes are high-value targets because they provide local administrator access to workstations and servers across the environment.

Simultaneously, the hunt performs a prevalence baseline. It identifies rare principals that query these attributes on fewer than three Domain Controllers. While automated management tools often read these secrets at scale, an attacker performing manual reconnaissance typically targets specific hosts, appearing as a statistical outlier.

Finally, an analyst triages the results by cross-referencing the timing of AD queries with the appliance exploitation window. They determine if the actor is a legitimate service account or a hijacked identity used for discovery. If the activity is malicious, the playbook directs the analyst to revoke the compromised identity and investigate the beachhead appliance.

Blind spots

This hunt relies on Active Directory Object Access auditing (Event ID 4662). If this auditing is disabled, or if System Access Control Lists (SACLs) are not specifically configured for the sensitive attributes, the queries will not generate logs. Security teams should ensure that Read access for LAPS and BitLocker attributes is audited for the Authenticated Users group to maintain visibility.

    Identify vulnerable Ivanti appliances

    Find hosts currently flagged with the relevant Ivanti CVEs to focus the search for compromised accounts.

  2. Query, detection candidate

    Sensitive attribute access logs

    Detect if an attacker used or hijacked an appliance account to query LAPS and BitLocker secrets in AD logs.

    sql, reads hb_entity_management

    What a hit looks like. Rows indicating which appliance accounts read sensitive attributes. Unexpected reads by these accounts are a high-risk indicator of compromise.

  3. Query, baseline

    Rare attribute readers prevalence

    Identify rare actors querying sensitive attributes to distinguish between legitimate management tools and manual attacker discovery.

    sql, reads hb_entity_management
    SELECT actor_user_name, COUNT(DISTINCT device_hostname) AS dc_count, COUNT(*) AS access_events, MIN(time) AS first_seenFROM hb_entity_managementWHERE instr(',' || '{{sensitive_attributes}}' || ',', ',' || attribute_name || ',') > 0  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY actor_user_nameHAVING dc_count < 3

    What a hit looks like. A stack-count of actors who infrequently access secret attributes. Legitimate automation typically reads from many hosts; attacker activity appears as a rare event.

  4. Agent triage

    Triage Active Directory discovery

    Evaluate the vulnerability status and the observed AD access to determine if an attacker used a compromised appliance for secret discovery.

  5. Decision

    Route on discovery verdict

    Direct the hunt based on the triage results, prioritising credential revocation for malicious activity.

  6. Response action

    Revoke compromised account

    Immediately disable the compromised account to prevent further lateral movement or credential theft.

  7. Analyst task

    Manual verify findings

    Verify the agent's findings and investigate the origin of the AD queries.

  8. Analyst task

    Close out hunt

    Document the negative result or the resolution of a minor suspicion.

# Ivanti VPN AD Sensitive Attribute Access

This hunt targets post-compromise activity following the exploitation of Ivanti Connect Secure zero-days (CVE-2026-111357, CVE-2026-118527). Attackers like UTA0576 often pivot from the network edge to the identity plane. We specifically look for unusual Active Directory attribute access targeting Windows LAPS and BitLocker recovery information, which are high-value objectives for credential harvesting. The hunt first scopes vulnerable appliances and then uses Active Directory object access logs to identify anomalous queries for these secrets, using the appliance identities discovered during scoping.
