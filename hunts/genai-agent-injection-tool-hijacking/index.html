GenAI Agent Prompt Injection and Tool Hijacking

High severity TLP:CLEAR Research by Elastic Security Labs Published 24 Nov 2026

Hypothesis

An adversary is manipulating GenAI agent behavior through natural language prompt injection or encoded payloads to bypass guardrails and execute unauthorized tool calls or API operations.

Brief

Why this hunt

Elastic Security Labs recently detailed how System 1 models detect prompt injection in Thinking fast about prompt injection: New System 1 models in Elastic. As organizations grant GenAI agents autonomy to call tools and access databases, prompt injection becomes more than a chat novelty; it becomes a vector for unauthorized tool execution and data exfiltration. This hunt moves beyond simple string matching to identify when an injection successfully hijacks an agent's behavior.

How the Hunt Flows

The first query lists every AWS Bedrock agent in the environment. This establishes the attack surface by identifying foundation models, account IDs, and agent statuses. By identifying which agents are active, an analyst focuses the search on high-value targets.

Next, two queries run simultaneously to find evidence of prompt manipulation in cloud API activity. The first scans logs for common injection strings like "ignore all instructions" or "developer mode". The second looks for specific encoded payloads and known hashes mentioned in the Elastic report, such as Base64-encoded instruction overrides.

After these searches, an analyst or an automated agent weighs the early signals. They determine if the observed strings show intentional instruction overrides or evasion attempts through encoding. This triage step narrows the focus to credible injection attempts.

The hunt then pivots to behavioral anomalies. A query calculates a baseline of tool usage per actor and identifies users exceeding 50 tool-related API calls. Large batches of tool requests from a single user often indicate automated or hijacked activity rather than standard human interaction.

Finally, a correlation phase links the injection verdicts with the tool volume spikes. This confirms if an injection was successful and led to actual tool misuse. If both signals align for a specific actor, the hunt routes to containment actions like revoking IAM credentials.

Blind Spots

CloudTrail Data Event Latency limits this hunt. If Data Events are not enabled for Bedrock, the request_attribute field may be truncated or missing, hiding the injection string from the logs. Additionally, AWS CloudTrail does not log the model's response body. The hunt cannot see if the agent refused the request, which is a key signal for identifying blocked but persistent exploit attempts.

Steps

  1. Query, scoping

    Identify AWS Bedrock agents

    Find the foundation models and agents currently configured in the environment to establish scope.

    sql, reads aws_bedrock_agent
    SELECT arn, agent_name, foundation_model, agent_status, account_idFROM aws_bedrock_agent

    What a hit looks like. A list of agents that could be targets for injection. Silence means no Bedrock agents are configured.

  2. Query, detection candidate

    Detect prompt injection strings

    Identify natural language strings used to override agent instructions in API calls.

    sql, reads hb_cloud_api_activity
    SELECT time, actor_user_name, request_attribute, api_operation, cloud_account_uidFROM hb_cloud_api_activityWHERE LOWER(api_service_name) LIKE '%bedrock%'  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || actor_user_name || ',') > 0)  AND (LOWER(request_attribute) LIKE '%ignore all%' OR LOWER(request_attribute) LIKE '%instruction override%' OR LOWER(request_attribute) LIKE '%developer mode%')  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A row indicates an explicit prompt injection attempt. Silence means no common override strings were found in the logged request attributes.

  3. Query, enrichment

    Detect encoded payloads and hashes

    Search for obfuscated content or hash strings used to bypass simple text filters.

    sql, reads hb_cloud_api_activity
    SELECT time, actor_user_name, request_attribute, api_operationFROM hb_cloud_api_activityWHERE LOWER(api_service_name) LIKE '%bedrock%'  AND (instr(request_attribute, '{{base64_payload}}') > 0 OR instr(request_attribute, '{{md5_ioc}}') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Specific indicators from the report appearing in Bedrock API traffic.

  4. Agent triage

    Weigh early-stage injection signals

    Assess whether the observed strings and encodings constitute a credible injection attempt.

  5. Query, baseline

    Detect anomalous tool invocation volume

    Corroborate injection attempts with subsequent behavioral anomalies in tool usage.

    sql, reads hb_cloud_api_activity
    SELECT actor_user_name, api_operation, COUNT(*) as call_count, MIN(time) as first_call, MAX(time) as last_callFROM hb_cloud_api_activityWHERE LOWER(api_service_name) LIKE '%bedrock%'  AND (LOWER(api_operation) LIKE '%invoke%' OR LOWER(api_operation) LIKE '%call%')  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY actor_user_name, api_operationHAVING call_count > 50ORDER BY call_count DESC

    What a hit looks like. A high-volume tool-request batch from a single user. Silence proves the absence of large automated tool misuse within the lookback.

  6. Agent triage

    Final correlation read

    Correlate injection attempts with subsequent tool misuse or refusals.

  7. Decision

    Route on verdict

    Route the hunt based on the final correlation result.

  8. Response action

    Revoke IAM access

    Contain the threat by revoking the credentials used to hijack the agent.

  9. Analyst task

    Analyst manual review

    Confirm the hijacking and review the impact of the tool misuse.

  10. Analyst task

    Close out

    Record findings and close the hunt.

# GenAI Agent Prompt Injection and Tool Hijacking

This hunt identifies attempts to hijack GenAI agents, specifically targeting AWS Bedrock. It correlates early-stage natural language injection attempts and encoded payloads with follow-on behavioral anomalies, such as unusually high tool invocation volume. The hunt uses a phased approach: first identifying vulnerable agents and injection attempts, then corroborating these with actual execution patterns across cloud API logs.

## detect-tool-volume-spikes
<!-- Detect anomalous tool invocation volume -->
Corroborate injection attempts with subsequent behavioral anomalies in tool usage.

```sqlite target=endpoint role=baseline params=(lookback_days=lookback_days)
~~~yaml
baseline:
  compare: prior_equal_window
  window: '{{lookback_days}}d'
expected: A high-volume tool-request batch from a single user. Silence proves the
  absence of large automated tool misuse within the lookback.
prevalence:
  by: actor_user_name
  key:
  - api_operation
  rare_below: 5
reads:
- actor_user_name
- api_operation
- time
- api_service_name
silence: evidence_of_absence
source: hb_cloud_api_activity
verified: dry-run
verified_at: '2026-11-24'
~~~
SELECT actor_user_name, api_operation, COUNT(*) as call_count, MIN(time) as first_call, MAX(time) as last_call FROM hb_cloud_api_activity WHERE LOWER(api_service_name) LIKE '%bedrock%' AND (LOWER(api_operation) LIKE '%invoke%' OR LOWER(api_operation) LIKE '%call%') AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY actor_user_name, api_operation HAVING call_count > 50 ORDER BY call_count DESC
```
