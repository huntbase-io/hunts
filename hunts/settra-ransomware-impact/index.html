Settra Ransomware Local Impact and Recovery Inhibition

Critical severity TLP:CLEAR Part 2 of 2 Research by Huntress Published 23 Sep 2026

Hypothesis

An adversary is executing Settra ransomware, using a domain-specific launcher and a BYOVD driver to disable defenses before inhibiting recovery and encrypting files.

Brief

Why this hunt

Huntress recently detailed a Settra ransomware variant in "Ready, Settra, Go: New Settra Ransomware Variant Deploys MeshAgent RMM" (https://www.huntress.com/blog/new-settra-ransomware-variant). This threat demonstrates a clear progression from gaining initial access to crippling local recovery options.

How the hunt flows

The hunt begins by inventorying active Windows hosts using the hb_devices surface. This scoping ensures the subsequent queries focus only on relevant endpoints where the ransomware is known to operate. The next phase looks for early-stage indicators. One query searches the hb_file_activity surface for the creation of gdrv.sys in common file paths. This vulnerable driver allows an attacker to gain kernel-level access and terminate antivirus or EDR processes that would otherwise block the encryption. Identifying this drop is a critical first step in flagging a high-severity intrusion. Simultaneously, another query identifies the execution of binaries named after the local domain on the hb_process_activity surface, typically with a _win64.exe suffix. This pattern is specific to the ransomware's deployment phase and helps filter out generic malware or automated tools. Following the early leads, the hunt searches for anti-recovery behaviors. It looks for rare commands involving reagentc /disable to turn off recovery environments and cipher /w: to wipe free space on the hb_process_activity surface. By baselining these commands across the fleet, the hunt flags instances where an attacker attempts to disable recovery partitions or wipe free space on only a few systems. This ensures that scheduled administrative tasks on servers do not trigger false positives. The final stage seeks evidence of successful impact on the hb_file_activity surface. It searches for artifacts like the .locked extension and the presence of the restore_files.txt ransom note. This correlates the preceding evasion and recovery inhibition with the actual encryption event, providing a complete attack timeline for responders.

What the hunt cannot see

This hunt lacks visibility into the specific instructions within diskpart scripts. While it flags the execution of diskpart, the exact partition changes remain hidden without the raw script content. Furthermore, if an adversary successfully kills the endpoint agent before it reports the driver drop or launcher execution, the hunt cannot see the compromise. There is also a risk of visibility loss if the attacker corrects typos in log paths which currently allow detection of event log clearing.

    Identify Windows host estate

    Scope the hunt to Windows endpoints where the Settra ransomware variant is known to operate.

    sql, reads hb_devices

    What a hit looks like. A list of active Windows hosts. Silence proves no Windows hosts have reported inventory within the lookback window.

  2. Query, triage

    BYOVD driver drop

    Find the creation of gdrv.sys, used by the attacker to disable security software.

    sql, reads hb_file_activity
    SELECT device_hostname, file_name, file_path, timeFROM hb_file_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND LOWER(file_name) = 'gdrv.sys'  AND activity_id = 1  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A row identifying the host and path where gdrv.sys was dropped. Silence is evidence of absence for this specific driver name.

  3. Query, detection candidate

    Settra launcher execution

    Identify the execution of the Settra launcher, which is typically named after the domain name.

    sql, reads hb_process_activity
    SELECT device_hostname, process_name, process_cmd_line, user_name, parent_process_name, timeFROM hb_process_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND (LOWER(process_name) LIKE '%_win64.exe' OR LOWER(process_cmd_line) LIKE '%_win64.exe')  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Processes identifying the launcher, user context, and host. Naming a binary after a domain string is a specific Settra pattern.

  4. Agent triage

    Early stage triage

    Assess whether the driver drop and launcher execution on the same host indicate the start of a Settra ransomware incident.

  5. Query, baseline

    Rare anti-recovery commands

    Find individual events of recovery inhibition commands that are rare across the fleet.

    sql, reads hb_process_activity
    SELECT device_hostname, user_name, process_name, process_cmd_line, timeFROM hb_process_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')  AND (LOWER(process_cmd_line) LIKE '%reagentc% /disable%' OR LOWER(process_cmd_line) LIKE '%cipher% /w:%' OR LOWER(process_cmd_line) LIKE '%wevtutil% cl %' OR LOWER(process_cmd_line) LIKE '%diskpart% /s %')  AND LOWER(process_cmd_line) IN (SELECT LOWER(process_cmd_line) FROM hb_process_activity WHERE (LOWER(process_cmd_line) LIKE '%reagentc% /disable%' OR LOWER(process_cmd_line) LIKE '%cipher% /w:%' OR LOWER(process_cmd_line) LIKE '%wevtutil% cl %' OR LOWER(process_cmd_line) LIKE '%diskpart% /s %') AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY LOWER(process_cmd_line) HAVING COUNT(DISTINCT device_hostname) < 3)

    What a hit looks like. A list of hosts running these commands where the activity is rare across the fleet. This allows pinning the behavior to a specific timeline and host identity.

  6. Query, triage

    Encrypted files and ransom notes

    Find the final evidence of encryption by searching for specific file extensions and the ransom note.

    sql, reads hb_file_activity

    What a hit looks like. Files renamed with .locked or .locked_wip extensions, or the creation of RESTORE_FILES.txt.

  7. Agent triage

    Final impact assessment

    Analyze all gathered evidence to determine if a Settra ransomware incident is confirmed.

  8. Decision

    Route on verdict

    Direct the workflow based on the agent's findings.

  9. Response action

    Isolate compromised host

    Halt the ransomware encryption process and prevent further spread.

  10. Analyst task

    Analyst incident review

    Review the evidence findings and coordinate recovery.

  11. Analyst task

    Hunt close-out

    Finalize documentation and update detection rules.

# Settra Ransomware Local Impact and Recovery Inhibition

This hunt follows the Settra ransomware attack chain on the endpoint, focusing on the transition from defense evasion to data destruction. It first identifies early indicators such as the drop of a vulnerable gdrv.sys driver and the execution of a domain-named launcher. The hunt then phases into a follow-on stage that correlates these leads with anti-recovery behaviors—disabling Windows Recovery, wiping free space, and clearing event logs—and the presence of encrypted file artifacts. This phased approach distinguishes malicious ransomware activity from legitimate administrative maintenance.
