# Endpoint Credential Harvesting and Ransomware Impact Hunt

Recently, Huntress published "Credential Theft: How Attackers Steal & Use Stolen Credentials" (https://www.huntress.com/blog/credential-theft-expanding-your-reach), which highlights the increasing efficiency of automated credential harvesting. Inspired by these observations, we have developed a hunt playbook designed to find the host-level footprints left behind when an attacker moves from an initial foothold to stealing secrets and, eventually, encrypting data.

### The Hypothesis
The hypothesis assumes an adversary has exploited an internet-facing vulnerability and is now active on the endpoint. They are either running infostealers to gather browser-saved secrets or dumping memory from the Local Security Authority Subsystem Service (LSASS) to move laterally. This activity often precedes the final, loud stage of a ransomware attack: mass file encryption. By joining these disparate signals, we can identify compromises that individual detection rules may miss.

### How the Hunt Flows
The hunt begins with scoping. We correlate critical vulnerabilities with assets confirmed to be internet-facing using the `hb_vulnerability_finding` and `hb_exposed_assets` surfaces. This narrows the field to high-risk targets. While the rest of the hunt can run fleet-wide, this initial correlation ensures we pay closest attention to the most likely entry points for an external threat actor.

We then pivot into behavioral checks. First, we look for rare binaries executing from user-writable paths like AppData or Public. Infostealers often land here to avoid the need for administrative privileges during initial execution. We specifically filter for binaries seen on fewer than three hosts across the estate to ignore common legitimate applications and focus on unique, suspicious artifacts.

Simultaneously, we monitor for credential dumping using native Windows components. Specifically, we look for `rundll32.exe` invoking `comsvcs.dll` with the `minidump` flag. This is a common "living off the land" technique used to dump LSASS memory without dropping custom malware, making it a reliable signal for credential harvesting that bypasses many simple file-based signatures.

The final behavioral check looks for impact. We monitor `hb_file_activity` for bursts of modifications or renames—defined as over 1,000 actions in a 30-minute window. While some developer tools or system updates might cause spikes, when this occurs on a host already flagged for rare binaries or vulnerability exposure, the confidence of an active ransomware event is high.

### What the Hunt Cannot See
There are inherent limitations to this approach. This hunt depends entirely on endpoint agent telemetry; if a host is unmanaged, it remains invisible to our process and file queries. Additionally, the credential dumping logic is focused on Windows-specific DLL exports. Attackers targeting Linux credentials or using kernel-level drivers to bypass standard DLL monitoring will not be captured by these specific queries.

### Why This Is a Hunt, Not a Detection
Detection rules often focus on a single atomic indicator, such as a known bad hash or a specific command-line string. While useful, these rules are prone to evasion. This hunt is designed to look for the intent and impact of an attacker's actions over time. By looking at the prevalence of a binary across the entire fleet and comparing that to the vulnerability status of the host, we identify anomalies that wouldn't necessarily trigger a high-severity alert on their own.

### How to Run It
This is an open `hunt.md` playbook. It can be imported into Huntbase or any hunt.md-aware runtime. It uses SQLite DSL to query standardized endpoint surfaces. The parameters allow you to adjust the lookback period and the threshold for file modifications, making it adaptable to different environment baselines. If your environment is particularly noisy, increasing the `min_file_actions` threshold can help filter out legitimate tools while still capturing the massive IOPS generated by modern encryption modules.
