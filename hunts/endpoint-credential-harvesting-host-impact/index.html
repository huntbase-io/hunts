Endpoint Credential Harvesting and Host Impact

An adversary has exploited an internet-facing vulnerability (T1190) and is now using local credential dumping or infostealers to harvest credentials before initiating a high-volume ransomware encryption event.

Brief

Recently, Huntress published "Credential Theft: How Attackers Steal & Use Stolen Credentials" (https://www.huntress.com/blog/credential-theft-expanding-your-reach), which highlights the increasing efficiency of automated credential harvesting. Inspired by these observations, we have developed a hunt playbook designed to find the host-level footprints left behind when an attacker moves from an initial foothold to stealing secrets and, eventually, encrypting data.

How the Hunt Flows

The hunt begins with scoping. We correlate critical vulnerabilities with assets confirmed to be internet-facing using the hb_vulnerability_finding and hb_exposed_assets surfaces. This narrows the field to high-risk targets. While the rest of the hunt can run fleet-wide, this initial correlation ensures we pay closest attention to the most likely entry points for an external threat actor.

We then pivot into behavioral checks. First, we look for rare binaries executing from user-writable paths like AppData or Public. Infostealers often land here to avoid the need for administrative privileges during initial execution. We specifically filter for binaries seen on fewer than three hosts across the estate to ignore common legitimate applications and focus on unique, suspicious artifacts.

Simultaneously, we monitor for credential dumping using native Windows components. Specifically, we look for rundll32.exe invoking comsvcs.dll with the minidump flag. This is a common "living off the land" technique used to dump LSASS memory without dropping custom malware, making it a reliable signal for credential harvesting that bypasses many simple file-based signatures.

The final behavioral check looks for impact. We monitor hb_file_activity for bursts of modifications or renames—defined as over 1,000 actions in a 30-minute window. While some developer tools or system updates might cause spikes, when this occurs on a host already flagged for rare binaries or vulnerability exposure, the confidence of an active ransomware event is high.

What the Hunt Cannot See

There are inherent limitations to this approach. This hunt depends entirely on endpoint agent telemetry; if a host is unmanaged, it remains invisible to our process and file queries. Additionally, the credential dumping logic is focused on Windows-specific DLL exports. Attackers targeting Linux credentials or using kernel-level drivers to bypass standard DLL monitoring will not be captured by these specific queries.

Why This Is a Hunt, Not a Detection

Detection rules often focus on a single atomic indicator, such as a known bad hash or a specific command-line string. While useful, these rules are prone to evasion. This hunt is designed to look for the intent and impact of an attacker's actions over time. By looking at the prevalence of a binary across the entire fleet and comparing that to the vulnerability status of the host, we identify anomalies that wouldn't necessarily trigger a high-severity alert on their own.

  1. Identify Vulnerable and Exposed Hosts

    Query · scoping

    Correlate critical vulnerabilities with known internet-facing assets to identify the highest-risk targets for initial exploitation.

    reads hb_vulnerability_findingsql
    SELECT v.device_uid, d.hostname AS device_hostname, v.cve_uid, v.affected_package_name, e.domain_or_ip AS exposed_as FROM hb_vulnerability_finding v JOIN hb_devices d ON v.device_uid = d.device_uid AND v.provider = d.provider JOIN hb_exposed_assets e ON (d.ip_address = e.ip_address OR d.hostname = e.domain_or_ip) WHERE v.severity_id >= 4 AND v.status != 'suppressed' AND v.collected_at >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A list of hosts that are both internet-exposed and carry critical vulnerabilities. Silence indicates no currently known overlap between exposed assets and unpatched findings.

  2. Rare Binaries in User-Writable Paths

    Query · baseline

    Detect infostealers by identifying rare processes executing from paths where users have write permissions, focusing on hosts identified in the scoping step.

    reads hb_process_activitysql
    SELECT device_hostname, process_path, process_name, COUNT(DISTINCT device_hostname) AS hosts, MIN(time) AS first_seen FROM hb_process_activity WHERE (LOWER(process_path) LIKE '%\\appdata\\%' OR LOWER(process_path) LIKE '%\\users\\public\\%') AND time >= datetime('now', '-{{lookback_days}} days') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) GROUP BY process_path, process_name HAVING hosts < 3 ORDER BY hosts ASC

    What a hit looks like. Binaries running from user paths that are unique to one or two hosts across the estate.

  3. LSASS Memory Dumping via Comsvcs

    Query · detection candidate

    Detect the use of rundll32 and comsvcs.dll to dump LSASS memory, a built-in method for credential harvesting.

    What a hit looks like. A specific command line execution. Zero rows indicates this specific technique was not observed on the monitored estate.

  4. High-Volume File Activity in 30m Buckets

    Query · enrichment

    Identify potential ransomware encryption by finding bursts of file modifications and renames within short windows.

    reads hb_file_activitysql
    SELECT device_hostname, actor_user_name, (unixepoch(time) / 1800) AS time_bucket_30m, COUNT(*) AS activity_count FROM hb_file_activity WHERE activity_id IN (3, 5) AND time >= datetime('now', '-{{lookback_days}} days') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) GROUP BY device_hostname, actor_user_name, time_bucket_30m HAVING activity_count > {{min_file_actions}}

    What a hit looks like. Spikes of file activity that exceed normal user background noise, suggesting automated encryption.

# Endpoint Credential Harvesting and Host Impact

This hunt identifies the host-level progression of a credential-theft campaign. It begins by correlating vulnerabilities with internet exposure, then branches to investigate three distinct endpoint behaviors: rare binaries executing from user-writable paths (infostealers), the use of comsvcs.dll for LSASS memory dumping, and volumetric file modification activity characteristic of ransomware encryption. By joining these disparate signals, the hunt identifies high-confidence host compromises that individual detection rules may miss.
