# Hunting UAT-10147 Post-Compromise Evasion and Persistence

The recent Cisco Talos report, [UAT-10147 integrates agentic AI into post-compromise operations](https://blog.talosintelligence.com/uat-10147-chinese-speaking-adversary-integrates-agentic-ai-into-post-compromise-operations/), highlights a shift in adversary behavior: the use of agentic AI to scale and automate post-compromise setup. While initial access typically targets vulnerabilities in software like IIS, Zimbra, or Telerik, the adversary's efficiency in establishing a foothold is driven by automated playbooks. We have published a new hunt design to identify these secondary phase operations.\n\nThe hypothesis for this hunt is that the adversary establishes persistence by disabling endpoint protections and creating masquerading scheduled tasks or rogue RDP accounts. Because these playbooks are likely generated by AI, they exhibit a structured workflow that can be identified by correlating evasion tactics with specific staging behaviors.\n\nThe hunt begins with scoping through `hb_software_inventory` to identify assets running vulnerable web server components. This ensures the investigation is focused on high-risk, internet-exposed systems where UAT-10147 is most likely to deploy its automated setup scripts.\n\nNext, we examine defense evasion by monitoring `hb_process_activity` and `hb_registry_activity`. The adversary specifically targets Windows Defender, using PowerShell commands like Add-MpPreference to exclude critical directories from scanning. We look for these modifications and the subsequent registry changes that confirm the exclusions have been applied. Blinding the local security agent is a prerequisite for their automated persistence setup.\n\nTo corroborate these findings, the hunt pivots to identifying persistence. We search the `hb_scheduled_job` surface for tasks with names like 'Google Chrome Start' that execute from unusual paths. This is coupled with stack-counting analysis of `hb_process_activity` in the C:\\ProgramData directory. By identifying rare binaries or batch scripts in this path, we can surface the staging payloads characteristic of the UAT-10147 workflow.\n\nFinally, we audit account management in `hb_process_activity` to detect unauthorized RDP provisioning. The adversary often adds local accounts to high-privilege groups to ensure long-term access. Correlating these account changes with Defender tampering and rare staging files provides a high-confidence signal of compromise.\n\nThis hunt has two primary blind spots. First, it relies on EDR telemetry from Windows hosts; assets without active monitoring or those running Linux will not be covered. Second, while the hunt targets known staging paths like ProgramData, any deviation by the adversary to less common directories may avoid detection by the current logic.\n\nThis is a hunt.md playbook. You can import it into Huntbase or any hunt.md-aware runtime to execute the queries and manage the investigation. This structured approach allows you to differentiate automated AI-driven setup from legitimate administrative activity through cross-surface correlation.
