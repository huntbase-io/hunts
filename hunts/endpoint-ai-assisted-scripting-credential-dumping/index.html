Brief

Why now

Recent research by Unit 42, "Attackers Expose Ongoing AI Tool Use Targeting Organizations in Latin America" (https://unit42.paloaltonetworks.com/ai-tool-use-targeting-latam-orgs/), highlights a shift in how adversaries use large language models to support their operations. Instead of just writing static malware, attackers use AI to generate troubleshooting scripts and iterate through execution failures in real-time. This hunt identifies these behaviors by looking for the trial-and-error patterns inherent in AI-assisted scripting.

How the hunt flows

The hunt begins by narrowing the fleet to Windows Servers and Domain Controllers. These hosts are the primary targets for the final stage of the attack: the theft of the Active Directory database (NTDS.dit). By focusing on these assets early, the analyst reduces noise from developer machines where script experimentation might be more common. An analyst uses the initial software inventory lead to populate the scope for subsequent queries. The first telemetry phase examines network and DNS traffic. A query identifies resolutions for specific DuckDNS subdomains like m-doxa-apodo.duckdns.org and general m-doxa prefixes reported in the campaign. Simultaneously, the hunt checks for outbound connections to attacker-controlled IPs and port 3000. Port 3000 often hosts the NextChat AI interface, which attackers use to interact with LLMs directly from their infrastructure to modify their scripts on the fly. The second telemetry phase moves to the endpoint. The hunt searches for rare process execution involving iterative names or AI-characteristic suffixes like _creative, _focused, or _careful. These names often result from the adversary prompting an LLM for different "styles" or "modes" of script output, or simply saving multiple versions (v1 through v9) as they debug their tools. The hunt stacks these results across the fleet to find scripts that appear on three or fewer hosts. This ensuring that legitimate corporate scripts do not drown out the signal. Next, the hunt looks for the "error" part of the trial-and-error process. The adversary frequently attempts to dump the SAM registry hive or NTDS.dit file using ntdsutil or reg save. Because these attempts often fail due to permissions or file locks, the attacker retries using volume shadow copies to bypass protections. The hunt flags repeated VSS creation commands and registry save operations on the previously identified servers. In the final phase, an analyst or agent synthesizes these leads. A high-confidence verdict requires a host to show both the infrastructure leads (DuckDNS or port 3000) and the behavioral artifacts (iterative scripts and credential dumping attempts). This correlation is what makes this a hunt rather than a simple detection; it separates a noisy "ntdsutil" alert from a confirmed, multi-stage intrusion. This synthesis ensures that even if the individual scripts are low-fidelity, their combination with known C2 infrastructure creates a high-fidelity lead.

What the hunt cannot see

The hunt has two primary blind spots. First, it cannot see execution on unmanaged WordPress or JBoss hosts where an endpoint agent is not installed. If the adversary uses these as their initial beachhead—as seen in the Latin American campaign—the hunt only begins once they move to managed Windows assets. Second, short DNS log retention may hide the infrastructure setup phase. If the intruder established their persistence months before the final data theft, the initial DNS resolutions may be missing from the lookback window.

# Endpoint AI-Assisted Scripting and Credential Dumping

This hunt identifies multi-stage intrusions where attackers leverage AI to generate troubleshooting and execution scripts. It follows the attack chain from early infrastructure setup and DuckDNS resolutions to the characteristic behavioral patterns of iterative script naming (v1-v9) and trial-and-error credential dumping via volume shadow copies. The hunt uses a phased approach to correlate infrastructure leads with rare endpoint execution behaviors.
