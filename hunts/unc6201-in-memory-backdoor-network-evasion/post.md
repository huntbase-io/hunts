# UNC6201: Hunting for SPA Backdoors on Dell RecoverPoint Appliances

Threat actors are increasingly targeting virtualized infrastructure and edge appliances where traditional EDR visibility is often limited. A recent report from Google Cloud, "UNC6201 exploiting a Dell RecoverPoint zero-day" (https://cloud.google.com/blog/topics/threat-intelligence/unc6201-exploiting-dell-recoverpoint-zero-day), details how the Silk Typhoon group (UNC6201) leverages vulnerabilities like CVE-2026-22769 to establish deep persistence. One of their most effective techniques is the use of Single Packet Authorization (SPA) combined with the GRIMBOLT backdoor.\n\nOur hypothesis for this hunt is that the adversary has modified the appliance's firewall configuration to implement SPA and is running a Native AOT-compiled backdoor from web-server directories, potentially operating as a deleted binary to evade file-based detection.\n\nThe hunt begins by scoping your environment for Dell RecoverPoint appliances or hosts running related Dell software. Since the target is specific to these appliances, focusing the behavioral analysis here reduces the noise inherent in broad network telemetry. If no Dell software is indexed, the hunt can be run across all Linux-based servers to look for the same patterns of network evasion.\n\nThe second phase examines the network and firewall layer. We look for process activity involving the iptables utility, specifically searching for rules that use hex-string matching or redirection to port 10443. This is a primary indicator of SPA, which allows an attacker to send a specific packet to open a hidden listener. We simultaneously check for active listeners on port 10443 to identify backdoors that are currently staged or active. Even if the rule was deleted, the historical process log of the iptables command remains a durable signal.\n\nThe third phase focuses on process execution. We triage root-level processes running from sensitive paths such as /home/kos/ or Tomcat library directories. A key indicator here is the 'on_disk' status; if a process is running but its backing binary has been deleted, it suggests a memory-resident backdoor like GRIMBOLT or BRICKSTORM. Native AOT-compiled binaries are often used in these campaigns to minimize dependencies and evade signature-based tools.\n\nThere are specific blind spots to consider. This hunt may miss iptables modifications if they were applied and immediately reverted before a telemetry snapshot occurred, or if the adversary used shell scripts that cleaned their own tracks. Furthermore, the creation of "Ghost NICs" on ESXi hosts—a management-plane action—is not visible through standard endpoint process or network surfaces. These require dedicated ESXi audit logs which are outside the scope of this particular playbook.\n\nThis is published as a hunt.md playbook. You can import it into Huntbase or any runtime that supports the hunt.md format to begin the scoping and behavioral analysis. Because SPA is specifically designed to be invisible to traditional port scanners, this hunt relies on the correlation of endpoint-level configuration changes and process context to find what network security tools cannot see.
