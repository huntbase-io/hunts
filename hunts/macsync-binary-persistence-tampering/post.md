# MacSync Binary Persistence and Crypto Wallet Application Tampering

### Why this hunt matters This hunt cites the Huntress research MacSync Stealer: How a Google Search for Claude Led to a macOS Infostealer (https://www.huntress.com/blog/fake-claude-macsync). The report describes a campaign where users download fake software that drops a persistent Mach-O RAT targeting credentials and crypto assets. This hunt focuses on the post-infection binary stages that established security controls often overlook. ### The Hypothesis The adversary establishes long-term persistence on a macOS host by installing a Mach-O RAT via a custom LaunchAgent and uses specialized capture agents to bypass TCC permissions and phish for crypto wallet recovery phrases. ### How the hunt flows The first phase baselines LaunchAgent activity in the user's library directory. The query identifies agents that appear on fewer than three hosts across the fleet. This targets the RAT's persistence mechanism, which often mimics legitimate software updater names but remains unique to the individual victim. Once the analyst identifies lead hosts, the hunt checks for network command and control. It searches for persistent WebSocket connections to known C2 infrastructure on port 8443. This provides a secondary indicator of infection that does not rely on the initial loader's polymorphic file name or hash. The third phase examines process execution for specific TCC-bypass behavior. The hunt targets capture helpers running with the --tcc-only and -o flags. These specific flag combinations are used by the malware to automate screen recording for credential theft and are rarely seen in legitimate software applications. Simultaneously, the hunt searches for file system artifacts created during the exfiltration phase. It looks for the hidden .mpwd credential file and the osalogging.zip archive in temporary directories. These hardcoded file names are strong indicators of successful credential harvesting and staging for theft. The final phase monitors the execution of common crypto wallet applications on the suspected hosts. By correlating the launch of software like MetaMask or Ledger with the previous indicators, the analyst confirms the final stage of the adversary's intent to rotate seeds or steal funds. ### Blind Spots This hunt relies on endpoint telemetry from managed devices and cannot observe activity on unmanaged macOS hosts. While it flags suspicious command-line parameters for screen capture, it cannot confirm if the user granted the TCC permission without access to the Unified Log Facility. Additionally, the TLS-encrypted WebSocket channel prevents the hunt from inspecting the specific commands sent or the volume of data exfiltrated. ### How to run this hunt This hunt is a hunt.md playbook. You can import it into Huntbase or any hunt.md-aware runtime. Start by running the baseline query to identify rare LaunchAgents, then use the identified lead hostnames to filter the subsequent network, file, and process checks.
