Brief

Strategic Intel Theft

A recent report from ESET Research, Gorbag: Orcs at the border harvesting intelligence from Ukraine, describes a targeted intelligence-gathering campaign. The adversary, likely Russia-aligned, focuses on Ukrainian justice and defense sectors to harvest credentials and VPN configurations. Their toolkit, including BeautyStealer, operates with a 'one-pass' philosophy: access the data, archive it, send it, and delete the evidence. We designed this hunt to find this specific progression of behaviors across an enterprise fleet.

How the Hunt Flows

The lead query identifies non-browser processes that read sensitive browser credential databases or VPN configuration files. It targets SQLite databases for Chrome and Edge, alongside OpenVPN and Cisco configuration files. A hit here indicates that a process other than the legitimate application is interested in identity secrets.

Once the hunt identifies suspicious access, it executes two parallel queries to build evidence. The first branch looks for rare process behaviors, specifically the creation of RAR or ZIP archives and file deletions within the ProgramData directory. This pattern matches the staging and cleanup behavior observed in BeautyStealer infections. The hunt stacks these events by host count to highlight outliers.

The second parallel branch examines network telemetry. It matches outbound connections against known command-and-control (C2) IPs and domains provided in the ESET report. It also flags any process communicating with the Telegram API (api.telegram.org), which the actor uses as a convenient, encrypted exfiltration channel.

Finally, an analyst or automated agent weighs these signals. A host where a rare process read a browser database, created a ZIP file, and then connected to Telegram represents a confirmed intrusion. This multi-stage approach ensures that the noise of legitimate administrative tools does not drown out the actual threat.

Blind Spots

This hunt relies on specific telemetry. If the environment does not have file read-access auditing enabled for user profile paths, the lead query will return no results. Without this visibility, unauthorized access to SQLite databases remains invisible. Additionally, while we identify traffic to Telegram, the use of RC4 encryption over HTTPS prevents us from seeing exactly what data was stolen without full SSL inspection.

Running the Hunt

This hunt is available as an open hunt.md playbook. You can import it directly into Huntbase or any other hunt.md-aware runtime. It uses a 14-day lookback by default and allows you to scope the search to specific high-value hosts or departments most likely to be targeted by Gorbag.

Steps

  1. Suspicious browser and VPN data access

    Query · detection candidate

    Identify non-browser processes reading sensitive credential databases or VPN configurations as a lead for data theft.

    reads hb_file_activitysql
    SELECT device_hostname, process_name, file_path, time FROM hb_file_activity WHERE activity_id = 2 AND (LOWER(file_path) LIKE '%\google\chrome\user data%\login data' OR LOWER(file_path) LIKE '%\microsoft\edge\user data%\login data' OR LOWER(file_path) LIKE '%\google\chrome\user data%\cookies' OR LOWER(file_path) LIKE '%.ovpn' OR LOWER(file_path) LIKE '%.pcf' OR LOWER(file_path) LIKE '%\etc\openvpn%') AND (LOWER(process_name) NOT LIKE '%\chrome.exe' AND LOWER(process_name) NOT LIKE '%\msedge.exe' AND LOWER(process_name) NOT LIKE '%\vpn.exe' AND LOWER(process_name) NOT LIKE '%\browser.exe') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A row names a process that has no business reading browser or VPN secrets. Silence suggests no such unauthorized access occurred via this vector.

  2. Rare archiving and cleanup activity

    Query · baseline

    Find rare processes creating archives or performing cleanup in ProgramData, characteristic of BeautyStealer.

    reads hb_file_activitysql
    SELECT LOWER(process_name) AS process, COUNT(DISTINCT device_hostname) AS host_count, COUNT(*) AS event_count, MIN(time) AS first_seen FROM hb_file_activity WHERE ((activity_id = 1 AND (LOWER(file_path) LIKE '%.rar' OR LOWER(file_path) LIKE '%.zip' OR LOWER(file_path) LIKE '%.7z')) OR (activity_id = 4 AND LOWER(file_path) LIKE 'c:\programdata\%')) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY 1 HAVING host_count <= 3 ORDER BY host_count ASC

    What a hit looks like. A rare process creating archives or deleting files in common malware staging paths. Frequent processes are likely legitimate software.

  3. Connections to exfiltration infrastructure

    Query · triage

    Match network traffic against known Gorbag infrastructure or the Telegram API used for exfiltration.

    reads hb_network_connectionsql

    What a hit looks like. Traffic to specific IPs or the Telegram API linked to a suspicious process confirms exfiltration.

    Agent triage

# Gorbag: Browser Data Harvesting and Exfiltration

This hunt identifies the one-pass data harvesting pattern of BeautyStealer and Prime ReverseShell, as observed in attacks against Ukrainian administrations and defense sectors. It begins by identifying unauthorized access to browser credential databases and VPN configurations. The hunt then corroborates this behavior using two parallel queries: one that identifies rare archiving and cleanup activity across the fleet, and another that matches network traffic against known exfiltration infrastructure and the Telegram API. Finally, an agent weighs the combined evidence to identify hosts where intelligence harvesting has occurred.
