Storm-2570 Data Exfiltration and Ransomware Impact

An intruder is exfiltrating staged directories and Active Directory database fragments using synchronization tools before deploying a ransomware payload for mass encryption.

Brief

Why now

Microsoft recently detailed Storm-2570's consistent tradecraft in 'Beyond the ransomware: Tracking Storm-2570’s consistent tradecraft across deployments' (https://www.microsoft.com/en-us/security/blog/2026/09/24/beyond-ransomware-tracking-storm-2570-consistent-tradecraft-across-deployments/). While their specific ransomware variants change, their pre-impact behaviors—staging and exfiltration—remain predictable. This hunt focuses on the final stages where data leaves the environment and encryption begins.

How the hunt flows

The triage phase searches for the execution of common synchronization tools like rclone and s5cmd. It specifically looks for process arguments involving Active Directory fragments (ntds.dit) or batch scripts designed to enable RDP, which the adversary uses to maintain access during the final impact. The second phase runs two queries in parallel to measure the impact. One query attributes outbound network traffic to specific processes by joining endpoint socket states with flow logs, filtering for transfers exceeding 100MB. The other query monitors file system activity for bursts of modifications or renames, identifying processes that touch more than 500 files in a short window. Finally, the hunt synthesizes these signals. A host showing both high-volume data transfer from a synchronization tool and rapid file modification provides a high-confidence indicator of active ransomware.

What the hunt cannot see

This hunt depends on network flow logs to calculate total transfer volumes; without these, the analyst cannot accurately attribute exfiltration size to a process. It also assumes encryption occurs via standard file system APIs. If the adversary uses low-level disk access or custom drivers to bypass the kernel-level file monitor, the burst activity might remain hidden.

    Query · triage

    Find the launch of synchronization tools or commands that stage the Active Directory database and RDP enablement scripts.

    What a hit looks like. Hits identify the host, user, and specific staging or exfiltration tool used. Silence means no known synchronization or database staging binaries were seen.

  2. High volume outbound traffic

    Query · enrichment

    Attribute network transfer volume to specific processes by joining endpoint socket states with flow logs.

    reads hb_network_connectionsql
    SELECT e.device_hostname, e.process_name, SUM(f.traffic_bytes) AS total_bytes_sent FROM hb_network_connection e JOIN hb_network_connection f ON e.src_endpoint_ip = f.src_endpoint_ip AND e.src_endpoint_port = f.src_endpoint_port AND e.dst_endpoint_ip = f.dst_endpoint_ip AND e.dst_endpoint_port = f.dst_endpoint_port AND e.protocol = f.protocol WHERE e.state_kind = 'live' AND f.state_kind = 'log' AND f.direction = 'outbound' AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || e.device_hostname || ',') > 0) AND f.time >= datetime('now', '-{{lookback_days}} days') GROUP BY e.device_hostname, e.process_name HAVING total_bytes_sent > 104857600

    What a hit looks like. A hit shows a process that has transferred over 100MB of data. Correlate these results with the exfiltration tools found in the lead query.

  3. Ransomware file activity bursts

    Query · detection candidate

    Identify processes that are performing mass file creations, modifications, or renames on the target hosts.

    reads hb_file_activitysql
    SELECT device_hostname, process_name, activity_name, COUNT(*) AS event_count, MIN(time) AS start_time, MAX(time) AS end_time FROM hb_file_activity WHERE activity_id IN (1, 3, 5) AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND ('{{scope_processes}}' = '' OR instr(',' || '{{scope_processes}}' || ',', ',' || LOWER(process_name) || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY device_hostname, process_name, activity_name HAVING event_count > 500

    What a hit looks like. A hit shows a process modifying or renaming hundreds of files in a short window. This is the primary indicator of encryption.

  4. Evaluate impact and exfiltration

    Agent triage

    Synthesize the results from tool execution, network volume, and file activity to confirm a ransomware attack.

  5. Route on impact verdict

    Decision

    Direct the workflow to immediate host isolation if malicious ransomware behavior is confirmed.

  6. Isolate host

    Response action

    Halt further encryption and data exfiltration by isolating the compromised device.

  7. Review suspicious impact evidence

    Analyst task

    Manually validate suspicious activity that did not trigger immediate isolation.

  8. Remediation and evidence capture

    Analyst task

    Finalize the incident by identifying the specific ransomware variant and capturing evidence.

Blind spots

  • Needs hb_network_connection flow log provider (state_kind = log). A negative result does not prove exfiltration did not occur; it only proves it was not seen on the flow surface. It would answer the total volume of data exfiltrated by a specific process.
  • Needs kernel-level file monitor on every host. Advanced ransomware may use drivers or low-level disk access to encrypt data without generating standard file activity rows. It would answer whether encryption is occurring via APIs that bypass standard activity logging.

# Storm-2570 Data Exfiltration and Ransomware Impact

This hunt targets the final, high-impact stages of a Storm-2570 intrusion. It first identifies the execution of exfiltration tools, the staging of the NTDS database, and the use of RDP enablement scripts. It then attributes large network outbound transfers to specific processes by joining endpoint socket states with network flow logs. Finally, it corroborates these signals with rapid file modification bursts to identify active ransomware events.

## exfil-tool-execution
<!-- Exfiltration tool and staging activity -->
