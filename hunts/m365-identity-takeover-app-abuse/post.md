# Hunting M365 Session Hijacking and Privileged Application Abuse

### Why This Hunt Matters  Attackers are shifting away from traditional exploits to focus on identity-based techniques. The Huntress article "Three Attacks, Zero Exploits in Microsoft 365" (https://www.huntress.com/blog/three-attacks-zero-exploits-microsoft-365) demonstrates how adversaries bypass MFA by hijacking active sessions. These attacks often culminate in the modification of cloud-native permissions to maintain long-term access. This hunt provides a structured way to look for those footprints in Entra ID and M365 audit logs.   ### Hypothesis  An adversary hijacks a legitimate M365 session via a device-code flow or session token theft. The actor then modifies MFA settings to establish a persistence mechanism and abuses over-permissioned applications to escalate their privileges to a Global Administrator role.   ### How the Hunt Flows  The hunt begins with a scoping phase to identify all privileged identities in the tenant. The first query lists active users holding administrative roles. This creates a list of high-value targets. Focusing on these accounts ensures the most efficient use of analyst time during the triage process.   Next, the hunt splits into two parallel tracks to identify initial compromise signals. The first track searches for sign-in activity using the device-code flow. It specifically identifies the Azure CLI application ID or signs of phishing platforms like EvilTokens. Simultaneously, the second track identifies modifications to authentication methods, such as an actor adding a new MFA device to a compromised account to ensure persistence.   An analyst or automated agent then correlates these findings. The hunt compares the timing between suspicious logons and MFA modifications. A successful match provides high confidence that an account takeover occurred. This correlation step reduces the noise generated by legitimate users changing their own MFA settings during normal business operations.   The final phase examines the tenant for privilege escalation. The hunt identifies rare users who create new application secrets or assign the Global Administrator role to themselves or other identities. By baselining these actions against known, authorized administrative activity, the hunt isolates the specific moment a beachhead account gains full control of the environment.   ### Blind Spots  This hunt depends on the availability of the Microsoft 365 Unified Audit Log. If a tenant has not enabled advanced auditing or if the activity occurred outside the standard 90-day retention window, the hunt will not find the necessary records. Furthermore, the hunt cannot see the local execution of token theft tools on an endpoint if that device lacks a managed security agent. It only detects the resulting cloud-side behavior.   ### How to Run This Hunt  This hunt is an open hunt.md playbook. It uses a phased approach to pivot across authentication logs and cloud audit data. You can import this playbook into Huntbase or any hunt.md-aware runtime. Analysts can use the provided parameters to scope the investigation to specific users or extend the lookback window as needed for a thorough forensic review.
