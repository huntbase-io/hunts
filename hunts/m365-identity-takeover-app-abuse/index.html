M365 Identity Takeover and Application Abuse

High severity TLP:CLEAR Part 2 of 2 Research by Huntress Published 27 Nov 2026

Hypothesis

An attacker has hijacked an M365 session via device-code flow or token theft, modified MFA for persistence, and abused over-permissioned applications to escalate to Global Administrator.

Brief

Why This Hunt Matters

Attackers are shifting away from traditional exploits to focus on identity-based techniques. The Huntress article "Three Attacks, Zero Exploits in Microsoft 365" (https://www.huntress.com/blog/three-attacks-zero-exploits-microsoft-365) demonstrates how adversaries bypass MFA by hijacking active sessions. These attacks often culminate in the modification of cloud-native permissions to maintain long-term access. This hunt provides a structured way to look for those footprints in Entra ID and M365 audit logs.

How the Hunt Flows

The hunt begins with a scoping phase to identify all privileged identities in the tenant. The first query lists active users holding administrative roles. This creates a list of high-value targets. Focusing on these accounts ensures the most efficient use of analyst time during the triage process.

Next, the hunt splits into two parallel tracks to identify initial compromise signals. The first track searches for sign-in activity using the device-code flow. It specifically identifies the Azure CLI application ID or signs of phishing platforms like EvilTokens. Simultaneously, the second track identifies modifications to authentication methods, such as an actor adding a new MFA device to a compromised account to ensure persistence.

An analyst or automated agent then correlates these findings. The hunt compares the timing between suspicious logons and MFA modifications. A successful match provides high confidence that an account takeover occurred. This correlation step reduces the noise generated by legitimate users changing their own MFA settings during normal business operations.

The final phase examines the tenant for privilege escalation. The hunt identifies rare users who create new application secrets or assign the Global Administrator role to themselves or other identities. By baselining these actions against known, authorized administrative activity, the hunt isolates the specific moment a beachhead account gains full control of the environment.

Blind Spots

This hunt depends on the availability of the Microsoft 365 Unified Audit Log. If a tenant has not enabled advanced auditing or if the activity occurred outside the standard 90-day retention window, the hunt will not find the necessary records. Furthermore, the hunt cannot see the local execution of token theft tools on an endpoint if that device lacks a managed security agent. It only detects the resulting cloud-side behavior.

Steps

  1. Query, scoping

    Scope privileged Azure AD identities

    Identify active privileged accounts to focus the investigation on the most high-impact potential takeover targets.

    sql, reads hb_users
    SELECT username, email, privileged, mfa_enabled, last_sign_inFROM hb_usersWHERE provider = 'azure_ad'  AND status = 'active'  AND privileged = 'true'

    What a hit looks like. A list of privileged accounts. A lack of MFA on these accounts is an immediate security gap.

  2. Query, triage

    Device code flow sign-in activity

    Identify logons via the device code flow, which is used by Phishing-as-a-Service platforms like EvilTokens to capture sessions.

    sql, reads hb_auth_signin
    SELECT src_endpoint_ip, src_endpoint_hostname, actor_user_name, client_app, timeFROM hb_auth_signinWHERE provider = 'm365'  AND (('{{device_code_app_id}}' <> '' AND app_id = '{{device_code_app_id}}') OR client_app LIKE '%DeviceCode%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || src_endpoint_hostname || ',') > 0 OR instr(',' || '{{scope_hosts}}' || ',', ',' || src_endpoint_ip || ',') > 0)  AND ('{{scope_users}}' = '' OR instr(',' || '{{scope_users}}' || ',', ',' || actor_user_name || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Logons from unexpected IPs using the device code flow. Zero results proves absence for the given window and parameters.

  3. Query, enrichment

    MFA method modifications

    Detect changes to authentication methods that attackers use to secure persistent access to a compromised account.

    sql, reads hb_cloud_api_activity
    SELECT actor_user_name, target_user_name, api_operation, target_modified_property_names, timeFROM hb_cloud_api_activityWHERE provider = 'm365'  AND api_operation IN ('Update user', 'Set-MsolUser')  AND instr(LOWER(target_modified_property_names), 'strongauthenticationmethod') > 0  AND ('{{scope_users}}' = '' OR instr(',' || '{{scope_users}}' || ',', ',' || actor_user_name || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A record of a user modifying their own or another user's MFA methods. This is suspicious if it occurs near a device-code logon.

  4. Agent triage

    Assess initial takeover probability

    Evaluate the sign-in and MFA evidence together to determine if an account takeover has occurred.

  5. Query, baseline

    Detect application and role escalation

    Identify rare users performing administrative role assignments or creating application secrets, which signals the transition from beachhead to full tenant control.

    sql, reads hb_cloud_api_activity
    SELECT actor_user_name, api_operation, COUNT(DISTINCT target_user_name) AS targets, MIN(time) AS first_seenFROM hb_cloud_api_activityWHERE provider = 'm365'  AND (api_operation = 'Add password' OR (api_operation = 'Add member to role' AND (instr(LOWER(target_modified_property_new_values), 'company administrator') > 0 OR instr(LOWER(target_modified_property_new_values), 'global administrator') > 0)))  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY actor_user_name, api_operationORDER BY targets ASC

    What a hit looks like. Rare users creating app secrets or assigning Global Admin roles. If only one user is doing this who isn't a known admin, it is highly malicious.

  6. Agent triage

    Final takeover verdict

    Synthesize the entire attack chain from initial access through to privilege escalation.

  7. Decision

    Route on takeover verdict

    Direct the hunt toward containment for high-confidence compromises or manual review for ambiguous signals.

  8. Response action

    Revoke tokens and application secrets

    Evict the attacker by invalidating all active sessions and removing persistent application-level access.

  9. Analyst task

    Manual analyst review

    Conduct a deep-dive review of all cited evidence to confirm the scope of the compromise and tune detection rules.

  10. Analyst task

    Close out hunt

    Finalize the hunt and record the baseline for future periodic reviews.

# M365 Identity Takeover and Application Abuse

This hunt targets the cloud-plane aftermath of identity compromise. It identifies the EvilTokens device-code flow pattern and subsequent persistence actions in Entra ID. The hunt uses a phased approach: it first isolates suspicious logins and MFA modifications, then examines high-impact behaviors like application secret creation and privileged role assignments. This progression helps analysts distinguish routine administrative changes from a coordinated account takeover attempt.
