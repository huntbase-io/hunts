Anomalous Cloud Identity and API Abuse (TeamPCP)

An adversary is leveraging credentials stolen through DevOps supply-chain injections to perform rapid automated secret validation and cloud discovery from known VPN/VPS hosting nodes.

Brief

Background. The TeamPCP group recently gained attention for targeting the DevOps supply chain, specifically injecting malicious code into popular tools like Trivy, KICKS, and LiteLLM. A detailed analysis by Wiz in their article Tracking TeamPCP: post-compromise attacks seen in the wild highlights how these attackers pivot from harvested secrets to cloud environments for discovery and exfiltration. ### The Hypothesis. Our hypothesis is that an adversary is leveraging these stolen credentials to perform rapid, automated secret validation and cloud service enumeration, often operating from specific VPN or VPS providers such as Mullvad and InterServer. ### Scoping the Hunt. The hunt begins by defining the blast radius. We scope the environment by identifying hosts where the targeted DevOps packages are installed. This uses software inventory surfaces to find specific versions of Trivy and LiteLLM that served as the initial infection vector. ### Detecting Adversary Authentication. Once the scope is established, we look for direct evidence of identity abuse. We pivot to authentication logs to find sign-ins to cloud providers or GitHub that originate from the IP ranges associated with TeamPCP infrastructure. This is a high-confidence step because these identities should typically not be authenticating from known VPN nodes. ### Identifying Offensive Tooling. Simultaneously, we analyze HTTP activity for specific offensive tool signatures. The group utilizes TruffleHog for secret validation and a custom tool called Nord Stream for GitHub management. By stack-counting rare user-agents and filtering for these specific strings on our scoped hosts, we can differentiate malicious automation from legitimate CI-CD processes. ### Cloud Discovery Patterns. The discovery phase is identified through AWS IAM telemetry. We look for principals that access an unusually wide range of management services such as IAM, Secrets Manager, and RDS within a short time window. This reflects the broad enumeration pattern documented in the research. ### Corroborating Exfiltration. Finally, we corroborate potential exfiltration by examining DNS activity. We look for queries to specific domains like git.clone and other researcher-identified exfiltration targets, specifically coming from the workstations identified in our initial scoping phase. ### Blind Spots. There are notable blind spots. Without detailed cloud audit logging, we may see that a principal performed discovery but not necessarily which specific secret values were retrieved. Additionally, if the malicious activity occurs on non-enrolled, ephemeral CI-CD runners, our endpoint-based HTTP and process visibility will be limited. ### How to Run. This is published as an open hunt.md playbook. You can import it into Huntbase or any runtime that supports the hunt.md format to begin investigating your DevOps and cloud surfaces.

# Anomalous Cloud Identity and API Abuse (TeamPCP)

Following the compromise of Trivy, KICKS, and LiteLLM, the TeamPCP group utilizes harvested secrets to validate access and enumerate cloud services. This hunt identifies hosts with targeted DevOps tools, identifies authentication from known adversary infrastructure (Mullvad, InterServer), and correlates this with the use of offensive tools like TruffleHog and Nord Stream across cloud and GitHub surfaces. It specifically pivots from identified suspicious software footprints to reduce noise from legitimate automation.
