Apex Accelerator npm supply-chain delivery

An adversary targets developer workstations by tricking users into installing malicious npm packages that masquerade as Web3 auditing tools to execute platform-specific backdoors from within the project directory.

Brief

Why now

Elastic Security Labs recently published research titled Auditing the auditor: Unmasking Apex Accelerator. The report details a campaign targeting crypto start-ups and Web3 developers through malicious npm packages. These packages, such as @apexacc/cli, appear to be legitimate auditing tools but actually deploy platform-specific backdoors. This hunt provides a structured way to identify these packages and any subsequent execution on developer workstations.

How the hunt flows

The hunt begins with a scoping phase focused on software inventory. A query against hb_software_inventory searches for the specific package names identified in the research and looks for the presence of hidden .apex directories within node_modules. This first step identifies which hosts and users are potential leads without requiring expensive process telemetry from the entire fleet.

An analyst then evaluates these initial leads. If the software inventory shows no signs of the Apex Accelerator packages, the hunt concludes to save resources. If a lead is confirmed, the hunt gates into a more intensive behavioral analysis phase focused only on the suspicious hosts.

The behavioral phase runs two queries in parallel to corroborate the infection. The first query searches hb_process_activity for any executable binary—such as PE files on Windows or Mach-O files on macOS—that launches from a node_modules directory. This generalized search captures the loader even if the adversary renames it. The second query examines hb_network_connection to find outbound network callbacks initiated by these same processes, identifying the C2 channel.

Finally, the analyst triages the correlated evidence. By combining the inventory lead with confirmed execution and network activity, the analyst reaches a high-confidence verdict. If the activity is malicious, the hunt provides a direct action to isolate the host and preserve its memory for deeper forensic review.

What the hunt cannot see

This hunt has two primary blind spots. First, local npm installations may not always appear in global software inventory scanners, depending on how the endpoint agent collects data. Second, the hunt relies on high-fidelity process attribution for network flows. If the telemetry cannot reliably link a network connection to the specific binary running in a project directory, the analyst must manually bridge that gap during triage.

  4. Generalized binary execution from node_modules

    Query · detection candidate

    Identify any executable binary (PE or Mach-O) launched from within a node_modules directory tree. This generalized search captures renamed loaders or supporting components.

    reads hb_process_activitysql
    SELECT device_hostname, process_name, process_path, process_cmd_line, user_name, COUNT(*) as runs, MIN(time) as first_seen FROM hb_process_activity WHERE (LOWER(process_path) LIKE '%\\node_modules\\%' OR LOWER(process_path) LIKE '%/node_modules/%') AND (LOWER(process_path) LIKE '%.exe' OR LOWER(process_path) LIKE '%.node' OR on_disk = 0 OR (on_disk = 1 AND process_name NOT LIKE '%.%')) AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY device_hostname, process_name, process_path, process_cmd_line, user_name

    What a hit looks like. An executable seen on very few machines launched from a project dependency directory. Fleet-wide presence would suggest a legitimate developer tool.

  5. Network activity from node_modules processes

    Query · enrichment

    Identify external network connections initiated by processes running from node_modules. This effectively pivots from the execution leads to find callbacks without relying on a static domain list.

    reads hb_network_connectionsql
    SELECT device_hostname, process_name, process_path, dst_endpoint_ip, dst_endpoint_port, COUNT(*) as connections, MIN(time) as first_seen FROM hb_network_connection WHERE (LOWER(process_path) LIKE '%\\node_modules\\%' OR LOWER(process_path) LIKE '%/node_modules/%') AND disposition = 'Allowed' AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY device_hostname, process_name, process_path, dst_endpoint_ip, dst_endpoint_port

    What a hit looks like. Network connections to external IPs from binaries located in node_modules project trees.

    Agent triage

    Correlate the package installation leads with generalized binary execution and network callbacks into a single verdict per host.

  7. Route on triage verdict

    Decision

    Escalate malicious findings to containment or route suspicious hits for human review.

  8. Isolate compromised host

    Response action

    Stop further command execution and exfiltration by isolating the affected host.

  9. Analyst forensic review

    Analyst task

    Review findings and prepare for incident response.

  10. Close out hunt

    Analyst task

    Record the results and confirm the absence of these specific packages.

Blind spots

  • Needs hb_software_inventory coverage for local node_modules. Local npm installations might not be picked up by global inventory scanners, and the lack of installation timestamps in the inventory surface prevents temporal correlation with execution events. It would answer whether a package was installed locally in a project directory rather than globally.
  • Needs hb_network_connection with process path enrichment on every flow. Without high-fidelity process attribution on network connections, identifying callbacks from binaries in project directories relies on endpoint telemetry that may be incomplete. It would answer whether a network flow initiated by a project-path binary is attributed correctly.

# Apex Accelerator npm supply-chain delivery

The adversary targets crypto start-ups by distributing backdoored npm packages. The hunt is gated on a software inventory lead to minimize telemetry costs. The hunt identifies these packages in software inventory, then fans out to examine generalized binary execution from within node_modules directories and associated network callbacks. The analyst reviews the correlated evidence to confirm the intrusion.
