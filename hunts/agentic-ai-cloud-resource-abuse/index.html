Agentic AI Cloud Resource Abuse (ARTEX)

An adversary is using an agentic AI framework to automate cloud discovery and data exfiltration, identified by rapid, self-correcting API probing patterns and service principal abuse from campaign-associated infrastructure.

Brief

The Shift to Agentic Automation

Microsoft recently detailed how threat actors use agentic AI tooling to find and abuse exposed secrets in their report, "Threat actors use agentic AI tooling to find and abuse exposed secrets" (https://www.microsoft.com/en-us/security/blog/2026/11/05/threat-actors-use-agentic-ai-tooling-to-find-and-abuse-exposed-secrets/). Unlike traditional scripts, agentic frameworks like ARTEX can autonomously navigate cloud environments, troubleshoot their own access errors, and exfiltrate data with minimal human intervention. This speed and adaptability require a move from static indicators to behavioral hunting.

How the Hunt Flows

The hunt begins by establishing the scope of active reporting devices within Entra ID authentication logs. An analyst uses the hb_auth_signin surface to identify the hostnames and providers involved in recent authentication events, ensuring the log pipeline is healthy before proceeding to deeper analysis. Next, the process runs two parallel checks for initial compromise. The first query looks for successful sign-ins originating from known ARTEX campaign IPs or Tor exit nodes. The second query baselines cloud discovery behaviors, identifying any identities performing high-frequency resource enumeration, such as listing subscriptions or getting multiple storage account keys in a short window. The core of this hunt focuses on the unique behavioral signature of AI agents: adaptive API troubleshooting. The query monitors the hb_cloud_api_activity surface for a specific sequence where an API request fails with a 400 error but is immediately followed by a successful 200 response for the same operation within 65 seconds. This pattern identifies an agent autonomously correcting its own method or version parameters. Finally, an agent correlates the sign-in data, discovery volume, and adaptive success patterns. This results in a high-confidence verdict on whether a service principal is under the control of an automated AI agent, allowing the team to move toward revocation and secret rotation.

Blind Spots

Two primary gaps exist in this detection strategy. First, Azure and Entra audit logs often suffer from ingestion latency ranging from 15 to 60 minutes. An AI agent can complete an entire exfiltration cycle in under five minutes, meaning the hunt might only identify activity after the damage occurs. Second, without Key Vault Data Plane logging enabled, the hunt can identify that a vault was accessed but cannot confirm which specific secrets were retrieved.

    Query · scoping

    Identify the reporting devices recorded in the authentication logs to establish a hunt scope.

    What a hit looks like. A list of hostnames that have reported Entra ID sign-in events. Silence suggests a gap in cloud-to-host log forwarding.

  2. Sign-ins from campaign IPs and Tor

    Query · triage

    Correlate Entra ID authentication with the report's IP addresses and Tor exit nodes, filtered by the scoped devices.

    reads hb_auth_signinsql

    What a hit looks like. Service principal or user logons from 199.19.77.84 or Tor nodes. Silence indicates no direct hits on the reported IPs.

  3. Automated cloud discovery patterns

    Query · baseline

    Identify identities performing high-frequency cloud resource enumeration.

    reads hb_cloud_api_activitysql
    SELECT actor_user_name, api_operation, api_service_name, src_endpoint_ip, COUNT(*) AS op_count, MIN(time) AS first_op FROM hb_cloud_api_activity WHERE (api_operation LIKE '%List%' OR api_operation LIKE '%Get%') AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY actor_user_name, api_operation, api_service_name, src_endpoint_ip HAVING op_count > 10 ORDER BY op_count DESC

    What a hit looks like. Identities querying multiple subscriptions or resources in quick succession. Silence means no high-volume enumeration was captured.

  4. Triage initial cloud compromise

    Agent triage

    Identify service principals showing early signs of takeover by correlating malicious sign-ins with discovery behaviors.

  5. Adaptive API troubleshooting signature

    Query · detection candidate

    Detect the core behavioral signature of an AI agent: immediate self-correction after API failures.

    reads hb_cloud_api_activitysql
    SELECT * FROM (SELECT time, actor_user_name, api_operation, status, request_uri, src_endpoint_ip, LAG(status) OVER (PARTITION BY actor_user_name, api_operation ORDER BY time) as prev_status, LAG(time) OVER (PARTITION BY actor_user_name, api_operation ORDER BY time) as prev_time FROM hb_cloud_api_activity WHERE time >= datetime('now', '-{{lookback_days}} days')) WHERE status = '200' AND prev_status = '400' AND (strftime('%s', time) - strftime('%s', prev_time)) <= 65

    What a hit looks like. An API request that fails (400) and is retried successfully (200) within 65 seconds by the same actor. This is the hallmark of agentic automation.

  6. Evaluate full agentic lifecycle

    Agent triage

    Combine the evidence of compromise, discovery, and adaptive behavior into a final verdict.

  7. Route on verdict

    Decision

    Decide whether to isolate the compromised identity based on the agent's findings.

  8. Revoke service principal

    Response action

    Immediately disable the compromised identity to halt further AI-driven exfiltration.

  9. Secret rotation and impact audit

    Analyst task

    Assess which secrets were accessed by the agent and ensure they are rotated.

  10. Hunt closure

    Analyst task

    Document findings and determine if the behavioral signature is ready for production detection.

# Agentic AI Cloud Resource Abuse (ARTEX)

This phased hunt targets the automated behaviors of agentic AI frameworks like ARTEX. It begins by identifying service principal sign-ins originating from known campaign IPs or Tor exit nodes. It then pivots to find the behavioral hallmark of AI agents: adaptive API troubleshooting, where the agent identifies and corrects its own API version or method errors (400 to 200 transitions) within seconds. Finally, an agent weighs the full lifecycle from compromise to discovery to exfiltration.
