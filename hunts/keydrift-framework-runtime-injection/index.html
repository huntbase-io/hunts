KeyDrift Framework Runtime Injection and Hooking

An adversary is using ptrace to inject malicious modules into the vdaemon process on a Cisco SD-WAN controller to intercept and exfiltrate control-plane keying material.

Brief

Why now

1000a Cisco Talos recently published a detailed analysis of UAT-11473 activity in their article, Inside KeyDrift: Analyzing historical UAT-11473 activity on Cisco SD-WAN. This actor uses the KeyDrift framework to compromise Cisco SD-WAN controllers, specifically targeting the vdaemon process to intercept sensitive control-plane keying material. Because the framework relies on memory-resident modules and transient configuration files, standard signature-based detection often misses the infection. 1000a

How the hunt flows

1000a The hunt begins by scanning the hb_file_activity surface for high-fidelity indicators. It searches for specific staging and configuration files, such as /var/tmp/vdaemon.bin and /tmp/system-vdaemon, in temporary directories. These files serve as encrypted repositories for stolen data. Because KeyDrift frequently deletes these files after use, their presence acts as a high-priority trigger for the next phase. 1000a If lead indicators are present, an agent assesses the findings to decide if the activity matches the KeyDrift framework staging behavior. This gate ensures the hunt only proceeds to expensive behavioral analysis when evidence warrants it. If the agent confirms the files are suspicious, the hunt moves into a deep investigation phase. 1000a The investigation phase runs two queries in parallel to capture runtime behavior. The first query monitors the hb_linux_audit surface for rare processes invoking the ptrace syscall. While ptrace is a legitimate tool for debugging, its use on production SD-WAN controllers is unusual. The hunt baselines this activity across the fleet to highlight outliers that may be acting as injectors. 1000a Simultaneously, the hunt examines the hb_module_activity surface to inspect the memory maps of the vdaemon process. It lists all loaded shared objects and filters for rare modules that appear on only a few hosts. This allows an analyst to identify the PolyFlame and LittleFilch modules—often named libdssl.so or libcommon.so—even if the adversary successfully hides the initial injection process. 1000a In the final triage phase, an agent correlates the file activity, ptrace invocations, and rare module findings to reach a high-confidence verdict. A host showing a rare injector process and unauthorized shared objects in vdaemon memory receives a malicious verdict. This workflow provides the specific evidence needed to justify immediate isolation and forensic imaging. 1000a

What the hunt cannot see

1000a KeyDrift is designed for stealth. It deletes configuration files immediately after reading them, meaning the initial file-based leads are highly transient. If an analyst runs the hunt after the actor cleans up the filesystem, these indicators will not appear. Additionally, if Linux syscall auditing is disabled for ptrace, the mechanism of injection becomes invisible to the telemetry. In such scenarios, the hunt must rely entirely on memory-resident module snapshots. 1000a

# KeyDrift Framework Runtime Injection and Hooking

This hunt targets the runtime behavior of the UAT-11473 KeyDrift framework. It begins with a lead query for high-fidelity staging files in /tmp and /var/tmp that indicate an active intrusion. If found, the hunt triggers a deep dive into Linux audit logs using prevalence to detect rare processes invoking ptrace and examines vdaemon process memory maps for rare shared objects. An agent correlates these behavioral signals to confirm that an adversary has established in-process collection of SD-WAN control traffic.
