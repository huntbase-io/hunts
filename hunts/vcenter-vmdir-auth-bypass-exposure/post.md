# VMware vCenter Directory Service Authentication Bypass Exposure

### Why This Hunt? 0 0 Rapid7 recently detailed CVE-2026-123903, a critical authentication bypass in the VMware Directory Service (vmdir) at https://www.rapid7.com/blog/post/etr-cve-2026-123903-critical-vmware-directory-service-authentication-bypass-affects-vcenter. This vulnerability allows unauthenticated attackers to bypass security controls by sending crafted LDAP or RPC traffic. Because vCenter serves as the core of the virtualization fabric, exploitation provides an attacker with full control over the virtualization environment. We designed this hunt to identify exposed instances and look for signs of active exploitation. 0 0 ### The Hypothesis 0 0 An unauthenticated attacker is attempting to exploit a critical authentication bypass in the VMware Directory Service (vmdir) by sending malicious LDAP or RPC traffic to exposed vCenter instances. 0 0 ### How the Hunt Flows 0 0 The hunt begins by scoping the estate to identify vulnerable vCenter servers. The first step queries hb_vulnerability_finding for existing security scan results matching the targeted CVEs. Simultaneously, a query against hb_software_inventory enumerates all vCenter installations and their versions. This dual approach ensures we catch known vulnerable systems and those that scans might have missed. 0 0 The second phase focuses on network telemetry. Using hb_network_connection, the hunt baselines inbound traffic to LDAP ports 389 and 636. We stack-count source IP addresses per host to find rare or unknown external sources. In a typical environment, only a few administrative workstations or load balancers communicate with these ports. Any outlier suggests a potential probe or exploitation attempt. 0 0 Next, the hunt examines host-level telemetry for post-exploitation evidence. We query hb_process_activity for the vmdir process and its children. The VMware Directory Service rarely spawns child processes like shells or unexpected binaries. If an attacker successfully bypasses authentication, their subsequent commands often appear as child activity of this service. 0 0 Finally, an automated agent triages the results. It weighs the vulnerability findings against the observed network prevalence and process anomalies. This provides a prioritized list of hosts that are not just vulnerable, but potentially compromised or actively targeted. This approach moves beyond simple CVE alerts by correlating vulnerability status with actual traffic patterns and process anomalies to find exposure that a single alert misses. 0 0 ### Blind Spots 0 0 The hunt relies on network connection logs. If inbound logging is disabled on the vCenter host or at the network boundary, we cannot see the source of the traffic. Additionally, LDAPS traffic on port 636 is encrypted. While we can see the connection itself, we cannot inspect the payload for specific malicious LDAP attributes without decryption or application-level audit logs. 0 0 ### How to Run This Hunt 0 0 This hunt is an open hunt.md playbook. You can import it directly into Huntbase or any security platform that supports the hunt.md format. The playbook guides you through the scoping, baselining, and triage phases with built-in logic to handle large volumes of network data.
