Brief

Why this hunt

Elastic Security Labs recently published Auditing the auditor: Unmasking Apex Accelerator (https://www.elastic.co/security-labs/threat-command/apex-accelerator-malicious-npm-packages). The campaign uses malicious npm packages to target developers. The adversary social-engineers victims into installing packages that contain Bun-compiled launchers. These launchers initiate a multi-stage infection process.

How the hunt flows

The first query scopes the estate for the Bun-compiled binaries. It looks for specific filenames like apex-windows-x64.exe or apex-darwin-arm64. These binaries are the root of the execution chain. The hunt then pivots to find evidence of staging and defense evasion. The registry query identifies changes that disable Smart App Control or add Defender exclusions for the .apex-audit path. Simultaneously, a file activity query searches for rare scripts like _apex_run.vbs or drop.ps1. These scripts often reside in temporary folders and appear on very few hosts. Once the analyst confirms staging, the hunt looks for the final payloads. It searches for the execution of binaries like bludness.exe and files within the CloudSyncD directory. These represent the active stealers. The final phase focuses on network activity. It identifies connections to the Telegram API or known Apex command-and-control domains. This step confirms whether the malware successfully exfiltrated data.

Blind spots

The hunt may miss exfiltration if network logs lack process correlation. Without this, Telegram traffic might look like legitimate user activity. Additionally, the adversary may use large encoded PowerShell commands. This can lead to script block truncation, which hides the second-stage URLs.

    Query · scoping

    Identify hosts running the primary Apex or Audit binaries that serve as the entry point for the secondary execution chain.

    reads hb_process_activitysql

    What a hit looks like. A list of hosts running the Apex-branded Bun executables. Absence means the primary launchers have not been observed.

  2. Identify security impairment

    Query · detection candidate

    Find evidence of Smart App Control disabling or Defender exclusion path additions used by Apex.

    reads hb_registry_activitysql
    SELECT device_hostname, reg_target, reg_value_data, process_name, time FROM hb_registry_activity WHERE ((LOWER(reg_target) LIKE '%\\verifiedandreputablepolicystate%' AND reg_value_data = '0') OR (LOWER(reg_target) LIKE '%\\exclusions\\\\paths%' AND LOWER(reg_value_data) LIKE '%.apex-audit%')) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Registry writes disabling Smart App Control or adding the .apex-audit path to Defender's exclusion list.

  3. Detect rare staging scripts

    Query · baseline

    Find temporary PowerShell and VBScript files used to launch the verification commands, stack-counting across the fleet.

    reads hb_file_activitysql
    SELECT LOWER(file_name) AS name, COUNT(DISTINCT device_hostname) AS hosts, COUNT(*) AS touches, MIN(time) AS first_seen FROM hb_file_activity WHERE instr(',' || '{{staging_files}}' || ',', ',' || LOWER(file_name) || ',') > 0 AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY 1 HAVING hosts <= 5

    What a hit looks like. Script files like _apex_run.vbs occurring on very few hosts. Fleet-wide files are likely legitimate and should be ignored.

  4. Triage early staging activity

    Agent triage

    Assess whether the Bun launchers and the observed staging/evasion activity indicate a successful breachhead.

  5. Detect malware binary execution

    Query · triage

    Find the execution of final payload binaries like bludness.exe or CloudSyncD on scoped hosts.

    reads hb_process_activitysql
    SELECT device_hostname, process_name, process_cmd_line, parent_process_name, time FROM hb_process_activity WHERE (instr(',' || '{{malicious_binaries}}' || ',', ',' || LOWER(process_name) || ',') > 0 OR LOWER(process_path) LIKE '%cloudsyncd%') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Processes named bludness.exe or CloudSyncD running on the same hosts that performed staging. High-confidence indicators of infection.

  6. Identify Telegram and C2 exfiltration

    Query · enrichment

    Detect network traffic to Telegram API or Apex verification domains from scoped hosts.

    What a hit looks like. Connections to Telegram or Apex domains. Silence suggests the infection has not reached the exfiltration phase.

# Apex Accelerator Post-Delivery Execution and Evasion

This hunt targets the post-delivery phase of the Apex Accelerator campaign (REF8801). It identifies Windows security impairment, such as disabling Smart App Control and adding Defender exclusions, alongside the creation of rare staging scripts. The hunt then pivots to find the execution of secondary payloads like bludness.exe or CloudSyncD and identifies outbound exfiltration to Telegram or attacker-controlled domains. It uses a phased flow to first confirm the staging breachhead before examining the final exfiltration and malware persistence.
