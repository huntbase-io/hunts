# Hunting Apex Accelerator Post-Delivery Execution and Stealer Exfiltration

### Why this hunt Elastic Security Labs recently published Auditing the auditor: Unmasking Apex Accelerator (https://www.elastic.co/security-labs/threat-command/apex-accelerator-malicious-npm-packages). The campaign uses malicious npm packages to target developers. The adversary social-engineers victims into installing packages that contain Bun-compiled launchers. These launchers initiate a multi-stage infection process. ### Hypothesis The adversary uses Bun-compiled launchers to stage PowerShell and VBScript payloads, impair local security controls, and deploy information stealers that exfiltrate data to Telegram. ### How the hunt flows The first query scopes the estate for the Bun-compiled binaries. It looks for specific filenames like apex-windows-x64.exe or apex-darwin-arm64. These binaries are the root of the execution chain. The hunt then pivots to find evidence of staging and defense evasion. The registry query identifies changes that disable Smart App Control or add Defender exclusions for the .apex-audit path. Simultaneously, a file activity query searches for rare scripts like _apex_run.vbs or drop.ps1. These scripts often reside in temporary folders and appear on very few hosts. Once the analyst confirms staging, the hunt looks for the final payloads. It searches for the execution of binaries like bludness.exe and files within the CloudSyncD directory. These represent the active stealers. The final phase focuses on network activity. It identifies connections to the Telegram API or known Apex command-and-control domains. This step confirms whether the malware successfully exfiltrated data. ### Blind spots The hunt may miss exfiltration if network logs lack process correlation. Without this, Telegram traffic might look like legitimate user activity. Additionally, the adversary may use large encoded PowerShell commands. This can lead to script block truncation, which hides the second-stage URLs. ### How to run it This hunt exists as an open hunt.md playbook. You can import it into Huntbase or any compatible runtime. The design uses a phased approach to reduce noise, gating expensive network queries behind confirmed indicators of staging and evasion.
