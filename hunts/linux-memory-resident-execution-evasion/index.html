Linux Memory-Resident Execution and Evasion

An adversary is executing payloads through anonymous memory descriptors (memfd_create) or unlinking binaries immediately after launch to evade on-disk scanning and durable detection.

Brief

Recent research by Elastic Security Labs, titled "Linux Detection Engineering - Fileless Execution," highlights a sophisticated shift in Linux malware tactics. Attackers are increasingly leveraging memory-resident techniques to evade traditional detection. By utilizing anonymous memory descriptors via the memfd_create syscall or unlinking binaries immediately after execution, these threats avoid creating durable artifacts on the disk.\n\n## The Hypothesis\n\nOur hypothesis for this hunt is that an adversary is currently maintaining persistence or executing payloads using these fileless methods. Because these processes do not have a backing file on disk, they often bypass EDR solutions that rely on file-integrity monitoring or point-of-write scanning.\n\n## How the Hunt Flows\n\nThe hunt flow begins with the broad identification of memory-resident processes. We use the hb_process_activity surface to filter for processes where the on_disk flag is false or where the execution path originates from memfd or /proc/ descriptors. This initial step captures potential fileless activity but also includes legitimate noise from container runtimes or dynamic system tools.\n\nTo refine these results, we move into a parallel corroboration phase. We first perform a prevalence analysis across the fleet to identify rare diskless binaries, as malicious implants are typically unique to a few targets. Simultaneously, we search for "(deleted)" markers in process paths, which indicate the binary was unlinked post-launch to frustrate analysis. We also pivot to the hb_module_activity surface to identify kernel modules loaded from memory, a high-confidence indicator of evasion.\n\nThe final phase involves an automated triage of these indicators. By weighing the process prevalence against the presence of unlinked paths or memory-loaded modules, we can distinguish between standard administrative behavior and an active intrusion. This layered approach ensures that the investigation focuses on the most suspicious deviations rather than the baseline noise of a modern Linux environment.\n\n## Blind Spots and Limitations\n\nThere are two primary blind spots to consider. First, on Linux kernels older than 5.10.16 or those without eBPF capabilities, the memfd_create syscall might not be explicitly logged. In these environments, the hunt relies on observing the secondary procfs descriptors. Second, there is a risk involving the snapshot interval. If a fileless loader executes and terminates within seconds, it may fall between process inventory collections.\n\n## How to Run This Hunt\n\nThis hunt is delivered as a hunt.md playbook. It is designed to be imported into Huntbase or any hunt.md-aware runtime. Since the logic depends heavily on fleet-wide prevalence stacking, we recommend running it against your entire Linux server estate to establish an accurate baseline.

    Query · detection candidate

    Find processes currently running where the binary is missing or the path indicates execution from an anonymous memory descriptor.

    reads hb_process_activitysql
    SELECT device_hostname, process_name, process_path, process_cmd_line, pid, time FROM hb_process_activity WHERE (on_disk = 0 OR LOWER(process_path) LIKE 'memfd:%' OR LOWER(process_path) LIKE '/proc/%/fd/%') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Rows naming processes running without disk artifacts. Legitimate container runtimes or updaters may appear, requiring prevalence analysis.

  2. Prevalence of Diskless Binaries

    Query · baseline

    Stack-count processes running from memory to highlight unique or rare binaries that differ from standard fleet-wide software.

    reads hb_process_activitysql
    SELECT process_path, process_cmd_line, COUNT(DISTINCT device_hostname) AS hosts, MIN(time) AS first_seen FROM hb_process_activity WHERE on_disk = 0 AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY process_path, process_cmd_line HAVING hosts <= 3 ORDER BY hosts ASC

    What a hit looks like. A diskless process seen on only 1 or 2 hosts is a strong indicator of a targeted payload.

  3. Processes from Unlinked Paths

    Query · enrichment

    Identify binaries that were deleted immediately after execution, leaving '(deleted)' markers in their path.

    reads hb_process_activitysql
    SELECT device_hostname, process_name, process_path, process_cmd_line, pid, time FROM hb_process_activity WHERE (LOWER(process_path) LIKE '%(deleted)%' OR LOWER(process_name) LIKE '%(deleted)%') AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Rows indicating processes unlinked from disk, a common evasion tactic to prevent binary analysis.

  4. Kernel Modules from Memory

    Query · enrichment

    Find loadable kernel modules (LKMs) sourced from memory or anonymous file descriptors rather than on-disk .ko files.

    reads hb_module_activitysql
    SELECT device_hostname, module_path, process_name, pid, time FROM hb_module_activity WHERE (LOWER(module_path) LIKE 'memfd:%' OR LOWER(module_path) LIKE '/proc/%') AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Kernel modules loaded from descriptors or memfd. This is a very high-confidence indicator of kernel-level fileless persistence.

# Linux Memory-Resident Execution and Evasion

This hunt identifies fileless execution patterns on Linux by detecting processes running without a corresponding binary on disk (on_disk = 0), identifying processes executing from '/proc' or 'memfd' paths, and finding kernel modules loaded from anonymous memory. It correlates this behavior with fleet-wide prevalence to distinguish legitimate administrative activity from malicious implants such as VoidLink.

## detect-memory-resident-processes
<!-- Identify Diskless or Descriptor-Based Processes -->
Find processes currently running where the binary is missing or the path indicates execution from an anonymous memory descriptor.

```sqlite target=endpoint role=detection-candidate params=(scope_hosts=scope_hosts, lookback_days=lookback_days)
~~~yaml
expected: Rows naming processes running without disk artifacts. Legitimate container
  runtimes or updaters may appear, requiring prevalence analysis.
reads:
- device_hostname
- process_name
- process_path
- process_cmd_line
- on_disk
- pid
- time
silence: not_evidence_of_absence
source: hb_process_activity
verified: dry-run
verified_at: '2026-09-17'
~~~
SELECT device_hostname, process_name, process_path, process_cmd_line, pid, time FROM hb_process_activity WHERE (on_disk = 0 OR LOWER(process_path) LIKE 'memfd:%' OR LOWER(process_path) LIKE '/proc/%/fd/%') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days')
```
