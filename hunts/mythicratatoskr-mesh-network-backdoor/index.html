MythicRatatoskr Mesh-Network Backdoor and Sandworm Handover

Brief

Why now: The UAC-0099 and Sandworm Handover

Recent reporting from ESET Research describes a collaboration between the initial access broker UAC-0099 and the Sandworm group. The adversary follows a specific progression: initial access via phishing leads to the MATCHWOK backdoor, which eventually hands off control to a sophisticated mesh-network backdoor called MythicRatatoskr. This transition is a precursor to destructive data-wiping attacks, making early discovery of the persistent backdoor critical.

How the Hunt Flows

The first phase scopes the environment for the initial beachhead. A query scans scheduled task metadata for the specific task name used by UAC-0099. This step identifies which hosts require deeper inspection and provides a temporal anchor for the rest of the hunt.

Once the hunt identifies potential hosts, it corroborates the access markers in parallel. It examines PowerShell script logs for the execution of payloads staged in temporary directories and searches the registry for the specific run-key persistence associated with the MATCHWOK infection. This step builds confidence that the initial access chain succeeded.

The hunt then pivots to the MythicRatatoskr deployment. It searches for specific binary filenames and service installations while simultaneously baselining rare network traffic. This network search focuses on the deprecated IPv6 range (200::/7) that the Yggdrasil mesh protocol uses. Finding these IPv6 connections on a small number of hosts provides a high-confidence signal of a decentralized backdoor.

Finally, the hunt synthesizes these phases. An analyst evaluates whether the hosts with early access markers are the same hosts showing mesh-network activity. This full-chain assessment confirms the transition from a simple phishing infection to a sophisticated, long-term persistence mechanism.

What the Hunt Cannot See

Visibility into the Yggdrasil mesh depends entirely on the granularity of IPv6 logging. If network sensors do not capture traffic in the 200::/7 range or if EDR agents do not report IPv6 destination addresses for local processes, the network-based corroboration will fail. Furthermore, if the adversary rotates binary filenames or task names beyond the known parameters, the scoping phase may return zero results even if the backdoor exists.

How to Run the Hunt

This hunt is an open hunt.md playbook. You can import the file into Huntbase or any other runtime that supports the hunt.md format. The playbook uses SQLite-based DSL for its queries and includes logic for scoping hosts, triaging results, and isolating compromised systems. To begin, set the lookback_days parameter to cover at least 60 days of telemetry to capture the full progression from initial access to backdoor installation.

  5. MythicRatatoskr binary execution

    Query · triage

    Identify the execution of specific filenames and service names associated with the MythicRatatoskr backdoor.

    reads hb_process_activitysql
    SELECT device_hostname, process_name, process_cmd_line, time FROM hb_process_activity WHERE (LOWER(process_name) LIKE '%\\updater.exe' OR LOWER(process_name) LIKE '%\\krbtman.exe' OR LOWER(process_name) LIKE '%\\windowsdefendersvc.exe' OR LOWER(process_name) LIKE '%\\onedriveliveupdater.exe' OR LOWER(process_name) LIKE '%\\applicationasphost.exe' OR LOWER(process_name) LIKE '%\\act64.exe' OR LOWER(process_name) LIKE '%\\ieupdate.exe' OR LOWER(process_name) LIKE '%\\ie.exe' OR LOWER(process_cmd_line) LIKE '%ieupdate%' OR instr(',' || '{{mythic_binaries}}' || ',', ',' || LOWER(process_name) || ',') > 0) AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Execution of updater.exe, krbtman.exe, or other reported binaries, particularly on hosts from the scoping phase. Suffix matching identifies binaries even when installed in unusual paths.

  6. Baseline rare Yggdrasil mesh traffic

    Query · baseline

    Find rare IPv6 traffic in the 200::/7 range indicating mesh-network C2.

    reads hb_network_connectionsql
    SELECT dst_endpoint_ip, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seen FROM hb_network_connection WHERE (dst_endpoint_ip >= '0200:' AND dst_endpoint_ip < '0400:') AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY dst_endpoint_ip HAVING host_count <= 3

    What a hit looks like. Connections to IPv6 addresses in the deprecated mesh range (0200:: to 03ff::), appearing on a small number of hosts.

  10. Forensic review of mesh config

    Review captured artifacts to identify the peer addresses and exfiltration scope.

  11. Close out hunt

    Analyst task

    Document results and recommend detection improvements.

# MythicRatatoskr Mesh-Network Backdoor and Sandworm Handover

The adversary gains initial access via phishing and persists using scheduled tasks and registry keys. The hunt identifies these early access markers and then pivots to find specialized mesh-network C2 telemetry. The phased flow ensures that the hunt weighs early access markers alongside specialized mesh C2 telemetry to confirm a high-confidence intrusion before the adversary transitions to data-wiping activity.

## yggdrasil-traffic-baseline
<!-- Baseline rare Yggdrasil mesh traffic -->
Find rare IPv6 traffic in the 200::/7 range indicating mesh-network C2.

```sqlite target=network role=baseline params=(lookback_days=lookback_days)
~~~yaml
baseline:
  compare: first_seen
  window: '{{lookback_days}}d'
expected: 'Connections to IPv6 addresses in the deprecated mesh range (0200:: to 03ff::),
  appearing on a small number of hosts.'
prevalence:
  by: device_hostname
  key:
  - dst_endpoint_ip
  rare_below: 3
reads:
- dst_endpoint_ip
- device_hostname
- time
silence: not_evidence_of_absence
source: hb_network_connection
```
