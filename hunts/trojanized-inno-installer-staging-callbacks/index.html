Trojanized Inno Installer Staging and Callbacks

Brief

Why this hunt

0x0A Microsoft recently detailed a campaign in their report, Fake-download campaign uses trojanized installers to deliver monetization payloads. The adversary lures users with cracked software and activators to run trojanized Inno Setup installers. These installers stage and execute monetization payloads like proxyware or compute-resource miners. These components use business assets for adversary profit and degrade network performance. 0x0A 0x0A

How the hunt flows

0x0A The hunt begins by scoping the environment for initial access indicators using the hb_software_inventory surface. The first query searches for software packages with names like crack, activator, or unlocker. Identifying these lures helps narrow the hunt to hosts where users are most likely to have executed deceptive installers. This targeted approach reduces the volume of data processed in later stages. 0x0A 0x0A Next, the hunt examines process activity for Inno Setup runner patterns on the hb_process_activity surface. One query looks for specific command-line arguments like /SL5 or /spawnwnd that characterize the Inno Setup wrapper. Simultaneously, a second query stack-counts processes executing from Inno-specific temporary directories. This identifies rare, numbered binaries such as eld0.exe or eld1.exe that stand out from legitimate system installers. 0x0A 0x0A The third phase identifies the monetization and persistence phase. The hunt queries the hb_dns_activity surface for resolutions to known offer-tracking and C2 domains listed in the threat intelligence. It also inspects the hb_scheduled_job surface for tasks related to WorldProxyPool, CharityEngine, or BOINC. Finding these persistent tasks confirms that the installer successfully deployed its payload and established a persistent presence on the host. 0x0A 0x0A Finally, an analyst triages the collected evidence. The hunt correlates the staging verdict with the network and persistence indicators. This triage process links the initial execution of the trojanized installer to the subsequent monetization activity. An analyst reviews the host-level evidence to confirm the infection chain before proceeding to containment. If the host shows both staging behavior and persistent monetization tasks, the analyst triggers isolation. 0x0A 0x0A

What the hunt cannot see

0x0A The hunt has two primary blind spots. If DNS logs only capture activity from a central resolver without client IP attribution, the hunt cannot link a tracking callback to a specific host. Additionally, if the HTTP telemetry truncates URL query parameters, the analyst loses the d=inno parameter used for campaign attribution. These visibility gaps mean that absence of network evidence is not proof of a clean host. 0x0A 0x0A

# Trojanized Inno Installer Staging and Callbacks

This hunt identifies the multi-stage execution and persistence model used by a fake-download campaign. The campaign lures users with cracked software and activators to run Inno Setup-style wrappers. These wrappers stage numbered payloads in the user's temp directory and contact rotating infrastructure to report offer outcomes. Finally, the campaign installs monetization components like proxyware or compute-resource miners, often persistent through SYSTEM-level scheduled tasks. The hunt follows these stages in two phases: first identifying the temporary staging activity and then corroborating it with the network callbacks and persistence mechanisms.
