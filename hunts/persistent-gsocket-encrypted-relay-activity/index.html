Persistent GSocket Encrypted Relay Activity

High severity TLP:CLEAR Part 2 of 2 Research by Microsoft Published 12 Nov 2026

Hypothesis

An intruder has maintained persistent access to a Linux server by deploying a GSocket relay after exploiting a kernel vulnerability, masquerading the relay as a system service while communicating outbound to a shared public network.

Brief

Why now

Recent research from Microsoft, The global socket: how threat actors are weaponizing GSocket for stealthy C2, describes how adversaries use GSocket to maintain a persistent backdoor on Linux systems. These actors often exploit the Dirty Frag kernel vulnerability (CVE-2026-43284) to gain the privileges needed for installation. Because GSocket uses a shared public relay network and initiates connections outbound, it bypasses many standard firewall configurations. We designed this hunt to find these relays by looking for the overlap of vulnerable kernels, masqueraded persistence, and relay infrastructure lookups.

How the hunt flows

The first phase identifies the attack surface. A query against vulnerability management data lists every Linux host currently reporting the Dirty Frag vulnerability. This provides a focused list of high-risk targets where an adversary likely succeeded in elevating privileges. While the hunt can run across the entire estate, these vulnerable hosts serve as the primary anchors for the analysis.

Next, the hunt initiates two parallel checks for evidence of weaponization. One query examines scheduled jobs in cron and systemd units. It looks for rare entries that use masqueraded names like 'systemd-remount-d' or 'defunct.service', or those that reference staging paths in /dev/shm. Simultaneously, a DNS activity query checks for outbound resolution attempts to known GSocket relay domains. This identifies hosts attempting to join the global relay network.

In the triage phase, an agent correlates these signals for each host. The agent weighs the presence of the Dirty Frag vulnerability against any discovered persistence mechanisms or DNS lookups. If a host shows both a vulnerable kernel and evidence of GSocket infrastructure, the agent assigns a malicious verdict. This correlation reduces noise from administrators who might use GSocket for legitimate, though non-standard, remote management.

Finally, the hunt provides a path to remediation. If the agent identifies a malicious relay, the playbook routes the host for immediate isolation. An analyst then terminates the masqueraded processes and removes the persistence artifacts before patching the kernel vulnerability to close the initial entry point.

What the hunt cannot see

This hunt has two primary blind spots. First, GSocket traffic is end-to-end encrypted. Without egress proxy TLS inspection, we cannot see the content of the C2 commands and must rely on process context and domain reputation to determine intent. Second, sophisticated variants of GSocket may use kernel-thread masquerading or system calls like prctl to rename threads dynamically. If the telemetry only captures the initial process command line and not subsequent thread renames, these more advanced persistence methods might remain hidden.

Steps

  1. Query, scoping

    Scope hosts vulnerable to Dirty Frag

    Identify Linux hosts reporting the Dirty Frag vulnerability (CVE-2026-43284), which was observed as a primary privilege escalation vector for GSocket deployment.

    sql, reads hb_vulnerability_finding

    What a hit looks like. A list of unique device identifiers currently reporting the kernel vulnerability. Silence suggests no unpatched hosts or no vulnerability scanning coverage.

  2. Query, detection candidate

    Identify rare GSocket persistence

    Find rare cron or systemd jobs referencing GSocket file names, masqueraded service names, or staging paths like /dev/shm.

    sql, reads hb_scheduled_job
    SELECT LOWER(job_cmd_line) AS cmd, job_name, device_hostname, COUNT(DISTINCT device_hostname) AS hosts, MIN(time) AS first_seenFROM hb_scheduled_jobWHERE (instr(',' || '{{gs_service_names}}' || ',', ',' || LOWER(job_name) || ',') > 0 OR job_cmd_line LIKE '%/dev/shm/%' OR job_cmd_line LIKE '%gs-netcat%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY LOWER(job_cmd_line), job_name, device_hostnameHAVING hosts <= 3ORDER BY hosts ASC

    What a hit looks like. Rare jobs on a few hosts that use masqueraded names or stage binaries in temporary memory-backed directories. Silence means no known names were found in job definitions.

  3. Query, enrichment

    Check for relay infrastructure lookups

    Identify hosts resolving GSocket domains, which indicates the client binary is attempting to connect to the shared relay network.

    sql, reads hb_dns_activity
    SELECT device_hostname, query_hostname, process_name, COUNT(*) AS lookups, MIN(time) AS first_seenFROM hb_dns_activityWHERE (instr(',' || '{{c2_domains}}' || ',', ',' || LOWER(query_hostname) || ',') > 0)  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY device_hostname, query_hostname, process_nameORDER BY lookups DESC

    What a hit looks like. Outbound DNS requests to the relay infrastructure. Silence proves no resolution attempts to these specific domains occurred in the window.

  4. Agent triage

    Analyze GSocket activity per host

    Weigh vulnerability status against persistence and C2 indicators to determine if GSocket is actively weaponized on a host.

  5. Decision

    Route by agent verdict

    Initiate automated containment for malicious findings or route to analyst review for suspicious activity.

  6. Response action

    Isolate host and remediate GSocket

    Sever the encrypted relay connection and remove persistence components to prevent further command execution.

  7. Analyst task

    Manual forensic review

    Confirm the effectiveness of remediation and identify any secondary implants or lateral movement.

  8. Analyst task

    Hunt closeout and documentation

    Document findings for detection engineering and close the incident.

# Persistent GSocket Encrypted Relay Activity

This hunt identifies Linux hosts weaponized with GSocket (Global Socket) for long-term command and control. Threat actors use the Dirty Frag kernel vulnerability (CVE-2026-43284) to elevate privileges before installing GSocket relays that masquerade as legitimate system services like systemd-remount. Because GSocket connects outbound to a shared public relay network, traditional inbound firewall rules and fixed C2 domain blocking are ineffective. This hunt correlates vulnerability status with rare persistence mechanisms and outbound relay traffic patterns to identify active intrusions that persist even after the initial entry point is patched.

Find rare cron or systemd jobs referencing GSocket file names, masqueraded service names, or staging paths like /dev/shm.

