Rebranded SoftEther VPN Tunneling

High severity TLP:CLEAR Research by Rapid7 Published 20 Nov 2026

Hypothesis

An intruder has established a persistent, covert tunnel by deploying a customized SoftEther VPN bridge that masquerades as legitimate network monitor software using modified PE metadata and encrypted configuration files.

Brief

Why Now

Rapid7 recently published Spying on Governments with Zero Lines of Malware: A Custom SoftEther Bridge in Webworm’s Toolkit. The research details how the Webworm APT uses an altered version of the SoftEther VPN bridge, dubbed NtMonitor, to establish persistent ingress and egress. Instead of developing custom malware, the adversary rebrands a powerful open-source tool. They modify PE metadata to mimic a legitimate vendor and use specific HTTP paths to blend in with normal traffic. This hunt provides a structured approach to identifying these bridges within an environment.

How the Hunt Flows

The first phase focuses on scoping via software inventory. The hunt looks for hosts where the software registry contains the fake vendor name "Network Systems Solutions Inc" or the specific SoftEther version 4.44.0.9807 found in the actor's build. Because the adversary may not always register the tool in the official inventory, this step acts as a high-confidence starting point rather than a definitive filter.

The second phase fans out to gather concurrent evidence across multiple surfaces. One query hunts for the persistent service installed by the tool, which often retains the name "sevpnbridge" or points to a binary named netcapa.exe. Simultaneously, the hunt stacks process activity by original file name to find rare instances of netcapa.exe across the fleet. The intruder typically deploys this on a very small subset of systems, making prevalence a strong indicator of unauthorized use.

Next, the hunt searches for the unique configuration file, setting.conf, and masqueraded network traffic. The adversary uses specific HTTP paths like /update/alive.cgi and /update/picture.cgi for C2. While these paths look like standard updates, they represent the custom VPN protocol in transit. The hunt correlates the presence of these network requests with the local file and service artifacts found in the previous steps.

Finally, a triage step brings all findings together. An analyst or agent reviews the host-level results to confirm if the service name, process metadata, and network paths appear together on the same system. This correlation helps distinguish the Webworm toolkit from legitimate, authorized installations of SoftEther or other network monitoring tools.

Blind Spots

The primary blind spot involves encrypted traffic. If the SoftEther bridge uses HTTPS and the organization does not perform TLS inspection, the specific CGI paths will remain hidden from network activity logs. In such cases, the hunt relies more heavily on endpoint artifacts like the setting.conf file and process metadata. Additionally, if the adversary changes the rebranding strings or binary names in a newer build, the specific metadata filters used in the scoping phase may miss the activity.

Steps

  1. Query, scoping

    Software Inventory Scoping

    Identify hosts running software with the actor's fake vendor name or the specific version of SoftEther used in the build.

    sql, reads hb_software_inventory
    SELECT device_hostname, vendor_name, package_name, package_versionFROM hb_software_inventoryWHERE (LOWER(vendor_name) LIKE '%' || LOWER('{{fake_vendor}}') || '%' OR package_version = '4.44.0.9807')

    What a hit looks like. Hosts with software attributed to the fake vendor or the exact version identified in the research. None proves this specific package is not registered in the inventory.

  2. Query, detection candidate

    VPN Bridge Service Persistence

    Find the persistent service installed by the actor, which often retains the original SoftEther service name.

    sql, reads hb_service_activity
    SELECT device_hostname, service_name, service_cmd_line, timeFROM hb_service_activityWHERE (LOWER(service_name) = 'sevpnbridge' OR LOWER(service_cmd_line) LIKE '%netcapa.exe%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Rows naming the SEVPNBRIDGE service or the netcapa.exe binary in the command line.

  3. Query, baseline

    Rare Processes with Actor Metadata

    Stack-count processes using the netcapa.exe OriginalFileName to find rare deployments that deviate from fleet baseline.

    sql, reads hb_process_activity
    SELECT LOWER(process_path) AS path, COUNT(DISTINCT device_hostname) AS hosts, MIN(time) AS first_seenFROM hb_process_activityWHERE (LOWER(process_original_file_name) = 'netcapa.exe' OR LOWER(process_path) LIKE '%netcapa.exe')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY pathHAVING hosts <= 3

    What a hit looks like. A process binary seen on very few hosts. Stock network tools would appear across many servers, whereas the intruder's build is likely rare.

  4. Query, enrichment

    Masqueraded HTTP C2 Traffic

    Identify outbound HTTP traffic to the specific CGI endpoints used by the custom SoftEther protocol.

    sql, reads hb_http_activity
    SELECT device_hostname, url_path, url_hostname, src_endpoint_ip, timeFROM hb_http_activityWHERE instr(',' || '{{c2_paths}}' || ',', ',' || LOWER(url_path) || ',') > 0  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Connections to /update/alive.cgi or /update/picture.cgi. Silence may mean traffic is encrypted and requires the blind spot note.

  5. Query, enrichment

    Encrypted Config File Presence

    Find the presence of the setting.conf file which contains the actor's custom encrypted configuration.

    sql, reads hb_file_activity
    SELECT device_hostname, file_path, file_name, timeFROM hb_file_activityWHERE LOWER(file_name) = 'setting.conf'  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. The creation or access of setting.conf, particularly in a directory containing netcapa.exe.

  6. Agent triage

    Triage VPN Findings

    Correlate service, process, and network evidence to determine if a host is running the Webworm VPN variant.

  7. Decision

    Route on Verdict

    Decide the next step based on the agent's confidence in the findings.

  8. Response action

    Isolate Beachhead

    Cut off the persistent VPN tunnel and prevent further lateral movement.

  9. Analyst task

    Manual Forensic Review

    Verify the presence of 'NtMonitor' strings and the RCEN magic bytes in the configuration.

  10. Analyst task

    Hunt Close-out

    Document results and promote durable signals to detection rules.

# Rebranded SoftEther VPN Tunneling

This hunt targets the NtMonitor variant of SoftEther VPN attributed to the Webworm APT. The actor rebrands the open-source tool as Network Monitor Software and uses masqueraded HTTP endpoints like /update/alive.cgi for C2. The hunt starts by identifying potential target hosts via software inventory, then fans out to find persistence through services, rare process metadata matching the actor's rebranding, the presence of the unique setting.conf encrypted configuration file, and custom HTTP URI paths. An agent triages these results to distinguish between legitimate network tools and the Webworm toolkit.
