# Shai-Hulud: Hunting for Credential Exfiltration and the Destructive Deadman Switch

### The Risk of the Deadman Switch Datadog Security Labs recently published a detailed analysis of the [Shai-Hulud open source framework](https://securitylabs.datadoghq.com/articles/shai-hulud-open-source-framework-static-analysis/), highlighting a significant risk for incident response teams. The framework is not just a tool for credential harvesting; it incorporates a defensive mechanism that punishes remediation efforts. This hunt focuses on identifying that mechanism before it triggers. ### Hypothesis An adversary uses the Shai-Hulud framework to exfiltrate stolen credentials via GitHub dead-drops. To protect their access, they install a monitoring daemon that polls the GitHub API. If the daemon detects that the defender has revoked the stolen token, it immediately executes a command to wipe the user's home directory. This activity aims to destroy local evidence and disrupt the user's work environment as a consequence of detection. ### Scoping via DNS An analyst begins the hunt by examining DNS activity for primary C2 domains. The framework relies on a set of default domains for initial communication and exfiltration. Identifying lookups to these domains allows the team to scope the investigation to specific hosts. This phase is critical because silence on the primary domain does not mean the threat is absent; the framework can rotate to new infrastructure via signed commits on GitHub. ### Parallel Behavioural Analysis The hunt then pivots to a parallel search across process and network surfaces to find the behavioral footprint of the infection. It searches process logs for the gh-token-monitor daemon and any instances of broad directory deletion commands. Simultaneously, the hunt examines HTTP traffic for high-frequency polling of the GitHub API user endpoint. This polling is a functional requirement for the deadman switch, as the daemon must constantly verify that its access remains valid. ### Triage and Correlation The triage phase combines these signals to confirm the framework's presence. A single process named gh-token-monitor or occasional GitHub API requests might appear benign in a developer environment. However, the hunt correlates the resolution of C2 domains with the specific polling frequency and the presence of the monitoring daemon. This correlation is why this is a hunt rather than a single detection: an analyst must weigh the combined evidence of exfiltration and the destructive payload before initiating remediation. ### Blind Spots This hunt has two primary blind spots. First, it requires process visibility with full command-line arguments. Without this, the analyst cannot see the specific wipe command or the daemon's process name. Second, the hunt relies on full URL visibility for HTTP traffic. If query parameters are stripped by a proxy or logging tool, the analyst cannot see the specific strings used to locate rotated C2 domains on GitHub. ### How to Run This Hunt This hunt is available as an open hunt.md playbook. You can import it into Huntbase or any hunt.md-aware runtime. Because of the destructive nature of the deadman switch, we recommend isolating malicious hosts before revoking any identified GitHub tokens. This prevents the daemon from detecting the revocation and executing its payload, ensuring the safety of local data during the recovery process.
