Malicious Python Package Persistence and Secret Theft

High severity TLP:CLEAR Part 1 of 2 Research by Elastic Security Labs Published 19 Nov 2026

Hypothesis

An intruder has installed a compromised version of the agent-framework package which persists via a .pth hook and harvests cloud credentials by reading environment variables from the /proc filesystem and local configuration files.

Brief

Why now

Elastic Security Labs recently reported in We caught the agent-framework PyPI compromise six minutes after it published a supply chain compromise involving the agent-framework PyPI package. The malicious versions, 1.26.1 and 1.26.2, contain a credential stealer that triggers every time a user starts a Python process.

How the hunt flows

The hunt begins with a software inventory check. The first query identifies hosts running the specific malicious versions of agent-framework. This narrows the scope to impacted systems before the analyst proceeds to deeper behavioral analysis.

Next, the hunt branches to look for indicators of persistence and initial execution. One query searches for the .pth hook files and associated telemetry scripts in the filesystem. A parallel query checks process activity for Python commands referencing these telemetry modules. This evidence proves the malicious hook successfully triggered the background stealer.

If the analyst confirms an infection, the hunt pivots to behavioral evidence. It uses Linux audit logs to detect Python processes reading environment files from other processes via the /proc filesystem. This behavior is rare. It indicates the stealer is in its harvesting phase, searching for secrets in the environment of up to 300 running processes.

In the final phase, an analyst reviews the correlated data to assign a verdict. If the hunt confirms active secret theft, the analyst isolates the host and begins rotating cloud credentials, including Azure CLI caches, .npmrc tokens, and GitHub OIDC federated credentials.

What the hunt cannot see

This hunt relies on specific auditd configurations. If the system does not log reads to the proc filesystem, specifically /proc/*/environ, the harvesting behavior remains invisible to the behavioral query. Additionally, ephemeral containers used in CI/CD pipelines may install the package, execute the theft, and terminate before the inventory scan or file activity logs capture their state.

    Triage host infection status

    Detect environment harvesting via /proc

    Detect the unusual behavior of a Python process reading environment files from other processes.

    Analyze active secret theft

    Correlate the confirmed infection with behavioral evidence of secret harvesting.

    Direct response actions based on the confirmed threat.

  8. Response action

    Isolate compromised host

    Halt credential exfiltration and preserve evidence for forensics.

  9. Analyst task

    Manual analyst review

    Review suspicious activity that did not meet the full threshold for automated isolation.

  10. Analyst task

Blind spots

  • Needs hb_linux_audit specifically monitoring /proc syscalls. The harvesting behavior might be invisible if the audit configuration does not capture reads to /proc/*/environ. It would answer: Are all environment variable reads via the proc filesystem being logged?
  • Needs real-time package inventory for container lifecycles. Build-and-destroy CI/CD nodes may install and run the stealer, perform the theft, and terminate before the inventory surface records their presence. It would answer: Did the package run in a container that was destroyed before a scan?

# Malicious Python Package Persistence and Secret Theft

This hunt identifies hosts impacted by the agent-framework supply-chain compromise. The malicious versions (1.26.1 and 1.26.2) use a .pth startup hook to execute a credential stealer every time any Python script starts. The stealer forks a background process to harvest environment variables from up to 300 running processes and searches for Azure, AWS, and GitHub credential caches on disk. We trace the lifecycle from package installation and hook creation to active secret harvesting behavior.

## harvesting-behavior
<!-- Detect environment harvesting via /proc -->
Detect the unusual behavior of a Python process reading environment files from other processes.

```sqlite target=endpoint role=baseline params=(scope_hosts=scope_hosts, lookback_days=lookback_days)
~~~yaml

  compare: first_seen
  window: '{{lookback_days}}d'
expected: Python processes reading multiple proc environment files. This is rare and
  indicative of the stealer's harvesting phase.
prevalence:
  by: device_hostname
  key:
  - process_path
  - path_name
  rare_below: 3
reads:
- device_hostname
- path_name
- process_path
- syscall
- time
silence: not_evidence_of_absence
```
