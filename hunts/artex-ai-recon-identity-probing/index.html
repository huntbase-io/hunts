ARTEX AI-Driven Perimeter Recon and Identity Probing

An autonomous AI-powered framework is conducting high-speed perimeter scanning and identity pressure, transitioning from credential sprays to sensitive configuration discovery at machine speed.

Brief

Why this hunt?###Microsoft recently detailed the ARTEX agentic AI framework in their article What defenders need to know about ARTEX, the agentic AI framework threat actors abuse. Adversaries like Storm-0940 use these frameworks to automate the entire initial access lifecycle. Traditional detections often fire on individual tools, but they miss the machine-speed coordination that characterizes ARTEX. This hunt identifies the specific transition from identity pressure to perimeter probing that indicates an autonomous agent is active against your infrastructure.###Hypothesis###An autonomous AI-powered framework is conducting high-speed perimeter scanning and identity pressure, transitioning from credential sprays to sensitive configuration discovery at machine speed.###How the hunt flows###The first phase identifies the attack surface and generates a lead. A query to software inventory tables lists every host running web server software like Apache, Nginx, or IIS. The hunt then scans identity provider logs for source IPs that exceed a high authentication failure threshold. This identifies the volume and velocity typical of AI-driven credential sprays.###An automated agent then evaluates the intensity of these authentication failures. It assesses the account diversity and timing to determine if the source IP behaves like a machine-speed actor. This step acts as a gate; the hunt only proceeds to more intensive data gathering if the lead shows high-confidence evidence of automation.###Once gated, the hunt performs parallel corroboration across network and endpoint surfaces. It inspects HTTP logs for rapid-fire requests targeting sensitive paths such as .env, web.config, or .git/config. Simultaneously, it searches process logs on the scoped web servers for the execution of pre-integrated ARTEX worker tools like sqlmap, hydra, or ncrack.###The final phase correlates these disparate artifacts. A triage agent reviews the identity pressure, the file probing, and the tool execution to confirm if they originate from the same actor. If confirmed, the hunt provides an action to isolate the compromised host and revoke credentials before the adversary can move laterally.###What the hunt cannot see###The hunt faces three primary blind spots. First, if an adversary uses a legacy or unmanaged identity provider that does not forward logs to the central platform, the initial lead will fail to trigger. Second, the hunt requires process visibility on Linux-based web servers to detect worker tools; without endpoint telemetry on these systems, the hunt relies solely on HTTP artifacts. Finally, incomplete HTTP logging that lacks full URL paths may mask the specific configuration file probes the framework uses.###How to run it###This hunt is provided as an open hunt.md playbook. You can import it directly into Huntbase or any runtime that supports the hunt.md standard. The playbook includes all necessary queries for software inventory, authentication logs, and process activity. Because it uses a gated design, you can run it periodically without generating excessive volume unless an automated lead is detected.

  1. Query, scoping

    Scope potential web server targets

    Identify hosts running web server software that are likely targets for autonomous scanning.

    sql, reads hb_software_inventory
    SELECT DISTINCT device_hostnameFROM hb_software_inventoryWHERE LOWER(package_name) LIKE '%apache%'  OR LOWER(package_name) LIKE '%nginx%'  OR LOWER(package_name) LIKE '%sharepoint%'  OR LOWER(package_name) LIKE '%screenconnect%'  OR LOWER(package_name) LIKE '%httpd%'  OR LOWER(package_name) LIKE '%iis%'

    What a hit looks like. A list of hosts running common web services. This scopes follow-on queries to the internet-facing estate.

  2. Query, detection candidate

    High-volume identity pressure lead

    Identify source IPs exhibiting machine-speed authentication failure patterns consistent with AI-driven sprays.

    sql, reads hb_auth_signin
    SELECT src_endpoint_ip, COUNT(*) AS attempt_count, COUNT(DISTINCT actor_user_name) AS unique_users, MIN(time) AS first_attempt, MAX(time) AS last_attemptFROM hb_auth_signinWHERE status_id = 2  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY src_endpoint_ipHAVING attempt_count >= {{auth_failure_threshold}}ORDER BY attempt_count DESC

    What a hit looks like. A single IP address attempting dozens or hundreds of logins across multiple accounts in a narrow window. This is the durable behavioral lead for ARTEX.

  3. Agent triage

    Evaluate identity pressure

    Determine if the identity spray pattern is likely an automated agent that warrants further investigation of web logs.

  4. Decision

    Gate on automated behavior

    Avoid expensive parallel queries if the initial spray does not show evidence of machine-speed automation.

  5. Query, baseline

    Sensitive configuration file probing

    Identify high-velocity HTTP requests for sensitive configuration files from the suspect IPs.

    sql, reads hb_http_activity
    SELECT device_hostname, src_endpoint_ip, url_path, status_code, COUNT(*) AS request_count, MIN(time) AS first_requestFROM hb_http_activityWHERE (('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0))  AND (instr(',' || '{{web_config_paths}}' || ',', ',' || LOWER(url_path) || ',') > 0 OR url_path LIKE '%.env%')  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY device_hostname, src_endpoint_ip, url_path, status_codeORDER BY request_count DESC

    What a hit looks like. Bursts of requests for .env, web.config, or my.cnf files targeting the scoped web assets. Silence confirms these IPs did not probe these specific paths.

  6. Query, triage

    Execution of offensive worker tools

    Identify the execution of ARTEX's integrated worker tools on systems in the scoped estate.

    sql, reads hb_process_activity
    SELECT device_hostname, process_name, process_cmd_line, user_name, timeFROM hb_process_activityWHERE (('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0))  AND (instr(',' || '{{offensive_tool_names}}' || ',', ',' || LOWER(process_name) || ',') > 0 OR instr(',' || '{{offensive_tool_names}}' || ',', ',' || LOWER(process_original_file_name) || ',') > 0 OR process_cmd_line LIKE '%sqlmap%' OR process_cmd_line LIKE '%hydra%' OR process_cmd_line LIKE '%ncrack%')  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Process execution for tools like nmap, hydra, or sqlmap. Silence proves these specific binaries did not run in the examined window.

  7. Agent triage

    Triage AI agent behavior

    Correlate the identity pressure with web probing and tool usage to confirm an ARTEX-enabled attack.

  8. Decision

    Route on triage verdict

    Trigger containment only if a malicious intrusion is confirmed by the triage agent.

  9. Response action

    Isolate compromised host

    Prevent further scanning or lateral movement from a confirmed autonomous agent.

  10. Analyst task

    Analyst forensic review

    Review the full attack chain and verify if any successful web exploitation occurred.

  11. Analyst task

    Close out hunt

    Record the results and adjust thresholds if false positives were identified.

# ARTEX AI-Driven Perimeter Recon and Identity Probing

This hunt identifies the early autonomous phases of an ARTEX intrusion. Threat actors like Storm-0940 use the framework to automate reconnaissance and initial access, often moving from a credential spray to web application probing in minutes. We start by scoping the web server estate and identifying high-volume authentication failures that serve as a cheap lead. A gated agent then decides whether to trigger expensive queries into web application probing and the execution of worker tools like sqlmap or hydra. The hunt concludes with a triage agent correlating external identity pressure with internal behavioral artifacts to confirm the presence of an autonomous penetration testing agent.
