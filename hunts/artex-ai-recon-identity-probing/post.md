# Hunting ARTEX Autonomous AI Recon and Identity Probing

### Why this hunt?###Microsoft recently detailed the ARTEX agentic AI framework in their article [What defenders need to know about ARTEX, the agentic AI framework threat actors abuse](https://www.microsoft.com/en-us/security/blog/2026/11/25/what-defenders-need-to-know-artex-agentic-ai-framework-threat-actors-abuse/). Adversaries like Storm-0940 use these frameworks to automate the entire initial access lifecycle. Traditional detections often fire on individual tools, but they miss the machine-speed coordination that characterizes ARTEX. This hunt identifies the specific transition from identity pressure to perimeter probing that indicates an autonomous agent is active against your infrastructure.###Hypothesis###An autonomous AI-powered framework is conducting high-speed perimeter scanning and identity pressure, transitioning from credential sprays to sensitive configuration discovery at machine speed.###How the hunt flows###The first phase identifies the attack surface and generates a lead. A query to software inventory tables lists every host running web server software like Apache, Nginx, or IIS. The hunt then scans identity provider logs for source IPs that exceed a high authentication failure threshold. This identifies the volume and velocity typical of AI-driven credential sprays.###An automated agent then evaluates the intensity of these authentication failures. It assesses the account diversity and timing to determine if the source IP behaves like a machine-speed actor. This step acts as a gate; the hunt only proceeds to more intensive data gathering if the lead shows high-confidence evidence of automation.###Once gated, the hunt performs parallel corroboration across network and endpoint surfaces. It inspects HTTP logs for rapid-fire requests targeting sensitive paths such as .env, web.config, or .git/config. Simultaneously, it searches process logs on the scoped web servers for the execution of pre-integrated ARTEX worker tools like sqlmap, hydra, or ncrack.###The final phase correlates these disparate artifacts. A triage agent reviews the identity pressure, the file probing, and the tool execution to confirm if they originate from the same actor. If confirmed, the hunt provides an action to isolate the compromised host and revoke credentials before the adversary can move laterally.###What the hunt cannot see###The hunt faces three primary blind spots. First, if an adversary uses a legacy or unmanaged identity provider that does not forward logs to the central platform, the initial lead will fail to trigger. Second, the hunt requires process visibility on Linux-based web servers to detect worker tools; without endpoint telemetry on these systems, the hunt relies solely on HTTP artifacts. Finally, incomplete HTTP logging that lacks full URL paths may mask the specific configuration file probes the framework uses.###How to run it###This hunt is provided as an open hunt.md playbook. You can import it directly into Huntbase or any runtime that supports the hunt.md standard. The playbook includes all necessary queries for software inventory, authentication logs, and process activity. Because it uses a gated design, you can run it periodically without generating excessive volume unless an automated lead is detected.
