Windows Shell and .NET Framework Zero-Day Bypasses

High severity TLP:CLEAR Research by Rapid7 Published 14 Oct 2026

Hypothesis

An adversary has exploited a Windows Shell MOTW bypass to execute malicious web downloads without warning, or has achieved stealthy persistence by registering a rare .NET assembly that evades Defender signature checks.

Brief

Why this hunt?

The Rapid7 — Patch Tuesday - October 2026 report highlights two high-risk vulnerabilities exploited in the wild. CVE-2026-96951 allows adversaries to bypass Windows Shell Mark of the Web (MOTW) protections, causing malicious files to execute without security warnings. Meanwhile, CVE-2026-108398 involves .NET Framework assembly hijacking, which an adversary uses to achieve persistence while evading Windows Defender signature checks. Because these involve core OS mechanisms, standard detections often struggle to separate malicious activity from legitimate system updates.

How the hunt flows

The hunt begins by scoping the environment for vulnerable assets. The first query searches vulnerability scan records for the specific CVE identifiers. This step identifies which hosts lack the October 2026 patches. An analyst uses the resulting list of hostnames to focus the subsequent behavioral searches, reducing noise from patched systems.

Once scoped, the hunt executes two parallel behavioral checks. The first check performs a stack-count of registry writes within .NET Framework and CLSID paths. By grouping these writes by the value data and counting occurrences across the fleet, the hunt surfaces rare assembly registrations. Legitimate updates usually appear on many hosts, while exploitation attempts typically appear on very few.

In the second parallel phase, the hunt examines file activity in user-writable directories like Downloads and Temp. It searches for files containing the Zone.Identifier alternate data stream with a ZoneID of 3, which indicates an internet origin. The presence of these files on hosts confirmed as vulnerable suggests the MOTW security feature failed to block or warn the user during the download.

The final phase uses an automated triage step to correlate these findings. The agent reviews the specific behavioral rows found on each vulnerable host and issues a verdict. If the registry or file activity matches the exploit profile, the hunt triggers an isolation action to contain the host while an analyst performs a manual review of the identified files.

What the hunt cannot see

This hunt relies on specific telemetry that may not be present in every environment. The MOTW bypass detection requires file activity logs that capture alternate data stream contents, such as Sysmon Event ID 15. Without this, the hunt cannot confirm if a file carried the untrusted internet tag. Additionally, the scoping step depends on the latest vulnerability scan data. If the scanner has not updated its logic for the October 2026 release, the hunt may overlook vulnerable hosts.

  2. Query, baseline

    Rare .NET assembly registrations

    Stack-count registry writes to .NET Framework paths to identify rare assembly registrations that may indicate hijacking.

    sql, reads hb_registry_activity
    SELECT LOWER(reg_target) AS target, reg_value_data, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seenFROM hb_registry_activityWHERE (('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0))  AND (LOWER(reg_target) LIKE '%\\software\\microsoft\\.netframework%' OR LOWER(reg_target) LIKE '%\\software\\classes\\clsid%')  AND activity_id = 2  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY 1, 2HAVING host_count <= 3ORDER BY host_count ASC

    What a hit looks like. A registry value seen on very few hosts. Legitimate software updates may appear, but a rare path or value data is the primary indicator of assembly hijacking.

  3. Query, triage

    MOTW bypass file indicators

    Find files downloaded from the internet (ZoneID=3) into user folders that may have bypassed security warnings.

    sql, reads hb_file_activity
    SELECT device_hostname, file_name, file_path, process_name, timeFROM hb_file_activityWHERE (('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0))  AND (LOWER(file_path) LIKE '%\\downloads\\%' OR LOWER(file_path) LIKE '%\\temp\\%')  AND LOWER(file_contents) LIKE '%zoneid=3%'  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Files with MOTW metadata in user-writable paths. The presence of such files on vulnerable hosts suggests a failure of the MOTW security feature.

  7. Analyst task

    Manually verify the agent's findings and the context of the identified registry and file activity.

# Windows Shell and .NET Framework Zero-Day Bypasses

This hunt targets two zero-day vulnerabilities from the October 2026 Patch Tuesday: CVE-2026-96951 (Windows Shell MOTW bypass) and CVE-2026-108398 (.NET Framework assembly hijacking). The hunt identifies vulnerable hosts and then looks for behavioral indicators of exploitation, specifically monitoring for rare registry modifications within the .NET Framework and CLSID paths, and hunting for files in user-writable directories that contain Zone.Identifier tags indicating an untrusted internet origin. An agent triage step settles the findings across these independent surfaces.

## rare-net-registrations
<!-- Rare .NET assembly registrations -->
Stack-count registry writes to .NET Framework paths to identify rare assembly registrations that may indicate hijacking.

```sqlite target=endpoint role=baseline params=(lookback_days=lookback_days, scope_hosts=scope_hosts)
~~~yaml
baseline:
  compare: first_seen
  window: '{{lookback_days}}d'
expected: A registry value seen on very few hosts. Legitimate software updates may
  appear, but a rare path or value data is the primary indicator of assembly hijacking.
prevalence:
  by: device_hostname
  key:
  - reg_target
  - reg_value_data
  rare_below: 3
reads:
- device_hostname
- reg_target
- reg_value_data
- time
silence: not_evidence_of_absence
source: hb_registry_activity
verified: dry-run
verified_at: '2026-10-14'
~~~
SELECT LOWER(reg_target) AS target, reg_value_data, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seen FROM hb_registry_activity WHERE (('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)) AND (LOWER(reg_target) LIKE '%\\software\\microsoft\\.netframework%' OR LOWER(reg_target) LIKE '%\\software\\classes\\clsid%') AND activity_id = 2 AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY 1, 2 HAVING host_count <= 3 ORDER BY host_count ASC
```

## analyst-review
<!-- Analyst review -->
```manual target=analyst
Examine the registry values and files cited by the agent. Check whether the file_contents confirm a MOTW ZoneID=3 download and whether the registry process is a known legitimate installer or an untrusted binary.
```
→ end

## close-out
<!-- Close out -->
```manual target=analyst

```
→ end
