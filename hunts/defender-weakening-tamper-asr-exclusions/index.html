Defender Weakening: Tamper Protection, ASR Rules and Exclusions

High severity TLP:CLEAR Part 1 of 5 Research by Protokol-7 Published 19 Nov 2026

Hypothesis

An operator with administrative rights on a Windows host has weakened Microsoft Defender before running tooling or ransomware: Tamper Protection off, ASR rules moved to audit or off, scan exclusions added, or the engine stopped, on one host rather than through fleet policy.

Brief

Why This Hunt Matters

Before ransomware runs, the operator usually turns Microsoft Defender down. The moves are familiar: an exclusion for the staging folder, ASR rules switched to audit, Tamper Protection off, or the service stopped. Each one is also ordinary administration when it arrives through Group Policy or Intune, so a rule on any one of them either fires all day or is tuned until it never fires.

Defender keeps its own record of some of this. In November 2026 Protokol-7 showed that the engine's encrypted database, mpenginedb.db, stores the engine's view of Tamper Protection and the ASR rule state changes it applied. On their test machine they recovered a Tamper Protection record set to off. The open-source osquery-defender-extension decrypts that database on each host and exposes it as defender_mpengine_* tables, so the question can be asked across a fleet.

How the Hunt Flows

The hunt opens with the engine's state on every host. Did the database decrypt? When did the engine last write an attack-scoring record or a path tag? Is Defender the active, up-to-date antivirus according to Windows Security Center? A busy host whose newest record is days old has an engine that stopped recording.

Five queries then run side by side. Two read the database: the Tamper Protection state the engine persisted, and every ASR rule state change, counted per rule and state. The third lists every exclusion configured now, local and policy, from the registry, which osquery can read because it runs as SYSTEM. The last two use ordinary telemetry: writes to Defender's policy keys with the writing process, and the commands operators use, such as Set-MpPreference -ExclusionPath, MSFT_MpPreference over WMI, MpCmdRun -RemoveDefinitions and sc stop WinDefend.

The comparison across the fleet is the core of the hunt. A policy rollout puts the same ASR state or the same exclusion on hundreds of hosts at once, written by the Group Policy or MDM client. An operator's change appears on one host, written by PowerShell or reg.exe. An agent sorts the changes on that basis and names the hosts changed by hand.

For those hosts the hunt looks for what weakening is usually for. It checks for binaries running from user-writable or excluded folders, and for shadow-copy, backup, boot-recovery and log-clearing commands. It also reads Defender's own ransomware detections and the files it was tracking for rollback. A second agent builds a timeline per host. Confirmed hosts go to an approval-gated action, which preserves the Scans folder first, then isolates the host and restores protection. Everything unclear goes to an analyst.

What the Hunt Cannot See

Microsoft does not document the values stored for Tamper Protection and ASR state, so they are read as stored and compared against hosts known to be correct. Protokol-7 also notes that a Tamper Protection record cannot be tied to an attacker on its own. Exclusions are not in mpenginedb.db. The registry shows them, but its timestamp is per key, so without registry change telemetry an exclusion can be seen but not dated. A host without the extension, or one where another antivirus is primary and Defender is passive, returns nothing or a stale database, which this hunt cannot tell apart from a host that was tampered with.

Steps

  1. Query, scoping

    Defender engine state per host

    Establish which hosts can answer and what state their engine is in. The extension's own status says whether the database decrypted; the newest attack-scoring and path-tag records say whether the engine is still writing; Windows Security Center says whether Defender is the active, up-to-date antivirus. A busy host whose newest record is days old has an engine that stopped recording.

    sql, reads defender_mpengine_status
    SELECT (SELECT hostname FROM system_info) AS device_hostname, s.protection, s.key_source, s.quick_check, s.error, s.db_size, s.wal_size, (SELECT MAX(insert_time) FROM defender_mpengine_rolling_queues) AS newest_scoring_record, (SELECT MAX(insert_time) FROM defender_mpengine_persist_context) AS newest_path_record, (SELECT GROUP_CONCAT(name || ' state=' || state || ' sigs=' || signatures_up_to_date, '; ') FROM windows_security_products WHERE type = 'Antivirus') AS antivirus_products, CAST(strftime('%s', 'now') AS INTEGER) AS checked_atFROM defender_mpengine_status s

    What a hit looks like. One row per Windows host. error = '' and quick_check = 'ok' mean the host can answer. A non-empty error, a missing Defender entry or a Defender state other than On, or newest records far older than checked_at on an active host are findings in themselves. A host that returns no row has no extension.

  2. Query, enrichment

    Tamper Protection state recorded by the engine

    Read the Tamper Protection state the engine persists. Protokol-7 recovered a record of it set to off from the WAL of a test machine; it is the one place the engine's own view of Tamper Protection is kept outside the registry.

    sql, reads defender_mpengine_persist_context
    SELECT (SELECT hostname FROM system_info) AS device_hostname, file_path, context AS recorded_state, insert_time, expire_timeFROM defender_mpengine_persist_contextWHERE file_path = 'MpTamperProtectionState'  OR context LIKE '%TamperProtection%'

    What a hit looks like. One row per host with the recorded state. A state meaning off on a host whose policy says on is the lead; the value is stored as Defender wrote it and is not documented, so compare it with hosts known to be correct.

  3. Query, baseline

    ASR rule state changes

    List the attack surface reduction rule state changes the engine recorded. A policy rollout changes the same rule to the same state on hundreds of hosts; an operator switching one rule to audit or off does it on one.

    sql, reads defender_mpengine_persist_context
    SELECT (SELECT hostname FROM system_info) AS device_hostname, asr_rule_id, asr_rule_name, context AS recorded_state, COUNT(*) AS records, MIN(insert_time) AS first_recorded, MAX(insert_time) AS last_recordedFROM defender_mpengine_persist_contextWHERE record_kind = 'asr_rule_state'GROUP BY asr_rule_id, asr_rule_name, context

    What a hit looks like. Rule and state pairs shared by most of the fleet are policy. A pair seen on fewer than three hosts, especially for the LSASS, Office child-process, PsExec/WMI or ransomware rules, is a lead.

  4. Query, baseline

    Defender exclusions configured now

    Inventory every path, process, extension and address excluded from scanning, local and policy. Exclusions are not in mpenginedb.db, but the registry holds them and osquery runs as SYSTEM, which can read them. An excluded folder is a folder the engine records nothing about.

    sql, reads registry
    SELECT (SELECT hostname FROM system_info) AS device_hostname, key AS exclusion_key, name AS excluded_item, CASE WHEN LOWER(key) LIKE '%\policies\%' THEN 'policy' ELSE 'local' END AS exclusion_source, mtime AS key_last_writtenFROM registryWHERE (key LIKE 'HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows Defender\Exclusions\%' OR key LIKE 'HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Windows Defender\Exclusions\%')  AND name NOT IN ('', '(Default)')

    What a hit looks like. Exclusions shared across a fleet segment are configuration. A local exclusion on one or two hosts, or one covering a user-writable folder, a whole drive, a script host or an archive extension, is a lead.

  5. Query, enrichment

    Writes to Defender policy keys

    Find who wrote Defender's exclusion, real-time protection, feature and ASR keys, and with what. This gives the time and the writing process that the registry inventory cannot.

    sql, reads hb_registry_activity
    SELECT device_hostname, time, reg_key_path, reg_value_name, reg_value_data, process_name, process_cmd_line, actor_user_nameFROM hb_registry_activityWHERE time >= datetime('now', '-{{lookback_days}} days')  AND (LOWER(reg_key_path) LIKE '%\windows defender\exclusions\%' OR LOWER(reg_key_path) LIKE '%\windows defender\real-time protection%' OR LOWER(reg_key_path) LIKE '%\windows defender\features%' OR LOWER(reg_key_path) LIKE '%\windows defender exploit guard\asr%' OR (LOWER(reg_key_path) LIKE '%\windows defender%' AND LOWER(reg_value_name) IN ('disableantispyware', 'disableantivirus', 'disablerealtimemonitoring', 'disablebehaviormonitoring', 'disableioavprotection', 'tamperprotection')))  AND LOWER(COALESCE(process_name, '')) NOT LIKE '%\msmpeng.exe'

    What a hit looks like. Writes by the Group Policy or MDM client across many hosts are policy. A write by powershell.exe, reg.exe or an unknown binary on one host is a lead.

  6. Query, detection candidate

    Commands that weaken Defender

    Catch the commands operators use: Set-MpPreference and Add-MpPreference exclusions or switches, WMI MSFT_MpPreference, MpCmdRun -RemoveDefinitions, stopping WinDefend, and reg.exe edits of Defender keys.

    sql, reads hb_process_activity
    SELECT device_hostname, time, user_name, parent_process_name, process_name, process_cmd_line, integrity_levelFROM hb_process_activityWHERE time >= datetime('now', '-{{lookback_days}} days')  AND (((LOWER(process_cmd_line) LIKE '%set-mppreference%' OR LOWER(process_cmd_line) LIKE '%add-mppreference%') AND (LOWER(process_cmd_line) LIKE '%-exclusion%' OR LOWER(process_cmd_line) LIKE '%-disable%' OR LOWER(process_cmd_line) LIKE '%attacksurfacereductionrules_actions%' OR LOWER(process_cmd_line) LIKE '%-mapsreporting%' OR LOWER(process_cmd_line) LIKE '%-submitsamplesconsent%')) OR LOWER(process_cmd_line) LIKE '%msft_mppreference%' OR (LOWER(process_cmd_line) LIKE '%mpcmdrun%' AND LOWER(process_cmd_line) LIKE '%-removedefinitions%') OR ((LOWER(process_name) LIKE '%\sc.exe' OR LOWER(process_name) LIKE '%\net.exe' OR LOWER(process_name) LIKE '%\net1.exe') AND LOWER(process_cmd_line) LIKE '%windefend%') OR ((LOWER(process_name) LIKE '%\reg.exe') AND LOWER(process_cmd_line) LIKE '%windows defender%'))

    What a hit looks like. Rare outside deployment tooling. An interactive or service account running one of these outside a change window is the strongest single signal in this hunt.

  7. Agent triage

    Was Defender weakened, and by whom

    Separate policy from hands-on weakening and decide which hosts to follow up.

  8. Query, triage

    Execution and recovery inhibition after the change

    Look for what weakening is usually for: binaries started from user-writable or excluded-looking folders, and the shadow-copy, backup, boot-recovery and log-clearing commands that come right before encryption.

    sql, reads hb_process_activity
    SELECT device_hostname, time, user_name, parent_process_name, process_name, process_cmd_lineFROM hb_process_activityWHERE time >= datetime('now', '-{{lookback_days}} days')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND ((LOWER(process_cmd_line) LIKE '%vssadmin%delete%shadows%' OR LOWER(process_cmd_line) LIKE '%shadowcopy%delete%' OR LOWER(process_cmd_line) LIKE '%wbadmin%delete%' OR LOWER(process_cmd_line) LIKE '%bcdedit%recoveryenabled%no%' OR LOWER(process_cmd_line) LIKE '%wevtutil%cl %' OR LOWER(process_cmd_line) LIKE '%cipher%/w%') OR (LOWER(process_name) LIKE '%\users\%' OR LOWER(process_name) LIKE '%\programdata\%' OR LOWER(process_name) LIKE '%\windows\temp\%' OR LOWER(process_name) LIKE '%\perflogs\%' OR LOWER(process_name) LIKE '%\$recycle.bin\%'))

    What a hit looks like. Recovery-inhibition commands on a weakened host are close to conclusive. User-space binaries need the exclusions from defender-exclusions-now to judge: a binary running from an excluded folder is the payload the exclusion was made for.

  9. Query, enrichment

    Defender's ransomware detections and rollback tracking

    Read what the engine itself concluded about ransomware on these hosts: detections with their remediation timeline, and the files and processes it started tracking for rollback.

    sql, reads defender_mpengine_ransomware_detections
    SELECT (SELECT hostname FROM system_info) AS device_hostname, 'detection' AS record, detection_guid AS item, detection_time AS event_time, remediation_complete_time AS remediated_at, impacted_cbp_namespacesFROM defender_mpengine_ransomware_detectionsWHERE detection_time >= (CAST(strftime('%s', 'now') AS INTEGER) - {{lookback_days}} * 86400)  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || (SELECT hostname FROM system_info) || ',') > 0)UNION ALL SELECT (SELECT hostname FROM system_info) AS device_hostname, 'rollback_tracking' AS record, file_path AS item, instance_time AS event_time, NULL AS remediated_at, impacted_cbp_namespacesFROM defender_mpengine_backup_process_infoWHERE instance_time >= (CAST(strftime('%s', 'now') AS INTEGER) - {{lookback_days}} * 86400)  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || (SELECT hostname FROM system_info) || ',') > 0)

    What a hit looks like. Any detection row is serious. Rollback tracking of a binary from a user-writable path on a weakened host means the engine suspected it even with protection reduced.

  10. Agent triage

    Host verdict

    Join the weakening to what followed it.

  11. Decision

    Route on verdict

    Act on hands-on weakening; send anything unclear to a person.

  12. Response action

    Isolate and restore protection

    Stop what the weakening enabled, then put protection back.

  13. Analyst task

    Analyst review

    Confirm each finding against change records and widen the search.

  14. Analyst task

    Close out

    Record results and keep the signal.

# Defender Weakening: Tamper Protection, ASR Rules and Exclusions

Ransomware operators turn Defender down before they deploy. The usual moves are an exclusion for the staging folder, ASR rules switched to audit, Tamper Protection off, or the service stopped. Each one is ordinary admin work when it arrives through Group Policy or Intune, which is why a single rule rarely catches it.

Defender's own database, mpenginedb.db, keeps the engine's view of Tamper Protection and the ASR rule state changes it applied, and it stops filling when the engine stops recording. The defender_mpengine osquery extension decrypts it on each host. This hunt reads that state, adds the live exclusion list from the registry and the registry writes and commands that made the change, and stacks every change across the fleet. A change on one host stands apart from a policy rollout.

Hosts that were weakened by hand are then checked for what usually follows: payloads running from the excluded folders, shadow-copy and backup deletion, and Defender's own ransomware detections and rollback tracking.


## asr-rule-state-changes
<!-- ASR rule state changes -->
List the attack surface reduction rule state changes the engine recorded. A policy rollout changes the same rule to the same state on hundreds of hosts; an operator switching one rule to audit or off does it on one.

```osquery target=hb-endpoint-control role=baseline
~~~yaml
baseline:
  compare: first_seen
  window: '{{lookback_days}}d'
expected: Rule and state pairs shared by most of the fleet are policy. A pair seen
  on fewer than three hosts, especially for the LSASS, Office child-process, PsExec/WMI
  or ransomware rules, is a lead.
prevalence:
  by: device_hostname
  key:
  - asr_rule_name
  - recorded_state
  rare_below: 3
reads:
- context
- record_kind
- asr_rule_id
- asr_rule_name
- insert_time
silence: not_evidence_of_absence
source: defender_mpengine_persist_context
verified: dry-run
verified_at: '2026-11-19'

SELECT (SELECT hostname FROM system_info) AS device_hostname, asr_rule_id, asr_rule_name, context AS recorded_state, COUNT(*) AS records, MIN(insert_time) AS first_recorded, MAX(insert_time) AS last_recorded FROM defender_mpengine_persist_context WHERE record_kind = 'asr_rule_state' GROUP BY asr_rule_id, asr_rule_name, context
```

## defender-exclusions-now
<!-- Defender exclusions configured now -->
Inventory every path, process, extension and address excluded from scanning, local and policy. Exclusions are not in mpenginedb.db, but the registry holds them and osquery runs as SYSTEM, which can read them. An excluded folder is a folder the engine records nothing about.

```osquery target=hb-endpoint-control role=baseline
~~~yaml
expected: Exclusions shared across a fleet segment are configuration. A local exclusion
  on one or two hosts, or one covering a user-writable folder, a whole drive, a script
  host or an archive extension, is a lead.
prevalence:
  by: device_hostname
  key:
  - excluded_item
  rare_below: 3
reads:
- key
- name
- mtime
silence: not_evidence_of_absence
source: registry
verified: dry-run
verified_at: '2026-11-19'
~~~
SELECT (SELECT hostname FROM system_info) AS device_hostname, key AS exclusion_key, name AS excluded_item, CASE WHEN LOWER(key) LIKE '%\policies\%' THEN 'policy' ELSE 'local' END AS exclusion_source, mtime AS key_last_written FROM registry WHERE (key LIKE 'HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows Defender\Exclusions\%' OR key LIKE 'HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Windows Defender\Exclusions\%') AND name NOT IN ('', '(Default)')
```

```sqlite target=endpoint role=enrichment params=(lookback_days=lookback_days)
~~~yaml
expected: Writes by the Group Policy or MDM client across many hosts are policy. A
  write by powershell.exe, reg.exe or an unknown binary on one host is a lead.
reads:
- time
- device_hostname
- actor_user_name
- reg_key_path
- reg_value_name
- reg_value_data
- process_name
- process_cmd_line
silence: not_evidence_of_absence

~~~
SELECT device_hostname, time, reg_key_path, reg_value_name, reg_value_data, process_name, process_cmd_line, actor_user_name FROM hb_registry_activity WHERE time >= datetime('now', '-{{lookback_days}} days') AND (LOWER(reg_key_path) LIKE '%\windows defender\exclusions\%' OR LOWER(reg_key_path) LIKE '%\windows defender\real-time protection%' OR LOWER(reg_key_path) LIKE '%\windows defender\features%' OR LOWER(reg_key_path) LIKE '%\windows defender exploit guard\asr%' OR (LOWER(reg_key_path) LIKE '%\windows defender%' AND LOWER(reg_value_name) IN ('disableantispyware', 'disableantivirus', 'disablerealtimemonitoring', 'disablebehaviormonitoring', 'disableioavprotection', 'tamperprotection'))) AND LOWER(COALESCE(process_name, '')) NOT LIKE '%\msmpeng.exe'
```

## defender-tamper-commands
<!-- Commands that weaken Defender -->
Catch the commands operators use: Set-MpPreference and Add-MpPreference exclusions or switches, WMI MSFT_MpPreference, MpCmdRun -RemoveDefinitions, stopping WinDefend, and reg.exe edits of Defender keys.

```sqlite target=endpoint role=detection-candidate params=(lookback_days=lookback_days)
~~~yaml
expected: Rare outside deployment tooling. An interactive or service account running
  one of these outside a change window is the strongest single signal in this hunt.
reads:
- time
- device_hostname
- process_name
- process_cmd_line
- parent_process_name
- user_name
- integrity_level
silence: not_evidence_of_absence
source: hb_process_activity
verified: dry-run
verified_at: '2026-11-19'
~~~
SELECT device_hostname, time, user_name, parent_process_name, process_name, process_cmd_line, integrity_level FROM hb_process_activity WHERE time >= datetime('now', '-{{lookback_days}} days') AND (((LOWER(process_cmd_line) LIKE '%set-mppreference%' OR LOWER(process_cmd_line) LIKE '%add-mppreference%') AND (LOWER(process_cmd_line) LIKE '%-exclusion%' OR LOWER(process_cmd_line) LIKE '%-disable%' OR LOWER(process_cmd_line) LIKE '%attacksurfacereductionrules_actions%' OR LOWER(process_cmd_line) LIKE '%-mapsreporting%' OR LOWER(process_cmd_line) LIKE '%-submitsamplesconsent%')) OR LOWER(process_cmd_line) LIKE '%msft_mppreference%' OR (LOWER(process_cmd_line) LIKE '%mpcmdrun%' AND LOWER(process_cmd_line) LIKE '%-removedefinitions%') OR ((LOWER(process_name) LIKE '%\sc.exe' OR LOWER(process_name) LIKE '%\net.exe' OR LOWER(process_name) LIKE '%\net1.exe') AND LOWER(process_cmd_line) LIKE '%windefend%') OR ((LOWER(process_name) LIKE '%\reg.exe') AND LOWER(process_cmd_line) LIKE '%windows defender%'))
```

## execution-after-weakening
<!-- Execution and recovery inhibition after the change -->
Look for what weakening is usually for: binaries started from user-writable or excluded-looking folders, and the shadow-copy, backup, boot-recovery and log-clearing commands that come right before encryption.

```sqlite target=endpoint role=triage params=(lookback_days=lookback_days, scope_hosts=scope_hosts)
~~~yaml
expected: 'Recovery-inhibition commands on a weakened host are close to conclusive.
  User-space binaries need the exclusions from defender-exclusions-now to judge: a
  binary running from an excluded folder is the payload the exclusion was made for.'
reads:
- time
- device_hostname
- process_name
- process_cmd_line
- parent_process_name
- user_name
silence: not_evidence_of_absence
source: hb_process_activity
verified: dry-run
verified_at: '2026-11-19'
~~~
SELECT device_hostname, time, user_name, parent_process_name, process_name, process_cmd_line FROM hb_process_activity WHERE time >= datetime('now', '-{{lookback_days}} days') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND ((LOWER(process_cmd_line) LIKE '%vssadmin%delete%shadows%' OR LOWER(process_cmd_line) LIKE '%shadowcopy%delete%' OR LOWER(process_cmd_line) LIKE '%wbadmin%delete%' OR LOWER(process_cmd_line) LIKE '%bcdedit%recoveryenabled%no%' OR LOWER(process_cmd_line) LIKE '%wevtutil%cl %' OR LOWER(process_cmd_line) LIKE '%cipher%/w%') OR (LOWER(process_name) LIKE '%\users\%' OR LOWER(process_name) LIKE '%\programdata\%' OR LOWER(process_name) LIKE '%\windows\temp\%' OR LOWER(process_name) LIKE '%\perflogs\%' OR LOWER(process_name) LIKE '%\$recycle.bin\%'))
```

## ransomware-tracking

```osquery target=hb-endpoint-control role=enrichment params=(lookback_days=lookback_days, scope_hosts=scope_hosts)
~~~yaml
expected: Any detection row is serious. Rollback tracking of a binary from a user-writable
  path on a weakened host means the engine suspected it even with protection reduced.
reads:
- detection_guid
- detection_time
- remediation_complete_time
- instance_time
- impacted_cbp_namespaces
silence: not_evidence_of_absence
source: defender_mpengine_ransomware_detections
verified: dry-run
verified_at: '2026-11-19'
~~~
SELECT (SELECT hostname FROM system_info) AS device_hostname, 'detection' AS record, detection_guid AS item, detection_time AS event_time, remediation_complete_time AS remediated_at, impacted_cbp_namespaces FROM defender_mpengine_ransomware_detections WHERE detection_time >= (CAST(strftime('%s', 'now') AS INTEGER) - {{lookback_days}} * 86400) AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || (SELECT hostname FROM system_info) || ',') > 0) UNION ALL SELECT (SELECT hostname FROM system_info) AS device_hostname, 'rollback_tracking' AS record, file_path AS item, instance_time AS event_time, NULL AS remediated_at, impacted_cbp_namespaces FROM defender_mpengine_backup_process_info WHERE instance_time >= (CAST(strftime('%s', 'now') AS INTEGER) - {{lookback_days}} * 86400) AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || (SELECT hostname FROM system_info) || ',') > 0)
```
