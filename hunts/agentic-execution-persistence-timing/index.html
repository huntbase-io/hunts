Agentic Execution and Persistence Timing

High severity TLP:CLEAR Part 2 of 2 Research by Cisco Talos Published 26 Nov 2026

Hypothesis

Autonomous agents are operating on web-facing infrastructure, identified by rapid reasoning bursts in process telemetry and high-speed iterative HTTP status transitions during web shell deployment.

Brief

Identifying the Autonomous Signature

Traditional detection logic often focuses on specific command strings or known malicious file paths. However, as tradecraft evolves toward agentic swarms—automated frameworks that reason and adapt in real-time—the most reliable signal becomes the timing and velocity of the activity itself. This hunt identifies those signatures, specifically looking for the high-speed iterative loops used by autonomous systems to gain persistence.

Cisco Talos recently detailed these behaviors in their research, The Great Escape: Tradecraft insights from an agentic swarm. Their analysis highlights how multi-agent AI systems, such as ARTEX, use rapid bursts of execution to refine their payloads and establish footholds.

The Adversary Agent

Autonomous agents operate on web-facing infrastructure using rapid reasoning bursts in process telemetry and high-speed iterative HTTP status transitions during web shell deployment. The adversary does not type commands at a human pace; instead, the agentic framework launches multiple processes in sub-second intervals to test environment variables and iteratively adjusts its web shell payloads based on immediate HTTP error responses.

Scoping the Estate

The hunt begins by narrowing the search to hosts running known web server processes. The first phase lists every host running services like Nginx, Apache, or IIS. By focusing on the web surface, the analyst isolates the systems most likely to face the automated probing and persistence attempts characteristic of these swarms.

Burst Analysis and Network Iteration

Once the scope is set, the hunt runs two parallel queries to gather independent timing signals. The first query identifies reasoning bursts by finding instances where more than ten process launches occur within a single minute on a scoped host. These bursts represent the agent processing its environment and deciding on its next move. This frequency typically exceeds what standard application behavior or human administrators produce.

Simultaneously, the second query looks for iterative HTTP status transitions. It identifies source IPs that hit multiple paths on a single server while transitioning through various HTTP status codes, such as a sequence of 404s and 403s followed by a 200. This pattern indicates an automated agent refining a web shell payload in real-time. The hunt then moves to a triage phase where an analyst or automated agent weighs these two signals together to determine if the activity represents a coordinated swarm.

Visibility and Blind Spots

This hunt relies heavily on high-fidelity timing and metadata. It faces two primary blind spots. First, sensor rate-limiting on the endpoint may cause an EDR to drop events during high-frequency bursts to protect system performance. If the sensor drops 90 percent of events, the signature of the reasoning loop is lost. Second, if the network activity occurs over encrypted channels without TLS inspection, the specific HTTP status codes and paths required for the iteration signature remain invisible to network-level sensors.

    What a hit looks like. A list of hostnames running web servers. Silence means no web server telemetry is available for analysis.

  2. Query, detection candidate

    High-velocity process bursts

    Identify reasoning bursts by finding single minutes with excessive process launches on scoped hosts.

    sql, reads hb_process_activity
    SELECT device_hostname, process_name, user_name, COUNT(*) AS launch_count, MIN(time) AS burst_start, MAX(time) AS burst_endFROM hb_process_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY device_hostname, process_name, user_name, strftime('%Y-%m-%d %H:%M', time)HAVING launch_count > 10ORDER BY launch_count DESC

    What a hit looks like. A host exhibiting more than 10 process launches in a single minute. Silence proves the absence of high-frequency execution bursts.

  3. Query, baseline

    Iterative HTTP status transitions

    Find source IPs that transition through multiple HTTP status codes while hitting multiple paths on a single server, characteristic of an agent refining a web shell.

    sql, reads hb_http_activity
    SELECT device_hostname, src_endpoint_ip, COUNT(DISTINCT status_code) AS status_changes, COUNT(DISTINCT url_path) AS paths, COUNT(*) AS total_reqs, MIN(time) AS first_req, MAX(time) AS last_reqFROM hb_http_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY device_hostname, src_endpoint_ipHAVING status_changes > 1  AND paths > 3  AND total_reqs > 15ORDER BY total_reqs DESC

    What a hit looks like. A single IP address generating varied status codes across multiple paths in a short window. Silence proves no iterative probing occurred.

  4. Agent triage

    Weigh timing and probing evidence

    Assess whether the observed bursts and transitions indicate the coordination of an agentic swarm.

  5. Decision

    Route based on verdict

    Choose between immediate isolation or further manual investigation.

  6. Response action

    Isolate the host

    Halt the autonomous operations of the agent swarm and prevent further exfiltration.

  7. Analyst task

    Investigate agent artifacts

    Manually confirm the presence of iterative web shells and self-labeling strings.

  8. Analyst task

    Close out hunt

    Document findings and determine if the timing detection should be formalized.

# Agentic Execution and Persistence Timing

This hunt targets the behavioral timing signatures of multi-agent AI systems and agentic attack frameworks like ARTEX. It specifically looks for 'burst-and-pause' reasoning loops where multiple processes are launched in very short intervals and the iterative refinement of web shells where an agent rapidly adjusts payloads based on HTTP error responses. By correlating high-velocity process activity with automated HTTP probing patterns, the hunt identifies intrusions where the speed of execution and adaptation suggests an autonomous agent rather than a human operator.
