Endpoint PowerShell Execution via Social Engineering

High severity TLP:CLEAR Part 1 of 2 Research by Huntress Published 27 Nov 2026

Hypothesis

An attacker has tricked a user into running a malicious PowerShell command via the Windows Run dialog by mimicking a CAPTCHA on a look-alike SharePoint site to exfiltrate session tokens.

Brief

Why This Hunt

Huntress recently detailed how adversaries use ClickFix tactics in their blog, Three Attacks, Zero Exploits in Microsoft 365 (https://www.huntress.com/blog/three-attacks-zero-exploits-microsoft-365). These attacks bypass technical MFA controls by tricking a user into manually running a command. Since standard security tools do not block the user, we hunt for the artifacts of the execution itself.

How the Hunt Flows

The first phase focuses on process activity in the hb_process_activity surface. The lead query identifies PowerShell instances where the parent process is Windows Explorer. This relationship is common when a user types a command into the Win+R Run dialog. The hunt stacks these command lines across the environment and keeps only the rarest entries. Legitimate administrative commands often appear on many hosts, while social engineering payloads typically appear on a single host.

The second phase runs three checks in parallel to gather evidence. We pull the full PowerShell script block content from hb_script_activity to look for obfuscation or token-theft logic. We search DNS logs in hb_dns_activity for look-alike Microsoft 365 or SharePoint domains. We also read the user's Run dialog history (the RunMRU registry key in hb_registry_activity), where the pasted command itself is recorded.

The final phase checks temporal correlation. An analyst or agent checks if a phishing domain lookup occurred within ten minutes of the rare PowerShell execution. If the script content involves web requests or encoded strings and the timing matches the DNS activity, we confirm the compromise.

Blind Spots

This hunt has two primary limitations. It depends on PowerShell script block logging to see the actual intent of the script. If logging is disabled, we only see the command line, which attackers often truncate or obfuscate. The Run dialog check needs registry telemetry for the RunMRU key. Without it, we cannot see the pasted command once the process has exited.

Steps

  1. Query, scoping

    Rare PowerShell launched via Run dialog

    Find rare instances of PowerShell starting from Windows Explorer, which is the parent process for commands launched via the Win+R Run dialog. This step performs prevalence counting to filter out common administrative noise.

    sql, reads hb_process_activity
    SELECT process_cmd_line, device_hostname, user_name, pid, timeFROM hb_process_activityWHERE LOWER(parent_process_name) LIKE '%\\explorer.exe'  AND LOWER(process_name) LIKE '%\\powershell.exe'  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY process_cmd_lineHAVING COUNT(DISTINCT device_hostname) <= 3

    What a hit looks like. Unique command lines launched from the Run dialog. Legitimate admin activity typically clusters across several hosts, whereas ClickFix payloads are often host-specific or rare.

  2. Query, triage

    PowerShell script block content

    Retrieve full PowerShell script block text to identify obfuscation or session cookie extraction logic that may not be visible in truncated process command lines.

    sql, reads hb_script_activity
    SELECT device_hostname, script_content, script_path, timeFROM hb_script_activityWHERE script_type = 'PowerShell'  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. PowerShell script blocks containing session or cookie keywords, web client calls, or encoded payloads.

  3. Query, enrichment

    DNS activity for phishing domains

    Find DNS lookups to look-alike domains. The results allow the agent to verify if these occurred within a 10-minute window prior to the PowerShell execution.

    sql, reads hb_dns_activity
    SELECT device_hostname, query_hostname, timeFROM hb_dns_activityWHERE (instr(',' || '{{phishing_domains}}' || ',', ',' || LOWER(query_hostname) || ',') > 0 OR (LOWER(query_hostname) LIKE '%sharepoint%' AND LOWER(query_hostname) NOT LIKE '%.sharepoint.com'))  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Any resolution of look-alike domains around the time of the lead execution.

  4. Query, triage

    Run dialog command history

    Read what was pasted into the Windows Run dialog. Windows keeps each Run command in the user's RunMRU registry key, so a PowerShell, mshta or curl one-liner there is the ClickFix delivery itself, even after the process has exited.

    sql, reads hb_registry_activity
    SELECT device_hostname, actor_user_name, reg_target, reg_value_data, timeFROM hb_registry_activityWHERE LOWER(reg_target) LIKE '%\\explorer\\runmru%'  AND (LOWER(reg_value_data) LIKE '%powershell%' OR LOWER(reg_value_data) LIKE '%pwsh%' OR LOWER(reg_value_data) LIKE '%mshta%' OR LOWER(reg_value_data) LIKE '%curl%' OR LOWER(reg_value_data) LIKE '%-enc%' OR LOWER(reg_value_data) LIKE '%iex%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Rows where a user's RunMRU entry holds a PowerShell, mshta, curl or encoded command. People rarely type these into Win+R, so each row is worth reading in full.

    Stop immediate token theft and potential lateral movement.

Blind spots

  • Needs Registry value-set events for the user's Explorer RunMRU key in hb_registry_activity (for example Sysmon event 13 or an EDR registry feed). Without this audit, the 'pasting' aspect cannot be verified, leaving only the process parent and script content for analysis. It would answer: Did the PowerShell process interact with the clipboard to receive the command?
  • Needs PowerShell Script Block Logging (Event 4104). If the command line is obfuscated and script block logging is disabled, the specific exfiltration logic remains invisible. It would answer: What was the intent of the executed PowerShell script?

# Endpoint PowerShell Execution via Social Engineering

This hunt identifies ClickFix tradecraft where social engineering bypasses technical controls by convincing users to manually execute code. It identifies rare PowerShell commands launched directly from Windows Explorer (the parent of the Run dialog), retrieves the full script block content to inspect for obfuscation, and correlates these events with DNS lookups to phishing domains within a tight temporal window. An agent weighs the combined evidence of rarity, phishing navigation, and Run dialog history to identify successful session hijacking.

## powershell-via-run-dialog
<!-- Rare PowerShell launched via Run dialog -->
Find rare instances of PowerShell starting from Windows Explorer, which is the parent process for commands launched via the Win+R Run dialog. This step performs prevalence counting to filter out common administrative noise.

```sqlite target=endpoint role=scoping params=(lookback_days=lookback_days, scope_hosts=scope_hosts)
~~~yaml
baseline:
  compare: first_seen
  window: '{{lookback_days}}d'
expected: Unique command lines launched from the Run dialog. Legitimate admin activity
  typically clusters across several hosts, whereas ClickFix payloads are often host-specific
  or rare.
prevalence:
  by: device_hostname
  key:
  - process_cmd_line
  rare_below: 3
reads:
- process_cmd_line
- device_hostname
- parent_process_name
- process_name
- user_name
- pid
- time
silence: not_evidence_of_absence
source: hb_process_activity
verified: dry-run
verified_at: '2026-11-27'
~~~
SELECT process_cmd_line, device_hostname, user_name, pid, time FROM hb_process_activity WHERE LOWER(parent_process_name) LIKE '%\\explorer.exe' AND LOWER(process_name) LIKE '%\\powershell.exe' AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY process_cmd_line HAVING COUNT(DISTINCT device_hostname) <= 3
```
