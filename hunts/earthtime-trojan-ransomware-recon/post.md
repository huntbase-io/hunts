# Detecting the Transition from EarthTime Trojan to Ransomware Discovery

### Why this hunt The DFIR Report recently published Blurring the Lines: Intrusion Shows Connection With Three Major Ransomware Gangs, detailing an intrusion that highlights the speed and complexity of modern ransomware affiliates. This hunt provides a structured approach to identifying these same patterns in your own environment by focusing on the critical period between initial access and data exfiltration. ### The Hypothesis An adversary gains a foothold using a trojanized installer for the EarthTime utility. They then establish a beachhead by injecting SectopRAT into a clean MSBuild.exe process and conduct broad environment discovery using specialized tools like AdFind and Grixba to prepare for a multi-gang ransomware deployment. ### Scoping the Initial Beachhead The hunt begins on the hb_process_activity surface to identify the initial execution of the malicious EarthTime.exe file from user Downloads folders. This scoping step isolates the hosts where the infection started, allowing the analyst to focus their investigation on systems with a confirmed initial access event. By identifying these specific entry points, we can narrow the scope of the search across the rest of the fleet and prioritize systems for deeper analysis. ### Identifying Injection and Command and Control Once we identify potential beachheads, the hunt pivots to find indicators of the SectopRAT payload. We search the hb_process_activity surface for MSBuild.exe running without any command-line arguments from a download directory, which is a high-fidelity signature of the ArechClient2 injection technique. At the same time, we check the hb_network_connection surface for traffic to the C2 infrastructure identified in the report. This dual-surface check provides the context needed to confirm that an active remote access trojan is communicating with external malicious servers. ### Staging and Persistence The third phase of the hunt examines the hb_file_activity surface for staging and persistence artifacts. We look for the creation of shortcut files in the Windows Startup directory and the placement of malicious DLLs like WakeWordEngine.dll in the Users Public Music folder. Adversaries often use these non-standard paths to avoid common file monitors and maintain access without triggering standard detections. Finding these files helps reconstruct the timeline of how the intruder established their presence and prepared for the next stage of the attack. ### Discovery Tool Prevalence The final stage identifies the reconnaissance tools used to map the network. We query the hb_process_activity surface for tools such as Grixba, AdFind, and SharpHound. By using a prevalence baseline, the hunt filters out common administrative activity and focuses on tools that appear on only a few hosts across the organization. This highlights the manual and targeted nature of the adversary's discovery phase, distinguishing it from routine system management tasks. ### Blind Spots and Limitations This hunt has specific limitations that analysts should consider. We cannot see if an endpoint successfully performed a certificate revocation check for the malicious installer unless the local operating system generates specific validation logs. Additionally, while we look for MSBuild anomalies, a more sophisticated adversary might use different process injection targets or in-memory techniques that do not leave command-line artifacts. ### Running the Hunt You can run this hunt as an open hunt.md playbook by importing it into Huntbase or any compatible runtime. This logic is designed as a hunt because it relies on the correlation of multiple rare events rather than a single alert. By following the flow from initial access to discovery, you gain the context necessary to confirm a high-severity intrusion before ransomware is deployed.
