Automated Triage Reproduction Monitoring

High severity TLP:CLEAR Research by Elastic Security Labs Published 20 Sep 2026

Hypothesis

Brief

The Risk of Automation

Elastic Security Labs recently detailed their Agents vs. Agents (https://www.elastic.co/security-labs/blog/ai-vulnerability-triage-bug-bounty-hackerone) approach to bug bounty triage. They use AI to reproduce reports in ephemeral sandboxes. While efficient, this process executes untrusted, researcher-provided code. We designed this hunt to ensure these reproduction environments do not become a vector for lateral movement or data exfiltration.

Hunt Flow

The hunt begins at the ingestion point. The first phase queries the hb_vulnerability_finding surface to identify reports that reached the internal triage pipeline. We specifically look for findings tagged for validation within a defined lookback period. This step provides the timestamps and metadata necessary to scope the infrastructure search.

The second phase pivots to the cloud infrastructure and container logs. We examine hb_devices to find GCP VM provisioning events matching the triage machine types, such as e2-standard-2 or e2-standard-4 instances. Simultaneously, we query hb_process_activity for Docker Compose executions. This identifies the exact window when the reproduction container was active.

An automated assessment correlates the report ingestion time with the VM lifecycle. The triage pipeline strictly adheres to a 30-minute window for reproduction. We look for any session that exceeds this limit or lacks a corresponding report, which might indicate unauthorized infrastructure use.

The final analysis phase focuses on behavior within the VM. We query hb_script_activity for researcher-provided scripts that attempt environment discovery or container breakouts. This includes searches for access to /proc/, the Docker socket, or namespace entry commands. We also baseline hb_dns_activity to find rare domain lookups. By filtering against a strict whitelist of authorized destinations, we identify potential tunneling or exfiltration attempts.

Blind Spots

This hunt has two primary limitations. First, it lacks visibility into the internal processes of the reproduction container because the agent runs on the VM host. A kernel exploit or container escape might happen without triggering script-level logs. Second, if an adversary uses the GCP metadata service or local proxies to reach internal services, the hunt depends on host-level DNS logs. If these requests bypass DNS or if proxy logs are unavailable, the egress check remains incomplete.

    Identify which reports reached the internal triage pipeline based on the status mapping for validation.

    sql, reads hb_vulnerability_finding

    What a hit looks like. Vulnerability findings that reached the triage workflow. Their collected_at timestamps must match the subsequent GCP VM creation times.

  2. Query, enrichment

    Ephemeral triage VM provisioning

    Identify the provisioning of e2-standard-2 and e2-standard-4 instances used by the triage pipeline.

    sql, reads hb_devices
    SELECT hostname, hardware_model, cloud_instance_id, timeFROM hb_devicesWHERE (LOWER(hardware_model) LIKE '%e2-standard-2%' OR LOWER(hardware_model) LIKE '%e2-standard-4%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Device inventory rows naming the specific triage machine types. None means no such VMs were provisioned.

  3. Query, enrichment

    Docker tester container startup

    Detect the specific Docker Compose execution for the sandboxed reproduction environment.

    sql, reads hb_process_activity
    SELECT device_hostname, process_cmd_line, user_name, timeFROM hb_process_activityWHERE LOWER(process_cmd_line) LIKE '%docker-compose%'  AND LOWER(process_cmd_line) LIKE '%tester%'  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Process activity showing the startup of the tester container. Silence suggests no reproduction attempts occurred.

  4. Agent triage

    Correlate reports and provisioning

    Verify that provisioned VMs correspond to ingested reports and strictly adhere to the 30-minute window.

  5. Query, detection candidate

    Researcher-provided script activity

    Identify scripts that attempt environment discovery or escape the Docker sandbox.

    sql, reads hb_script_activity
    SELECT device_hostname, script_content, script_type, timeFROM hb_script_activityWHERE (LOWER(script_content) LIKE '%/proc/%' OR LOWER(script_content) LIKE '%docker.sock%' OR LOWER(script_content) LIKE '%nsenter%' OR LOWER(script_content) LIKE '%mount %')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Scripts performing environment enumeration or container breakout attempts. Legitimate reproductions may use these; correlation is required.

  6. Query, baseline

    Unauthorized DNS resolution prevalence

    Detect DNS queries to non-whitelisted domains that may indicate tunneling or exfiltration, stack-counted across the fleet.

    sql, reads hb_dns_activity
    SELECT LOWER(query_hostname) AS domain, COUNT(DISTINCT device_hostname) AS hosts, COUNT(*) AS lookups, MIN(time) AS first_seenFROM hb_dns_activityWHERE NOT (instr(',' || '{{whitelist_domains}}' || ',', ',' || LOWER(query_hostname) || ',') > 0)  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY LOWER(query_hostname)ORDER BY hosts ASC

    What a hit looks like. DNS queries to external domains not in the approved policy. Rare domains seen on single triage VMs indicate potential exfiltration.

  7. Agent triage

    Analyze reproduction outcomes

    Synthesize early environment data with execution behavior to identify sandbox escapes.

  8. Decision

    Route on compromise verdict

    Isolate the environment if the triage session is judged as malicious.

  9. Response action

    Shutdown compromised triage VM

    Immediately terminate the suspected VM and revoke session credentials.

  10. Analyst task

    Analyst triage review

    Verify the threat and update whitelists if the egress was part of a valid reproduction.

  11. Analyst task

    Hunt closeout

    Document findings and verify auto-shutdown reliability.

  • Needs squid proxy access logs. If host-level DNS activity misses a local metadata request, the proxy is the last line of defense; without its logs, the egress check is incomplete. It would answer: whether encrypted traffic reached internal GCP services via the proxy

# Automated Triage Reproduction Monitoring

This hunt examines the lifecycle of an automated bug bounty triage system. It correlates the ingestion of validated HackerOne reports with the provisioning of ephemeral GCP virtual machines and the subsequent execution of researcher-provided scripts. By monitoring the 30-minute reproduction window and comparing network egress against a strict whitelist, the hunt identifies sandbox escapes where untrusted code reaches internal services or unauthorized external destinations.
