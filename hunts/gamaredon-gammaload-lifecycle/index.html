Brief

Why now

Gamaredon's Gammaload Malware Sekoia recently detailed the Gammaload malware used by Gamaredon (UAC-0010) in their report "FSB’s matryoshka #2/3: Gamaredon's Gammaload Malware" (https://www.sekoia.com/blog/fsbs-matryoshka-2-3-gamaredons-gifts-that-keeps-unpacking-gammaload). The adversary uses a multi-stage chain to ensure persistence and deliver follow-on stealers.

How the hunt flows

The hunt begins by scoping the environment for Windows endpoints. It assumes the infection lifecycle targets standard Windows workstations where VBScript and PowerShell execution is common. The first investigation phase runs two parallel searches. One query looks for specific registry modifications in the HKCU\Console hive. Gammaload stores its C2 URLs in values like HistoryURL, WindowsResponBy, CloudURL, or IPURL. These keys are not commonly used by standard applications for URL storage, making them high-fidelity indicators when found on workstations. Simultaneously, the hunt checks HTTP activity for connections to known Dead Drop Resolvers (DDR) including Telegram (telegram.me), Telegraph (te.legra.ph), and others like Cloudflare Workers. It identifies randomized URL paths using specific keywords identified in the Sekoia research, such as "mosquito", "menace", or "reproof". An analyst then evaluates these results through an automated agent. The goal is to find hosts that show both the specific registry caching and the corresponding network discovery traffic. This correlation provides high confidence that an early-stage Gammaload loader is active. The second phase targets the persistent components of the infection. It searches for scheduled tasks, specifically looking for the name DsSvcCleanup or command lines that reference files with a colon, which indicates an Alternate Data Stream (ADS). It also monitors for PowerShell script blocks that disable certificate validation to download additional in-memory payloads. Finally, the hunt synthesizes all evidence. An automated agent reviews the correlated registry and network findings alongside the persistent task and PowerShell activity. This confirms the full Gammaload lifecycle.

What the hunt cannot see

This hunt relies heavily on registry and file system telemetry. If an organization does not log modifications to the HKCU registry hive, the initial C2 caching will remain invisible. Similarly, without telemetry for NTFS Alternate Data Streams, the hunt cannot confirm the presence of the hidden dropper payloads.

# Gamaredon GammaLoad Intrusion Lifecycle

This hunt targets the GammaLoad malware used by Gamaredon (UAC-0010). The malware is characterized by a multi-stage execution chain that fingerprints hosts and uses Dead Drop Resolvers (DDR) to update C2 configuration stored in the HKCU\Console registry hive. It establishes persistence by writing payloads to Alternate Data Streams (ADS) and creating scheduled tasks to execute them. The hunt follows this lifecycle from initial C2 discovery through to the regular execution of obfuscated PowerShell memory loaders.
