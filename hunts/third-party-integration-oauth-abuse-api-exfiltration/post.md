# Hunting Klue Supply Chain Integration Abuse and API Exfiltration

### Why this hunt? 10 Recent research by Datadog Security Labs in their article "Detecting the Klue supply chain attack in Salesforce" (https://securitylabs.datadoghq.com/articles/detecting-the-klue-supply-chain-attack-in-salesforce/) describes a campaign where adversaries compromised a third-party vendor to gain access to customer Salesforce environments. The attack bypasses standard perimeters because it uses valid, though often dormant, OAuth tokens. This type of supply chain compromise is difficult to detect because the traffic originates from a trusted integration. 10 10 ### Hypothesis 10 An intruder has abused a dormant Klue integration to exfiltrate Salesforce data by using compromised OAuth tokens to perform automated API harvesting. 10 10 ### Hunt Flow 10 The hunt begins with a scoping phase to identify any authentication events tied to the Klue Battlecards integration. The first query lists successful sign-ins and the associated source IP addresses from the last 14 days. This step establishes whether the integration is currently active in the tenant and identifies the primary actors. 10 10 Next, an analyst evaluates these sign-in patterns. This step uses an agent to determine if the authentication events appear suspicious, such as sign-ins from external or unexpected IPs not associated with known legitimate synchronization sources. If the integration authenticates from these anomalous origins, the hunt triggers a fan-out investigation. 10 10 The exfiltration evidence phase runs two queries in parallel to find artifacts of data harvesting. The first query searches for automated HTTP activity using Python user-agents, such as Python-urllib or the numeric 5238 string. It specifically targets Salesforce query endpoints like "/services/data/*/query". This behavior is a strong indicator of automated record harvesting rather than manual user interaction. The second query checks for direct network connections to known malicious infrastructure identified by Klue and Huntress. 10 10 Finally, the hunt correlates the initial authentication lead with the behavioral signals. A malicious verdict is reached if the integration sign-ins coincide with the automated API requests or connections to actor IPs. This triage ensures that the response focus remains on confirmed compromises. 10 10 ### Blind Spots 10 This hunt relies on visibility into Salesforce sign-in events. If the integration communicates through an intermediate gateway that does not log granular OAuth sub-types, anomalous authentication might be missed. Additionally, while the hunt identifies the behavior of data harvesting, precisely identifying every record or field accessed requires native Salesforce audit logs, such as RestApi message fields, which are out of scope for this specific playbook. 10 10 ### How to run this hunt 10 This hunt is an open-source playbook in the hunt.md format. You can import it directly into Huntbase or any other hunt.md-aware runtime. The playbook automates the logic of the initial scoping and the gated execution of the exfiltration queries, ensuring that expensive network searches only run when a suspicious authentication lead is confirmed.
