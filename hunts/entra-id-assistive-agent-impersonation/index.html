Entra ID Assistive Agent Impersonation

An adversary has gained initial access by tricking a user into consenting to an assistive agent blueprint, then used an on-behalf-of flow to execute malicious Graph API actions from a macOS-based PowerShell environment.

Brief

Why this hunt?

Red Canary recently highlighted risks in Entra ID Assistive Agents in their post: Investigating suspicious AI workflows in Microsoft Entra Agent ID: Assistive agents (https://redcanary.com/blog/threat-detection/entra-id-ai-workflows-assistive-agents/). These agents allow automated workflows to act on behalf of users, creating a stealthy path for impersonation and data exfiltration. As organizations adopt AI-driven automation, protecting the integrity of Entra Agent ID becomes critical to prevent automated workflows from being used as exfiltration channels.

How the Hunt Flows

The hunt starts with scoping. The first query on hb_software_inventory lists every macOS host running Microsoft PowerShell (pwsh) to define the target environment where the malicious execution is possible. The identity phase then pivots to hb_auth_signin logs. We search for authentications to the Microsoft Graph Command Line Tools followed by rare sign-ins to agent blueprints or assistive agents used by three or fewer users. This combination suggests a user has granted delegated permissions that an agent is now using for automated tasks. The execution phase moves to the endpoint to correlate identity risk with local activity. We examine hb_process_activity on the scoped macOS hosts to find rare PowerShell command lines that deviate from the established baseline. This activity is then corroborated with hb_network_connection logs to identify traffic reaching graph.microsoft.com or known malicious IPs. A final triage step synthesizes the identity risk, the rare macOS PowerShell execution, and the Graph network activity into a single cohesive story of impersonation.

Blind Spots

The primary limitation is telemetry depth in standard logs. Entra ID sign-in metadata may not always expose the deep agenticAppInstance flags needed to distinguish OBO flows from standard service principal usage without high-fidelity cloud-native logs. Additionally, while the hunt identifies network traffic to the Graph API, the specific intent and actions performed—such as which files were accessed or which emails were sent—remain opaque without Microsoft Graph Activity Logs, which require specific subscription tiers.

    Query · scoping

    Identify the subset of the estate where the malicious execution (PowerShell on macOS) is possible.

    reads hb_software_inventorysql

    What a hit looks like. A list of macOS hostnames with Microsoft PowerShell installed. These hosts represent the potential beachheads for the macOS execution stage.

  2. Identify Graph CLI authentication

    Query · triage

    Locate authentications to the Graph CLI application, which often precedes the local capture of authorization codes.

    reads hb_auth_signinsql
    SELECT actor_user_name, src_endpoint_ip, dst_endpoint_name, time FROM hb_auth_signin WHERE (dst_endpoint_name = '{{graph_cli_app_id}}' OR LOWER(dst_endpoint_name) LIKE '%microsoft graph command line%') AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A list of users who have authenticated to the Graph CLI. This is the pool of potentially compromised users who may have granted agent consent.

  3. Detect agentic OBO sign-in patterns

    Query · baseline

    Stack-count sign-ins to agent blueprints to find rare and suspicious assistive agent activity across the tenant.

    reads hb_auth_signinsql
    SELECT dst_endpoint_name, COUNT(DISTINCT actor_user_name) as user_count, MIN(time) as first_seen FROM hb_auth_signin WHERE (LOWER(dst_endpoint_name) LIKE '%blueprint%' OR LOWER(dst_endpoint_name) LIKE '%agent%') AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY dst_endpoint_name HAVING user_count <= 3

    What a hit looks like. Rare agent blueprint targets. While some agents are legitimate, those used by only a few users are high-priority for investigation.

  4. Evaluate early identity risk

    Agent triage

    Assess whether the Graph CLI authentication and rare agent sign-ins indicate a user impersonation event via assistive agents.

  5. Detect rare macOS PowerShell execution

    Query · baseline

    Find outlier PowerShell activity on macOS that may indicate the execution of agent-controlled tasks.

    What a hit looks like. Network activity from identified hosts to Graph API endpoints, confirming that the local execution has a corresponding cloud-side impact.

# Entra ID Assistive Agent Impersonation

This hunt targets the abuse of Microsoft Entra Agent ID, specifically the assistive agent workflow. It follows the attack chain from the initial OAuth consent for the access_agent scope to the final malicious action performed via the Graph API. The hunt identifies high-risk identity sessions and then verifies corresponding endpoint execution. We look for the correlation of unusual Entra ID sign-in patterns, specifically agentic app instances, with endpoint-side PowerShell activity on macOS and corresponding network traffic to Microsoft Graph services.
