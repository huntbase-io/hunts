# Investigating Entra ID Assistive Agent Impersonation on macOS

### Why this hunt? Red Canary recently highlighted risks in Entra ID Assistive Agents in their post: Investigating suspicious AI workflows in Microsoft Entra Agent ID: Assistive agents (https://redcanary.com/blog/threat-detection/entra-id-ai-workflows-assistive-agents/). These agents allow automated workflows to act on behalf of users, creating a stealthy path for impersonation and data exfiltration. As organizations adopt AI-driven automation, protecting the integrity of Entra Agent ID becomes critical to prevent automated workflows from being used as exfiltration channels. ### The Hypothesis An adversary gains initial access by tricking a user into consenting to an assistive agent blueprint. They then use an on-behalf-of (OBO) flow to execute malicious Graph API actions from a macOS-based PowerShell environment. This hunt targets the abuse of Microsoft Entra Agent ID by looking for the specific intersection of unusual cloud identity patterns and local execution outliers across multiple planes. ### How the Hunt Flows The hunt starts with scoping. The first query on hb_software_inventory lists every macOS host running Microsoft PowerShell (pwsh) to define the target environment where the malicious execution is possible. The identity phase then pivots to hb_auth_signin logs. We search for authentications to the Microsoft Graph Command Line Tools followed by rare sign-ins to agent blueprints or assistive agents used by three or fewer users. This combination suggests a user has granted delegated permissions that an agent is now using for automated tasks. The execution phase moves to the endpoint to correlate identity risk with local activity. We examine hb_process_activity on the scoped macOS hosts to find rare PowerShell command lines that deviate from the established baseline. This activity is then corroborated with hb_network_connection logs to identify traffic reaching graph.microsoft.com or known malicious IPs. A final triage step synthesizes the identity risk, the rare macOS PowerShell execution, and the Graph network activity into a single cohesive story of impersonation. ### Blind Spots The primary limitation is telemetry depth in standard logs. Entra ID sign-in metadata may not always expose the deep agenticAppInstance flags needed to distinguish OBO flows from standard service principal usage without high-fidelity cloud-native logs. Additionally, while the hunt identifies network traffic to the Graph API, the specific intent and actions performed—such as which files were accessed or which emails were sent—remain opaque without Microsoft Graph Activity Logs, which require specific subscription tiers. ### How to Run This is a hunt, not a simple detection, because no single event in the chain is inherently malicious. PowerShell on macOS is common in IT workflows, and Graph API access is expected for many enterprise applications. The hunt exists in the correlation of the consent event, the rare sign-in, and the rare endpoint execution. This hunt is provided as a hunt.md playbook. You can import it into any hunt.md-aware runtime or Huntbase to execute the queries and manage the triage workflow across your identity and endpoint surfaces.
