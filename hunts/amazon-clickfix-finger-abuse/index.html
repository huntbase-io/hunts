Amazon ClickFix Finger Utility Abuse

High severity TLP:CLEAR Part 1 of 2 Research by Huntress Published 22 Oct 2026

Hypothesis

An adversary has lured a user to a spoofed Amazon page and pastejacked a command that uses finger.exe to download malicious payloads from a remote domain.

Brief

The Campaign

Huntress recently published a report titled Amazon-Themed ClickFix Campaign Serves Up Finger-Licking Malware. The campaign uses SEO poisoning to drive victims to fake Amazon login pages. Once there, the site prompts the user to fix a supposed error by pasting a command into their terminal. This command abuses a legacy Windows utility to fetch malware.

How the Hunt Flows

The hunt begins with a scoping phase on the DNS surface. It queries hb_dns_activity for resolutions to known campaign infrastructure, including domains like orders-amazon.com.advancedfences.com and various BBQ-themed URLS. This step identifies which hosts in the environment interacted with the initial lure.

Next, the hunt pivots to process activity to examine the behavior of the finger utility. It specifically looks for finger.exe executions that include an @ symbol, which indicates a remote connection. It also checks for shell-escape characters such as ^, ,, or - that the adversary uses to obfuscate the command and bypass simple string-matching detections.

To catch variations that do not match known patterns, the hunt performs a prevalence stack. It counts every unique finger command line across the entire fleet and filters for those appearing on three or fewer hosts. Since finger is a legacy tool with almost no modern administrative use, rare command lines are high-probability indicators of suspicious activity.

Finally, the workflow synthesizes these leads. An analyst or agent verifies if a host resolved a malicious domain shortly before executing a suspicious finger command. This temporal correlation confirms the user was successfully pastejacked, allowing for immediate isolation of the host before the attacker deploys follow-on stealers like Doina or Lumma.

Blind Spots

This hunt has two primary blind spots. First, most environments do not log traffic on TCP port 79. Without this network visibility, the hunt can identify that finger.exe ran but cannot confirm if the payload download succeeded or what content the remote server returned. Second, without specific clipboard monitoring, the link between the browser interaction and the manual command execution relies on timing rather than a direct chain of custody.

  2. Query, detection candidate

    Obfuscated or remote finger execution

    Find finger executions that include an @ symbol for remote connections or command-line obfuscation characters used in this campaign.

    sql, reads hb_process_activity
    SELECT device_hostname, process_cmd_line, parent_process_name, timeFROM hb_process_activityWHERE (LOWER(process_name) LIKE '%finger' OR LOWER(process_name) LIKE '%finger.exe')  AND (process_cmd_line LIKE '%@%' OR instr(process_cmd_line, '^') > 0 OR instr(process_cmd_line, ',') > 0 OR instr(process_cmd_line, '-') > 0 OR instr(process_cmd_line, '_') > 0)  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A process row showing the finger utility targeting a remote user or using shell-escape characters. Silence is expected as finger is a legacy tool.

  3. Query, baseline

    Rare finger command lines

    Stack-count finger command lines to identify rare or unique activity that deviates from standard administrative use.

    What a hit looks like. Unique or rare finger commands that appear on only a few hosts. High counts likely indicate legacy scripts.

# Amazon ClickFix Finger Utility Abuse

Attackers use SEO poisoning to drive victims to a fake Amazon login page where a pastejacked command is copied to the clipboard. The command uses finger.exe to communicate with a remote server over port 79, retrieving a malicious script hidden within a .plan file. This hunt identifies the initial access and execution stages of a ClickFix campaign that uses the legacy finger.exe utility as a LOLbin. The hunt scopes for suspicious DNS resolutions to known campaign infrastructure, identifies obfuscated finger.exe executions, and uses a prevalence count to highlight rare command-line arguments across the environment.

## finger-cmdline-prevalence
<!-- Rare finger command lines -->
Stack-count finger command lines to identify rare or unique activity that deviates from standard administrative use.

```sqlite target=endpoint role=baseline params=(lookback_days=lookback_days)
~~~yaml
baseline:
  compare: first_seen
  window: '{{lookback_days}}d'
expected: Unique or rare finger commands that appear on only a few hosts. High counts
  likely indicate legacy scripts.
prevalence:
  by: device_hostname
  key:
  - process_cmd_line
  rare_below: 3
reads:
- process_cmd_line
- device_hostname
- time
silence: not_evidence_of_absence
source: hb_process_activity
verified: dry-run
verified_at: '2026-10-22'
~~~
SELECT LOWER(process_cmd_line) AS cmd, COUNT(DISTINCT device_hostname) AS hosts, MIN(time) AS first_seen FROM hb_process_activity WHERE (LOWER(process_name) LIKE '%finger' OR LOWER(process_name) LIKE '%finger.exe') AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY cmd HAVING hosts <= 3
```
