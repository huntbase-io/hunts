Unauthenticated N-central Administrator Account Creation

High severity TLP:CLEAR Research by Rapid7 Published 28 Sep 2026

Hypothesis

An intruder has exploited a routing discrepancy between Envoy and Jetty in an N-central server to bypass authentication and create a new administrative account for persistence.

Brief

Why this hunt

Rapid7 recently detailed a vulnerability chain in N-able N-central (CVE-2026-86206 and CVE-2026-86207) that allows unauthenticated administrative account creation. Because N-central is a high-privilege Remote Monitoring and Management (RMM) platform, a compromise here grants an adversary access to the entire managed estate. This makes the platform a high-value target for actors seeking broad access to multiple organizations.

How the hunt flows

The first query identifies N-central nodes across the environment. It checks the software inventory for specific package names like n-central-proxy, n-central, or dmsservice. An analyst or an automated agent confirms these results to ensure the hunt only targets active management servers. This scoping step prevents the hunt from generating noise on systems that do not run the vulnerable software. Once confirmed, the hunt runs two parallel searches to gather evidence. The first query searches HTTP activity for URIs containing semicolons, specifically targeting the /dms or /internal endpoints. This pattern indicates a direct attempt to evade the proxy and reach the backend application logic. The second query focuses on the consequences of a bypass. It stacks account creation events across the scoped hosts to find local users created on only one or two systems. This prevalence-based approach helps separate standardized administrative accounts from those created during an unauthorized intrusion. A final correlation phase links the bypass URIs to these rare account creations. If both signals appear on the same host within the same lookback window, the agent flags the activity for immediate triage. This correlation helps determine if a scanning attempt successfully reached the account creation phase.

Blind Spots

The hunt cannot see the contents of HTTP POST bodies. This means it cannot verify if the adversary invoked the specific UserTwoFactorLogin SOAP operation. The triage process relies on the observable consequence — the account creation — rather than the specific API call. Additionally, the hb_http_activity surface does not capture the Forwarded header, so the hunt infers the bypass from the URI structure and the destination host.

Steps

  1. Query, scoping

    Identify N-central management servers

    Find systems running N-central proxy or DMS components to scope the behavioral analysis.

    sql, reads hb_software_inventory
    SELECT device_hostname, package_name, package_version, install_pathFROM hb_software_inventoryWHERE (instr(',' || '{{n_central_packages}}' || ',', ',' || LOWER(package_name) || ',') > 0 OR LOWER(package_name) LIKE '%n-central%')

    What a hit looks like. A list of hosts acting as RMM management nodes. Silence indicates no N-central software is present on monitored endpoints.

  2. Agent triage

    Assess lead presence

    Confirm if the inventory results represent active RMM nodes that warrant expensive telemetry queries.

  3. Decision

    Gate on RMM presence

    Avoid running expensive web and account queries unless an RMM server is identified.

  4. Query, detection candidate

    Detect semicolon URI bypass

    Find HTTP POST requests using semicolons to bypass Envoy's prefix checks while reaching Jetty's servlets.

    sql, reads hb_http_activity
    SELECT device_hostname, src_endpoint_ip, url_path, status_code, timeFROM hb_http_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND (instr(url_path, ';') > 0)  AND (LOWER(url_path) LIKE '%/dms%' OR LOWER(url_path) LIKE '%/internal%')  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Web requests containing semicolons in paths associated with N-central services. Silence proves absence only if URIs are logged without normalization.

  5. Query, baseline

    Stack-count rare account creations

    Identify new local accounts that are unique to the RMM nodes, standing out from fleet-wide standard accounts.

    sql, reads hb_account_change
    SELECT user_name, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seenFROM hb_account_changeWHERE activity_id = 1  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY user_nameHAVING host_count <= 2ORDER BY host_count ASC

    What a hit looks like. Accounts created on very few hosts. Silence suggests no new local account activity occurred in the window.

  6. Agent triage

    Triage correlated intrusion

    Correlate the presence of bypass URIs with the creation of rare accounts to determine if an unauthenticated administrative takeover occurred.

  7. Decision

    Route on triage verdict

    Direct confirmed intrusions to immediate containment.

  8. Response action

    Isolate compromised RMM server

    Contain the threat to prevent the adversary from using the RMM to compromise downstream managed devices.

  9. Analyst task

    Manual forensic review

    Verify the agent's correlation and check for lateral movement into the managed fleet.

  10. Analyst task

    Close out

    Document the hunt outcome and any observed scanning activity.

Blind spots

  • Needs hb_software_inventory on the N-central host. A host missing software inventory might be skipped by the scoping lead, leading to a false negative for that host. It would answer: whether N-central servers can be correctly identified
  • Needs hb_http_activity capturing the Forwarded header. The hb_http_activity surface does not record the Forwarded header, so the bypass is inferred only from the URI pattern. It would answer: whether the spoofed local-address header (127.0.0.\1) was present
  • Needs POST body telemetry. The operation name is carried in the POST body, which is not captured by hb_http_activity. Triage must rely on the subsequent account creation. It would answer: whether the UserTwoFactorLogin SOAP operation was invoked

# Unauthenticated N-central Administrator Account Creation

This hunt targets the authentication bypass chain in N-able N-central (CVE-2026-86206 and CVE-2026-86207). It uses a gated flow to first identify hosts running the N-central RMM platform. Once confirmed, it parallelizes a behavioral search for semicolon-decorated URIs—which evade Envoy proxy rules—and a prevalence-based search for rare account creations across those same hosts. An agent then correlates these signals to identify successful administrative takeover.

<!-- Identify N-central management servers -->
Find systems running N-central proxy or DMS components to scope the behavioral analysis.

```sqlite target=endpoint role=scoping params=(n_central_packages=n_central_packages)
~~~yaml

  software is present on monitored endpoints.

- install_path

```

## rare-account-creation
<!-- Stack-count rare account creations -->
Identify new local accounts that are unique to the RMM nodes, standing out from fleet-wide standard accounts.

```sqlite target=endpoint role=baseline params=(scope_hosts=scope_hosts, lookback_days=lookback_days)
~~~yaml
baseline:
  compare: first_seen
  window: '{{lookback_days}}d'
expected: Accounts created on very few hosts. Silence suggests no new local account
  activity occurred in the window.
prevalence:
  by: device_hostname
  key:
  - user_name
  rare_below: 2
reads:
- user_name
- device_hostname
- time
silence: evidence_of_absence
source: hb_account_change
verified: dry-run
verified_at: '2026-09-28'
~~~
SELECT user_name, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seen FROM hb_account_change WHERE activity_id = 1 AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY user_name HAVING host_count <= 2 ORDER BY host_count ASC
```

## analyst-review
<!-- Manual forensic review -->
```manual target=analyst
Review the identified HTTP requests and rare account creations. Determine if the new user performed any downstream RMM actions (script deployment, agent installs).
```
→ close-out

## close-out
<!-- Close out -->
```manual target=analyst
Document which N-central hosts were scanned and any behavioral anomalies found. If only bypass attempts were found without account changes, report as unsuccessful scanning.
```
