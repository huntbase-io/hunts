Unauthenticated N-central Administrator Account Creation

An intruder has exploited a routing discrepancy between Envoy and Jetty in an N-central server to bypass authentication and create a new administrative account for persistence.

Brief

Why this hunt

Rapid7 recently detailed a vulnerability chain in N-able N-central (CVE-2026-86206 and CVE-2026-86207) that allows unauthenticated administrative account creation. Because N-central is a high-privilege Remote Monitoring and Management (RMM) platform, a compromise here grants an adversary access to the entire managed estate. This makes the platform a high-value target for actors seeking broad access to multiple organizations.

How the hunt flows

The first query identifies N-central nodes across the environment. It checks the software inventory for specific package names like n-central-proxy, n-central, or dmsservice. An analyst or an automated agent confirms these results to ensure the hunt only targets active management servers. This scoping step prevents the hunt from generating noise on systems that do not run the vulnerable software. Once confirmed, the hunt runs two parallel searches to gather evidence. The first query searches HTTP activity for URIs containing semicolons, specifically targeting the /dms or /internal endpoints. This pattern indicates a direct attempt to evade the proxy and reach the backend application logic. The second query focuses on the consequences of a bypass. It stacks account creation events across the scoped hosts to find local users created on only one or two systems. This prevalence-based approach helps separate standardized administrative accounts from those created during an unauthorized intrusion. A final correlation phase links the bypass URIs to these rare account creations. If both signals appear on the same host within the same lookback window, the agent flags the activity for immediate triage. This correlation helps determine if a scanning attempt successfully reached the account creation phase.

Blind Spots

The hunt cannot see the contents of HTTP POST bodies. This means it cannot verify if the adversary invoked the specific UserTwoFactorLogin SOAP operation. The triage process relies on the observable consequence — the account creation — rather than the specific API call. Additionally, the hb_http_activity surface does not capture the Forwarded header, so the hunt infers the bypass from the URI structure and the destination host.

# Unauthenticated N-central Administrator Account Creation

This hunt targets the authentication bypass chain in N-able N-central (CVE-2026-86206 and CVE-2026-86207). It uses a gated flow to first identify hosts running the N-central RMM platform. Once confirmed, it parallelizes a behavioral search for semicolon-decorated URIs—which evade Envoy proxy rules—and a prevalence-based search for rare account creations across those same hosts. An agent then correlates these signals to identify successful administrative takeover.

## rare-account-creation
<!-- Stack-count rare account creations -->
Identify new local accounts that are unique to the RMM nodes, standing out from fleet-wide standard accounts.

```sqlite target=endpoint role=baseline params=(scope_hosts=scope_hosts, lookback_days=lookback_days)
~~~yaml

  compare: first_seen
  window: '{{lookback_days}}d'
expected: Accounts created on very few hosts. Silence suggests no new local account
  activity occurred in the window.
prevalence:
  by: device_hostname
  key:
  - user_name
  rare_below: 2
reads:
- user_name
- device_hostname
- time
silence: evidence_of_absence
source: hb_account_change
verified: dry-run
```
