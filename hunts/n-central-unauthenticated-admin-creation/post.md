# N-able N-central Unauthenticated Administrator Account Creation

### Why this hunt Rapid7 recently detailed a vulnerability chain in N-able N-central (CVE-2026-86206 and CVE-2026-86207) that allows unauthenticated administrative account creation. Because N-central is a high-privilege Remote Monitoring and Management (RMM) platform, a compromise here grants an adversary access to the entire managed estate. This makes the platform a high-value target for actors seeking broad access to multiple organizations. ### The Hypothesis An intruder exploits a routing discrepancy between the Envoy proxy and the Jetty backend. The adversary uses semicolon-decorated URIs to bypass Envoy’s prefix-based access controls and reach sensitive internal APIs. This access allows the adversary to invoke specific SOAP operations that create a new administrative account, providing persistent access to the RMM server. ### How the hunt flows The first query identifies N-central nodes across the environment. It checks the software inventory for specific package names like n-central-proxy, n-central, or dmsservice. An analyst or an automated agent confirms these results to ensure the hunt only targets active management servers. This scoping step prevents the hunt from generating noise on systems that do not run the vulnerable software. Once confirmed, the hunt runs two parallel searches to gather evidence. The first query searches HTTP activity for URIs containing semicolons, specifically targeting the /dms or /internal endpoints. This pattern indicates a direct attempt to evade the proxy and reach the backend application logic. The second query focuses on the consequences of a bypass. It stacks account creation events across the scoped hosts to find local users created on only one or two systems. This prevalence-based approach helps separate standardized administrative accounts from those created during an unauthorized intrusion. A final correlation phase links the bypass URIs to these rare account creations. If both signals appear on the same host within the same lookback window, the agent flags the activity for immediate triage. This correlation helps determine if a scanning attempt successfully reached the account creation phase. ### Blind Spots The hunt cannot see the contents of HTTP POST bodies. This means it cannot verify if the adversary invoked the specific UserTwoFactorLogin SOAP operation. The triage process relies on the observable consequence — the account creation — rather than the specific API call. Additionally, the hb_http_activity surface does not capture the Forwarded header, so the hunt infers the bypass from the URI structure and the destination host. ### How to run it This hunt is an open hunt.md playbook. You can import it into Huntbase or any security platform that supports the hunt.md format. The playbook includes the specific scoping logic, behavioral queries, and correlation steps needed to identify this activity. We recommend running this against any environment where N-central manages client assets.
