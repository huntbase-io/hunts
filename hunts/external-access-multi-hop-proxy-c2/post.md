# Hunting External Access and Multi-Hop Proxy C2 During Staffing Gaps

### Why this hunt  Recent analysis by Huntress in their article Operational Resilience: IT Security Risks with Reduced Staffing (https://www.huntress.com/blog/operational-resilience-reduced-staffing-risks) highlights how adversaries capitalize on holiday windows. When fewer analysts are on the clock, dwell times often increase. This hunt addresses that gap by proactively looking for the intersection of high-risk vulnerabilities and suspicious outbound command-and-control traffic.   ### The Hypothesis  An adversary exploits unpatched internet-facing vulnerabilities or phishes users to establish multi-hop proxy C2, banking on reduced holiday staffing to delay detection and response.   ### How the hunt flows  The hunt begins by scoping the environment for unpatched critical vulnerabilities. The first query checks the vulnerability surface for any active findings with a high severity rating. An agent then evaluates these results to determine if the exposure warrants further investigation, focusing on internet-facing or widely distributed assets that represent the most significant risk.   If the agent identifies high-risk exposure, the hunt moves into a parallel behavioral analysis phase. One branch monitors the process surface for phishing execution patterns, specifically looking for productivity applications that spawn command interpreters like PowerShell or cmd.exe. Simultaneously, a second branch examines the network surface for rare outbound connections to known proxy and Tor ports. This two-pronged approach catches both the initial delivery and the subsequent C2 establishment.   In the final phase, an agent correlates the vulnerability findings with the behavioral evidence. If a host shows both a critical exposure and suspicious activity, the playbook can trigger an automated isolation action. This provides immediate containment during periods when a human analyst might not be available to respond instantly to every alert.   ### Beyond Detection  Standard detection rules fire on specific Tor domains or ngrok indicators. This hunt goes further by pivoting across three distinct data surfaces—vulnerabilities, process execution, and network egress—to find intrusions that individual rules often miss. By weighting behavioral alerts based on the underlying vulnerability exposure of the host, we reduce noise and find the true signals of compromise that require immediate attention.   ### What the hunt cannot see  This hunt relies on recent vulnerability scan data. If a scan failed or the data is stale, the initial scoping might miss new exposures. On the network side, the hunt focuses on explicit proxy ports such as 9050 or 8080. If an adversary tunnels C2 traffic over port 443 using standard HTTPS, this hunt will not identify that traffic without additional TLS fingerprinting or deep packet analysis.   ### How to run it  This hunt is an open hunt.md playbook. You can import it into Huntbase or any runtime that supports the hunt.md specification. It is designed to run periodically, especially during holiday periods or scheduled staffing reductions, to maintain operational resilience when your security team is lean.
