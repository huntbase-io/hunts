# Hunting AI-Generated Scripts and Automated Credential Scraping

### The Shift to AI-Assisted Attacks. Unit 42 recently detailed how threat actors use artificial intelligence to plan and execute cybercrime in their report, “Next Exploit Opportunities” (https://unit42.paloaltonetworks.com/ai-assisted-cybercrime-analysis/). This shift lowers the barrier for entry, allowing attackers to generate functional reverse shells and automated scraping scripts with minimal manual effort. Our team developed this hunt to identify the specific footprints left by these AI-generated toolsets. ### The Hypothesis. An intruder deploys AI-generated scripts to establish persistent reverse shells and automate the discovery of sensitive environment files or API keys. The actor coordinates this activity through a centralized command-and-control infrastructure, using the generated scripts to bridge the gap between initial access and full host compromise. ### Scoping the Network Lead. The hunt begins by examining network connection logs for any host communicating with known actor-controlled IP addresses. We use specific infrastructure leads, such as 162.243.3.92, to establish an initial scope. This first phase acts as a gate; if the hunt identifies network communication, it automatically narrows the subsequent, more intensive behavioral checks to those specific hosts to reduce noise and processing time. ### Deep Dive into Scripting and Utilities. In the second phase, the hunt examines script block activity for patterns indicative of AI-generated shells. We look for the presence of socket-related objects in PowerShell and VBScript, specifically targeting code that attempts to bridge standard input and output with a network connection. Since AI often generates functional but recognizable templates for these tasks, searching for specific .NET classes provides a high-confidence signal for manual review. ### Analyzing Process Execution. The hunt also monitors the execution of networking utilities and command-line shells. We focus on tools like ncat or PowerShell instances using encoded command arguments. These utilities often facilitate the tunneling or execution phases of the intrusion. By correlating the use of these tools with the initial network leads, an analyst can quickly determine if the activity represents a legitimate administrative session or an active exploit. ### Baselining Sensitive File Access. A fleet-wide prevalence check identifies rare access to sensitive files, such as .env files, SSH keys, or cloud provider credentials. Automated scraping tools generated by AI often perform broad searches for these secrets across the file system. The hunt calculates a baseline for file access events and highlights instances where an unusual process reads a sensitive file on fewer than three hosts in the environment. This helps isolate automated theft from standard system operations. ### Blind Spots and Limitations. Several blind spots exist within this hunt design. The scoping phase relies on agent-based network logging; endpoints missing this visibility will not trigger the initial gate. Additionally, if an adversary uses significant obfuscation or splits their AI-generated scripts across multiple execution blocks, keyword-based searches for socket objects may fail. Analysts should ensure comprehensive script block logging is enabled to maximize the effectiveness of the behavioral checks. ### Running the Hunt. This hunt is published as a hunt.md playbook. It integrates directly into Huntbase or any runtime capable of parsing the hunt.md format. To run it, import the playbook and provide the relevant lookback period. The results provide a prioritized list of hosts with synthesized evidence from network, process, and script activity, allowing for rapid triage and isolation of compromised systems.
