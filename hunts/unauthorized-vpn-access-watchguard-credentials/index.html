Unauthorized VPN Access via Stolen WatchGuard Credentials

Adversaries are using credentials stolen from lookalike WatchGuard VPN download sites to authenticate to corporate VPNs from anomalous geographic regions or hosting provider IP space.

Brief

The Threat

Huntress recently detailed a campaign where attackers use lookalike WatchGuard download sites to harvest VPN credentials (https://www.huntress.com/blog/fake-watchguard-vpn-credential-phishing). These sites deliver legitimate installers while silently exfiltrating cleartext passwords. Once they obtain credentials, the adversaries attempt to establish a foothold within the corporate network.

Adversaries use credentials stolen from lookalike WatchGuard VPN download sites to authenticate to corporate VPNs from anomalous geographic regions or hosting provider IP space. Because these logins use valid credentials, they often bypass traditional security controls that do not account for behavioral shifts post-authentication.

How the Hunt Flows

The first phase identifies every active VPN gateway in the environment. The hunt queries authentication logs for service names and destination endpoints containing VPN-related keywords. This scoping step ensures the analyst focuses only on the systems acting as the perimeter entry point for remote users.

In the second phase, the hunt runs a parallel analysis of source rarity and user behavior. One branch stack-counts successful VPN logins by country and city to find locations associated with three or fewer users. A second branch collects high-impact cloud API operations, such as creating, updating, or deleting resources, performed during the lookback window.

The final phase correlates these findings. An analyst evaluates whether a login from a rare country or a known proxy precedes significant cloud modifications. This correlation reduces the false positives typical of simple geo-fencing by requiring evidence of impactful activity following the suspicious login. If the session appears unauthorized, the hunt provides a path to revoke the session and lock the account.

Blind Spots

This hunt relies entirely on the ingestion of VPN gateway authentication logs into a central data lake. If an organization runs an unmonitored appliance or an external service that does not export sign-in events, the hunt cannot see the access.

Additionally, attackers increasingly use residential proxy services to mimic the home networks of legitimate users. If an adversary uses a residential IP located in the same country or city as the victim, the statistical rarity check may fail to trigger. Identifying these sessions requires advanced IP reputation data that distinguishes residential ISPs from commercial data centers.

Steps

  1. Identify Active VPN Gateways

    Query · scoping

    Identify the hostnames and service names acting as VPN gateways to scope the subsequent behavioral analysis.

    reads hb_auth_signinsql
    SELECT DISTINCT device_hostname, service_name, dst_endpoint_name FROM hb_auth_signin WHERE (LOWER(service_name) LIKE '%vpn%' OR LOWER(dst_endpoint_name) LIKE '%vpn%' OR LOWER(logon_process_name) LIKE '%vpn%') AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A list of hostnames reporting VPN-related authentication. Silence indicates no VPN logs matched the keywords.

  2. Rare VPN Source Locations

    Query · baseline

    Stack-count VPN logins by country and city to identify successful authentications from locations that are statistically rare for the organization.

    reads hb_auth_signinsql
    SELECT src_location_country, src_location_city, is_proxy, COUNT(DISTINCT actor_user_name) AS user_count, COUNT(*) AS login_count FROM hb_auth_signin WHERE activity_id = 1 AND status_id = 1 AND (LOWER(service_name) LIKE '%vpn%' OR LOWER(dst_endpoint_name) LIKE '%vpn%') AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY src_location_country, src_location_city, is_proxy HAVING user_count <= 3

    What a hit looks like. VPN logins from countries or cities with very few associated users. Large user counts indicate known regional offices or remote work hubs.

  3. Post-Authentication Cloud Actions

    Query · enrichment

    Identify administrative or impactful cloud API operations that occurred after a user logged in, which may indicate an attacker using the session.

    reads hb_cloud_api_activitysql
    SELECT actor_user_name, src_endpoint_ip, api_operation, api_service_name, resource_name, status, time FROM hb_cloud_api_activity WHERE activity_id IN (1, 3, 4) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Create, Update, or Delete API calls. These are enriched for the analyst to correlate with rare VPN logins.

  4. Triage Suspected Sessions

    Agent triage

    Evaluate whether the VPN logins are unauthorized by correlating location rarity and subsequent cloud actions per user.

  5. Route on Access Verdict

    Decision

    Direct high-confidence compromises to containment and uncertain cases to manual analyst review.

  6. Revoke Compromised Session

    Response action

    Immediately terminate the suspected unauthorized access to prevent further damage.

  7. Analyst Verification

    Analyst task

    Perform a deeper investigation into the user's activity to ensure no other internal resources were accessed.

  8. Hunt Closure

    Analyst task

    Document findings and update any baselines or watchlists for future monitoring.

# Unauthorized VPN Access via Stolen WatchGuard Credentials

This hunt examines the identity plane for unauthorized VPN sessions that match the Storm-2561 phishing profile. It looks for successful authentications from rare countries or proxies, then fans out to correlate those sessions with potentially sensitive administrative actions in the cloud. By weighing the source rarity against the user's subsequent behavior, an agent can identify session hijacking or credential abuse that bypasses standard login rules. This hunt focuses on the initial access stage where stolen credentials are used to bypass the perimeter.
