# Hunting Certutil Payload Delivery and Rare PowerShell Execution

### The Persistence of Living-off-the-Land 10 10Elastic Security Labs discusses the evolution of detection in Why 2026 is the Year to Upgrade to an Agentic AI SOC (https://www.elastic.co/security-labs/blog/why-2026-is-the-year-to-upgrade-to-an-agentic-ai-soc). This hunt focuses on the persistent challenge of Living-off-the-Land (LotL) binaries. Attackers frequently use signed Microsoft tools like certutil.exe to blend in with administrative traffic and bypass perimeter filters. 10 10### The Hypothesis 10 10An adversary exploits an internet-facing application to execute certutil.exe. They use this binary to proxy payload downloads from malicious infrastructure and then execute the payload using rare, encoded PowerShell script blocks. By chaining these behaviors, the adversary avoids writing suspicious new files to disk until the final execution stage. 10 10### How the Hunt Flows 10 10The hunt begins on the DNS surface. A query scans for any instance of certutil.exe resolving domains known for command-and-control or payload hosting. This lead query provides a cost-effective way to filter the fleet before committing to more resource-intensive investigations. If the query identifies suspicious resolutions, an agent evaluates the hosts to determine if the activity appears unauthorized. 10 10Once the hunt identifies suspicious hosts, it fans out to search for preceding and succeeding evidence. It looks for successful HTTP responses involving dynamic file extensions like .php, .jsp, or .asp, which suggest a web exploit served as the entry vector. Simultaneously, the hunt baselines PowerShell script activity across the fleet. It isolates encoded script blocks that appear on only a handful of systems, pointing toward unique malicious payloads rather than standard enterprise scripts. 10 10In the final phase, an agent correlates the timelines across the DNS, HTTP, and script surfaces. If a web exploit attempt leads to a certutil download which then triggers an encoded PowerShell block, the agent marks the host for isolation. This multi-surface correlation reduces the false positives typically associated with monitoring individual LolBins. 10 10### Visibility and Limitations 10 10The hunt depends on endpoint DNS logging. If a host resolves a malicious domain via local cache, the lead query will not see the activity. Furthermore, the hunt requires PowerShell Script Block Logging to decode and analyze the final execution stage. Without it, the content of the payload remains invisible. Finally, unmanaged servers in the DMZ that lack EDR coverage represent a significant visibility gap where an adversary could stage payloads unmonitored. 10 10### How to Run the Hunt 10 10This hunt is an open hunt.md playbook. Analysts can import it into Huntbase or any compatible hunt.md-aware runtime. The playbook includes the logic to automate the initial scoping and the multi-surface correlation, allowing human responders to focus on the final verdict and remediation steps. 10
