Bypass of Legacy Identity Controls and Persistence via NHIs

Brief

Why identity resilience matters

Proofpoint recently published 18 Outdated Identity And Access Management Assumptions To Retire, highlighting how traditional security boundaries have dissolved. Static MFA and permanent administrative rights create a false sense of security. Modern attackers do not break in; they log in using stolen sessions or by exhausting users through MFA fatigue. This hunt provides a structured way to verify if these identity-centric defenses are holding or if an intruder has already pivoted to persistent, non-human identities.

How the Hunt Flows

The hunt starts by scoping the environment for remote access gateways. It queries the software inventory for VPN and remote access packages to determine which hosts serve as the primary entry points for external traffic. Once gateways are identified, the hunt runs parallel queries to detect initial access anomalies. One query looks for MFA push fatigue: a sequence of multiple authentication failures followed by a single success for the same user and IP. Another query checks for outbound connections to known VPN indicators of compromise. An analyst triages these leads to confirm suspicious entry. This verdict then triggers the persistence phase. The hunt searches for rare sign-ins from non-human identities (NHIs) like service accounts or bots. It baselines these accounts to find instances where they appear on an unusual number of hosts or from new source IPs. Finally, the hunt pulls an inventory of standing administrative accounts. An agent correlates the initial access findings with any subsequent NHI or admin activity. If an account compromised via push fatigue is seen using service account credentials from the same infrastructure, the analyst confirms a malicious linkage.

Blind Spots

The hunt cannot determine if a specific session token was hijacked from a trusted device without debug-level IDP logs that track session identifiers. We also face a visibility gap regarding Just-In-Time (JIT) elevations. Without JIT logs, we cannot distinguish between a malicious actor using standing admin rights and a legitimate administrator performing unscheduled maintenance.

  1. Identify Remote Access Gateways

    Query · scoping

    Identify hosts running VPN or remote access software to focus the later network traffic analysis.

    reads hb_software_inventorysql
    SELECT DISTINCT device_hostname, package_name, package_version FROM hb_software_inventory WHERE (LOWER(package_name) LIKE '%checkpoint%' OR LOWER(package_name) LIKE '%vpn%')

    What a hit looks like. A list of hosts acting as remote gateways. Silence indicates no managed VPN software is recorded in inventory.

  2. Patterns of MFA Push Fatigue

    Query · detection candidate

    Identify accounts experiencing high failure rates followed by a successful login, typical of push fatigue.

    reads hb_auth_signinsql
    SELECT actor_user_name, src_endpoint_ip, activity_id, COUNT(*) AS count, MIN(time) AS first_event, MAX(time) AS last_event FROM hb_auth_signin WHERE activity_id IN (1, 5) AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY actor_user_name, src_endpoint_ip, activity_id

    What a hit looks like. High failure counts (activity_id 5) coupled with a final success (activity_id 1) for the same user and IP.

  3. Connections to VPN IOC Domains

    Query · enrichment

    Corroborate whether identified gateways or other hosts are communicating with the reported VPN IOC domain.

    reads hb_network_connectionsql
    SELECT time, device_hostname, dst_endpoint_hostname, dst_endpoint_ip, dst_endpoint_port FROM hb_network_connection WHERE instr(',' || '{{vpn_domains}}' || ',', ',' || LOWER(dst_endpoint_hostname) || ',') > 0 AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Outbound traffic to vpn.com or related domains from internal hosts. Silence indicates no traffic to these domains in the window.

  4. Triage Initial Access Lead

    Agent triage

    Evaluate whether the MFA patterns and network traffic indicate a successful session hijack or gateway compromise.

  5. Rare Non-Human Identity Sign-ins

    Query · baseline

    Identify service accounts signing in from unusual or rare source IPs, which may indicate attacker reuse.

    reads hb_auth_signinsql
    SELECT actor_user_name, src_endpoint_ip, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seen FROM hb_auth_signin WHERE (LOWER(actor_user_name) LIKE 'svc_%' OR LOWER(actor_user_name) LIKE '%bot%') AND time >= datetime('now', '-{{lookback_days}} days') GROUP BY actor_user_name, src_endpoint_ip HAVING host_count < 3

    What a hit looks like. Service accounts appearing on a small number of hosts or new IPs. Silence means no service accounts matched naming patterns in the window.

  6. Inventory of Standing Administrative Privileges

    Query · enrichment

    Retrieve a list of accounts with permanent administrative roles to cross-reference with early-stage anomalies.

    reads hb_userssql
    SELECT id, name, email, privileged, status, provider FROM hb_users WHERE (LOWER(privileged) = 'true') AND status = 'active'

    What a hit looks like. A list of standing administrators. The agent will compare these against identities performing suspicious transactions.

  7. Triage Identity Persistence

    Agent triage

    Correlate early access anomalies with follow-on service account and admin activity to confirm an ongoing threat.

  8. Route on Persistence Verdict

    Decision

    Direct the response based on whether a confirmed identity compromise has reached the persistence phase.

  9. Suspend Compromised Accounts

    Response action

    Immediately revoke access for compromised users and service accounts to stop further lateral movement.

  10. IAM Governance Review

    Analyst task

    Perform a broader audit to identify systematic failures in identity resilience and governance.

  11. Hunt Close-out

    Analyst task

    Document findings and telemetry gaps discovered during the hunt.

# Bypass of Legacy Identity Controls and Persistence via NHIs

An adversary steals active sessions or triggers push fatigue to bypass traditional authentication hurdles. The hunt first identifies internet-facing gateways and scans for high-frequency MFA failures that culminate in a single success. By correlating these access anomalies with the behavior of non-human identities and standing administrative accounts, the hunt identifies identities an intruder has repurposed for persistence. An analyst then reviews the linked chain of events to revoke compromised credentials and recommend phishing-resistant controls.
