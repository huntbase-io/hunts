# Hunting Identity Bypass and Non-Human Identity Persistence

### Why identity resilience matters. Proofpoint recently published 18 Outdated Identity And Access Management Assumptions To Retire, highlighting how traditional security boundaries have dissolved. Static MFA and permanent administrative rights create a false sense of security. Modern attackers do not break in; they log in using stolen sessions or by exhausting users through MFA fatigue. This hunt provides a structured way to verify if these identity-centric defenses are holding or if an intruder has already pivoted to persistent, non-human identities. ### The Hypothesis. An intruder has bypassed traditional MFA via session hijacking or push fatigue and established persistence using overprivileged non-human identities or standing administrative accounts. The adversary relies on the fact that most organizations monitor the front door but lose visibility once an actor assumes the identity of a service account or an always-on admin. ### How the Hunt Flows. The hunt starts by scoping the environment for remote access gateways. It queries the software inventory for VPN and remote access packages to determine which hosts serve as the primary entry points for external traffic. Once gateways are identified, the hunt runs parallel queries to detect initial access anomalies. One query looks for MFA push fatigue: a sequence of multiple authentication failures followed by a single success for the same user and IP. Another query checks for outbound connections to known VPN indicators of compromise. An analyst triages these leads to confirm suspicious entry. This verdict then triggers the persistence phase. The hunt searches for rare sign-ins from non-human identities (NHIs) like service accounts or bots. It baselines these accounts to find instances where they appear on an unusual number of hosts or from new source IPs. Finally, the hunt pulls an inventory of standing administrative accounts. An agent correlates the initial access findings with any subsequent NHI or admin activity. If an account compromised via push fatigue is seen using service account credentials from the same infrastructure, the analyst confirms a malicious linkage. ### Blind Spots. The hunt cannot determine if a specific session token was hijacked from a trusted device without debug-level IDP logs that track session identifiers. We also face a visibility gap regarding Just-In-Time (JIT) elevations. Without JIT logs, we cannot distinguish between a malicious actor using standing admin rights and a legitimate administrator performing unscheduled maintenance. ### How to Run This Hunt. This hunt is an open hunt.md playbook. You can import it into Huntbase or any runtime that supports the hunt.md standard. The flow is designed to be iterative, using two triage stages to ensure that high-volume authentication data is filtered before deep correlation begins.
