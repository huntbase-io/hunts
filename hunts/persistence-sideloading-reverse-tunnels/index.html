Persistence via Sideloading and Reverse Tunnels

High severity TLP:CLEAR Part 2 of 2 Research by Huntress Published 12 Nov 2026

Hypothesis

An attacker has established persistence using ClickFix-dropped batch scripts that install DLL sideloading implants and reverse SSH tunnels to maintain long-term access.

Brief

Why this hunt

The Huntress team recently detailed the progression of ClickFix campaigns in their article, "The evolving tradecraft of ClickFix" (https://www.huntress.com/blog/the-evolving-tradecraft-of-clickfix). While early stages of these attacks rely on social engineering and clipboard manipulation, the endgame involves durable persistence. Adversaries now deploy batch scripts to stage DLL sideloading implants and maintain access through reverse SSH tunnels. This hunt finds these persistent footholds by looking for specific registry artifacts and behavioral anomalies.

Hunt Flow

The hunt begins by inspecting registry activity to identify new or modified Run keys. The query specifically targets keys that point to the ProgramData directory or use campaign-specific value names like CertEnrollCtrl_Y0db6oZq9, LockScreenContentServer_qQrRrJiHX, or DuskDesk. Staging in ProgramData allows the adversary to maintain persistence across reboots while staying hidden in a directory often overlooked by casual inspection.

Next, the hunt pivots into a parallel investigation of module loads and network connections. The module query performs a stack-count on DLLs loaded from ProgramData subdirectories. It looks for rare modules—those appearing on three or fewer hosts—to identify potential sideloading. When an adversary sideloads a DLL, they often place it in a unique folder alongside a legitimate executable. By identifying these outliers across the fleet, we can isolate implants that use unique file names for every victim.

Simultaneously, the network query checks for connections to known reverse-tunnel infrastructure and C2 IPs. This step focuses on connections originating from processes frequently used to bridge network traffic, such as node.exe or powershell.exe. The presence of a connection to a known tunnel IP, combined with an unusual parent process, strongly suggests an active reverse shell or proxy.

An automated agent then triages these findings. It evaluates whether the registry persistence, rare module loads, and network activity occur on the same host. The agent assigns a verdict of malicious, suspicious, or benign based on the intersection of these behaviors. This correlation reduces the noise inherent in registry-only detections and ensures analysts focus on hosts where the full lifecycle of the implant is visible.

Blind Spots

This hunt relies on endpoint visibility via registry and module load telemetry. If a host lacks an agent or EDR coverage, the persistence artifacts remain invisible even if the host participates in a reverse tunnel. Furthermore, if PowerShell Script Block Logging is disabled, analysts cannot inspect the contents of ephemeral scripts like r.ps1 used to establish the tunnel.

Steps

  1. Query, detection candidate

    ProgramData Run key persistence

    Find Run keys that point to scripts or binaries staged in ProgramData, matching specific campaign patterns.

    sql, reads hb_registry_activity
    SELECT device_hostname, reg_target, reg_value_data, reg_value_name, timeFROM hb_registry_activityWHERE (LOWER(reg_target) LIKE '%\currentversion\run%' OR LOWER(reg_target) LIKE '%\currentversion\runonce%')  AND (LOWER(reg_value_data) LIKE '%c:\programdata\%' OR instr(',' || '{{target_run_paths}}' || ',', ',' || reg_value_name || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A Run key pointing to a ProgramData path or using a known campaign value name. Silence means no such persistence was identified via Registry.

  2. Query, baseline

    Rare modules loaded from ProgramData

    Stack-count module loads from ProgramData to identify rare DLLs that may be sideloaded.

    sql, reads hb_module_activity
    SELECT module_name, module_path, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_loadFROM hb_module_activityWHERE LOWER(module_path) LIKE 'c:\programdata\%'  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY module_name, module_pathHAVING host_count <= 3ORDER BY host_count ASC

    What a hit looks like. A module load from a ProgramData subdirectory occurring on only a few hosts across the fleet.

  3. Query, enrichment

    Network connections to tunnel infrastructure

    Match network connections to known ClickFix and reverse SSH tunnel infrastructure.

    sql, reads hb_network_connection
    SELECT device_hostname, process_name, dst_endpoint_ip, dst_endpoint_port, timeFROM hb_network_connectionWHERE instr(',' || '{{c2_ips}}' || ',', ',' || dst_endpoint_ip || ',') > 0  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. A host connecting to a known tunnel IP, especially via processes like node.exe or powershell.exe.

  4. Agent triage

    Triage implants and tunnels

    Evaluate whether the persistence mechanisms, rare module loads, and network activity together indicate a successful ClickFix implant.

  5. Decision

    Route on verdict

    Take containment action on malicious hosts or route to manual review.

  6. Response action

    Isolate compromised host

    Halt C2 communication and prevent lateral movement.

  7. Analyst task

    Analyst forensic review

    Verify the findings and collect evidence from the ProgramData staging path.

  8. Analyst task

    Hunt close-out

    Document results and findings.

# Persistence via Sideloading and Reverse Tunnels

This hunt targets the persistent phase of ClickFix campaigns where initial script execution leads to established footholds. It focuses on non-standard Registry Run keys pointing to ProgramData staging paths, identifies rare module loads that indicate DLL sideloading, and corroborates these findings with network connections to known reverse-tunnel infrastructure. An agent weighs the persistence, module prevalence, and network telemetry to identify compromised hosts.

