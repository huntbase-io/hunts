Brief

Why now

Elastic Security Labs recently detailed REVSTEALER, an infostealer that harvests credentials and deploys impact modules. The adversary targets users of common gaming and communication software. They use resilient blockchain-based infrastructure for command and control. We published this hunt to address the specific behaviors and persistence mechanisms identified in their report: REVSTEALER ramps up: analysis of up-and-coming infostealer (https://www.elastic.co/security-labs/threat-command/revstealer-credential-harvesting-infostealer).

How the hunt flows

The hunt begins with an inventory of targeted software. The first query searches the fleet for packages like Slack, Steam, or qBittorrent. This narrowed list focuses the subsequent analysis on high-risk workstations where lures or targets already exist.

The second phase runs three concurrent queries to corroborate malicious behavior. The file activity query looks for processes reading sensitive gaming configuration files such as loginusers.vdf or battle.net.config. This identifies potential credential theft that occurs before the data leaves the host.

The network analysis phase monitors for DNS resolutions to known C2 domains and Polygon smart-contract RPC endpoints. Because REVSTEALER uses these blockchain endpoints as a dead-drop to rotate its final C2 server, identifying this traffic is a key indicator of its resilience mechanism.

A process check identifies task-delivered modules. It baselines execution to find rare instances of modules like ProManager or XMRig. This step highlights the actual impact on the machine, such as resource hijacking or persistent access.

The triage phase uses an automated agent to weigh the evidence across file access, network activity, and process execution. The agent evaluates whether a host shows multiple overlapping indicators. If the agent confirms a malicious verdict, the playbook directs the analyst to isolate the host and initiate session revocation for all potentially compromised accounts.

What the hunt cannot see

This hunt has specific blind spots. It cannot see credential extraction that bypasses file-based monitoring, such as when an adversary uses hardware breakpoints to circumvent App-Bound Encryption in browsers. Additionally, while we monitor for initial Polygon RPC traffic, visibility into the final C2 destination depends on decryption or further behavioral analysis after the smart contract rotation occurs.

  • Needs hb_module_activity with debugger-specific eventing. Traditional file access rules miss the memory-based bypass of browser security, allowing silent extraction of browser-bound keys. It would answer Was App-Bound Encryption bypassed via hardware breakpoints?.

# REVSTEALER: Credential Theft and Follow-on Impact

This hunt targets the core stealing behavior and resilience mechanisms of REVSTEALER. It identifies hosts with targeted gaming or communication software, then correlates this with evidence of sensitive configuration file access, DNS resolutions to Polygon-based dead-drop infrastructure, and the execution of task-delivered impact modules like XMRig. An agent weighs these signals together to identify active account takeovers and resource hijacking across the fleet.
