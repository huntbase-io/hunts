# Hunting REVSTEALER Infostealer Activity and Blockchain-Based Persistence

### Why now 10Elastic Security Labs recently detailed REVSTEALER, an infostealer that harvests credentials and deploys impact modules. The adversary targets users of common gaming and communication software. They use resilient blockchain-based infrastructure for command and control. We published this hunt to address the specific behaviors and persistence mechanisms identified in their report: REVSTEALER ramps up: analysis of up-and-coming infostealer (https://www.elastic.co/security-labs/threat-command/revstealer-credential-harvesting-infostealer).1010### The hypothesis10An intruder has deployed an infostealer to harvest credentials from gaming and communication platforms. The adversary uses blockchain-based fallback infrastructure to maintain C2 and deploys impact modules like miners and proxies.1010### How the hunt flows10The hunt begins with an inventory of targeted software. The first query searches the fleet for packages like Slack, Steam, or qBittorrent. This narrowed list focuses the subsequent analysis on high-risk workstations where lures or targets already exist.1010The second phase runs three concurrent queries to corroborate malicious behavior. The file activity query looks for processes reading sensitive gaming configuration files such as loginusers.vdf or battle.net.config. This identifies potential credential theft that occurs before the data leaves the host.1010The network analysis phase monitors for DNS resolutions to known C2 domains and Polygon smart-contract RPC endpoints. Because REVSTEALER uses these blockchain endpoints as a dead-drop to rotate its final C2 server, identifying this traffic is a key indicator of its resilience mechanism.1010A process check identifies task-delivered modules. It baselines execution to find rare instances of modules like ProManager or XMRig. This step highlights the actual impact on the machine, such as resource hijacking or persistent access.1010The triage phase uses an automated agent to weigh the evidence across file access, network activity, and process execution. The agent evaluates whether a host shows multiple overlapping indicators. If the agent confirms a malicious verdict, the playbook directs the analyst to isolate the host and initiate session revocation for all potentially compromised accounts.1010### What the hunt cannot see10This hunt has specific blind spots. It cannot see credential extraction that bypasses file-based monitoring, such as when an adversary uses hardware breakpoints to circumvent App-Bound Encryption in browsers. Additionally, while we monitor for initial Polygon RPC traffic, visibility into the final C2 destination depends on decryption or further behavioral analysis after the smart contract rotation occurs.1010### How to run it10A simple rule on Polygon RPC endpoints would be too noisy for environments with common cryptocurrency users. This hunt joins those network signals with rare process execution and specific file access to create a high-confidence behavioral picture. To run this investigation, download the hunt.md playbook and import it into Huntbase or any hunt.md-aware runtime.
