GTA VI Fake Installer and Phishing Scams

High severity TLP:CLEAR Part 1 of 2 Research by ESET Research Published 15 Nov 2026

Hypothesis

The adversary exploits GTA VI anticipation by delivering Vidar infostealers through fraudulent storefronts and installers, identifiable by rare DNS resolutions and subsequent credential access from staging directories.

Brief

Why Now

ESET Research recently detailed how scammers exploit GTA VI anticipation in their article GTA VI isn’t out yet – and the scams are already in full swing. The campaign uses fake storefronts like CyberLeek to distribute Vidar malware. Because these attacks rely on social engineering and legitimate-looking installers, they often bypass standard email filters and perimeter defenses that focus on exploit-based delivery.

How the Hunt Flows

The hunt begins with DNS telemetry on the hb_dns_activity surface. The first query identifies hosts that resolved known scam domains or infrastructure containing the cyberleek string. It also identifies rare domains resolved by these same hosts to catch infrastructure pivots. An analyst evaluates these leads to decide if the DNS interaction indicates a likely visit to a scam storefront. Once a lead is qualified, the hunt pivots to endpoint behavior in two parallel paths. The first path uses the hb_file_activity surface to look for rare file creations in common staging directories like Downloads, Temp, or Public folders. These drops represent the fake installer or ISO being placed on the disk by the browser. The second path monitors for processes running from these same staging locations that attempt to read sensitive browser files such as Login Data or Cookies. This behavior is a core signature of Vidar exfiltration. The final phase correlates the initial DNS entry point with the file drops and the credential access behavior. An analyst confirms the verdict of malicious if a process launched from a staging directory accesses profile data shortly after the host interacts with the scam infrastructure.

What the Hunt Cannot See

This hunt relies on visible DNS activity. If a user visits a scam storefront using a browser configured for DNS over HTTPS (DoH), the initial lead query will miss the resolution, and the hunt will not trigger. Additionally, the hunt uses file path rarity rather than file size telemetry. Without precise file size columns, legitimate one-off downloads might trigger the staging file query, requiring manual validation of the installer names.

Steps

  1. Query, scoping

    Lead: DNS resolutions for scam infrastructure

    Identify hosts resolving domains associated with the CyberLeek campaign or fraudulent GTA VI offers, including rare infrastructure seen on those same hosts.

    sql, reads hb_dns_activity
    WITH target_hosts AS (SELECT DISTINCT device_hostname FROM hb_dns_activity WHERE (LOWER(query_hostname) LIKE '%cyberleek%' OR instr(',' || '{{scam_domains}}' || ',', ',' || LOWER(query_hostname) || ',') > 0) AND time >= datetime('now', '-{{lookback_days}} days')) SELECT d.device_hostname, d.query_hostname, d.timeFROM hb_dns_activity dINNER JOIN target_hosts h ON d.device_hostname = h.device_hostnameWHERE d.time >= datetime('now', '-{{lookback_days}} days')GROUP BY 1, 2HAVING (LOWER(d.query_hostname) LIKE '%cyberleek%' OR instr(',' || '{{scam_domains}}' || ',', ',' || LOWER(d.query_hostname) || ',') > 0 OR COUNT(DISTINCT d.device_hostname) < 3)

    What a hit looks like. A list of hostnames and the domains they resolved. Any resolution of a known scam domain or a rare domain on a suspicious host is a hit.

  2. Agent triage

    Evaluate DNS leads

    Assess the initial DNS leads to decide if full forensic queries are justified.

  3. Decision

    Proceed to investigation

    Open expensive behavioral queries only when the DNS lead indicates a likely interaction.

  4. Query, baseline

    Rare files created in staging directories

    Locate rare files dropped in common user-writable directories, which often precede installer execution.

    sql, reads hb_file_activity
    SELECT device_hostname, file_path, file_name, time, COUNT(DISTINCT device_hostname) as fleet_hostsFROM hb_file_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND (LOWER(file_path) LIKE '%\\downloads\\%' OR LOWER(file_path) LIKE '%\\temp\\%' OR LOWER(file_path) LIKE '%\\users\\public\\%')  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY 1, 2, 3HAVING fleet_hosts < 3

    What a hit looks like. Creation of an installer or ISO in a staging folder that appears on very few hosts. Silence in the 10-minute window of the DNS lead suggests no drop occurred.

  5. Query, triage

    Credential store access from staging processes

    Identify non-browser processes launched from staging paths that read sensitive browser files, a core Vidar infostealer behavior.

    sql, reads hb_file_activity
    SELECT device_hostname, process_name, file_path, file_name, timeFROM hb_file_activityWHERE ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND activity_id = 2  AND LOWER(file_name) IN ('login data', 'cookies', 'web data')  AND (LOWER(process_name) LIKE '%\\downloads\\%' OR LOWER(process_name) LIKE '%\\temp\\%' OR LOWER(process_name) LIKE '%\\users\\public\\%')  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Rows showing a process in a temp/download folder reading Chrome or Edge profile data. This is high-confidence evidence of infostealer execution.

  6. Agent triage

    Triage infection verdict

    Determine if the combination of DNS activity, staging-file drops, and credential harvesting confirms an infection.

  7. Decision

    Route on final verdict

    Initiate containment for confirmed infections and manual review for suspicious patterns.

  8. Response action

    Isolate malicious host

    Prevent the infostealer from exfiltrating harvested credentials or session cookies.

  9. Analyst task

    Analyst review

    Perform manual validation of the evidence and refine future lead parameters.

  10. Analyst task

    Close out

    Finalize the hunt and document findings.

  • Needs hb_dns_activity from all endpoints. If the browser performs encrypted DNS, the lead query will not see the resolution, missing the entry point. It would answer: whether the user visited the scam site via a browser using DNS over HTTPS (DoH)
  • Needs hb_file_activity with file size. Without file size columns, the hunt relies on path rarity and behavior, which may increase false positives for legitimate one-off downloads. It would answer: whether the dropped file matches the specific 1.1MB size reported for Vidar

# GTA VI Fake Installer and Phishing Scams

The adversary uses the hype around GTA VI to lure victims into interacting with malicious storefronts and downloading fake installers. The hunt identifies hosts resolving CyberLeek-linked domains or rare infrastructure, then pivots to examine file creation in user-writable directories. Finally, the hunt correlates these drops with unauthorized processes attempting to harvest browser credentials, confirming a Vidar infection.
