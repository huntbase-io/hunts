# Hunting Vidar Infostealers in Fake GTA VI Installers

### Why Now ESET Research recently detailed how scammers exploit GTA VI anticipation in their article [GTA VI isn’t out yet – and the scams are already in full swing](https://www.welivesecurity.com/en/cybersecurity/gta-vi-isnt-out-yet-scams-full-swing/). The campaign uses fake storefronts like CyberLeek to distribute Vidar malware. Because these attacks rely on social engineering and legitimate-looking installers, they often bypass standard email filters and perimeter defenses that focus on exploit-based delivery. ### The Hypothesis The adversary exploits GTA VI anticipation by delivering Vidar infostealers through fraudulent storefronts and installers, identifiable by rare DNS resolutions and subsequent credential access from staging directories. ### How the Hunt Flows The hunt begins with DNS telemetry on the hb_dns_activity surface. The first query identifies hosts that resolved known scam domains or infrastructure containing the cyberleek string. It also identifies rare domains resolved by these same hosts to catch infrastructure pivots. An analyst evaluates these leads to decide if the DNS interaction indicates a likely visit to a scam storefront. Once a lead is qualified, the hunt pivots to endpoint behavior in two parallel paths. The first path uses the hb_file_activity surface to look for rare file creations in common staging directories like Downloads, Temp, or Public folders. These drops represent the fake installer or ISO being placed on the disk by the browser. The second path monitors for processes running from these same staging locations that attempt to read sensitive browser files such as Login Data or Cookies. This behavior is a core signature of Vidar exfiltration. The final phase correlates the initial DNS entry point with the file drops and the credential access behavior. An analyst confirms the verdict of malicious if a process launched from a staging directory accesses profile data shortly after the host interacts with the scam infrastructure. ### What the Hunt Cannot See This hunt relies on visible DNS activity. If a user visits a scam storefront using a browser configured for DNS over HTTPS (DoH), the initial lead query will miss the resolution, and the hunt will not trigger. Additionally, the hunt uses file path rarity rather than file size telemetry. Without precise file size columns, legitimate one-off downloads might trigger the staging file query, requiring manual validation of the installer names. ### How to Run This hunt is an open hunt.md playbook. You can import it into Huntbase or any compatible hunt.md-aware runtime to execute the queries against your telemetry. The playbook gates the resource-intensive behavioral queries behind the initial DNS lead to ensure the hunt remains efficient and only investigates hosts with clear evidence of interaction with the scam campaign.
