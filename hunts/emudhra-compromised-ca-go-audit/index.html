eMudhra Compromised Certificate and Go Runtime Audit

An adversary impersonates a trusted service or signs a malicious binary using a compromised eMudhra intermediate certificate in an environment that lacks strict revocation checking or runs a vulnerable Go runtime.

Brief

Why Now?

Cisco Talos recently published an analysis (https://blog.talosintelligence.com/compromised-intermediate-certificates/) identifying several eMudhra intermediate CA private keys as compromised. These certificates were generated with insufficient entropy, allowing attackers to potentially forge signatures for malicious code or impersonate trusted services.

How the Hunt Flows

The lead step queries module activity to identify any process loading a file signed by eMudhra or emsign. This initial signal narrows the scope from the entire fleet to only those hosts actively interacting with the eMudhra ecosystem. An agent evaluates these results to confirm the context of the module load before proceeding. If the hunt finds active eMudhra signatures, it fans out to examine three distinct surfaces. First, it baselines Go runtime versions across the scoped hosts. This identifies older or rare versions susceptible to CVE-2026-111943, where the runtime fails to properly check certificate revocation lists. Simultaneously, the hunt scans the system certificate stores and the filesystem for the specific fingerprints of the eight compromised intermediate certificates. This determines if the host still maintains a trust relationship with the compromised CA. In the final phase, an agent correlates the findings. A host is marked as high-risk only if it contains a trusted but compromised CA and is either running eMudhra-signed code or using a vulnerable Go runtime. This correlation distinguishes between benign legacy software and genuine exposure to the CA compromise.

What the Hunt Cannot See

This hunt has two primary blind spots. First, it relies on module-level auditing, which may be absent on certain Linux or containerized workloads. Malicious binaries running in these environments might not trigger the lead query. Second, while the hunt identifies compromised certificates in the global store, the underlying schema for certificate discovery requires an agent to map those certificates back to specific local users or device contexts.

# eMudhra Compromised Certificate and Go Runtime Audit

This hunt identifies exposure to eight compromised eMudhra intermediate certificates whose private keys were generated with insufficient entropy. The hunt first finds hosts executing code signed by eMudhra. If it finds such activity, the hunt fans out to identify vulnerable Go runtimes (CVE-2026-111943) that ignore revocation and scans for certificate files matching known compromised fingerprints. An agent then weighs the combination of trust anchors and execution context to help an analyst decide on remediation.
