# Hunting Rogue RMM Delivery via Trusted Service Phishing

### Why hunt for RMM delivery The report Rogue RMM Abuse: How Attackers Exploit Remote Access Tools (https://www.huntress.com/blog/rogue-rmm-abuse-phishing-persistent-access) describes how attackers gain persistence using Remote Monitoring and Management (RMM) tools like ScreenConnect and ITarian. Attackers host these installers on trusted cloud services like Adobe and TransferXL to bypass email security filters. These reputable domains often use encrypted traffic, making the lure content invisible to standard inspection. ### The Hypothesis An adversary compromises a host by delivering a rogue RMM installer through a phishing lure on a legitimate cloud service. The attacker uses the reputation of platforms like Adobe to trick users into downloading and executing software that grants remote control over the endpoint. This method hides the delivery of command-and-control tools within normal business traffic. ### How the hunt flows The hunt begins by inventorying existing RMM software across the fleet. This step establishes a baseline of authorized activity. A wide distribution of a tool often suggests an IT-managed deployment, while a single instance on a workstation signals a potential threat. Next, the hunt runs two parallel queries to gather evidence. One query monitors HTTP connections to known lure-hosting domains like indesign.adobe.com or transferxl.com. Simultaneously, another query searches for the arrival of rare RMM-related binaries, filtering for file names like ScreenConnect or ITarian and extensions such as .msi or .exe. An agent then triages these findings. It looks for a specific sequence where a visit to a lure domain precedes the download of a rare RMM installer on the same host. This correlation separates rogue installations from authorized IT updates that might otherwise trigger false positives. ### Blind Spots The hunt has two primary blind spots. Encrypted web traffic hides the specific URL paths on domains like Adobe. An analyst sees the connection to the trusted host but cannot confirm the click or the download content without full TLS inspection. Additionally, if an attacker renames the installer to a generic name like setup.exe, the keyword-based file query will not catch the arrival. The hunt then depends on execution activity to identify the threat. ### How to run this hunt This hunt is provided as an open hunt.md playbook. It imports directly into Huntbase or any hunt.md-aware runtime for immediate execution. Analysts should focus their initial review on workstations where RMM software is not part of the standard build. This targeted approach ensures that the most suspicious activity is prioritized before expanding the hunt to the rest of the fleet.
