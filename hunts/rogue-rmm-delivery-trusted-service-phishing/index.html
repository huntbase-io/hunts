Rogue RMM Delivery via Trusted Service Phishing

Medium severity TLP:CLEAR Part 1 of 2 Research by Huntress Published 25 Sep 2026

Hypothesis

An attacker has compromised a host by delivering a rogue RMM installer (ScreenConnect or ITarian) via phishing lures hosted on legitimate cloud services like Adobe or TransferXL, bypassing traditional email security filters.

Brief

Why hunt for

RMM delivery The report Rogue RMM Abuse: How Attackers Exploit Remote Access Tools (https://www.huntress.com/blog/rogue-rmm-abuse-phishing-persistent-access) describes how attackers gain persistence using Remote Monitoring and Management (RMM) tools like ScreenConnect and ITarian. Attackers host these installers on trusted cloud services like Adobe and TransferXL to bypass email security filters. These reputable domains often use encrypted traffic, making the lure content invisible to standard inspection.

How the hunt flows

The hunt begins by inventorying existing RMM software across the fleet. This step establishes a baseline of authorized activity. A wide distribution of a tool often suggests an IT-managed deployment, while a single instance on a workstation signals a potential threat. Next, the hunt runs two parallel queries to gather evidence. One query monitors HTTP connections to known lure-hosting domains like indesign.adobe.com or transferxl.com. Simultaneously, another query searches for the arrival of rare RMM-related binaries, filtering for file names like ScreenConnect or ITarian and extensions such as .msi or .exe. An agent then triages these findings. It looks for a specific sequence where a visit to a lure domain precedes the download of a rare RMM installer on the same host. This correlation separates rogue installations from authorized IT updates that might otherwise trigger false positives.

Blind Spots

The hunt has two primary blind spots. Encrypted web traffic hides the specific URL paths on domains like Adobe. An analyst sees the connection to the trusted host but cannot confirm the click or the download content without full TLS inspection. Additionally, if an attacker renames the installer to a generic name like setup.exe, the keyword-based file query will not catch the arrival. The hunt then depends on execution activity to identify the threat.

  1. Query, scoping

    Inventory of existing RMM software

    Identify hosts that already have the RMM tools mentioned in the report to provide baseline context for the analyst.

    What a hit looks like. A list of hosts with matching software; widespread presence usually indicates approved IT tools, while isolated instances warrant closer inspection.

  2. Query, detection candidate

    Lure web traffic

    Find connections to the trusted domains hosting the malicious lures.

    sql, reads hb_http_activity
    SELECT device_hostname, url_hostname, url_full, timeFROM hb_http_activityWHERE instr(',' || '{{lure_domains}}' || ',', ',' || LOWER(url_hostname) || ',') > 0  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')

    What a hit looks like. Hosts visiting Adobe or TransferXL domains; zero results suggest the initial phishing link was not clicked.

  3. Query, baseline

    Rare RMM payload drops

    Identify RMM installers arriving on disk that are rare across the fleet, suggesting unauthorized installation.

    sql, reads hb_file_activity
    SELECT device_hostname, file_name, file_path, COUNT(DISTINCT device_hostname) AS host_count, MIN(time) AS first_seenFROM hb_file_activityWHERE (LOWER(file_name) LIKE '%.exe' OR LOWER(file_name) LIKE '%.msi' OR LOWER(file_name) LIKE '%.zip' OR LOWER(file_name) LIKE '%.pdf')  AND (instr(',' || '{{rmm_keywords}}' || ',', ',' || LOWER(file_name) || ',') > 0 OR LOWER(file_name) LIKE '%itarian%' OR LOWER(file_name) LIKE '%screenconnect%')  AND ('{{scope_hosts}}' = '' OR instr(',' || '{{scope_hosts}}' || ',', ',' || device_hostname || ',') > 0)  AND time >= datetime('now', '-{{lookback_days}} days')GROUP BY file_name, file_pathHAVING host_count <= 3

    What a hit looks like. Rare RMM-themed binaries; common IT updaters appearing on dozens of hosts are ignored.

  4. Agent triage

    Triage RMM delivery chain

    Correlate the software inventory, lure traffic, and rare file drops to confirm a rogue RMM installation.

  5. Decision

    Route on verdict

    Direct high-confidence hits to containment and lower-confidence hits to manual review.

  6. Response action

    Isolate host

    Immediately sever the attacker's remote connection via the rogue RMM.

  7. Analyst task

    Forensic investigation

    Investigate the isolated host for secondary RMM stacking and persistence.

  8. Analyst task

    Remediation and tuning

    Finalize the hunt by updating RMM inventory and tuning detection rules.

# Rogue RMM Delivery via Trusted Service Phishing

This hunt identifies the early stages of RMM abuse where attackers use legitimate document-sharing platforms to deliver installers. It correlates web-based lure visits on Adobe and TransferXL with the subsequent arrival of RMM-related binaries on the same endpoints. By identifying these transitions, the hunt distinguishes unauthorized rogue RMM deployments from legitimate IT operations. An agent weighs the timing and rarity of these events to confirm an intrusion.


## forensic-investigation
<!-- Forensic investigation -->
```manual target=analyst
Search for secondary RMM installations (ScreenConnect, ITarian) and defense evasion binaries like HideUL_x64.exe on the host. Verify if the ZIP/PDF lure resulted in execution via hb_process_activity.
```
→ remediation-and-tuning

## remediation-and-tuning
<!-- Remediation and tuning -->
```manual target=analyst
Record the findings in the incident report. Update the authorized RMM software inventory to include any newly discovered legitimate tools found during the baseline step.
```
