Brief

Behind the Manufactured Reality Business Email Compromise

(BEC) often involves more than just credential harvesting. As detailed by Rapid7 in "When Business Email Compromise Starts Rewriting Reality" (https://www.rapid7.com/blog/post/ve-business-email-compromise-rewriting-reality-zimbra-cve), attackers can compromise mail servers like Zimbra to manipulate the organization's perception of truth. This hunt focuses on identifying the "manufactured reality" phase, where an adversary alters the system of record to facilitate fraud.

The Hunt Flow

The hunt begins by identifying authoritative Zimbra collaboration servers within the environment. We use software inventory data to focus the investigation on the mail backbone. This scoping ensures we do not waste time on user workstations or irrelevant servers. Once we identify the servers, the hunt executes two parallel checks. First, it stacks administrative command lines to find rare uses of the "zmprov" utility that modify account settings or set the "zimbraMailForwardingAddress" attribute. Attackers use these commands to silently redirect sensitive communications to external accounts. Second, it looks for outbound network connections from the Zimbra server process to external meeting platforms like Zoom, Teams, or Webex. Zimbra servers typically do not initiate these connections directly; users do from their endpoints. A server-initiated connection suggests an attacker is manipulating calendar invitations or staging meetings. Finally, an analyst triages the evidence. We look for hosts that show both administrative manipulation and anomalous network activity. This correlation provides the evidence needed to distinguish routine maintenance from an active BEC campaign.

Blind Spots

This hunt relies on OS-level visibility. It cannot see internal Zimbra database changes, such as an attacker deleting items from the "Sent" folder or flipping RSVP statuses via the application's internal logic. These actions leave no process or file logs. Similarly, the hunt identifies that a file was modified on a shared drive, but it cannot inspect the content to determine if a financial summary or HR memo was maliciously altered.

Running the Hunt

This hunt is provided as an open hunt.md playbook. You can import it into Huntbase or any other hunt.md-aware runtime to automate the data collection and correlation. Because it uses prevalence baselines and behavioral correlation across different surfaces, it identifies patterns that a static detection rule would miss.

# Zimbra BEC: Manufactured Reality and Manipulation

This hunt targets the manufactured reality phase of Business Email Compromise (BEC) within Zimbra environments. Unlike simple data theft, this attack involves altering the organization's system of record to gaslight users and facilitate fraud. We hunt for two primary behavioral indicators: the use of Zimbra administrative tools to silently configure mail forwarding and server-initiated network connections to meeting platforms like Zoom. These patterns indicate an attacker is actively shaping the communication environment to prop up fraudulent narratives.

<!-- Prevalence of mail forwarding commands -->
Stack-count administrative commands that set mail forwarding to identify rare or unauthorized redirection across the Zimbra fleet.

